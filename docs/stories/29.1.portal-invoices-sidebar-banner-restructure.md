# Story 29.1 - Reestruturar Faturas no Portal: Sidebar Separado + Banner de Urgencia com Receita

## Epic
Epic 29 - Portal Invoice UX Improvement

## Contexto
Atualmente, "Faturas" esta no sidebar principal junto com itens que dependem de loja ativa (Dashboard, Campanhas, Flows, etc.). Faturas e por **cliente**, nao por loja, o que cria confusao no modelo mental do usuario. Alem disso, faturas pendentes/vencidas nao tem visibilidade suficiente.

## Objetivo
1. Separar o sidebar em duas secoes: **"Menu"** (itens por loja) e **"Conta"** (itens por cliente)
2. Adicionar um **banner de urgencia** no topo do conteudo quando ha fatura pendente/vencida
3. Mostrar no banner a **receita gerada pela Convertfy** no periodo (ultimos 30d) como justificativa de valor

## Acceptance Criteria

### AC 29.1.1 - Sidebar separado em secoes
**GIVEN** o usuario portal esta autenticado
**WHEN** o sidebar renderiza (desktop ou mobile)
**THEN** exibe secao "Menu" com 6 itens (Dashboard, Analise, Campanhas, Flows, Integracoes, Rastreamento)
**AND** exibe secao "Conta" separada por divider com 2 itens (Faturas, Configuracoes)
**AND** secao "Conta" fica apos "Menu" e antes do footer (Store Switcher + Avatar)
**AND** "Faturas" e "Configuracoes" NAO aparecem mais no dropdown do avatar

### AC 29.1.2 - Banner de urgencia com soma de faturas
**GIVEN** o usuario tem permissao `view_invoices = true`
**AND** existem faturas pendentes (vencimento <= 5 dias) ou vencidas
**WHEN** qualquer pagina do portal carrega (exceto `/portal/invoices`)
**THEN** um banner aparece no topo do conteudo com contagem, soma total e CTA
**AND** o banner e amber para pendente, vermelho para vencida (overdue tem prioridade)

### AC 29.1.3 - Banner mostra receita gerada quando favoravel
**GIVEN** o banner esta visivel com faturas pendentes/vencidas
**AND** a receita atribuida ao Klaviyo (cache `store_revenue_summary` 30d) e >= total das faturas
**WHEN** o banner renderiza
**THEN** exibe "Receita gerada pela Convertfy: R$ X" com destaque visual
**AND** os dados vem exclusivamente do cache Supabase (zero chamadas Klaviyo/Asaas)

### AC 29.1.4 - Receita nao exibida quando desfavoravel
**GIVEN** a receita no cache e menor que o total das faturas OU e zero OU nao ha dados de cache
**WHEN** o banner renderiza
**THEN** o bloco de receita NAO aparece
**AND** o banner mostra apenas o valor das faturas normalmente

### AC 29.1.5 - Banner nao aparece quando desnecessario
**GIVEN** todas as faturas estao pagas/canceladas OU usuario nao tem permissao OU esta em `/portal/invoices`
**WHEN** a pagina carrega
**THEN** nenhum banner aparece

### AC 29.1.6 - Badge no sidebar
**GIVEN** existe fatura pendente ou vencida
**WHEN** o sidebar renderiza
**THEN** o item "Faturas" na secao "Conta" exibe um dot vermelho
**AND** o dot pulsa se a fatura esta vencida

### AC 29.1.7 - Endpoint leve e seguro
**GIVEN** o banner precisa de dados
**WHEN** o fetch e feito para `/api/portal/invoices/status`
**THEN** a resposta contem soma das faturas + receita do cache
**AND** nenhuma chamada ao Asaas ou Klaviyo e feita
**AND** a latencia e < 200ms
**AND** dados de receita vem APENAS das lojas do cliente autenticado (isolamento multi-tenant)

## Decisoes Tecnicas

| Decisao | Escolha | Razao |
|---------|---------|-------|
| State management | Estado local no componente | Portal nao usa Zustand; dado consumido em ponto unico |
| Endpoint | Novo `/invoices/status` leve | Evita N chamadas Asaas no layout |
| Dismiss do banner | Nao dismissivel | Fatura e urgencia financeira real |
| Ciclo de fetch | Mount + CustomEvent `invoice-status-loaded` | Layout nao re-monta no App Router |
| Links de pagamento | Lazy (so na pagina `/invoices`) | Nao chamar Asaas no banner |
| Fonte de receita | `store_revenue_summary` com `period_label = '30d'` | Cache existente, zero chamadas Klaviyo, ~80ms |
| Periodo da receita | Ultimos 30 dias (rolling window) | Nao existe cache mensal; 30d e proxy razoavel |
| Guard de receita | `receita >= totalPending + totalOverdue` | Evitar efeito contrario se receita for baixa |
| Label da receita | "Receita gerada pela Convertfy" | Decisao do PO |
| Fallback Klaviyo | NUNCA no banner | Rate limits criticos (~1 req/s); cron e o unico responsavel pelo cache |
| Moeda | Usar apenas lojas BRL ou aplicar conversao existente | Evitar soma de moedas diferentes |

## Riscos

| Risco | Severidade | Mitigacao |
|-------|-----------|-----------|
| Receita baixa/zero tem efeito contrario | Critico | Guard: so exibir se `receita >= total faturas` |
| Cross-tenant data leak via store_id | Critico | Chain: `client_id -> client_stores -> store_revenue_summary` |
| Fetch extra no layout | Alto | Endpoint leve ~80ms, sem Asaas/Klaviyo |
| Periodo 30d nao corresponde ao mes da fatura | Medio | Label honesto: "Receita dos ultimos 30 dias". V2: cache mensal |
| Cache desatualizado | Medio | Dados vem do cron; nao fazer fallback live |
| Permissao nao disponivel no layout | Medio | API retorna 403 -> banner nao renderiza |
| Double-fetch em `/portal/invoices` | Baixo | Banner se esconde nessa rota (`startsWith`) |
| Race condition navegacao rapida | Medio | AbortController no useEffect |
| Cliente sem lojas / sem cache | Baixo | Bloco de receita nao aparece, sem erro |
| Moedas mistas (BRL + USD) | Baixo | Filtrar por currency ou usar conversao existente |

## Fonte de Dados para Receita

```
Query chain:
1. client_portal_users.client_id (auth)
2. client_stores WHERE client_id = X AND is_active = true -> [store_ids]
3. store_revenue_summary WHERE store_id IN ([store_ids]) AND period_label = '30d' AND sync_status IN ('ok', 'partial')
4. SUM(klaviyo_total_revenue) -> revenueGenerated
5. Guard: showRevenue = (revenueGenerated >= totalPending + totalOverdue)
```
