# Story 57.6 — Bundle: rate limit failClosed + OAuth error sanitization + user enumeration

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint"]

## Story

**Como** engenheiro de segurança,
**Quero** corrigir 3 achados de severidade média em um único PR,
**Para que** a superfície de ataque em endpoints de autenticação e OAuth seja reduzida.

## Contexto

3 achados MEDIUM da security review que são pequenos, correlacionados (auth/security hardening) e podem ser corrigidos juntos:

1. **Rate limit fail-open**: Se Redis cair, requests passam sem rate limiting
2. **OAuth error reflection**: Parâmetro `error` do OAuth refletido sem sanitização na redirect URL
3. **User enumeration**: Reset de senha retorna erros diferentes para "não existe" vs "inválido"

## Acceptance Criteria

### 57.6.1 — Rate limit failClosed em endpoints de autenticação

- [x] Identificar todos os endpoints de auth que usam `checkRateLimit()`
- [x] Garantir que endpoints críticos (login, reset-password, verify) usem `failClosed: true`
- [x] Se Redis estiver indisponível e `failClosed: true`, retornar 503 Service Unavailable

**Given-When-Then:**

```
GIVEN Redis is unavailable
AND auth endpoint uses failClosed: true
WHEN user makes request to auth endpoint
THEN response is 503 Service Unavailable
AND request is NOT processed
```

### 57.6.2 — Sanitizar erro OAuth em redirects

- [x] Em `src/app/api/integrations/meta/callback/route.ts` (linha ~21): usar códigos de erro predefinidos
- [x] Em `src/app/api/integrations/google/callback/route.ts` (linha ~31): idem
- [x] Lista de códigos válidos: `access_denied`, `server_error`, `invalid_scope`, `unknown_error`
- [x] Qualquer erro fora da lista → mapear para `unknown_error`

**Given-When-Then:**

```
GIVEN Meta OAuth returns error=<script>alert(1)</script>
WHEN callback processes the error
THEN redirect URL contains error=unknown_error (not the raw error)
```

### 57.6.3 — Resposta genérica no reset de senha

- [x] Em `src/app/api/portal-users/reset-password/route.ts`: quando portal user não encontrado, retornar mesma resposta de sucesso (200) sem indicar se o usuário existe
- [x] Log interno mantido para debugging

**Given-When-Then:**

```
GIVEN userId does not exist in portal_users
WHEN admin calls POST /api/portal-users/reset-password
THEN response is 200 with { success: true } (same as success case)
AND server logs warn about non-existent user (for debugging)
AND no email is sent (obviously)
```

### 57.6.4 — Typecheck

- [x] `npm run typecheck` passa sem erros novos
