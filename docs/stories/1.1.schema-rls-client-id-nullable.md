## Story

**As a** administrador do sistema,
**I want** que o banco de dados suporte lojas sem `client_id`,
**so that** a equipe comercial possa cadastrar lojas de forma independente.

## Acceptance Criteria

1. Migration criada: `client_stores.client_id` e nullable (`ALTER COLUMN client_id DROP NOT NULL`)
2. FK `REFERENCES clients(id) ON DELETE CASCADE` mantida (nao remover, apenas tornar nullable)
3. RLS INSERT policy atualizada para aceitar `client_id IS NULL` para admins e comercial
4. Trigger `set_store_org_id()` criado: preenche `org_id` via `current_org_id()` automaticamente quando NULL no INSERT (garante consistencia a nivel de banco)
5. Indice parcial criado: `CREATE INDEX idx_client_stores_orphan ON client_stores(org_id) WHERE client_id IS NULL`
6. Lojas existentes nao sao afetadas (todas mantem `client_id` atual — nenhum UPDATE em dados existentes)
7. RLS SELECT, UPDATE e DELETE policies continuam funcionando sem mudanca
8. **[ARCH-C2]** `store_alerts.client_id` tornado nullable (`ALTER COLUMN client_id DROP NOT NULL`) — lojas avulsas precisam gerar alertas
9. **[ARCH-C3]** `store_onboarding_data.client_id` tornado nullable (`ALTER COLUMN client_id DROP NOT NULL`) — lojas avulsas precisam de onboarding
10. **[ARCH-AD2]** Novos valores adicionados ao enum `activity_type`: `store_created`, `store_linked`, `store_unlinked` — para audit trail de vinculo/desvinculo
11. **[GAP-G3]** `client_onboardings.client_id` tornado nullable (`ALTER COLUMN client_id DROP NOT NULL`) — lojas avulsas podem ter onboarding ativo

**RLS INSERT policy atual (de 20250215):**
```sql
CREATE POLICY "Users can insert client_stores" FOR INSERT
  WITH CHECK (is_admin() OR can_access_client(client_id));
```

**Deve ser alterada para:**
```sql
CREATE POLICY "Users can insert client_stores" FOR INSERT
  WITH CHECK (is_admin() OR client_id IS NULL OR can_access_client(client_id));
```

**RLS helpers disponiveis (de 20250125_05):**
- `current_org_id()` — retorna org_id do usuario logado via `org_members`
- `is_admin()` — verifica `profiles.role = 'admin'`
- `can_access_client(p_client_id)` — admin, org owner, ou tem `can_view` em alguma loja do cliente

**Decisao arquitetural (AD1) — org_id via Trigger:**

Usar TRIGGER ao inves de logica na aplicacao. Isso garante consistencia a nivel de banco — qualquer INSERT (API, RPC, migration futura) tera `org_id` preenchido automaticamente.

```sql
CREATE OR REPLACE FUNCTION set_store_org_id()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.org_id IS NULL THEN
    NEW.org_id := current_org_id();
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER trg_set_store_org_id
  BEFORE INSERT ON client_stores
  FOR EACH ROW EXECUTE FUNCTION set_store_org_id();
```

**Tabelas satelite que precisam de client_id nullable (descoberto na revisao arquitetural):**

- `store_alerts` — tabela em `supabase/migrations/20260223_store_alerts.sql` tem `client_id UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE`. SEM ISSO, lojas avulsas NAO geram alertas. **(ARCH-C2)**
- `store_onboarding_data` — tabela em `supabase/migrations/20260220_store_onboarding_system.sql` tem `client_id UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE`. A FK principal ja e `store_id UNIQUE`. **(ARCH-C3)**

**Novos activity types (AD2 — Audit Trail):**

O projeto usa a tabela `activities` (de `00001_initial_schema.sql`) com enum `activity_type`. Adicionar:
- `store_created` — quando loja avulsa e criada
- `store_linked` — quando loja e vinculada a cliente
- `store_unlinked` — quando loja e desvinculada

NOTA: `ALTER TYPE ... ADD VALUE` nao pode rodar dentro de transaction no PostgreSQL — executar em statement separado na migration.

**Migration SQL consolidada recomendada:**

```sql
-- Parte 1: Enum (fora de transaction)
ALTER TYPE activity_type ADD VALUE IF NOT EXISTS 'store_created';
ALTER TYPE activity_type ADD VALUE IF NOT EXISTS 'store_linked';
ALTER TYPE activity_type ADD VALUE IF NOT EXISTS 'store_unlinked';

-- Parte 2: Schema changes (em transaction)
BEGIN;

-- client_stores
ALTER TABLE client_stores ALTER COLUMN client_id DROP NOT NULL;
CREATE INDEX IF NOT EXISTS idx_client_stores_orphan
  ON client_stores(org_id) WHERE client_id IS NULL;

-- store_alerts (ARCH-C2)
ALTER TABLE store_alerts ALTER COLUMN client_id DROP NOT NULL;

-- store_onboarding_data (ARCH-C3)
ALTER TABLE store_onboarding_data ALTER COLUMN client_id DROP NOT NULL;

-- Trigger para org_id automatico (AD1)
CREATE OR REPLACE FUNCTION set_store_org_id()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.org_id IS NULL THEN
    NEW.org_id := current_org_id();
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER trg_set_store_org_id
  BEFORE INSERT ON client_stores
  FOR EACH ROW EXECUTE FUNCTION set_store_org_id();

-- RLS INSERT policy
DROP POLICY IF EXISTS "Users can insert client_stores" ON client_stores;
CREATE POLICY "Users can insert client_stores"
  ON client_stores FOR INSERT TO authenticated
  WITH CHECK (
    is_admin()
    OR client_id IS NULL
    OR can_access_client(client_id)
  );

COMMIT;
```
