# Story 23.2 -- Validacao Server-Side + CHECK Constraints no Banco

## Status
Ready for Review

## Story

**Como** sistema,
**Quero** validar valores monetarios no backend e no banco de dados,
**Para que** valores invalidos (zero, negativos, absurdos) sejam rejeitados como rede de seguranca.

---

## Dependencia

> Story 23.1 deve ser concluida primeiro (frontend fix).
> Esta story adiciona camada extra de protecao server-side.

## Contexto

Atualmente as API routes de cobranças, assinaturas e contratos NAO validam o range dos valores recebidos. O valor do body JSON e passado direto para o Supabase/Asaas. Alem disso, as colunas `value`/`monthly_value` no banco nao tem CHECK constraints -- aceitam zero e negativos.

### Auditoria do schema atual

| Tabela | Coluna | Tipo | Constraints |
|--------|--------|------|-------------|
| `client_charges` | `value` | `numeric(10,2)` | NOT NULL (sem CHECK) |
| `client_subscriptions` | `value` | `numeric(10,2)` | NOT NULL (sem CHECK) |
| `contracts` | `monthly_value` | `numeric(10,2)` | NOT NULL (sem CHECK) |

- [x] `src/app/api/integrations/asaas/charges/route.ts` (POST):

  - Validar `value` com `validateMonetaryValue(value)`
  - Rejeitar com 400 se invalido

- [x] `src/app/api/clients/contracts/route.ts` (POST):
  - Validar `monthly_value` com `validateMonetaryValue(monthly_value, "Valor mensal")`

### 23.2.4 -- CHECK constraints no banco de dados

- [x] Criar migration Supabase com:
  ```sql
  ALTER TABLE client_charges
    ADD CONSTRAINT client_charges_value_range
    CHECK (value > 0 AND value <= 99999999.99);

  ALTER TABLE client_subscriptions
    ADD CONSTRAINT client_subscriptions_value_range
    CHECK (value > 0 AND value <= 99999999.99);

  ALTER TABLE contracts
    ADD CONSTRAINT contracts_monthly_value_range
    CHECK (monthly_value > 0 AND monthly_value <= 99999999.99);
  ```
- [x] Documentar rollback:
  ```sql
  ALTER TABLE client_charges DROP CONSTRAINT client_charges_value_range;
  ALTER TABLE client_subscriptions DROP CONSTRAINT client_subscriptions_value_range;
  ALTER TABLE contracts DROP CONSTRAINT contracts_monthly_value_range;
  ```
- [x] Verificar que nao ha registros existentes que violem o constraint antes de aplicar

### 23.2.5 -- Helper de validacao compartilhado

- [x] Criar funcao reutilizavel em `src/lib/schemas/common.ts`:
  ```typescript
  export function validateMonetaryValue(value: unknown, fieldName: string = "Valor"): number {
    const num = Number(value)
    if (!Number.isFinite(num) || num <= 0 || num > 99999999.99) {
      throw new AppError(
        `${fieldName} invalido. Deve ser positivo e menor que R$ 100.000.000`,
        400
      )
    }
    return num
  }
  ```
- [x] Usar em todas as API routes de 23.2.1 a 23.2.3

## Dev Notes

- As tabelas estao vazias ou com dados validos (auditoria confirmou). CHECK constraints podem ser aplicados sem risco.
- `AppError` ja existe no projeto e e o padrao para erros em API routes.
- Asaas tem limites proprios por billing type, mas a validacao aqui e generica (> 0). Limites especificos do Asaas sao tratados pela propria API.
- CHECK constraints incluem upper bound (`<= 99999999.99`) para alinhar com validacao da API e limite do `numeric(10,2)`.
- Verificar se `src/lib/schemas/common.ts` ja existe. Se nao, criar o arquivo.
