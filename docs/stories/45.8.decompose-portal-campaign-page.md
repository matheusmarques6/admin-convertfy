# Story 45.8 — Decompose Portal Campaign Page Into Focused Components

## Status: Ready for Review
## Effort: HIGH (3-4h)
## Priority: MEDIUM

## Context

`src/app/client/campaigns/page.tsx` is a 1309-line monolith containing inline sub-components, render functions, modals, stats, filters, and the calendar grid. This makes it impossible to test individual pieces, prevents `React.memo` boundaries, and creates maintenance burden.

## Target Structure

```
src/app/client/campaigns/
  page.tsx                          # ~150 lines: compose components, wire hook

src/components/calendar/
  calendar-grid.tsx                 # Generic <CalendarGrid> with render props for day cells
  calendar-day-cell.tsx             # Individual day cell with campaign slots
  calendar-navigation.tsx           # < Month Year > Today

src/components/campaigns/
  campaign-stats-bar.tsx            # Grid of 4 StatCards (open rate, sent, recipients, revenue)
  campaign-filter-bar.tsx           # Store + Channel + Status dropdowns
  campaign-calendar-card.tsx        # Compact campaign card for grid cells
  campaign-detail-modal.tsx         # Full campaign detail dialog with metrics
  campaign-day-list-modal.tsx       # List of campaigns for a clicked day
```

## Guidelines

- Each component should have a clear single responsibility
- Use `React.memo` on `CalendarDayCell` and `CampaignCalendarCard` (rendered many times)
- Props should be typed explicitly — no `any`
- Keep state management in page.tsx + hook — components are presentational
- `CalendarGrid` should accept a generic render function for day content (enables admin reuse)
