## Contexto

Dois problemas de concorrencia foram identificados no live fetch:

### Problema 1: Race Condition — Live upsert destrói campos do cron

O cron popula `store_revenue_summary` com dados completos: `klaviyo_total_revenue`, `klaviyo_campaign_revenue`, `klaviyo_flow_revenue`, `store_total_revenue`, e campos de audience (adicionados na migration `20260228_add_audience_to_revenue_summary.sql`).

O live fetch faz upsert do mesmo row com `onConflict: "store_id,period_label"`, mas NAO inclui os campos de audience (`total_leads`, `engaged_leads`, etc). O upsert do Supabase (PostgreSQL) substitui apenas os campos especificados, mas se o live fetch roda DEPOIS do cron, o `updated_at` muda e o `sync_source` vira `'live'`, mesmo que os dados do cron fossem mais completos.

Pior cenario: cron roda, popula audience. Live fetch roda 30s depois (usuario abre dashboard), sobrescreve `fetched_at` e `sync_source` mas nao toca audience. Porem se uma futura Story adicionar audience ao live fetch, o upsert sem audience zeraria esses campos.

### Problema 2: Timeout 50s descarta lojas silenciosamente

Em `total-revenue/route.ts`, o live fetch usa `Promise.allSettled` com timeout de 50 segundos. Lojas que nao completam sao simplesmente descartadas da response — o usuario ve menos lojas sem nenhum indicador de que algo deu timeout.

---

## Objetivo

1. Proteger campos do cron contra sobrescrita pelo live fetch usando upsert seletivo
2. Registrar timeouts no cache para que o usuario saiba que dados estao incompletos

  ```typescript
  // OPCAO A: Upsert condicional — nao sobrescreve se cron escreveu depois

  //   UPDATE store_revenue_summary
  //   SET klaviyo_total_revenue = $1, ...
  //   WHERE store_id = $2 AND period_label = $3
  //     AND (sync_source = 'live' OR fetched_at < $4)

  // OPCAO B (mais simples): Live fetch sempre escreve, mas preserva
  // campos que nao possui. Garantir que o upsert do live NUNCA

  ```

  ```typescript
  // IMPORTANTE: Live fetch upsert NUNCA deve incluir campos que

  // Se precisar adicionar audience ao live fetch no futuro,
  // usar merge condicional (não upsert cego).
  ```

### Timeout Handling

- [x] **11.6.3** Quando o live fetch timeout (50s), registrar as lojas que nao completaram no log E na response:
  ```typescript
  // Apos Promise.allSettled com timeout, identificar lojas que falharam:
  const timedOutStores = stores.filter(
    (s) => !collectedStoreIds.has(s.id)
  )

  if (timedOutStores.length > 0) {
    log.warn("[LiveFetch] Stores timed out:", {
      timedOut: timedOutStores.map(s => s.store_name),
      timeout: "50s",
    })
  }
  ```

- [x] **11.6.4** Para lojas que deram timeout, gravar no cache com `sync_status: 'error'` e `sync_error: 'timeout'`:
  ```typescript
  // Fire-and-forget: mark timed out stores in cache
  for (const store of timedOutStores) {
    adminSupabase.from("store_revenue_summary").upsert({
      store_id: store.id,
      org_id: store.org_id || orgId,
      period_label: period,
      klaviyo_total_revenue: 0,
      klaviyo_campaign_revenue: 0,
      klaviyo_flow_revenue: 0,
      currency: "BRL",
      sync_status: "error",
      sync_source: "live",
      sync_error: "Live fetch timeout (50s)",
      expires_at: new Date(Date.now() + 5 * 60 * 1000).toISOString(), // retry in 5min
      fetched_at: new Date().toISOString(),
    }, { onConflict: "store_id,period_label" })
      .then(() => log.info(`[LiveFetch] Marked ${store.store_name} as timed out`))
      .catch(() => {}) // best-effort
  }
  ```

## Arquitetura Tecnica

### Fluxo de Protecao

```
Cron sync (a cada 2h):
  -> Popula ALL fields (revenue + audience + store_total_revenue)
  -> sync_source: 'cron', expires_at: +6h

Live fetch (on-demand, user opens dashboard):
  -> Popula ONLY revenue fields
  -> sync_source: 'live', expires_at: +6h
  -> NAO toca audience fields (safe upsert)

Query do dashboard:
  -> Le do cache (qualquer sync_source)
  -> hasPartialData = true se algum row tem sync_status: 'error'
```

### Timeout Detection

O live fetch em `total-revenue/route.ts` ja usa `Promise.allSettled` com race contra um timer. Apos o settled, verificar quais stores nao retornaram resultado:

```typescript
// Pseudocode do fluxo existente:
const results = await Promise.allSettled(
  stores.map(store => fetchWithTimeout(store, 50_000))
)

// Identificar timeouts:
const collectedStoreIds = new Set(collected.map(c => c.storeId))
const timedOutStores = stores.filter(s => !collectedStoreIds.has(s.id))
```

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
