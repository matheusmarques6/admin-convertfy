## Story

**Como** usuario do portal do cliente,
**Quero** que o sistema valide se o storeId salvo no localStorage ainda e valido antes de usa-lo,
**Para que** eu nao receba dados vazios por causa de um ID de loja invalido ou de outro cliente.

---

## Contexto

A maioria das paginas do portal (dashboard, analytics, flows, integrations) leem
`localStorage.getItem("portal_active_store")` para determinar qual loja buscar dados.
**Nota:** `campaigns/page.tsx` NAO le localStorage — usa dropdown com default "all".

Varios cenarios fazem esse valor ficar invalido:

1. **Primeiro acesso**: chave nao existe → `storeId = null` → API sem store_id
2. **Store deletada**: admin removeu a loja, mas localStorage ainda tem o ID antigo
3. **Outro cliente logou**: browser compartilhado, localStorage tem store de outro client
4. **Modo incognito**: localStorage pode nao funcionar
5. **Corrupcao**: valor nao e UUID valido

Quando `storeId` e invalido, a API retorna `{ campaigns: [], totalCount: 0 }` silenciosamente
(200 OK) sem indicar erro.

---

## Criterios de Aceitacao

- [ ] **CA1**: Ao carregar portal, validar que `portal_active_store` do localStorage
      existe na lista de stores retornada por `/api/portal/stores`
- [ ] **CA2**: Se storeId invalido/inexistente, limpar localStorage e usar primeira store da lista
- [ ] **CA3**: Se lista de stores esta vazia, mostrar mensagem "Nenhuma loja configurada"
      em vez de dados zerados
- [ ] **CA4**: Ao fazer logout, limpar `portal_active_store` do localStorage
- [ ] **CA5**: Validar formato UUID antes de enviar para API
- [ ] **CA6**: Typecheck + lint passando
