# Story 41.3 — Hook usePortalCampaignsCalendar + Tipos Atualizados

## Story

**Como** desenvolvedor frontend mantendo o calendario de campanhas do portal,
**Quero** um hook dedicado com SWR e tipos atualizados para campanhas com metricas,
**Para que** a page.tsx fique limpa e o carregamento de metricas seja eficiente (lazy loading no modal).

## Contexto

### Estado atual

A `page.tsx` do calendario de campanhas (`src/app/client/campaigns/page.tsx`) contem toda a logica de estado inline: navegacao de mes, selecao de campanha, fetch de dados, filtros. Isso dificulta manutencao e nao suporta lazy loading de metricas detalhadas.

### Mudancas

1. **Atualizar interface `PortalCampaign`** — adicionar campos de metricas retornados pela API
2. **Criar hook `usePortalCampaignsCalendar`** — extrair logica de estado + SWR para lista e metricas detalhadas

### Padrao SWR lazy

O hook usa SWR com key condicional para metricas detalhadas:
- Key `null` quando modal fechado -> SWR nao faz fetch
- Key com campaign ID quando modal aberto -> SWR faz fetch automatico
- Revalidacao automatica quando `selectedCampaignId` muda

### 41.3.3 — Criar hook usePortalCampaignsCalendar

- [x] Implementacao:

- [x] SWR para lista de campanhas:
  - Key: `["/api/portal/campaigns", month, year, selectedStore]`
  - Revalida quando mes, ano ou loja muda
  - Query params: `?start_date=YYYY-MM-01&end_date=YYYY-MM-DD&store_id=X`
- [x] SWR lazy para metricas detalhadas:
  - Key: `selectedCampaign?.id ? ["/api/portal/campaigns", selectedCampaign.id, "metrics"] : null`
  - Key `null` quando nenhuma campanha selecionada -> SWR nao faz fetch
  - Revalida quando `selectedCampaign` muda
- [x] Gerencia de estado:
  - `month` / `year` com `useState`
  - `selectedCampaign` com `useState<PortalCampaign | null>(null)`
  - `selectedStore` com `useState<string | null>(null)`
  - Reset `selectedCampaign` para null ao mudar mes/ano/loja
- [x] Fetcher padrao para SWR — **IMPORTANTE:** a API usa `successResponse()` que faz spread: `{ success: true, ...data }`. Ou seja, os campos ficam no root (NAO dentro de `.data`):
  ```typescript
  const fetcher = async (url: string) => {
    const res = await fetch(url)
    if (!res.ok) throw new Error(`API error: ${res.status}`)
    return res.json()
    // successResponse produz: { success: true, campaigns: [...], totalCount: N }
    // Os campos ficam no ROOT, NAO dentro de .data
  }
  ```
- [x] O SWR de lista: `data.campaigns` (array) e `data.totalCount` — campos no root do JSON
- [x] O SWR de metricas: `data.metrics` (object | null) — campo no root do JSON
