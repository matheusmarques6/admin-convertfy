# Story 36.1 — Constantes Compartilhadas de Onboarding

## Contexto

Os dois formularios de onboarding usam listas divergentes de plataformas, paises, idiomas e tipos de frete. Isso causa inconsistencia de dados no banco.

| Dado | Form Publico | Wizard Portal |
|------|-------------|---------------|
| Plataformas | shopify, nuvemshop, woo, tray, vtex, other | shopify, woo, nuvemshop, tray, dupla_estrutura, other |
| Paises | 15 opcoes | 4 opcoes |
| Idiomas | 8 opcoes | 3 opcoes |
| Frete | all/conditional/none | fixed/custom/none |

## Objetivo

Criar arquivo unico de constantes usado por ambos os forms e pelo schema Zod do backend.

## Criterios de Aceitacao

- [x] **AC 36.1.1**: Criar `src/lib/constants/onboarding.ts` com exports: `PLATFORMS`, `COUNTRIES`, `LANGUAGES`, `SHIPPING_TYPES`
- [x] **AC 36.1.2**: Unificar lista de plataformas — incluir: shopify, nuvemshop, woocommerce, tray, vtex, dupla_estrutura, other
- [x] **AC 36.1.3**: Unificar paises — usar a lista completa (15 opcoes do form publico)
- [x] **AC 36.1.4**: Unificar idiomas — usar a lista completa (8 opcoes do form publico)
- [x] **AC 36.1.5**: Unificar tipos de frete — padronizar: `all` (frete gratis total), `conditional` (condicional), `none` (sem frete gratis)
- [x] **AC 36.1.6**: Form publico (`/cliente/onboarding/page.tsx`) importa constantes de `onboarding.ts` e remove arrays locais
- [x] **AC 36.1.7**: Wizard portal (`/portal/onboarding/wizard/page.tsx`) importa constantes de `onboarding.ts` e remove listas inline
- [x] **AC 36.1.8**: Schema Zod (`public-onboarding.schema.ts`) usa os valores de `onboarding.ts` para enums de validacao
- [x] **AC 36.1.9**: Verificar se existe CHECK constraint em `client_stores.platform` no banco — se existir, criar migration para aceitar novos valores

> **Nota AC 36.1.9**: `client_stores.platform` usa `VARCHAR(100)` (migration `20241212`), sem CHECK constraint. Existe um ENUM `store_platform` na tabela antiga (`00001_initial_schema.sql`) com valores limitados, mas `client_stores` nao o utiliza. Nenhuma migration necessaria.

## Impacto por Disciplina

- **Dev**: 4 arquivos (1 novo + 3 editados), ~80 linhas
- **Arquiteto**: Decisao sobre quais valores sao fonte da verdade (lista maior vence)
- **DB**: Possivel migration se houver constraint em `platform`
- **QA**: Verificar selects renderizam opcoes corretas em ambos os forms

## Arquivos Envolvidos

- `src/lib/constants/onboarding.ts` (NOVO)
- `src/app/cliente/onboarding/page.tsx` (remover PLATFORMS, COUNTRIES, LANGUAGES locais)
- `src/app/portal/onboarding/wizard/page.tsx` (remover listas inline)
- `src/lib/schemas/public-onboarding.schema.ts` (usar enums do constants)

Baixo no codigo. Atencao no DB se existir constraint.
