# Story 15.2b — DROP das Tabelas Legacy Klaviyo (pós-migração)

## Contexto

Após a Story 15.2 remover todas as referências de código às tabelas legacy, esta story executa o DROP das 6 tabelas criadas pela migration `20250125_10_klaviyo_metrics.sql`.

**Pré-condição obrigatória:** Story 15.2 deve estar 100% concluída e grep em `src/` deve confirmar zero referências antes de executar esta story.

## Objetivo

**Como** engenheiro de banco de dados,
**Quero** dropar as 6 tabelas legacy do banco de dados,
**Para que** o schema fique limpo sem tabelas não utilizadas.

## Acceptance Criteria

- [ ] **15.2b.1** — Grep confirma zero referências às tabelas em `src/` antes de aplicar a migration.
- [ ] **15.2b.2** — Migration `20260304_drop_legacy_klaviyo_tables.sql` dropa os 5 triggers com os nomes reais (confirmados na migration original).
- [ ] **15.2b.3** — Migration dropa as 6 tabelas na ordem correta (child tables primeiro).
- [ ] **15.2b.4** — Migration dropa as 3 funções auxiliares órfãs (`update_klaviyo_updated_at`, `check_campaign_metrics_alerts`, `create_metrics_snapshot`).
- [ ] **15.2b.5** — Migration aplica sem erros.
- [ ] **15.2b.6** — Supabase Dashboard não exibe as tabelas nem as funções removidas.

## Arquitetura Técnica

Nomes reais dos triggers e funções confirmados via leitura de `20250125_10_klaviyo_metrics.sql`:

| Trigger | Tabela | Função chamada |
|---------|--------|----------------|
| `trigger_klaviyo_campaigns_updated` | `klaviyo_campaigns` | `update_klaviyo_updated_at()` |
| `trigger_campaign_metrics_updated` | `campaign_metrics` | `update_klaviyo_updated_at()` |
| `trigger_sync_config_updated` | `klaviyo_sync_config` | `update_klaviyo_updated_at()` |
| `trigger_check_metrics_alerts` | `campaign_metrics` | `check_campaign_metrics_alerts()` |
| `trigger_create_metrics_snapshot` | `campaign_metrics` | `create_metrics_snapshot()` |

Funções auxiliares a dropar (criadas pela migration original, ficam órfãs após DROP das tabelas):
- `update_klaviyo_updated_at()`
- `check_campaign_metrics_alerts()`
- `create_metrics_snapshot()`

**Arquivo:** `supabase/migrations/20260304_drop_legacy_klaviyo_tables.sql`

```sql
-- Drop legacy Klaviyo tables (safe after Story 15.2 removes all code references)
-- Tables from migration 20250125_10_klaviyo_metrics.sql
--
-- Trigger names confirmed from the original migration file (corrected from v1 story).

-- Drop triggers explicitly before tables
-- (kampanye triggers)
DROP TRIGGER IF EXISTS trigger_klaviyo_campaigns_updated ON klaviyo_campaigns;
-- (campaign_metrics triggers)
DROP TRIGGER IF EXISTS trigger_campaign_metrics_updated ON campaign_metrics;
DROP TRIGGER IF EXISTS trigger_check_metrics_alerts ON campaign_metrics;
DROP TRIGGER IF EXISTS trigger_create_metrics_snapshot ON campaign_metrics;
-- (sync_config triggers)
DROP TRIGGER IF EXISTS trigger_sync_config_updated ON klaviyo_sync_config;

-- Drop tables in dependency order (child tables first)
DROP TABLE IF EXISTS campaign_alerts CASCADE;
DROP TABLE IF EXISTS campaign_metrics_history CASCADE;
DROP TABLE IF EXISTS campaign_metrics CASCADE;
DROP TABLE IF EXISTS klaviyo_campaigns CASCADE;
DROP TABLE IF EXISTS klaviyo_sync_jobs CASCADE;
DROP TABLE IF EXISTS klaviyo_sync_config CASCADE;

-- Drop orphan auxiliary functions (no longer needed after tables are gone)
DROP FUNCTION IF EXISTS update_klaviyo_updated_at() CASCADE;
DROP FUNCTION IF EXISTS check_campaign_metrics_alerts() CASCADE;
DROP FUNCTION IF EXISTS create_metrics_snapshot() CASCADE;
```

#### Pre-condition Verification (AC 15.2b.1)

Grep ran across all `src/**/*.ts` and `src/**/*.tsx` files.

Files with references to the 6 legacy table names:

- `src/lib/integrations/klaviyo-sync.ts` — 5 active string references (`klaviyo_campaigns` at lines 462, 494, 501, 532; `campaign_metrics` at line 575) inside `KlaviyoSyncService.syncStore()`.
- `src/lib/services/sync-persistence.service.ts`, `src/app/api/integrations/klaviyo/campaigns/route.ts`, `src/app/api/portal/dashboard/route.ts`, `src/app/api/clients/[id]/performance/route.ts` — all reference `klaviyo_campaign_metrics`, which is a **different table** not in the DROP list. These files are irrelevant.

**Verdict on pre-condition:** The 5 references inside `klaviyo-sync.ts` reside in `KlaviyoSyncService`, which has **zero callers** anywhere in `src/`. The class is never imported or instantiated outside its own file. The pre-condition is functionally satisfied. Literal AC wording ("zero references") is not met — see Concern #1.

**Critical clarification on `/api/campaigns/sync-all`:** Verified by full file read. This endpoint has its own independent inline implementation (`syncStoreFromKlaviyo()`) that writes exclusively to the `campaigns` table. It does NOT call `KlaviyoSyncService.syncStore()` and has zero references to any legacy table being dropped.

---

#### SQL Script Validation (ACs 15.2b.2, 15.2b.3, 15.2b.4)

**Trigger names** — All 5 confirmed correct against `20250125_10_klaviyo_metrics.sql` (lines 294, 299, 304, 408, 450).

**Function names** — All 3 confirmed correct against original migration (lines 284, 310, 414).

**Table drop order:**

| Step | Table | Assessment |
|---|---|---|
| 1 | `campaign_alerts` | Correct — FK child of `klaviyo_campaigns` |
| 2 | `campaign_metrics_history` | Correct — FK child of `klaviyo_campaigns` |
| 3 | `campaign_metrics` | Correct — FK child of `klaviyo_campaigns` |
| 4 | `klaviyo_campaigns` | Correct — parent, all direct children dropped first |
| 5 | `klaviyo_sync_jobs` | Minor concern — also FK child of `klaviyo_campaigns` (line 213 of original migration). Functionally safe because step 4 uses CASCADE which removes the FK constraint. Would be cleaner at position 3. |
| 6 | `klaviyo_sync_config` | Correct — no FK dependencies on other legacy tables |

**CASCADE analysis:** No tables outside the 6 being dropped hold FKs pointing to them. CASCADE will correctly drop RLS policies and indexes on the targeted tables. No unexpected side effects identified.

---

#### Concerns (non-blocking)

**Concern #1 — AC 15.2b.1 literal wording**
The AC says "grep confirms zero references." Five references remain in a dead class. Recommend updating the AC to "grep confirms zero active references (no callers in src/)" or deleting the dead class before execution to make the AC literally pass. Team's call.

**Concern #2 — `klaviyo_sync_jobs` drop order**
`klaviyo_sync_jobs` should ideally be dropped before `klaviyo_campaigns` to make the dependency order explicit. Currently it is dropped after, relying on CASCADE. Functionally safe but potentially confusing. Low risk.

**Concern #3 — Dead class in `klaviyo-sync.ts`**
After the DROP, `KlaviyoSyncService.syncStore()` will become permanently broken (Postgres error if ever invoked). The class should be removed as follow-up technical debt. Suggested follow-up task: delete `KlaviyoSyncService` from `src/lib/integrations/klaviyo-sync.ts` or remove the file if nothing else depends on it.
