## Story

**Como** usuario que encontra um erro no layout do dashboard,
**Quero** ver uma pagina de erro amigavel em vez de tela branca,
**Para que** eu saiba que algo deu errado e possa tentar novamente.

---

## Contexto

O `src/app/error.tsx` existe e captura erros nos **filhos** do root layout. Porem, erros que ocorrem no **proprio root layout** ou em Server Components de layouts aninhados nao sao capturados — o Next.js 15 requer `src/app/global-error.tsx` para isso.

O erro "An error occurred in the Server Components render" que aparece no ErrorBoundary e um sintoma de erros nao-capturados no layout, especialmente quando `getPermissions()` falha (6 queries Supabase sem timeout).

### Arquivos afetados

- `src/app/global-error.tsx` (nao existe — criar)
- `src/app/error.tsx` (referencia — ja existe)

---

## Acceptance Criteria

### 28.5.1 — Criar global-error.tsx

- [ ] Criar `src/app/global-error.tsx` com `"use client"`
- [ ] Deve receber props `{ error, reset }` conforme Next.js App Router convention
- [ ] Deve incluir tags `<html>` e `<body>` proprias (requisito Next.js para global-error)
- [ ] UI minima: mensagem de erro + botao "Tentar novamente" que chama `reset()`
- [ ] Logar `error.message` e `error.digest` no console para debug
- [ ] Manter visual consistente com o `error.tsx` existente

### 28.5.2 — Validacao

- [ ] `npm run lint` e `npm run typecheck` passam
- [ ] Verificar que erros de layout sao capturados (pode testar simulando throw em `getPermissions`)
