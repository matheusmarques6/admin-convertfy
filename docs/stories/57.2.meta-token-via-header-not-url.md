# Story 57.2 — Meta access token via Authorization header (não URL)

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint"]

## Story

**Como** engenheiro de segurança,
**Quero** que o access token do Meta/Facebook seja enviado via header `Authorization: Bearer` em vez de query parameter,
**Para que** o token não fique exposto em logs de HTTP, proxies e server logs.

## Contexto

### Problema

O callback do Meta (`src/app/api/integrations/meta/callback/route.ts`) passa o access token na URL:

```typescript
// Linha 93-94
const userInfoResponse = await fetch(
  `${META_GRAPH_URL}/me?fields=id,name,email&access_token=${accessToken}`
)

// Linha 101
`${META_GRAPH_URL}/me/adaccounts?fields=id,account_id,name&access_token=${accessToken}`

// Linha 114
`${META_GRAPH_URL}/me/accounts?fields=id,instagram_business_account&access_token=${accessToken}`
```

A Graph API do Meta suporta `Authorization: Bearer` header como alternativa.

## Acceptance Criteria

### 57.2.1 — Migrar todas as chamadas para Authorization header

- [x] Todas as chamadas `fetch()` ao `META_GRAPH_URL` devem usar header `Authorization: Bearer ${accessToken}` em vez de `?access_token=` na URL
- [x] Remover `access_token` de todos os query parameters

**Given-When-Then:**

```
GIVEN Meta OAuth callback receives a valid code
WHEN the callback exchanges code for token and calls Graph API
THEN all Graph API requests use Authorization: Bearer header
AND no access_token appears in any URL
AND user info, ad accounts, and Instagram accounts are fetched correctly
```

### Padrão a seguir

```typescript
// ANTES:
const response = await fetch(
  `${META_GRAPH_URL}/me?fields=id,name,email&access_token=${accessToken}`
)

// DEPOIS:
const response = await fetch(
  `${META_GRAPH_URL}/me?fields=id,name,email`,
  {
    headers: { Authorization: `Bearer ${accessToken}` }
  }
)
```
