# Story 40.1 — DB Migration: Step Lifecycle + DAG Columns

## Story

**Como** desenvolvedor da plataforma,
**Quero** que o schema do banco suporte o novo lifecycle de steps e dependencias DAG,
**Para que** as stories subsequentes possam implementar resolucao de dependencias e sync bi-direcional.

## Contexto

### Estado atual

- `onboarding_template_steps.depends_on` e `UUID` (referencia unica, single parent)
- `onboarding_step_status` enum: `pending`, `in_progress`, `blocked`, `completed`, `skipped`
- `tasks.source_type` CHECK constraint lista fixa de valores
- Nao existe coluna linkando `client_onboarding_steps` de volta para `tasks`

### O que precisa mudar

1. Nova coluna `depends_on_steps UUID[]` em `onboarding_template_steps` para suportar DAG (multiplas dependencias, steps paralelos). Coluna antiga `depends_on` mantida para compatibilidade
2. Nova coluna `depends_on_step_ids UUID[]` em `client_onboarding_steps` para DAG de instancias
3. Step status precisa de novos estados: `waiting` (dependencias nao satisfeitas) e `pending` (pronto para iniciar, deps met)
4. `tasks.source_type` precisa incluir `auto_onboarding_step`
5. `client_onboarding_steps` precisa de `task_id` para link reverso ao board
6. `phase TEXT` adicionado a ambas as tabelas de steps
7. `is_required BOOLEAN DEFAULT true` adicionado a `client_onboarding_steps`
8. `org_id UUID` adicionado a `client_onboarding_steps` com backfill

- [x] **AC 40.1.2**: Novos valores `waiting` adicionado ao enum `onboarding_step_status`. `pending` mantido como "ready to start" (deps met, actionable). NAO usar `ready` como enum value. Steps existentes com status `pending` que tem dependencias nao satisfeitas migrados para `waiting`

## Technical Notes

### Migration SQL

```sql
-- 1. Adicionar novos valores ao enum onboarding_step_status
ALTER TYPE onboarding_step_status ADD VALUE IF NOT EXISTS 'waiting' BEFORE 'pending';
ALTER TYPE onboarding_step_status ADD VALUE IF NOT EXISTS 'review' AFTER 'in_progress';
-- NOTE: 'pending' already exists and means "ready to start" (deps met, actionable)
-- Do NOT add 'ready' as an enum value

-- 2. Adicionar depends_on_steps UUID[] em onboarding_template_steps (NEW column, keep old depends_on)
ALTER TABLE onboarding_template_steps
  ADD COLUMN IF NOT EXISTS depends_on_steps UUID[] DEFAULT '{}';

-- Backfill from old depends_on column
UPDATE onboarding_template_steps
  SET depends_on_steps = CASE
    WHEN depends_on IS NOT NULL THEN ARRAY[depends_on]
    ELSE '{}'::UUID[]
  END
  WHERE depends_on_steps = '{}' OR depends_on_steps IS NULL;

-- Add phase column to template steps
ALTER TABLE onboarding_template_steps
  ADD COLUMN IF NOT EXISTS phase TEXT;

-- 3. Adicionar novas colunas em client_onboarding_steps
ALTER TABLE client_onboarding_steps
  ADD COLUMN IF NOT EXISTS depends_on_step_ids UUID[] DEFAULT '{}',
  ADD COLUMN IF NOT EXISTS task_id UUID REFERENCES tasks(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS phase TEXT,
  ADD COLUMN IF NOT EXISTS is_required BOOLEAN DEFAULT true,
  ADD COLUMN IF NOT EXISTS org_id UUID;

-- 4. Backfill org_id from client_onboardings
UPDATE client_onboarding_steps cos
  SET org_id = co.org_id
  FROM client_onboardings co
  WHERE cos.onboarding_id = co.id
  AND cos.org_id IS NULL;

-- 5. Backfill depends_on_step_ids, phase, is_required from template steps
-- (needs app-level logic to map template step IDs to client step IDs)

-- 6. Atualizar CHECK constraint de tasks.source_type
ALTER TABLE tasks DROP CONSTRAINT IF EXISTS tasks_source_type_check;
ALTER TABLE tasks ADD CONSTRAINT tasks_source_type_check
  CHECK (source_type IN (
    'manual', 'auto_onboarding', 'auto_meeting', 'auto_campaign',
    'auto_feedback', 'auto_report', 'auto_contract', 'auto_onboarding_step'
  ));

-- 7. Migrar steps existentes: pending -> waiting (para steps com dependencias nao resolvidas)
UPDATE client_onboarding_steps
  SET status = 'waiting'
  WHERE status = 'pending'
  AND depends_on_step_ids != '{}';

-- Steps sem dependencias permanecem como pending (= ready to start)

-- 8. Indexes
CREATE INDEX IF NOT EXISTS idx_cos_task_id ON client_onboarding_steps(task_id);
CREATE INDEX IF NOT EXISTS idx_cos_onboarding_status ON client_onboarding_steps(onboarding_id, status);
```

### Cuidados

- `ALTER TYPE ADD VALUE` nao pode rodar dentro de transaction em PostgreSQL. Usar statements separados.
- A coluna antiga `depends_on` em `onboarding_template_steps` e mantida para compatibilidade. Nova coluna `depends_on_steps UUID[]` e a fonte de verdade para DAG
- Steps de onboardings ja concluidos (`status = 'completed'`) NAO devem ser migrados para `waiting`
- `pending` = "ready to start" (deps met). NAO usar `ready` como valor de enum
