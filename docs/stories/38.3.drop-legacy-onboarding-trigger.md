# Story 38.3 -- Remover trigger legado `handle_onboarding_completion`

## Story

Como engenheiro de dados,
Quero remover a trigger legada `handle_onboarding_completion` e o sistema de `onboarding_stage` da tabela `clients`,
Para que haja uma unica fonte de verdade para o tracking de onboarding (o sistema novo com `client_onboardings`).

## Contexto

### Problema observado

O sistema legado de onboarding (`20250107_onboarding_system.sql`) criou:

1. Enum `onboarding_stage` na tabela `clients` (valores: `cadastro`, `configuracao`, `treinamento`, `lancamento`, `concluido`)
2. Trigger `handle_onboarding_completion` na tabela `clients` que:
   - Detecta quando `onboarding_stage` muda para `concluido`
   - Seta `clients.status = 'active'`
   - Agenda `next_feedback_date` em 30 dias para todas as stores do cliente
3. Trigger `record_onboarding_stage_change` que registra mudancas na tabela `onboarding_history`
4. Tabela `onboarding_history` para audit log

O sistema novo (`client_onboardings` + `onboarding-phase.service.ts`) substituiu completamente esse fluxo. As triggers legadas nao sao mais acionadas pelo codigo atual, mas continuam ativas no banco.

### Risco de manter

- Complexidade: Novos devs podem se confundir com dois sistemas
- Colunas orfas: `onboarding_stage`, `onboarding_started_at`, `onboarding_completed_at`, `onboarding_assigned_to` na tabela `clients`
- A trigger `handle_onboarding_completion` pode disparar acidentalmente se alguem atualizar `onboarding_stage` diretamente
