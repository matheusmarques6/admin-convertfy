## Contexto

A tabela `store_revenue_summary` nao tem como distinguir se um row foi populado pelo cron ou pelo live fetch. Isso dificulta debugging quando ha inconsistencias. Alem disso:

1. **Sem `sync_source`:** Nao sabemos se o dado veio do cron (confiavel, timezone correto) ou do live fetch (pode ter timezone incorreto, race conditions)
2. **Sem `updated_at` com trigger:** O campo `fetched_at` e atualizado manualmente, mas nao ha trigger automatico para rastrear ultima modificacao
3. **Indice composto subotimo:** A query principal do dashboard filtra por `(org_id, period_label)` e ordena por `expires_at DESC`, mas o indice existente `idx_revenue_summary_org` cobre apenas `(org_id, period_label)` sem incluir `expires_at`

---

## Objetivo

Adicionar migration com melhorias de observabilidade e performance na tabela `store_revenue_summary`.

## Arquitetura Tecnica

### Migration SQL Completa

```sql
-- =============================================
-- Migration: Revenue Summary Observability
-- =============================================
-- Adds sync_source, updated_at trigger, and optimized composite index
-- to store_revenue_summary for better debugging and query performance.
-- Epic 11 - Dashboard Store Count Integrity

-- 1. sync_source column
ALTER TABLE store_revenue_summary
  ADD COLUMN IF NOT EXISTS sync_source VARCHAR(10) NOT NULL DEFAULT 'cron'
  CHECK (sync_source IN ('cron', 'live'));

COMMENT ON COLUMN store_revenue_summary.sync_source IS
  'Source of the data: cron (scheduled sync) or live (on-demand fallback)';

-- 2. updated_at column + trigger
ALTER TABLE store_revenue_summary
  ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW();

CREATE OR REPLACE FUNCTION update_revenue_summary_updated_at()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS trg_revenue_summary_updated_at ON store_revenue_summary;
CREATE TRIGGER trg_revenue_summary_updated_at
  BEFORE UPDATE ON store_revenue_summary
  FOR EACH ROW
  EXECUTE FUNCTION update_revenue_summary_updated_at();

-- 3. Optimized composite index (replaces idx_revenue_summary_org)
DROP INDEX IF EXISTS idx_revenue_summary_org;

CREATE INDEX idx_revenue_summary_org_period_expires
  ON store_revenue_summary(org_id, period_label, expires_at DESC);
```

### Impacto nos Upserts

Os upserts existentes no cron e live fetch passam a incluir `sync_source`. Como o default e `'cron'`, rows existentes nao sao afetados pela migration.

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Migration falha em producao | `ADD COLUMN IF NOT EXISTS` e idempotente. `DROP INDEX IF EXISTS` seguro |
| Default `'cron'` para rows existentes pode ser incorreto | Rows existentes foram realmente criados pelo cron — default correto |
| Indice composto maior que o anterior | Apenas 3 colunas, tamanho aceitavel para a quantidade de rows (~200 max) |
| Trigger `updated_at` adiciona overhead | Overhead negligivel (<1ms) para tabela com poucas rows |
