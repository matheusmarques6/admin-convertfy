## Contexto

O cron e o live fetch usam filtros de credenciais diferentes para decidir quais lojas sincronizar:

- **Cron** (`src/app/api/cron/sync-reports/route.ts` linha 286): usa `.or("klaviyo_private_key.not.is.null,klaviyo_api_key.not.is.null")` — aceita AMBOS os campos
- **Live fetch** (`src/app/api/dashboard/total-revenue/route.ts` linha 372): usa `.not("klaviyo_private_key", "is", null)` — aceita APENAS `klaviyo_private_key`

Isso significa que lojas que tem apenas `klaviyo_api_key` (campo legado) sao sincronizadas pelo cron mas ignoradas pelo live fetch. O resultado e que o cache mostra uma contagem diferente do live fetch para a mesma org.

Alem disso, o `getKlaviyoRevenueForStore` (em `report-summary.ts` linha 50-51) ja faz `const apiKey = storeData.klaviyo_private_key || storeData.klaviyo_api_key`, ou seja, o service ja suporta ambos os campos. O problema e so no filtro SQL do live fetch.

---

## Objetivo

Unificar o filtro de credenciais em ambos os paths para usar a mesma logica: aceitar lojas que tenham `klaviyo_private_key` OU `klaviyo_api_key`.

## Arquitetura Tecnica

### Novo Export: `src/lib/services/credentials.service.ts`

```typescript
/**
 * Supabase OR filter string for stores with Klaviyo credentials.
 * Used by cron sync-reports and live fetch endpoints to ensure
 * identical store selection.
 *
 * Both klaviyo_private_key (current) and klaviyo_api_key (legacy)
 * are accepted because getStoreCredentials() handles both.
 */
export const KLAVIYO_CREDENTIALS_FILTER =
  "klaviyo_private_key.not.is.null,klaviyo_api_key.not.is.null"
```

### Impacto no Cron

```typescript
// src/app/api/cron/sync-reports/route.ts linha 286
import { KLAVIYO_CREDENTIALS_FILTER } from "@/lib/services/credentials.service"

const { data: stores, error: storesError } = await supabase
  .from("client_stores")
  .select("id, store_name, org_id")
  .or(KLAVIYO_CREDENTIALS_FILTER)
  .not("org_id", "is", null)
```

### Impacto no Live Fetch

```typescript
// src/app/api/dashboard/total-revenue/route.ts linha 370-372
import { KLAVIYO_CREDENTIALS_FILTER } from "@/lib/services/credentials.service"

let storeQuery = adminSupabase
  .from("client_stores")
  .select("id, store_name, org_id, client_id, clients(name)")
  .eq("org_id", orgId)
  .or(KLAVIYO_CREDENTIALS_FILTER)
```
