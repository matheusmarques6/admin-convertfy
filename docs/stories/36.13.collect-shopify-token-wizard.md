# Story 36.13 — Coletar e Validar Shopify Admin API Token no Wizard

## Contexto

A story 36.12 adiciona o step instrucional com campo opcional de token no wizard. Esta story implementa o backend que valida e salva o token de forma segura.

**IMPORTANTE**: O token so e coletado no WIZARD (autenticado), NAO no form publico.

## Objetivo

Implementar backend handler no wizard para:
1. Validar formato do token (`shpat_*`)
2. Testar o token contra a Shopify Admin API
3. Salvar encriptado via `credentials.service.ts`
4. Incluir no calculo de `wizardComplete`

## Contexto Tecnico

- Coluna `shopify_access_token` JA EXISTE em `client_stores` (text, nullable)
- Campo JA ESTA na lista `ENCRYPTED_FIELDS` do `credentials.service.ts`
- Padrao de encriptacao: AES-256-GCM, prefixo `enc:v1:`
- `updateStoreCredentials()` ja suporta este campo
- Validacao de caracteres ASCII ja existe (`validateCredentialField()`)

## Criterios de Aceitacao

### Backend — Wizard API Route
- [ ] **AC 36.13.1**: Novo case `"create_shopify_app"` no switch do POST de `/api/portal/onboarding/wizard`
- [ ] **AC 36.13.2**: Se `token` vazio/null → salvar step como completo sem token (step e opcional)
- [ ] **AC 36.13.3**: Se `token` preenchido → validar formato: deve comecar com `shpat_` e ter >= 20 caracteres
- [ ] **AC 36.13.4**: Se token valido no formato → testar com GET `https://{shopify_store_domain}/admin/api/2024-10/shop.json` com header `X-Shopify-Access-Token`
- [ ] **AC 36.13.5**: Se API retorna 200 → token valido. Salvar via `updateStoreCredentials(storeId, { shopify_access_token: token, shopify_store_domain: domain }, "shopify")`. O `domain` vem do campo `shopify_myshopify_domain` adicionado na story 36.12 (AC 36.12.18b), NAO derivado do `store_url`
- [ ] **AC 36.13.6**: Se API retorna 401 → retornar erro: "Token invalido. Verifique se copiou corretamente."
- [ ] **AC 36.13.7**: Se API retorna 403 → retornar erro: "Token sem permissoes suficientes. Verifique os escopos configurados."
- [ ] **AC 36.13.8**: Se API timeout/erro de rede → retornar erro: "Nao foi possivel validar o token. Verifique o dominio da loja." Usar `AbortController` com timeout de 10s (padrao do projeto em `credential-validator.service.ts`)

### Wizard Completion Logic
- [ ] **AC 36.13.9**: Step `create_shopify_app` e SEMPRE considerado "complete" no calculo de `wizardComplete` — e um step opcional/instrucional que NAO bloqueia a conclusao do wizard. Implementar: `shopifyAppComplete = true` (independente de platform ou token). O token e um bonus, nao requisito

### Frontend — Wizard
- [ ] **AC 36.13.11**: `handleNext()` para o step `create_shopify_app`: se token preenchido, chama `saveStep("create_shopify_app", { store_id, token })`. Se vazio, avanca sem chamar API
- [ ] **AC 36.13.12**: Erro de API (token invalido) aparece inline abaixo do campo de token (pattern da story 36.3)
- [ ] **AC 36.13.13**: Indicacao visual de "Validando token..." com spinner durante a chamada API. Botao "Continuar" desabilitado durante validacao (prevenir double-click/race condition)

### Schema
- [ ] **AC 36.13.14**: Validacao do token no wizard route handler (NAO no schema Zod do form publico, pois o token so e coletado no wizard). Formato: `shpat_` prefix + minimo 20 caracteres

## Impacto por Disciplina

- **Dev**: 1 arquivo backend (~40 linhas), 1 arquivo frontend (~15 linhas), 1 schema (~1 linha)
- **Arquiteto**: Padrao identico ao fluxo Klaviyo que ja existe. Usar `updateStoreCredentials()`
- **DB**: ZERO — coluna ja existe, encriptacao ja suportada
- **QA**: Testar: token valido → salva encriptado. Token invalido → erro inline. Token vazio → pula. Caracteres estranhos → rejeitado pelo `validateCredentialField()`

## Arquivos Envolvidos

- `src/app/api/portal/onboarding/wizard/route.ts` (novo case no POST + ajuste no GET)
- `src/app/portal/onboarding/wizard/page.tsx` (handleNext para o step, enviar token + domain)
- `src/lib/services/credentials.service.ts` (ja pronto, apenas consumir `updateStoreCredentials`)

## Dependencias

- 36.12 (step instrucional com campo de token)

## Risco

Medio. Validacao de token contra API externa pode falhar por timeout/rede. Tratamento de erro robusto e essencial.

## Seguranca

- Token transportado via HTTPS (Vercel)
- Validado por `validateCredentialField()` (ASCII printable)
- Encriptado com AES-256-GCM antes de gravar
- NUNCA exposto em logs ou resposta de API
- NAO coletado no form publico (sem auth)
