# Story AE-15 — QA cascade: alt_text grátis + vision condicional + 4 novos `QaIssueType` pra imagem

## User Story

**Como** plataforma de qualidade,
**quero** que o QA agent valide tambem a imagem hero do email (nicho coerente, paleta, overlay reserve, cena),
**para que** falhas tipo "L'Hombre + hero de cueca" sejam bloqueadas antes do designer ver — sem inflar custo (alt_text gratis pega 80%, Claude vision so se passou o filtro).

---

## Contexto

Hoje (após AE-14):
- QA agent (`src/lib/agents/chains/qa.chain.ts`, AE-5) valida HTML + blocks + briefing — **mas nao olha pra imagem**
- `QaIssueType` enum tem 8 valores textuais (`spam_score_alto`, `html_invalido`, etc) — nenhum tipo dedicado a imagem
- `phase2-runner` ja gera imagem antes do QA: tem `image_url` em `email_blocks.content.image_url`
- `productRefDescriptionFallback` e o prompt mestre AE-14 ja injetam descricao textual rica do produto

Esta story implementa o QA cascade definido no plano §5 (`/root/.claude/plans/muito-bom-agora-vamos-playful-marble.md`):

**Etapa 1 — alt_text grátis** (sempre roda):
- Gera `image_alt` descritivo no momento da geracao da imagem (extrai do proprio prompt — ja temos `PRODUTO_HEROI`, `CENARIO`, `MOOD`)
- QA agent (LLM textual existente) compara `image_alt` com `{PRODUTO_HEROI}` esperado — custo zero adicional (LLM ja roda)
- Issue type novo: `image_nicho_mismatch` (severity high se threshold=high)

**Etapa 2 — vision condicional** (só dispara se filtro determinístico passa):
- Filtro determinístico: se Etapa 1 nao pegou nada óbvio E `EMAIL_QA_VISION_ENABLED=true`
- Manda `image_url` + `{NICHO}` + `{PRODUTO_HEROI}` + paleta pra Claude Sonnet 4.6 com vision
- Issue types: `image_paleta_off`, `image_overlay_reserva_ausente`, `image_cena_inadequada`
- Custo ~1.5¢/email (so quando passar o filtro)

## Dev Notes

### Por que cascade (textual primeiro, vision condicional)?
- 80% dos casos óbvios (L'Hombre+cueca) pegam via comparação textual `image_alt` vs `PRODUTO_HEROI` — custo zero
- 20% restantes (nuances de paleta, overlay, cena) precisam vision — custo 1.5¢/email
- Cascade evita gastar $ em casos triviais

### Por que Claude Sonnet 4.6 com vision?
- LangChain `ChatAnthropic` suporta multimodal (texto + image_url) desde Claude 3
- Custo: ~$3/MTok input, ~$15/MTok output. Tipico: 1KB input + 0.5KB output → ~$0.005-0.015/call
- Output JSON-estruturado via tool_use ou prompt strict

### `image_alt` formato
Curto, factual, pra o QA textual comparar:
```
"Capa banco couro preto em interior de carro premium, mood masculino sobrio"
```
Não confundir com `image_alt` de acessibilidade HTML (esse fica no render final do email, pode ser mais conciso).

### Vision: o que avaliar?
1. **Produto coerente com NICHO+PRODUTO_HEROI**: "essa imagem mostra capa de banco?" (sim/não)
2. **Paleta da marca**: "as cores dominantes batem com paleta de hex {PALETA_1}+{PALETA_2}?"
3. **Overlay reserve quando esperado**: "terço inferior é mais escuro/limpo pra texto?"
4. **Cena coerente**: "ambiente compatível com posicionamento (premium/popular/medio)?"

Cada um vira issue type específico (severity ajustável via env).

### Threshold de bloqueio
- Já existe `EMAIL_QA_BLOCK_SEVERITY` (AE-5). Default `high`.
- `image_nicho_mismatch` deve ser `high` (bloqueia). Outros 3 (paleta/overlay/cena) ficam `medium` por default (não bloqueiam, mas aparecem em UI).
