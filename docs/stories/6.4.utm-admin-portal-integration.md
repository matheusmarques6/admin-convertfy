## Contexto

O sistema e multi-tenant: agencias (admin em `/stores/[id]`) gerenciam lojas de clientes (portal em `/portal/`). As Stories 6.1-6.3 implementam separadamente:

- **6.1**: Tab UTM na pagina da loja no admin (dados de conversao Shopify)
- **6.2**: CRUD de templates UTM no admin (tabela `utm_templates` com RLS por `org_id`/`store_id`)
- **6.3**: Expansao de dados UTM no portal do cliente (bySource, byMedium, byCampaign)

Porem, **nao existe ponte entre o que a agencia configura (templates) e o que o cliente ve (portal)**. O cliente nao sabe quais UTMs estao sendo usadas nas campanhas dele, nem ve performance por template. Alem disso, os dados de conversao UTM no portal (`/api/portal/dashboard`) e no admin (`/api/integrations/shopify/report`) podem divergir porque usam caminhos de agregacao diferentes.

**Multi-tenant (Portal):** O portal usa autenticacao propria via `client_portal_users`. O acesso a templates deve respeitar o vinculo `client_stores.client_id` — o cliente so ve templates das lojas vinculadas a ele. Templates sao criados pela agencia (`org_id`), mas vistos pelo cliente via `client_id`.

---

## Objetivo

Criar a camada de integracao que conecta os templates UTM configurados no admin com a visualizacao no portal do cliente, incluindo: (1) endpoint read-only de templates para o portal, (2) secao de templates ativos na pagina da loja no portal, e (3) garantia de consistencia de dados entre admin e portal. **V2 (adiado)**: cruzamento template x conversao (match exato por campaign name e fragil e sera redesenhado).

## Arquitetura Tecnica

### Fluxo de Dados: Admin -> Portal

```
ADMIN (Agencia)                           PORTAL (Cliente)
─────────────────                         ─────────────────
1. Agencia cria template UTM
   POST /api/stores/[id]/utm-templates
   -> salva em utm_templates (org_id,
      store_id)

2. Agencia usa template em campanhas
   (Klaviyo, SMS, etc)

3. Pedidos chegam com UTM params
   -> Shopify registra landing_site

4. Admin ve performance na tab UTM        5. Cliente ve templates e performance
   GET /api/integrations/shopify/report      GET /api/portal/stores/[id]/utm-templates
   -> utmConversions cruzado com             -> templates ativos (read-only)
      templates                              GET /api/portal/stores/[id]/report
                                             -> utmConversions cruzado com templates
```

### Endpoint Portal UTM Templates

```typescript
// src/app/api/portal/stores/[id]/utm-templates/route.ts
export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  try {
    const { id: storeId } = await params
    const supabase = await createClient()
    // Pattern manual do portal (NAO usar requireAuth — nao existe)
    const { data: { user } } = await supabase.auth.getUser()
    if (!user) throw new AppError("Unauthorized", 401)
    const adminClient = createAdminClient()

    // Verificar portal user
    const { data: portalUser } = await adminClient
      .from("client_portal_users")
      .select("id, client_id")
      .eq("auth_user_id", user.id)
      .eq("is_active", true)
      .single()

    if (!portalUser) throw new AppError("Nao autorizado", 401)

    // Verificar que loja pertence ao cliente
    const { data: store } = await adminClient
      .from("client_stores")
      .select("id, org_id")
      .eq("id", storeId)
      .eq("client_id", portalUser.client_id)
      .single()

    if (!store) throw new AppError("Loja nao encontrada", 404)

    // Buscar templates ativos (excluir soft-deleted)
    const { data: templates } = await adminClient
      .from("utm_templates")
      .select("id, name, description, utm_source, utm_medium, utm_campaign, utm_content, utm_term, usage_count, created_at")
      .eq("store_id", storeId)
      .eq("org_id", store.org_id)
      .eq("is_active", true)
      .is("deleted_at", null)
      .order("usage_count", { ascending: false })

    return Response.json({ success: true, templates: templates || [] })
  } catch (error) {
    return errorResponse(request, error, "GET /api/portal/stores/[id]/utm-templates")
  }
}
```

## Consideracoes de Seguranca

- **Isolamento Portal**: O endpoint `/api/portal/stores/[id]/utm-templates` usa `adminClient` para bypassar RLS mas valida manualmente que `client_stores.client_id = portalUser.client_id`. O cliente nunca tem acesso direto a tabela `utm_templates`.
- **Dados ocultos**: Campos `org_id` e `created_by` nao sao expostos ao portal. O cliente ve apenas o nome do template e os parametros UTM — nao sabe quem na agencia criou.
- **Read-only no portal**: O portal so le templates (GET). Nao ha endpoints POST/PATCH/DELETE para o portal. Toda gestao e feita pelo admin.
- **Sem cross-tenant**: Um cliente nao pode ver templates de lojas de outro cliente, mesmo que pertencam a mesma organizacao. O filtro e por `client_id`, nao por `org_id`.
- **Dados UTM**: Parametros UTM sao metadados publicos de marketing, nao contem PII.
