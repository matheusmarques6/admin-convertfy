## Story

**Como** desenvolvedor frontend do portal,
**Quero** que as APIs retornem status HTTP corretos quando dados estao indisponiveis,
**Para que** o frontend possa distinguir "sem dados" de "erro" e mostrar mensagens adequadas.

---

## Contexto

Varios endpoints retornam HTTP 200 OK com dados vazios quando ha problemas reais:

### Problema 1a: campaigns route retorna [] com store invalido
```typescript
// src/app/api/portal/campaigns/route.ts:64-70
if (storeId && !clientStoreIds.includes(storeId)) {
  return successResponse(request, { campaigns: [], totalCount: 0 }) // 200 OK!
}
```
Store invalido deveria retornar 400 ou 404, nao 200 com array vazio.

### Problema 1b: campaigns route retorna [] quando client nao tem stores
```typescript
// src/app/api/portal/campaigns/route.ts:44-49
if (!clientStores || clientStores.length === 0) {
  return successResponse(request, { campaigns: [], totalCount: 0 }) // 200 OK!
}
```
Nenhuma store configurada deveria retornar erro indicando "configure uma loja".

### Problema 2: Klaviyo sem API key retorna 200 (endpoint de integracao)
```typescript
// src/app/api/integrations/klaviyo/campaigns/route.ts:407
if (!apiKey) {
  return NextResponse.json({ success: false, error: "API Key nao configurada" })
  // SEM status HTTP! Default 200 OK
}
```
**Nota:** Este endpoint (`/api/integrations/klaviyo/*`) e usado pelo admin dashboard,
NAO diretamente pelo portal. Porem, corrigir para consistencia geral.

### Problema 3: Dashboard retorna dataStatus "error" com HTTP 200
```typescript
// src/app/api/portal/dashboard/route.ts:750
response.dataStatus = "error"
response.klaviyoError = "Dados indisponiveis..."
// Mas HTTP status e 200 OK
```

---

## Criterios de Aceitacao

- [ ] **CA1**: `/api/portal/campaigns` retorna 400 quando `store_id` nao pertence ao client
      com mensagem: `{ error: "Store nao encontrada", code: "INVALID_STORE" }`
- [ ] **CA1b**: `/api/portal/campaigns` retorna 404 quando client nao tem nenhuma store
      com mensagem: `{ error: "Nenhuma loja configurada", code: "NO_STORES" }`
- [ ] **CA2**: `/api/integrations/klaviyo/campaigns` retorna 400 quando API key nao configurada
      com mensagem: `{ error: "API Key do Klaviyo nao configurada", code: "NO_API_KEY" }`
      (endpoint admin, mas corrigir para consistencia)
- [ ] **CA3**: Dashboard API retorna 503 quando todos os dados estao indisponiveis
      (nao parcialmente — se tem invoices mas nao Klaviyo, retorna 200 com dataStatus)
- [ ] **CA4**: Frontend trata 400/503 mostrando mensagem especifica ao usuario
- [ ] **CA5**: Manter retrocompatibilidade: se apenas Klaviyo falha mas Shopify funciona,
      continuar retornando 200 com `dataStatus` indicando o estado parcial
- [ ] **CA6**: Typecheck + lint passando
