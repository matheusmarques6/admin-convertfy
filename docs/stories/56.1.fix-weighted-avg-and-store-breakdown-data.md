# Story 56.1 — Fix Weighted Avg + Fix clickRate Format + Expose Store Breakdown Data

**Epic:** 56 - Multi-Store Breakdown na Visão Geral do Cliente
**Prioridade:** P0 (bug fix + data foundation)
**Esforço:** LOW
**Dependências:** Nenhuma
**Revisado por:** QA, Arquiteto, Dev, Data Engineer, Analyst (2026-03-19)

---

## Contexto

A função `aggregateTotals()` na API route `/api/clients/[id]/performance` calcula `avgOpenRate` e `avgClickRate` como **média simples** por loja, ignorando o volume de entregas. Uma loja com 100 emails e 50% open rate tem o mesmo peso que uma loja com 10.000 emails e 30% — resultado incorreto.

Além disso, existe um **bug de formato** no `avgClickRate`: a API retorna como percentual (ex: 5.0 = 5%), mas a UI multiplica por 100 novamente, exibindo 500%. O `avgOpenRate` não tem esse bug (UI usa direto).

O hook `useClientPerformance` já retorna `data.stores[]` com dados per-store, mas não expõe um array de breakdown formatado para consumo direto pela UI.

## Objetivo

1. Corrigir o cálculo de open/click rate para média ponderada por `totalDelivered`
2. Corrigir o formato do `avgClickRate` (unificar API + UI)
3. Expor `storeBreakdown[]` no hook para consumo pela UI (Story 56.2)

---

## Acceptance Criteria

### AC 56.1.1 — Weighted Average em aggregateTotals

- [ ] Acumular `totalDelivered`, `totalOpens`, `totalClicks` de todas as lojas
- [ ] `avgOpenRate` = `(totalOpens / totalDelivered) * 100` → percentual (ex: 30.5)
- [ ] `avgClickRate` = `(totalClicks / totalDelivered) * 100` → percentual (ex: 5.0)
- [ ] Se `totalDelivered === 0`, ambos retornam `0`
- [ ] **Ambos os campos retornam no mesmo formato: percentual (multiplicado por 100)**

**Arquivo:** `src/app/api/clients/[id]/performance/route.ts`
**Função:** `aggregateTotals()` (linhas 326-381)

**Mudança:**
```typescript
// ANTES (média simples — incorreto):
if (store.klaviyo.avgOpenRate > 0) {
  openRateSum += store.klaviyo.avgOpenRate
  clickRateSum += store.klaviyo.avgClickRate
  rateCount++
}
// avgOpenRate: rateCount > 0 ? openRateSum / rateCount : 0

// DEPOIS (média ponderada — correto):
totalDelivered += store.klaviyo.totalDelivered
totalOpens += store.klaviyo.totalOpens
totalClicks += store.klaviyo.totalClicks
// avgOpenRate: totalDelivered > 0 ? (totalOpens / totalDelivered) * 100 : 0
// avgClickRate: totalDelivered > 0 ? (totalClicks / totalDelivered) * 100 : 0
```

### AC 56.1.2 — Fix avgClickRate na UI (bug de dupla multiplicação)

- [ ] **Remover o `* 100`** na exibição do `avgClickRate` em `client-performance-review.tsx`
- [ ] Linha 223 atual: `{(data.totals.avgClickRate * 100).toFixed(2)}%` → `{data.totals.avgClickRate.toFixed(2)}%`
- [ ] Corrigir TODAS as ocorrências de `clickRate * 100` no componente:
  - Linha 223: KPI card "Campanhas & Flows" → `{data.totals.avgClickRate.toFixed(2)}%` — **CORRIGIR**
  - Linha 417: tabela campanhas `{(campaign.clickRate * 100).toFixed(2)}%` → `{campaign.clickRate.toFixed(2)}%` — **CORRIGIR**
  - Linha 476: tabela flows `{(flow.clickRate * 100).toFixed(2)}%` → `{flow.clickRate.toFixed(2)}%` — **CORRIGIR**
- [ ] **Formato definitivo**: `avgOpenRate` e `avgClickRate` são AMBOS percentuais na API. UI usa `.toFixed(2)%` sem multiplicação.

**CONFIRMADO pelo QA (cadeia de dados rastreada):**
1. Klaviyo API retorna `clickRate` como decimal (ex: 0.035)
2. `klaviyo-performance.service.ts:605` converte: `Math.round(m.clickRate * 100 * 100) / 100` = 3.5 (percentual)
3. `sync-persistence.service.ts:229` salva no banco como percentual (3.5)
4. `performance/route.ts:134` lê do banco: `Number(c.click_rate) || 0` = 3.5 (percentual)
5. UI `* 100` = 350% — **BUG em TODAS as 3 linhas** (223, 417, 476)
6. `openRate` NÃO tem este bug (UI usa `.toFixed(2)%` sem multiplicação — correto)

**Arquivo:** `src/components/clients/client-performance-review.tsx`
