# Story 45.4 — Fix RPC COALESCE Returning 0 Instead of NULL for Missing Rates

## Status: Ready for Review
## Effort: LOW (30min)
## Priority: HIGH

## Context

The RPC `get_portal_campaigns_with_metrics` uses `COALESCE(lm.km_open_rate, 0)` for rate metrics. When a campaign has no Klaviyo data (manual campaign or not yet synced), the LEFT JOIN returns NULL, and COALESCE converts it to `0.0`.

This makes manual campaigns appear to have `0% open rate` — looks like terrible performance when in reality there is simply no data.

## File

`supabase/migrations/20260314_portal_campaigns_metrics_rpc.sql` — lines ~121-131

## Current (Misleading)

```sql
COALESCE(lm.km_open_rate, 0)::NUMERIC AS open_rate,
COALESCE(lm.km_click_rate, 0)::NUMERIC AS click_rate,
COALESCE(lm.km_bounce_rate, 0)::NUMERIC AS bounce_rate,
COALESCE(lm.km_conversion_rate, 0)::NUMERIC AS conversion_rate,
```

## Fix

Remove COALESCE for rate fields — return NULL when no Klaviyo data:

```sql
lm.km_open_rate::NUMERIC AS open_rate,
lm.km_click_rate::NUMERIC AS click_rate,
lm.km_bounce_rate::NUMERIC AS bounce_rate,
lm.km_conversion_rate::NUMERIC AS conversion_rate,
```

Keep COALESCE for count fields (recipients, delivered, etc.) where 0 is a valid fallback from the campaigns table.

## Frontend Impact

Update UI to show "—" or "N/A" when rate is `null` instead of "0%". There are at least 3 locations that display rates:

1. **CampaignCard compact mode** (~line 277) — shows `openRate` in monthly grid cells
2. **Campaign detail modal** — shows full metrics table with all rates
3. **Stats `weightedOpenRate`** — already filters by `hasKlaviyoMetrics`, should be OK

Also update `transformCampaignData` rate fields from `?? 0` to `?? undefined` so null rates propagate correctly (cross-dependency with 45.1).

## Migration Safety

- `CREATE OR REPLACE FUNCTION` is idempotent — safe to apply
- **MUST reemit REVOKE/GRANT** statements because function is `SECURITY DEFINER`
- Rollback = reemit previous version of the function
