# Story 56.3 — Passar orgId nos OAuth Callback Routes

## Story

**Como** engenheiro de seguranca,
**Quero** que os OAuth callbacks extraiam `org_id` do state e passem para `updateStoreCredentials`,
**Para que** o defense-in-depth do `credentials.service.ts` valide que a loja pertence a org correta antes de gravar credenciais.

## Contexto

### Problema

Os callbacks OAuth (`shopify/callback`, `meta/callback`) chamam `updateStoreCredentials(storeId, credentials)` **sem** passar `orgId` nas options. Isso significa que o defense-in-depth do `credentials.service.ts` (linha 341: `useOrgCheck = !!options?.orgId && !options?.skipOrgCheck`) nao e ativado.

Apos a Story 56.2, o state OAuth contera `org_id`. O callback precisa:
1. Extrair `stateData.org_id` do state decodificado
2. Passar `{ orgId: stateData.org_id }` para `updateStoreCredentials()`

### Backwards compatibility

Fluxos OAuth ja em andamento (state sem `org_id`) devem continuar funcionando:
- Se `org_id` ausente no state → `log.warn` mas NAO bloquear
- `updateStoreCredentials` sem orgId continua funcionando (apenas perde defense-in-depth)

### Codigo atual (vulneravel)

**Shopify callback** (`src/app/api/integrations/shopify/callback/route.ts`):
```typescript
// Linhas 116-123: sem orgId
await updateStoreCredentials(stateData.store_id, {
  shopify_access_token: accessToken,
  shopify_store_domain: shop,
})
```

**Meta callback** (`src/app/api/integrations/meta/callback/route.ts`):
```typescript
// Linhas 126-137: sem orgId
await updateStoreCredentials(stateData.store_id, {
  meta_access_token: longLivedToken,
  meta_page_id: selectedPage.id,
  meta_page_name: selectedPage.name,
})
```

## Acceptance Criteria

### 56.3.1 — Shopify callback + orgId

- [x] Extrair `org_id` do state decodificado:
  ```typescript
  const orgId = stateData.org_id // pode ser undefined (fluxos antigos)
  ```
- [x] Passar orgId para `updateStoreCredentials`:
  ```typescript
  await updateStoreCredentials(stateData.store_id, {
    shopify_access_token: accessToken,
    shopify_store_domain: shop,
  }, orgId ? { orgId } : undefined)
  ```
- [x] Se `org_id` ausente no state, logar warning:
  ```typescript
  if (!orgId) {
    log.warn("[Shopify Callback] state missing org_id — skipping org check (legacy flow)")
  }
  ```

**Given-When-Then:**

```
GIVEN a valid Shopify OAuth callback
AND the state contains org_id from Org A
AND the store_id belongs to Org A
WHEN the callback processes
THEN credentials are saved successfully
AND updateStoreCredentials receives { orgId: "org-a-id" }

GIVEN a valid Shopify OAuth callback
AND the state contains org_id from Org A
AND the store_id belongs to Org B (state tampering)
WHEN the callback processes
THEN updateStoreCredentials throws (org mismatch)
AND credentials are NOT saved
AND user is redirected with error

GIVEN a valid Shopify OAuth callback from a flow initiated before 56.2
AND the state does NOT contain org_id
WHEN the callback processes
THEN a warning is logged
AND credentials are saved normally (backwards compat)
```

### 56.3.2 — Meta callback + orgId

- [x] Mesmo padrao do Shopify: extrair `org_id`, passar para `updateStoreCredentials`, warn se ausente

**Given-When-Then:**

```
GIVEN a valid Meta OAuth callback
AND the state contains org_id from Org A
AND the store_id belongs to Org A
WHEN the callback processes
THEN credentials are saved (meta_access_token, meta_page_id, meta_page_name)
AND updateStoreCredentials receives { orgId: "org-a-id" }

GIVEN a valid Meta OAuth callback
AND the state contains org_id from Org A
AND the store_id belongs to Org B
WHEN the callback processes
THEN updateStoreCredentials throws (org mismatch)
AND credentials are NOT saved
```

### 56.3.3 — Tratar erro do org check no callback

- [x] Se `updateStoreCredentials` lanca erro de org mismatch, tratar com redirect:
  ```typescript
  try {
    await updateStoreCredentials(...)
  } catch (err) {
    if (err instanceof AppError && err.statusCode === 403) {
      log.error("[Callback] Org mismatch on credential save", { storeId, orgId })
      return NextResponse.redirect(
        new URL("/stores?error=org_mismatch", request.nextUrl.origin)
      )
    }
    throw err // re-throw outros erros
  }
  ```

### 56.3.4 — Typecheck

- [x] `npm run typecheck` passa sem erros novos
