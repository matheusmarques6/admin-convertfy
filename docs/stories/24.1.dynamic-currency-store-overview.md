## Story

**Como** operador de agencia que gerencia lojas internacionais (EUA, Europa, etc.),
**Quero** que os valores monetarios na visao geral da loja sejam exibidos na moeda correta da loja (USD, EUR, etc.),
**Para que** eu nao confunda valores em dolares com reais e tenha informacao precisa sobre a performance de cada loja.

---

## Contexto

### Problema observado

Na pagina `/stores/[id]`, ao visualizar a "Visao Geral" de uma loja com pais principal EUA (ou qualquer pais nao-Brasil), todos os valores monetarios sao exibidos como BRL (R$), mesmo que os dados originais estejam em USD, EUR, etc.

Exemplo: uma loja americana com receita de $10,000 exibe "R$ 10.000,00" em vez de "US$ 10.000,00".

### Causa raiz

O backend **ja retorna** `account.currency` (ex: "USD") e `account.currencySymbol` (ex: "$") do Klaviyo em todos os endpoints relevantes (report, campaigns, flows). Porem:

1. **Elo perdido no hook**: `useStorePerformance` extrai receita do `reportData` mas descarta `reportData.account.currency`. A interface `StorePerformanceTotals` nao tem campo `currency`.
2. **Formatadores hardcoded**: Existem 3 implementacoes duplicadas de `formatCurrency`, todas com BRL fixo.
3. **`R$` literal**: `store-detail-tabs.tsx` usa `R$ ${...toLocaleString("pt-BR")}` em 4 pontos.

### Bug pre-existente: cache retorna "BRL" hardcoded

Os endpoints de campaigns (`campaigns/route.ts:439`) e flows (`flows/route.ts:408`) retornam `currency: "BRL"` hardcoded quando servem dados do cache, em vez da moeda real da conta. Somente o fetch live retorna `accountInfo.currency` corretamente. Este bug precisa ser corrigido como prerequisito.

### Decisoes de escopo (consenso Dev + QA + Arquiteto)

| Decisao | Justificativa |
|---------|---------------|
| Control panel (`store-control-panel.tsx`) fica FORA de escopo | Compara lojas lado a lado — BRL como moeda de comparacao uniforme faz sentido para agencia brasileira |
| Portal fica FORA de escopo | Fase futura, tratado separadamente |
| Fase 3 (campo `currency` em `client_stores`) DESNECESSARIA por agora | Klaviyo Account API ja fornece currency com cache de 1h |
| Locale fixo `pt-BR` para todos os valores | Dashboard serve operadores brasileiros. `Intl.NumberFormat("pt-BR", { currency: "USD" })` gera `US$ 1.234,56` — correto para esse contexto |
| NAO unificar os 2 arquivos de utils | Manter separacao `utils.ts` / `utils/format.ts`, apenas alinhar assinaturas |

```typescript
export function formatCurrencyCompact(value: number, currency = "BRL"): string {
  if (value >= 1_000_000) {
    return new Intl.NumberFormat("pt-BR", {
      style: "currency", currency, notation: "compact",
      maximumFractionDigits: 1
    }).format(value)
  }
  if (value >= 1_000) {
    return new Intl.NumberFormat("pt-BR", {
      style: "currency", currency, notation: "compact",
      maximumFractionDigits: 1
    }).format(value)
  }
  return formatCurrency(value, currency)
}
```

## Notas Tecnicas

### Fontes de currency disponveis (em ordem de confiabilidade)

1. **Klaviyo Account API** — `getAccountInfo(apiKey).currency` — fonte primaria, ja retornada pelo backend
2. **Shopify Shop API** — `GET /admin/api/2024-10/shop.json` retorna `currency` — requer chamada extra
3. **Campo `country` em `client_stores`** — texto livre, nao mapeia para currency

### Locale decision

Todos os valores usam locale `pt-BR` (agencia brasileira). `Intl.NumberFormat("pt-BR", { currency: "USD" })` formata como `US$ 1.234,56` — separador de milhar com ponto, decimal com virgula. Correto para operadores brasileiros visualizando lojas internacionais.

### Riscos e mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Regressao em lojas BRL (maioria) | Default `"BRL"` em todos os formatadores — call sites existentes nao quebram |
