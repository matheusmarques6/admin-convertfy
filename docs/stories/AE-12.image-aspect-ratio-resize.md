# Story AE-12 — Aspect ratio + overlay reserve por slot (resize com `sharp`)

## User Story

**Como** plataforma,
**quero** que cada slot de imagem (Welcome E1..E6, etc.) gere com o **aspect ratio correto** (4:5, 3:5, 4:3, 1:1) e com **terço inferior escuro reservado** para overlay quando aplicável,
**para que** o designer receba imagens prontas pro layout sem precisar recortar/redimensionar.

---

## Contexto

Hoje (apos AE-11):
- `image.chain.ts` chama OpenRouter com modelo `openai/gpt-5.4-image-2` e recebe base64
- Output: imagem com aspect ratio que o modelo decidir (historicamente landscape ~16:9 ou square)
- `DEFAULT_IMAGE_PROMPT_TEMPLATE` (legacy) menciona `600x300 landscape` no prompt — modelo ignora
- Template novo (AE-11 seed) usa vars `{{PALETA_1}}` etc, mas **NAO menciona aspect** — falta integrar

O plano (`/root/.claude/plans/muito-bom-agora-vamos-playful-marble.md` §3) define:

| Email | Aspect | Overlay reserve | Notas |
|---|---|---|---|
| Welcome E1 | 4:5 (1200×1500) | sim (terço inferior) | hero lifestyle |
| Welcome E2 | 4:5 | sim | produto + overlay grande |
| Welcome E3 | 3:5 (720×1200) | **não** | central vertical |
| Welcome E4 | 4:5 | sim | aspiracional |
| Welcome E5 | 4:3 (1200×900) | **não** | fachada |
| Welcome E6 | 4:5 | sim | high-impact |

**Estrategia segura**: instrução textual no prompt + **redimensionar pós-geração** usando `sharp` (resize com `fit: 'cover'` mantém composição).

## Dev Notes

### Por que `sharp` e nao redimensionar no modelo?
- OpenRouter `image_size` historicamente eh ignorado por `gpt-5.4-image-2`
- `sharp` eh stdard na industria (Vercel + Next ja suportam), ~5MB extra no bundle
- Resize `fit: 'cover'` mantem composicao centralizada — modelo geralmente centraliza o produto

### Por que instrucao textual TAMBEM no prompt?
- Aspect ratio influencia composicao do modelo mesmo quando ele nao respeita a dimensao final
- "Reserve bottom 30%" eh respeitado pelo modelo na **composicao** (deixa area mais escura), e o resize preserva isso
- Sem a instrucao + reserve, modelo pode centralizar o produto perfeitamente — o overlay cobre

### Quando aplicar resize?
- **Antes do upload pro Supabase Storage**
- Buffer ja em memoria, custo extra ~50-100ms
- Output sempre PNG (perde tamanho mas mantem qualidade)

### Matriz de aspect ratio

```ts
const WELCOME_ASPECT_BY_EMAIL: Record<number, AspectKey> = {
  1: '4:5', 2: '4:5', 3: '3:5', 4: '4:5', 5: '4:3', 6: '4:5',
}
// Outros flows: default '4:5' ate que stories futuras definam
```
