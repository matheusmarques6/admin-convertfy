# Story 54.9 — Add TTL/Cleanup for Flow/Campaign Metrics Tables

## Story

**Como** DBA responsavel pela saude do banco,
**Quero** que as tabelas `klaviyo_flow_metrics` e `klaviyo_campaign_metrics` tenham cleanup automatico,
**Para que** nao cresçam indefinidamente ao longo de meses/anos de operacao.

## Contexto

### Problema

| Tabela | Tem TTL? | Tem cleanup? |
|--------|----------|-------------|
| `store_revenue_summary` | Sim (`expires_at`) | Sim (`clean_expired_revenue_summaries()`) |
| `dashboard_cache` | Sim (`expires_at`) | Sim (`clean_expired_dashboard_cache()`) |
| `klaviyo_flow_metrics` | **NAO** | **NAO** |
| `klaviyo_campaign_metrics` | **NAO** | **NAO** |
| `klaviyo_audiences` | **NAO** (mas delete-all+insert mantem bounded) | Implicito |

O cron faz DELETE+UPSERT por `(store_id, period_label)`, mas se uma loja for removida, desativada, ou trocar de org, os rows antigos permanecem para sempre.

### Estimativa de crescimento

- 50 lojas x 4 periodos x 30 campaigns = ~6000 rows (aceitavel)
- 200 lojas x 4 periodos x 50 campaigns = ~40000 rows (preocupante)
- Com lojas removidas/desativadas acumulando: potencialmente ilimitado

## Acceptance Criteria

### 54.9.1 — Adicionar `expires_at` a flow/campaign metrics

- [ ] Migration para adicionar `expires_at TIMESTAMPTZ` a ambas tabelas
- [ ] Default: NULL (rows existentes mantidas)
- [ ] Cron preenche `expires_at` no upsert (ex: NOW() + 48h)

### 54.9.2 — Funcao de cleanup

- [ ] Criar funcao `clean_expired_metrics()` SECURITY DEFINER:
  ```sql
  DELETE FROM klaviyo_flow_metrics WHERE expires_at IS NOT NULL AND expires_at < NOW();
  DELETE FROM klaviyo_campaign_metrics WHERE expires_at IS NOT NULL AND expires_at < NOW();
  ```
- [ ] Chamar no cron apos sync completo (junto com `clean_expired_revenue_summaries`)

### 54.9.3 — Cleanup de lojas orfas

- [ ] Adicionar cleanup para rows de lojas que foram deletadas (ON DELETE CASCADE ja faz isso via FK)
- [ ] Verificar que FK com CASCADE esta configurada em ambas tabelas

### 54.9.4 — Validacao

- [ ] `npm run build` passa
- [ ] Cleanup nao deleta rows validos (apenas expirados)

## Dependencias

- **Upstream**: 54.3 (atomic write) — o novo pattern de UPSERT+CLEANUP ja pode popular `expires_at`

## Riscos

| Risco | Mitigacao |
|-------|----------|
| Cleanup deleta dados ainda necessarios | TTL conservador (48h); cleanup so roda no cron (nao em path de leitura) |
| Rows existentes sem expires_at | WHERE `expires_at IS NOT NULL` garante que nao sao tocados |
