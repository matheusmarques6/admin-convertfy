# Story 42.4 — Google Calendar Sync Service: create/update/delete events com Meet

## Story

**Como** admin user da plataforma,
**Quero** que reunioes criadas no Convertfy sejam automaticamente sincronizadas com meu Google Calendar,
**Para que** eu veja as reunioes no meu calendario com link do Meet e participantes recebam convites.

## Contexto

### Estado atual

- `GoogleCalendarService` existe em `src/lib/integrations/google-calendar.ts` com metodos funcionais
- `createEventWithMeet` usa `requestId: 'meet-${Date.now()}'` — **vulneravel a colisao (C4)**
- `deleteEvent` usa `fetch` raw em vez de `fetchWithRetry` — **sem retry (C7)**
- Service recebe `accessToken` no constructor mas nao faz refresh automatico
- Nao existe orquestracao entre o service e a tabela `meetings`

### O que precisa mudar

Criar `google-calendar-sync.service.ts` que:
1. Orquestra sincronizacao: busca meeting do banco, busca token do user, chama Google Calendar API, atualiza status
2. Usa `google-auth.service.getValidAccessToken()` para tokens sempre validos
3. Corrige `requestId` (C4) e `deleteEvent` (C7) ao chamar o `GoogleCalendarService` existente
4. Gerencia `google_sync_status` e `google_sync_error` em cada operacao

## Acceptance Criteria

- [x] **AC 42.4.1**: Service criado em `src/lib/services/google-calendar-sync.service.ts`

- [x] **AC 42.4.2**: Funcao `syncMeetingToGoogle(meetingId, organizerUserId)`:
  - Busca meeting completa do banco (com participants)
  - Busca token valido do organizador via `getValidAccessToken()`
  - Cria `GoogleCalendarService` com o token
  - Cria evento no Google Calendar do organizador
  - Salva `google_event_id`, `google_calendar_id`, `meeting_url`, `meeting_url_source`, `google_sync_status = 'synced'` no banco
  - Se organizador nao tem Calendar conectado: `google_sync_status = 'not_connected'`, retorna sem chamar Google

- [x] **AC 42.4.3**: **[C4]** `requestId` do Meet usa `crypto.randomUUID()`:
  - Ao chamar `createEvent` com `conferenceData`, usar `requestId: crypto.randomUUID()` em vez de `Date.now()`
  - Corrigir diretamente no `GoogleCalendarService.createEventWithMeet` (linha 175 de google-calendar.ts)

- [x] **AC 42.4.4**: **[R3]** `sendUpdates: "all"` usado em `createEvent` e `updateEvent` para enviar convites por email a todos os participantes
  - **[H2] IMPORTANTE:** O fix de `sendUpdates: "all"` deve ser aplicado DENTRO do metodo `createEventWithMeet` em `google-calendar.ts` (linha ~181), que chama `this.createEvent(eventWithConference, { conferenceDataVersion: 1 })` — adicionar `sendUpdates: "all"` nessas options. Caso contrario, reunioes criadas com Meet via `createEventWithMeet` NAO enviarao convites. Alternativamente, o sync service pode chamar `createEvent` diretamente com `{ conferenceDataVersion: 1, sendUpdates: "all" }` em vez de usar `createEventWithMeet`

- [x] **AC 42.4.5**: **[R5]** Meet link salvo em `meetings.meeting_url` com `meeting_url_source = 'google_meet'`:
  - NAO criar coluna `google_meet_link` separada
  - Se meeting ja tinha `meeting_url` manual, sobrescrever com Meet link (Meet tem prioridade)

- [x] **AC 42.4.6**: Participantes adicionados como attendees pelo email:
  - Para `participant_type = 'org_member'`: buscar email de `profiles` via `org_members.user_id`
  - Para `participant_type = 'profile'`: buscar email de `profiles`
  - Para participantes com `email` preenchido em `meeting_participants`: usar diretamente
  - Todos adicionados no array `attendees` do evento Google
  - Salvar email resolvido em `meeting_participants.email` se estava vazio

- [x] **AC 42.4.7**: Funcao `updateGoogleEvent(meetingId)`:
  - Busca meeting atualizada do banco
  - Busca `google_event_id` da meeting
  - Se nao tem `google_event_id`: tenta criar (pode ser meeting que falhou na criacao)
  - PATCH evento no Google Calendar com dados atualizados (titulo, data, participantes)
  - Usa `sendUpdates: "all"` (R3)
  - Atualiza `google_sync_status = 'synced'`

- [x] **AC 42.4.8**: **[C7]** Funcao `deleteGoogleEvent(meetingId)`:
  - Busca `google_event_id` da meeting
  - Se nao tem `google_event_id`: noop (nada para deletar)
  - DELETE evento no Google Calendar usando `fetchWithRetry` (corrigir bug C7)
  - **Correcao**: alterar `GoogleCalendarService.deleteEvent` para usar `this.request()` em vez de `fetch()` raw (linha 134 de google-calendar.ts)
  - Usa `sendUpdates: "all"` para notificar participantes
  - Limpa `google_event_id`, `google_sync_status = 'not_connected'` no banco

- [x] **AC 42.4.9**: Se organizador sem Calendar conectado (`getValidAccessToken` retorna null):
  - `google_sync_status = 'not_connected'`
  - Nenhuma chamada ao Google
  - Meeting local criada normalmente
  - Retornar `{ synced: false, reason: 'not_connected' }`

- [x] **AC 42.4.12**: **[M6]** `GoogleCalendarService.request()` deve tratar response 204 No Content:
  - DELETE do Google Calendar API retorna 204 sem body
  - `response.json()` em um 204 lanca erro de parse
  - Fix: no metodo `request()` de `google-calendar.ts`, verificar `if (response.status === 204) return null` ANTES de chamar `response.json()`
  - Isso permite que `deleteEvent` use `this.request()` sem quebrar (fix C7 do AC 42.4.8)

- [x] **AC 42.4.10**: Se API Google falha (qualquer erro):
  - Meeting local intacta (nao reverter)
  - `google_sync_status = 'error'`
  - `google_sync_error` populado com mensagem do erro
  - Retornar `{ synced: false, reason: 'error', error: message }`
  - Log com `log.error` incluindo meetingId e erro

- [x] **AC 42.4.11**: **[C8]** Timezone da reuniao enviado para Google Calendar API:
  - Usar `meetings.timezone` (default 'America/Sao_Paulo') nos campos `start.timeZone` e `end.timeZone` do evento Google

### Correcoes no GoogleCalendarService existente

Duas correcoes diretas em `src/lib/integrations/google-calendar.ts`:

1. **requestId (C4)** — linha 175:
```typescript
// ANTES
requestId: `meet-${Date.now()}`,
// DEPOIS
requestId: crypto.randomUUID(),
```

2. **createEventWithMeet sendUpdates (H2)** — linha ~181:
```typescript
// ANTES
return this.createEvent(eventWithConference, { conferenceDataVersion: 1 })
// DEPOIS
return this.createEvent(eventWithConference, { conferenceDataVersion: 1, sendUpdates: "all" })
```

3. **request() 204 handling (M6)**:
```typescript
// No metodo request(), ANTES de response.json():
if (response.status === 204) return null
```

4. **deleteEvent (C7)** — linha 134:
```typescript
// ANTES
await fetch(`${CALENDAR_API_URL}${endpoint}`, {
  method: "DELETE",
  headers: { Authorization: `Bearer ${this.accessToken}` },
})
// DEPOIS
await this.request(endpoint, { method: "DELETE" })
```
Nota: `this.request` ja usa `fetchWithRetry` e ja inclui o Authorization header.
O `deleteEvent` nao retorna body (204 No Content), entao ajustar `this.request` para verificar `response.status === 204` e retornar `null` antes de chamar `response.json()` (ver AC 42.4.12).

### Busca de emails dos participantes
