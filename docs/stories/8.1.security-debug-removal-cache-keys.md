# Story 8.1 - Remover Debug de Credenciais e Corrigir Cache Keys de Isolamento

## Contexto

O endpoint `total-revenue/route.ts` contem uma query de debug (`allStoresDebug`) que le campos sensiveis como `klaviyo_private_key` e `klaviyo_api_key` e loga informacoes sobre eles. Embora os valores nao sejam logados diretamente (apenas `!!s.klaviyo_private_key`), a query busca esses campos do banco desnecessariamente e representa risco de seguranca.

Alem disso, as cache keys dos endpoints `total-revenue` e `stores/control` nao incluem `org_id`, criando riscos de cross-tenant cache poisoning:
- `total-revenue` usa `user.id` como chave (linha 113), fazendo dois usuarios da mesma org duplicarem chamadas.
- `stores/control` usa cache keys sem prefixo de org.

---

## Objetivo

1. Remover completamente a query `allStoresDebug` e seus logs associados
2. Corrigir cache keys para usar `${orgId}:${period}` em vez de `user.id`
3. Corrigir cache key em `stores/control` para incluir `orgId`

Remover completamente o trecho que busca `allStoresDebug` (aproximadamente linhas 128-153):

#### Mudanca 2 - Corrigir cache key

```typescript

// DEPOIS:

```

### Arquivo 2: `src/app/api/stores/control/route.ts`
