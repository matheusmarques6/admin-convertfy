# Story 35.3 — Normalizar client_id no user_metadata

## Story

**Como** desenvolvedor que trabalha com portal users,
**Quero** que todos os caminhos de criacao de portal user incluam `client_id` no user_metadata,
**Para que** o metadata seja consistente e possa ser usado para lookups rapidos sem query em `client_portal_users`.

## Contexto

### Inconsistencia atual

Existem 3 caminhos para criar um portal user no sistema. Dois deles incluem `client_id` no `user_metadata`, mas o principal (formulario publico) nao inclui:

| Caminho | Arquivo | Inclui client_id? |
|---------|---------|-------------------|
| Formulario publico (onboarding) | `src/lib/services/portal-account.service.ts` | NAO |
| Admin cria portal user | `src/app/api/admin/portal-users/route.ts` | SIM (linha 108) |
| Admin reenvia invite | `src/app/api/admin/portal-users/[id]/send-invite/route.ts` | SIM (linha 93) |

### Codigo atual do PortalAccountService (BUG)

```typescript
// src/lib/services/portal-account.service.ts - linhas 28-36
const { data: authData, error: authError } = await adminClient.auth.admin.createUser({
  email: params.email,
  password: tempPassword,
  email_confirm: true,
  user_metadata: {
    name: params.name,
    is_portal_user: true,
    // FALTA: client_id: params.clientId
  },
})
```

### Codigo dos outros endpoints (correto)

```typescript
// src/app/api/admin/portal-users/route.ts - linhas 105-109
user_metadata: {
  name: body.name,
  is_portal_user: true,
  client_id: body.client_id,  // PRESENTE
}

// src/app/api/admin/portal-users/[id]/send-invite/route.ts - linhas 90-94
user_metadata: {
  name: portalUser.name,
  is_portal_user: true,
  client_id: portalUser.client_id,  // PRESENTE
}
```

### Por que normalizar

O `client_id` no metadata permite:
1. Lookup rapido sem query em `client_portal_users` (util no middleware, Story 35.2)
2. Debugging mais facil ao inspecionar `auth.users`
3. Consistencia entre todos os caminhos de criacao

## Acceptance Criteria

### 35.3.1 — Adicionar client_id ao user_metadata no PortalAccountService

- [x] Em `src/lib/services/portal-account.service.ts`, adicionar `client_id: params.clientId` ao objeto `user_metadata`:
```typescript

  name: params.name,
  is_portal_user: true,
  client_id: params.clientId,  // ADICIONAR
},
```
- [x] Verificar que `params.clientId` esta disponivel no tipo do parametro (ja esta: `clientId: string`)

**Arquivo:** `src/lib/services/portal-account.service.ts`

### 35.3.2 — Novo portal user via formulario tem client_id no metadata

- [ ] Criar portal user via formulario publico de onboarding

### 35.3.3 — Consistencia entre todos os caminhos

- [ ] Verificar que TODOS os 3 caminhos de criacao de portal user incluem os mesmos campos no metadata: `name`, `is_portal_user`, `client_id`
- [ ] Nenhum caminho inclui campos extras que outros nao incluem
