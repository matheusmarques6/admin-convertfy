# Story 45.5 — Fix Stats Inconsistency: Opens/Clicks Include Non-Metric Campaigns

## Status: Ready for Review
## Effort: LOW (20min)
## Priority: MEDIUM

## Context

In the stats calculation useMemo, `totalRevenue` correctly filters to only campaigns `withMetrics` (sent + has Klaviyo data). But `totalOpens` and `totalClicks` sum across ALL campaigns including draft/scheduled ones, mixing Klaviyo-sourced data with stale fallback data from the campaigns table.

## File

`src/app/client/campaigns/page.tsx` — stats useMemo (~lines 565-575)

## Current (Inconsistent)

```typescript
totalRevenue: withMetrics.reduce((sum, c) => sum + (c.revenue || 0), 0),  // ✓ filtered
totalOpens: campaigns.reduce((sum, c) => sum + (c.opened || 0), 0),       // ✗ ALL campaigns
totalClicks: campaigns.reduce((sum, c) => sum + (c.clicked || 0), 0),     // ✗ ALL campaigns
```

## Fix

```typescript
totalRevenue: withMetrics.reduce((sum, c) => sum + (c.revenue ?? 0), 0),
totalOpens: withMetrics.reduce((sum, c) => sum + (c.opened ?? 0), 0),      // ✓ filtered
totalClicks: withMetrics.reduce((sum, c) => sum + (c.clicked ?? 0), 0),    // ✓ filtered
```

## Decision: `totalRecipients` filter

Currently `totalRecipients` uses `sentCampaigns` (all sent campaigns), while `totalRevenue` uses `withMetrics` (sent + has Klaviyo data). This is a product decision:

- **`sentCampaigns`** = includes manual campaigns that have recipient count but no Klaviyo metrics
- **`withMetrics`** = only Klaviyo-sourced data

**Recommendation**: Use `sentCampaigns` for `totalRecipients` (recipient count is available even without Klaviyo), but use `withMetrics` for `totalOpens` and `totalClicks` (these are only meaningful with Klaviyo data).
