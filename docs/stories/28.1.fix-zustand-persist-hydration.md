## Story

**Como** usuario do dashboard,
**Quero** que a pagina carregue sem erros de hydration,
**Para que** a interface seja estavel e nao apresente flash de conteudo ou erros no console.

---

## Contexto

O `useUIStore` em `src/lib/store/index.ts` (linhas 39-52) usa Zustand `persist` middleware com `localStorage`. O campo `sidebarCollapsed` tem default `false`, mas se o usuario ja colapsou a sidebar anteriormente, o `persist` rehidrata com `true` do `localStorage` **antes** do React completar a hydration.

Resultado:
- **Server**: sidebar renderiza com `w-[240px]`, labels visiveis, `<Logo>`
- **Client**: sidebar renderiza com `w-[70px]`, apenas icones, `<LogoIcon>`

Isso causa mismatch em toda a arvore do `<Sidebar>` incluindo:
- Width classes (`w-[240px]` vs `w-[70px]`)
- Navegacao items (labels vs tooltips)
- Logo component (Logo vs LogoIcon)
- Framer Motion `layoutId="sidebar-active"` com estado divergente

### Arquivos afetados

- `src/lib/store/index.ts` (linhas 39-52: `useUIStore` com `persist`)
- `src/components/layout/sidebar.tsx` (linha 102: consome `sidebarCollapsed`)

## Acceptance Criteria

### 28.1.1 — Adicionar `skipHydration` ao persist config

- [ ] Em `src/lib/store/index.ts`, adicionar `skipHydration: true` ao objeto de config do `persist` middleware do `useUIStore`
- [ ] Isso faz o store iniciar com os valores default no primeiro render (server e client iguais)

### 28.1.2 — Rehidratar manualmente apos montagem (no layout, NAO no sidebar)

- [ ] Chamar `useUIStore.persist.rehydrate()` dentro de um `useEffect` em `src/app/(dashboard)/layout.tsx` (Client Component wrapper) ou em um provider dedicado tipo `<StoreHydration>`
- [ ] **NAO** colocar o `rehydrate()` dentro de `sidebar.tsx` — evita duplicacao quando story 28.3 tambem modificar o sidebar
- [ ] O primeiro render do client DEVE usar os mesmos valores default do server (`sidebarCollapsed: false`, `sidebarOpen: true`)
- [ ] Apos `useEffect`, o store rehidrata com os valores do `localStorage` e a UI atualiza normalmente

### 28.1.3 — Verificar que nao ha hydration error

- [ ] Testar com sidebar previamente colapsada: a pagina deve carregar com sidebar expandida por um instante e depois colapsar (sem erro #418)
- [ ] Testar com sidebar previamente expandida: sem mudanca visual
- [ ] Console nao deve exibir React error #418 em nenhum cenario
- [ ] **Nota**: esta story sozinha pode NAO eliminar 100% dos #418 — o theme toggle no sidebar (story 28.3) tambem contribui. O #418 sera totalmente eliminado apos 28.1 + 28.3

### 28.1.4 — Regressao: localStorage continua persistindo

- [ ] Colapsar a sidebar, recarregar a pagina — sidebar deve voltar colapsada apos mount
- [ ] Expandir a sidebar, recarregar — sidebar deve voltar expandida apos mount
- [ ] Limpar localStorage, recarregar — sidebar deve usar defaults (`sidebarCollapsed: false`)

### 28.1.5 — Lint e typecheck passam

- [ ] `npm run lint` passa sem erros
- [ ] `npm run typecheck` passa sem erros
