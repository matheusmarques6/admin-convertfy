# Story 3.5 - Fluxo de Copys: Aprovação → Geração → Design → Implementação

## Contexto
O fluxo desejado é:
1. Cliente preenche formulário de onboarding (portal/público)
2. COO revisa e aprova os dados
3. N8N é ativado e gera as copys automaticamente
4. Design recebe as copys e cria peças visuais
5. Implementação recebe tudo e publica nas lojas

A tab "Copy" em campanhas já existe como placeholder ("Coming Soon"). O feature `campaign_copy` já existe no catalog.

## Objetivo
Estruturar o fluxo de copys como pipeline com status tracking, integrando com o sistema de aprovação do onboarding e preparando a interface para quando N8N for implementado.

## Acceptance Criteria

- [x] **3.5.1** Criar tabela `copy_pipeline` para tracking do fluxo:
  ```sql
  CREATE TABLE copy_pipeline (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id UUID REFERENCES organizations(id),
    client_id UUID REFERENCES clients(id),
    store_id UUID REFERENCES client_stores(id),

    -- Status do pipeline
    status TEXT NOT NULL DEFAULT 'pending_approval'
      CHECK (status IN (
        'pending_approval',    -- Aguardando COO aprovar onboarding
        'approved',            -- COO aprovou, aguardando geração
        'generating',          -- N8N gerando copys
        'pending_design',      -- Copys geradas, aguardando design
        'in_design',           -- Design trabalhando
        'pending_implementation', -- Design concluiu, aguardando impl.
        'implementing',        -- Implementação em andamento
        'completed'            -- Publicado
      )),

    -- Dados
    briefing_id UUID REFERENCES client_briefings(id),
    generated_copys JSONB,       -- Copys geradas pelo N8N
    design_assets JSONB,         -- Assets criados pelo design

    -- Tracking
    approved_by UUID REFERENCES org_members(id),
    approved_at TIMESTAMPTZ,
    design_assigned_to UUID REFERENCES org_members(id),
    design_started_at TIMESTAMPTZ,
    design_completed_at TIMESTAMPTZ,
    impl_assigned_to UUID REFERENCES org_members(id),
    impl_started_at TIMESTAMPTZ,
    impl_completed_at TIMESTAMPTZ,

    -- Meta
    notes TEXT,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
  );
  ```

- [x] **3.5.2** Criar RLS policies para `copy_pipeline`:
  - SELECT: `can_access_client(client_id)` + (`campaign_copy` OR `campaign_control`)
  - UPDATE status transitions:
    - `pending_approval` → `approved`: precisa `onboarding_control`
    - `pending_design` → `in_design`: precisa `campaign_copy`
    - `pending_implementation` → `implementing`: precisa `campaign_control`

- [x] **3.5.3** API routes para copy pipeline:
  - `GET /api/copy-pipeline` — listar por status/client
  - `PATCH /api/copy-pipeline/[id]/status` — atualizar status
  - `POST /api/copy-pipeline/[id]/assign` — atribuir a membro

- [x] **3.5.4** Implementar tab "Copy" em campanhas com view do pipeline:
  - Kanban horizontal com colunas por status
  - Cards mostram: cliente, loja, stage atual, assignee
  - Ações contextuais por role (aprovar, marcar design concluído, etc.)

- [ ] **3.5.5** Integrar com onboarding approval:
  - Quando COO aprova onboarding → criar entry em `copy_pipeline` automaticamente
  - Status inicial: `approved` (pronto para N8N quando implementado)

- [ ] **3.5.6** Auto-criar tasks no board quando pipeline muda de status:
  - `pending_design` → task para design assignee
  - `pending_implementation` → task para impl assignee

## Dependências

- N8N: a etapa `generating` será implementada quando N8N for integrado. Por agora, transição manual de `approved` → `pending_design`
