# Story 33.1 — Fix Engagement Rate >100% Bug

## Story

**Como** operador do painel admin que monitora metricas de audiencia das lojas,
**Quero** que o engagement rate seja calculado corretamente e nunca ultrapasse 100%,
**Para que** os dados exibidos no dashboard e portal sejam confiaveis e nao confundam clientes.

## Contexto

### Problema observado em producao

O cron `sync-reports` calcula `engagementRate = (engagedLeads / totalLeads) * 100`. Porem:

- **`totalLeads`** usa `profile_count` da **maior lista individual** do Klaviyo
- **`engagedLeads`** usa `profile_count` do **segmento "Engaged 90d"**, que pode abranger profiles de **multiplas listas**

Resultado: quando o segmento engaged tem mais profiles que a maior lista (porque agrega profiles de varias listas), o rate ultrapassa 100%.

### Evidencias de producao (2026-03)

| Loja | totalLeads | engagedLeads | Rate | Correto? |
|------|-----------|-------------|------|----------|
| Almira | 1,200 | 1,548 | 129% | NO |
| Vivazz | 2,000 | 2,700 | 135% | NO |
| Karm | 500 | 1,620 | 324% | NO |

### Causa raiz

O codigo em ambos os arquivos usa `reduce` para encontrar a lista com maior `profileCount`, mas deveria somar TODOS os `profileCount` de todas as listas.

**Arquivo 1** — `klaviyo-sync.service.ts` (linhas 255-259):
```typescript
// ANTES (bug): usa apenas a maior lista
const largestList = allLists.reduce(
  (max, l) => (l.profileCount > max.profileCount ? l : max),
  { id: "", name: "", profileCount: 0 },
)
const totalLeads = largestList.profileCount
```

**Arquivo 2** — `klaviyo-performance.service.ts` (linhas 176-179):
```typescript
// ANTES (bug): usa apenas a maior lista
const largestList = allLists.length > 0
  ? allLists.reduce((max, l) => l.profileCount > max.profileCount ? l : max, allLists[0])
  : null
const totalLeads = largestList?.profileCount || 0
```

### Fix

**Em `klaviyo-sync.service.ts`:** MANTER `largestList` (e usado na linha 305 para setar `isMainList` nos audience items). Apenas mudar o calculo de `totalLeads` para soma:
```typescript
// ANTES (bug):
const largestList = allLists.reduce(
  (max, l) => (l.profileCount > max.profileCount ? l : max),
  { id: "", name: "", profileCount: 0 },
)
const totalLeads = largestList.profileCount

// DEPOIS (fix): manter largestList, mas totalLeads = soma de todas
const largestList = allLists.reduce(
  (max, l) => (l.profileCount > max.profileCount ? l : max),
  { id: "", name: "", profileCount: 0 },
)
const totalLeads = allLists.reduce((sum, l) => sum + l.profileCount, 0)
// largestList continua usado abaixo para isMainList (linha 305)
```

**Em `klaviyo-performance.service.ts`:** `largestList` pode ser REMOVIDO — so era usado para `totalLeads`:
```typescript
// DEPOIS (fix): soma de todas as listas, largestList removido
const totalLeads = allLists.reduce((sum, l) => sum + l.profileCount, 0)
```

E adicionar safety cap no calculo do rate:
```typescript
const rawRate = totalLeads > 0 ? (engagedLeads / totalLeads) * 100 : 0
if (rawRate > 100) {
  log.warn(`[Audience] Engagement rate ${rawRate.toFixed(1)}% exceeds 100% — capping. totalLeads=${totalLeads}, engagedLeads=${engagedLeads}`)
}
const engagementRate = Math.min(rawRate, 100)
```
