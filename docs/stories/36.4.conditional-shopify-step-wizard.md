# Story 36.4 — Step Shopify Condicional no Wizard

## Contexto

O form publico ja esconde o step "Codigo Colaborador" quando `platform !== "shopify"` (via `getVisibleSteps()`). O wizard portal NAO faz isso — o step Shopify aparece sempre, mesmo para lojas WooCommerce ou Nuvemshop.

## Objetivo

Aplicar a mesma logica condicional do form publico no wizard portal.

## Criterios de Aceitacao

- [x] **AC 36.4.1**: Criar funcao `getVisibleSteps()` no wizard que filtra o step `shopify_code` quando `platform !== "shopify"`
- [x] **AC 36.4.2**: Ajustar indices de `currentStep` para usar `visibleSteps` em vez de `STEPS` fixo
- [x] **AC 36.4.3**: Ajustar `handleNext()` para respeitar steps visiveis
- [x] **AC 36.4.4**: Se usuario mudar plataforma de "shopify" para outra enquanto esta no step Shopify, navegar de volta para step da loja
- [x] **AC 36.4.5**: Backend (`/api/portal/onboarding/wizard`) deve aceitar wizard completo SEM step `shopify_code` quando platform != shopify
- [x] **AC 36.4.6**: Stepper visual reflete corretamente os steps visiveis (3 ou 4 circles)

## Impacto por Disciplina

- **Dev**: 1 arquivo frontend (~30 linhas), 1 arquivo backend (verificar logica de completude)
- **Arquiteto**: Verificar se API de wizard marca `shopifyCode.complete = true` automaticamente quando platform != shopify
- **DB**: Zero — `shopify_collaborator_code` ja e nullable
- **QA**: Testar fluxo com Shopify (4 steps) e sem Shopify (3 steps). Mudar plataforma mid-flow. Verificar onboarding conclui em ambos os caminhos

## Arquivos Envolvidos

- `src/app/portal/onboarding/wizard/page.tsx`
- `src/app/api/portal/onboarding/wizard/route.ts`

## Risco

Medio. A logica do backend de "wizard completo" pode depender de todos os 4 steps existirem.
