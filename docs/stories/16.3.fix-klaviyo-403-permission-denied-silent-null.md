## Story

**Como** administrador que configura uma API key da Klaviyo com scopes insuficientes,
**Quero** receber uma mensagem de erro clara indicando quais scopes estao faltando,
**Para que** eu possa corrigir a configuracao da API key ao inves de ver o dashboard vazio sem explicacao.

---

## Contexto

Quando a Klaviyo retorna 403 com `permission_denied`, o cliente HTTP em `src/lib/integrations/klaviyo/client.ts` (linhas 140-142) simplesmente loga o erro e retorna `null`. Callers recebem `null` sem nenhuma indicacao sobre o motivo real — o dashboard fica silenciosamente vazio.

Logs observados em producao:

```
[Klaviyo] API ERROR 403: {"errors":[{"code":"permission_denied","detail":"Your API key is missing required scopes: accounts:read"}]}
[Klaviyo] API ERROR 403: {"errors":[{"code":"permission_denied","detail":"Your API key is missing required scopes: metrics:read"}]}
```

O usuario ve o dashboard vazio e nao sabe se o problema e a API key, a loja, ou os dados em si. O 403 de `permission_denied` e fundamentalmente diferente de outros 4xx: e um erro de configuracao permanente que o retry nao vai resolver e que exige acao do usuario.

**Codigo atual (bugado)**:

```typescript
if (!response.ok) {
  log.error(`[${logTag}] API ERROR ${response.status}:`, responseText.substring(0, 500))
  return null
}
```

**Ponto de insercao**: logo antes do `return null` existente na funcao `_klaviyoRequestInner()`.

O padrao de erro tipado ja existe no arquivo — `KlaviyoRateLimitError` foi implementado na linha 17 exatamente para distinguir rate limits de outros erros. O mesmo padrao deve ser aplicado para erros de permissao.

## Arquitetura Tecnica

### Arquivo Principal Modificado

**`src/lib/integrations/klaviyo/client.ts`**

#### Adicionar apos KlaviyoRateLimitError (linha ~24)

```typescript
/**
 * Thrown when Klaviyo returns 403 with permission_denied.
 * Indicates the API key is missing required scopes — not a transient error.
 * Callers should surface this to the user as a configuration issue.
 */
export class KlaviyoPermissionError extends Error {
  public missingScopes: string[]
  constructor(missingScopes: string[]) {
    super(`Klaviyo API key is missing required scopes: ${missingScopes.join(", ")}`)
    this.name = "KlaviyoPermissionError"
    this.missingScopes = missingScopes
  }
}
```

#### BEFORE — bloco de erro generico (linha ~140)

```typescript
const responseText = await response.text()

if (!response.ok) {
  log.error(`[${logTag}] API ERROR ${response.status}:`, responseText.substring(0, 500))
  return null
}
```

#### AFTER — com deteccao de 403 permission_denied

```typescript
const responseText = await response.text()

if (!response.ok) {
  // Detect 403 permission_denied — not retryable, surface to caller
  if (response.status === 403) {
    try {
      const errBody = JSON.parse(responseText)
      const firstError = errBody?.errors?.[0]
      if (firstError?.code === "permission_denied") {
        const detail: string = firstError.detail ?? ""
        const match = detail.match(/scopes?:\s*(.+)$/i)
        const missingScopes = match
          ? match[1].split(",").map((s: string) => s.trim()).filter(Boolean)
          : ["unknown"]
        log.error(`[${logTag}] Permission denied — missing scopes: ${missingScopes.join(", ")}`)
        throw new KlaviyoPermissionError(missingScopes)
      }
    } catch (parseErr) {
      if (parseErr instanceof KlaviyoPermissionError) throw parseErr
      // Parse failed — fall through to generic error handling
    }
  }

  log.error(`[${logTag}] API ERROR ${response.status}:`, responseText.substring(0, 500))
  return null
}
```

#### No catch block — re-lancar KlaviyoPermissionError (linha ~148)

```typescript
} catch (error) {
  if (error instanceof KlaviyoRateLimitError) {
    log.warn(`[${logTag}] Rate limited after all retries for ${endpoint}`)
    throw error  // ja estava sendo relancado
  }
  // ADICIONAR:
  if (error instanceof KlaviyoPermissionError) {
    throw error  // nao retryar — e erro de configuracao permanente
  }
  log.error(`[${logTag}] REQUEST ERROR:`, error)
  if (attempt < maxRetries) continue
  return null
}
```

### Comportamento por status code

| Status | Codigo de erro | Comportamento |
|--------|---------------|---------------|
| 403    | `permission_denied` | Lanca `KlaviyoPermissionError` — nao retryado |
| 403    | outros / sem codigo | Log + return null (atual) |
| 401    | qualquer | Log + return null (atual) |
| 404    | qualquer | Log + return null (atual) |
| 422    | qualquer | Log + return null (atual) |
| 429    | qualquer | `KlaviyoRateLimitError` (existente) |
| 5xx    | qualquer | Retry com backoff (existente) |

### Por que nao retryar 403

Erros de permissao sao deterministicos: nenhuma quantidade de retries vai fazer a Klaviyo aceitar uma API key sem os scopes necessarios. Retryar seria desperdicar tentativas e aumentar latencia sem beneficio. O padrao e identico ao tratamento de `KlaviyoRateLimitError` com `rawWaitTime > MAX_RETRY_AFTER_MS` — fail fast e deixar o caller decidir o que fazer.
