# Story 56.2 — Adicionar requireStoreAccess nos OAuth Authorize Routes

## Story

**Como** engenheiro de seguranca,
**Quero** que os endpoints de OAuth authorize validem ownership do store_id antes de iniciar o fluxo,
**Para que** um usuario autenticado nao possa conectar credenciais OAuth a uma loja de outra organizacao.

## Contexto

### Problema

Os endpoints de OAuth authorize (`shopify/authorize`, `meta/authorize`) aceitam `store_id` dos query params sem nenhuma validacao de ownership. Um atacante autenticado pode:

1. Iniciar OAuth para `store_id` de outra org
2. Completar o fluxo OAuth com suas proprias credenciais
3. O callback grava as credenciais do atacante na loja vitima
4. O proximo cron sync puxa dados da loja do atacante para o dashboard da vitima

### Codigo atual (vulneravel)

**Shopify authorize** (`src/app/api/integrations/shopify/authorize/route.ts`):
```typescript
// Linha 20: store_id vem direto dos query params, sem validacao
const storeId = searchParams.get("store_id")
// ...
// Linhas 55-63: store_id e embarcado no state OAuth
const state = Buffer.from(JSON.stringify({
  store_id: storeId,
  // ... sem org_id!
})).toString("base64")
```

**Meta authorize** (`src/app/api/integrations/meta/authorize/route.ts`):
```typescript
// Linha 21: store_id vem direto dos query params
const storeId = searchParams.get("store_id")
// Linha 52: permite store_id vazio!
storeId || ""
```

### Fix

1. Adicionar `requireStoreAccess(storeId, user.id, "can_edit")` antes de montar o state OAuth
2. Incluir `orgId` (retornado pelo `requireStoreAccess`) no state JSON
3. Se `requireStoreAccess` falhar, redirect com `?error=store_access_denied`
4. Meta authorize: rejeitar `store_id` vazio

## Acceptance Criteria

### 56.2.1 — Shopify authorize + requireStoreAccess

- [x] Importar `requireStoreAccess` de `@/lib/api/require-store-access`
- [x] Antes de montar o state OAuth, chamar:
  ```typescript
  const storeAccess = await requireStoreAccess(storeId, user.id, "can_edit")
  ```
- [x] Tratar erro com redirect user-friendly:
  ```typescript
  try {
    const storeAccess = await requireStoreAccess(storeId, user.id, "can_edit")
  } catch (err) {
    const redirectUrl = new URL("/stores", request.nextUrl.origin)
    redirectUrl.searchParams.set("error", "store_access_denied")
    return NextResponse.redirect(redirectUrl)
  }
  ```
- [x] Incluir `org_id` no state JSON:
  ```typescript
  const state = Buffer.from(JSON.stringify({
    store_id: storeId,
    org_id: storeAccess.orgId,  // NOVO
    // ... demais campos
  })).toString("base64")
  ```

**Given-When-Then:**

```
GIVEN User A is authenticated in Org A
AND Store S1 belongs to Org B
WHEN User A calls GET /api/integrations/shopify/authorize?shop=test.myshopify.com&store_id=<S1_id>
THEN User A is redirected to /stores?error=store_access_denied
AND no OAuth flow is initiated

GIVEN User A is authenticated in Org A
AND Store S2 belongs to Org A
AND User A has can_edit on S2
WHEN User A calls GET /api/integrations/shopify/authorize?shop=test.myshopify.com&store_id=<S2_id>
THEN OAuth flow is initiated normally
AND state contains org_id from Org A
```

### 56.2.2 — Meta authorize + requireStoreAccess

- [x] Mesmo padrao do Shopify (importar, chamar, tratar erro)
- [x] Rejeitar `store_id` vazio ou ausente:
  ```typescript
  if (!storeId) {
    return NextResponse.redirect(
      new URL("/stores?error=missing_store_id", request.nextUrl.origin)
    )
  }
  ```
- [x] Incluir `org_id` no state JSON

**Given-When-Then:**

```
GIVEN User A is authenticated in Org A
AND Store S1 belongs to Org B
WHEN User A calls GET /api/integrations/meta/authorize?store_id=<S1_id>
THEN User A is redirected to /stores?error=store_access_denied

GIVEN any authenticated user
WHEN User calls GET /api/integrations/meta/authorize (sem store_id)
THEN User is redirected to /stores?error=missing_store_id

GIVEN User A is authenticated in Org A
AND Store S2 belongs to Org A
AND User A has can_edit on S2
WHEN User A calls GET /api/integrations/meta/authorize?store_id=<S2_id>
THEN OAuth flow is initiated normally
AND state contains org_id from Org A
```

### 56.2.3 — Store_id ausente no Shopify authorize

- [x] Se `store_id` ausente ou vazio, redirect com `?error=missing_store_id` (mesmo padrao do Meta)
- [x] NAO permitir que o fluxo continue sem store_id

### 56.2.4 — Typecheck

- [x] `npm run typecheck` passa sem erros novos
