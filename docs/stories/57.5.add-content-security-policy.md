# Story 57.5 — Adicionar Content-Security-Policy header

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint", "manual-review"]

## Story

**Como** engenheiro de segurança,
**Quero** que a aplicação retorne um header Content-Security-Policy restritivo,
**Para que** ataques XSS sejam mitigados mesmo se houver falha de sanitização no código.

## Contexto

### Problema

`next.config.mjs` já tem vários security headers (X-Frame-Options, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy), mas **falta CSP**.

CSP é a defesa mais efetiva contra XSS e é recomendação OWASP Top 10.

### Complexidade

CSP em Next.js requer cuidado com:
- `unsafe-inline` para estilos do Tailwind/Next.js
- `unsafe-eval` pode ser necessário para alguns componentes
- Domínios externos (Supabase, Klaviyo, Meta, Google Analytics, Vercel Analytics)
- Imagens de domínios externos (logos de lojas, avatars)

**Recomendação:** Começar com CSP em `Content-Security-Policy-Report-Only` para não quebrar nada, depois migrar para enforcement.

## Acceptance Criteria

### 57.5.1 — Adicionar CSP em Report-Only mode

- [ ] Adicionar header `Content-Security-Policy-Report-Only` em `next.config.mjs`
- [ ] Diretivas mínimas:
  - `default-src 'self'`
  - `script-src 'self' 'unsafe-inline' 'unsafe-eval'` (necessário para Next.js)
  - `style-src 'self' 'unsafe-inline'` (necessário para Tailwind)
  - `img-src 'self' data: blob: https:` (imagens de diversas fontes)
  - `font-src 'self'`
  - `connect-src 'self' https://*.supabase.co wss://*.supabase.co https://a.klaviyo.com https://graph.facebook.com`
  - `frame-ancestors 'none'` (redundante com X-Frame-Options mas mais moderno)
- [ ] CSP NÃO deve ser aplicado às rotas públicas do widget (`/api/script/*`, `/api/tracking/*`)

**Given-When-Then:**

```
GIVEN User loads any admin or portal page
WHEN browser receives the response
THEN Content-Security-Policy-Report-Only header is present
AND no CSP violations are reported in browser console for normal usage

GIVEN Widget script is loaded on external site
WHEN browser fetches /api/script/widget.js
THEN CSP header is NOT present (widget precisa funcionar em qualquer domínio)
```

### Pontos de Atenção

- Next.js injeta inline scripts para hydration — `unsafe-inline` é necessário para `script-src`
- Vercel Analytics pode precisar de domínio adicional
- Supabase usa WebSocket (`wss://`) para realtime — incluir em `connect-src`
- Começar em Report-Only permite identificar violações antes de enforçar

### Testing

- Abrir admin dashboard, portal dashboard, e login
- Verificar console do browser para CSP violations
- Se nenhuma violation, migrar para enforcement em story futura
