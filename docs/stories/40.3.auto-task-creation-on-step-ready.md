# Story 40.3 — Auto-Task Creation on Step Ready

## Story

**Como** membro da equipe (designer, developer, copywriter, etc.),
**Quero** que quando uma etapa de onboarding ficar pronta para mim, um card apareca automaticamente no meu board pessoal,
**Para que** eu saiba exatamente o que preciso fazer sem depender de alguem me avisar.

## Contexto

O `TaskAutomationService` ja cria tasks automaticas para eventos como onboarding started, meeting created e campaign scheduled. Esta story expande esse servico para criar tasks quando um `client_onboarding_step` transiciona para `pending` (= ready to start, deps met).

A task criada deve:
- Aparecer no board pessoal do membro atribuido ao step
- Ter `source_type = 'auto_onboarding_step'` e `source_id` = ID do step
- Manter link reverso: `client_onboarding_steps.task_id` aponta para a task criada
- Respeitar `board_config` do membro (se `show_onboarding_tasks` esta habilitado)

- [x] **AC 40.3.1**: Metodo `TaskAutomationService.onOnboardingStepPending()` criado, recebe step data e cria task no board do assignee
- [x] **AC 40.3.2**: Task criada com `type = 'onboarding'`, `source_type = 'auto_onboarding_step'`, `source_id = step.id`
- [x] **AC 40.3.3**: Apos criar a task, o campo `client_onboarding_steps.task_id` e atualizado com o ID da task
- [x] **AC 40.3.4**: Se o step nao tem `assigned_to`, buscar membro pelo `default_assignee_role` do template step na org do onboarding

- [x] **AC 40.3.6**: `SOURCE_TO_CONFIG_COLUMN` atualizado: `auto_onboarding_step` -> `show_onboarding_tasks`
- [x] **AC 40.3.7**: Task title segue formato: `[Onboarding] {step.name} - {client.name}` (ex: "Klaviyo Conectado - Loja XYZ")

## Technical Notes

### Novo metodo em TaskAutomationService

```typescript
static async onOnboardingStepPending(params: {
  stepId: string
  stepName: string
  onboardingId: string
  clientId: string
  clientName: string
  storeId?: string
  storeName?: string
  assignedTo?: string           // org_member_id direto
  defaultAssigneeRole?: string  // fallback: buscar membro por role
  orgId: string
  dueDate?: string
}): Promise<string | null>     // retorna task_id ou null
```

### Fluxo

```
1. Determinar assignee:
   a. Se params.assignedTo existe → usar
   b. Senao, buscar org_member com role = params.defaultAssigneeRole na org
   c. Se multiplos membros com o role, usar o primeiro ativo
   d. Se nenhum encontrado → log.warn e return null

2. Chamar createAutoTask() com source_type = 'auto_onboarding_step'

3. Se task criada:
   a. Atualizar client_onboarding_steps.task_id = task.id
   b. Retornar task.id
```

### Onde chamar este metodo

Este metodo sera chamado pelo `OnboardingSyncService` (story 40.4) apos o DB trigger transicionar steps de `waiting` para `pending`. Nesta story, apenas criar o metodo e testar isoladamente.

### Resolucao de assignee por role

```typescript
// Buscar membro ativo na org com o role especificado
const { data: members } = await supabase

  .limit(1)
```
