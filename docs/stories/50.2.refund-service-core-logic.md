# Story 50.2 — RefundService: Core Logic

## Story

**Como** sistema que precisa processar reembolsos de forma segura e consistente,
**Quero** um service centralizado que orquestre refunds via Asaas (async) e manuais (sync), com validacoes, audit trail, e rate limiting,
**Para que** os endpoints de API (stories 50.3, 50.4) e o webhook handler (story 50.6) tenham uma camada de logica reutilizavel.

## Contexto

O `RefundService` e o coracao do Epic 50. Ele encapsula:
- **initiateAsaasRefund**: Chama `AsaasService.refundPayment()`, insere refund com status 'requested', aguarda webhook
- **processManualRefund**: Para cobranças locais, marca imediatamente como 'processed' e atualiza status da charge
- **handleAsaasRefundWebhook**: Processa confirmacao do Asaas, atualiza refund para 'processed', checa se totalmente reembolsado
- **listRefunds**: Query paginada com filtros por client_id e status

- [x] INSERT em `refunds`: invoice_id, client_id, amount, reason, source='asaas', status='requested', processed_by=userId
- [x] Retornar `{ refundId, status: 'requested', originalAmount, refundAmount }`

```typescript
// Pseudocodigo da validacao de amount
const invoice = await adminClient.from('invoices').select('*').eq('id', invoiceId).single()
if (!invoice.data) throw new AppError(400, 'Invoice nao encontrada')
if (invoice.data.status !== 'paid') throw new AppError(400, 'Apenas faturas pagas podem ser reembolsadas')
if (!invoice.data.asaas_id) throw new AppError(400, 'Esta fatura nao possui cobranca Asaas vinculada. Use reembolso manual.')

const summary = await adminClient.from('refund_summaries').select('total_refunded').eq('invoice_id', invoiceId).maybeSingle()
const alreadyRefunded = summary?.data?.total_refunded ?? 0
const remaining = invoice.data.amount - alreadyRefunded
const refundAmount = amount ?? remaining

if (refundAmount > remaining) throw new AppError(400, `Valor excede o disponivel para reembolso (R$ ${remaining.toFixed(2)})`)
if (remaining <= 0) throw new AppError(409, 'Esta fatura ja foi totalmente reembolsada')
```

### AC 50.2.6 — Rate limiting

- [x] Implementar rate limit: 5 refunds por minuto por org_id
- [x] Usar in-memory Map com window de 60s (suficiente para serverless — cold start reseta, e o rate limit e uma protecao extra sobre o trigger DB)
- [x] Aplicar em `initiateAsaasRefund` e `processManualRefund` (nao em webhook)
- [x] Se excedido: throw AppError 429 "Limite de reembolsos excedido. Tente novamente em 1 minuto."

```typescript
const refundRateLimit = new Map<string, { count: number; resetAt: number }>()
const REFUND_RATE_LIMIT = { windowMs: 60_000, max: 5 }

function checkRefundRateLimit(orgId: string): void {
  const now = Date.now()
  const entry = refundRateLimit.get(orgId)
  if (!entry || now > entry.resetAt) {
    refundRateLimit.set(orgId, { count: 1, resetAt: now + REFUND_RATE_LIMIT.windowMs })
    return
  }
  if (entry.count >= REFUND_RATE_LIMIT.max) {
    throw new AppError(429, 'Limite de reembolsos excedido. Tente novamente em 1 minuto.')
  }
  entry.count++
}
```

- [x] Quando Asaas API falha → type: `refund_failed`, metadata: `{ invoice_id, amount, error_message }`
- [x] Usar `client_id` para vincular ao client correto

```typescript
// Exemplo de helper para activity logging
async function logRefundActivity(
  adminClient: SupabaseClient,
  type: 'refund_initiated' | 'refund_manual' | 'refund_completed' | 'refund_failed',
  clientId: string,
  metadata: Record<string, unknown>
) {
  try {
    await adminClient.from('activities').insert({
      client_id: clientId,
      type,
      metadata,
      created_at: new Date().toISOString(),
    })
  } catch (err) {
    console.warn(`[Refund] Failed to log activity ${type}:`, err)
  }
}
```
