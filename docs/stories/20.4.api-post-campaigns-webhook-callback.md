## Story

**Como** sistema n8n que completou a geracao de copies,
**Quero** enviar o resultado (drive folder + status por loja) via callback,
**Para que** o admin-convertfy atualize o status da campanha e lojas no banco.

---

## Contexto

Esta rota recebe o callback do n8n apos a geracao de copies. Ela:
1. Valida o header `x-webhook-secret` contra `N8N_WEBHOOK_SECRET`
2. Parseia o body com `webhookCallbackSchema` (story 20.1)
3. Atualiza `campaign_generations` com drive info e status final
4. Atualiza cada `campaign_generation_stores` com status individual
5. Erros parciais sao normais: se uma loja falha, a campanha ainda fica "done"
6. Deve ser idempotente: chamar novamente com mesmos dados nao deve causar erro

Os testes TDD cobrem: seguranca (3), validacao (2), all done (3), partial errors (3), edge cases (2) = 13 testes.


### Fluxo resumido

```
Request -> Validate x-webhook-secret header
  -> Parse body with webhookCallbackSchema
  -> Lookup generation by id (404 if not found)
  -> Fetch existing generation stores
  -> Update campaign_generations (drive info + status=done)
  -> For each store in payload: update status + generated_at/error_message
  -> Ignore unknown store_ids
  -> Return 200
```

### Decisao importante: status "done" SEMPRE

O `campaign_generations.status` vai para "done" quando o n8n termina, independente de erros parciais ou totais nas lojas. O CHECK constraint so permite `draft | processing | done` (sem "error" na campanha). Erros sao rastreados individualmente em `campaign_generation_stores.status`. O frontend usa os status individuais das lojas para mostrar quais deram erro. Isso simplifica o polling: se status != "processing", a geracao terminou.
