# Story 58.4 — Adicionar store_total_revenue ao RPC custom cache

## Executor Assignment

executor: "@dev"
quality_gate: "@qa"
quality_gate_tools: ["typecheck", "lint", "migration-review"]

## Story

**Como** operador do admin,
**Quero** que o relatorio de periodo personalizado mostre a receita total da loja (metric-aggregates) correta mesmo quando servido do cache,
**Para que** a porcentagem de atribuicao (receita Klaviyo / receita total) esteja correta.

## Contexto

### Problema

A funcao `upsert_custom_range_cache` em SQL hardcoda `store_total_revenue = 0`:

```sql
-- Na migration, dentro do RPC:
INSERT INTO store_revenue_summary (
  ...
  store_total_revenue,
  ...
) VALUES (
  ...
  0,              -- ← HARDCODED ZERO
  ...
)
```

O parametro `p_store_total_revenue` nao existe na funcao. Resultado:

1. **Primeiro fetch (live)**: `getKlaviyoRevenueForStore` busca `storeRevenue` via metric-aggregates (correto, ex: R$200.000)
2. **Cache write**: Grava `store_total_revenue = 0` no banco
3. **Segundo fetch (cache hit)**: Le `store_total_revenue = 0` do cache
4. **UI**: Mostra "Receita Total: R$0" ou calcula `attributedPercent = Infinity`

### No relatorio

No `buildResultSnapshot` (process/route.ts:362):
```typescript
totalRevenue += data.storeRevenue > 0 ? data.storeRevenue : data.totalRevenue
```

Quando `storeRevenue = 0` (do cache), o fallback usa `totalRevenue` (campaign+flow). Isso faz `total_revenue === klaviyo_attributed_revenue`, e a porcentagem de atribuicao fica 100% — o que e incorreto.

## Acceptance Criteria

### 58.4.1 — Adicionar parametro p_store_total_revenue ao RPC

- [ ] Criar nova migration SQL que usa `CREATE OR REPLACE FUNCTION` para atualizar `upsert_custom_range_cache`:
  - Adicionar parametro `p_store_total_revenue NUMERIC DEFAULT 0`
  - No INSERT: usar `p_store_total_revenue` em vez de `0`
  - No ON CONFLICT UPDATE: adicionar `store_total_revenue = p_store_total_revenue`
- [ ] A migration deve ser retrocompativel: o DEFAULT 0 garante que chamadas existentes sem o parametro continuem funcionando

### 58.4.2 — Passar storeRevenue na chamada do RPC

- [ ] Em `src/lib/integrations/klaviyo/report-summary.ts`, no bloco de write-through para custom ranges:
  - Adicionar `p_store_total_revenue: storeRevenue` na chamada `adminClient.rpc("upsert_custom_range_cache", {...})`
  - Se `storeRevenue` for 0 (metric-aggregates falhou), ainda passar 0 — nao criar inconsistencia

### 58.4.3 — Verificar leitura do cache

- [ ] No bloco de cache read para custom ranges (linhas ~207-211):
  - Verificar que `row.store_total_revenue` e lido e mapeado para `storeRevenue` no return
  - Se ja estiver sendo feito, nenhuma mudanca necessaria

### Migration SQL (rascunho — baseado na RPC real com correcoes da revisao QA/DataEngineer/Arquiteto)

**IMPORTANTE**: Este rascunho deve ser comparado com a migration original (`20260318_report_generation_cache.sql`) antes de aplicar. Os tipos de parametros (VARCHAR vs TEXT), SECURITY DEFINER, REVOKE/GRANT, e campos do INSERT devem ser IDENTICOS ao original exceto pela adicao do novo parametro.

```sql
-- Story 58.4: Add p_store_total_revenue parameter to upsert_custom_range_cache
-- Backward compatible: DEFAULT 0 preserves existing callers

CREATE OR REPLACE FUNCTION upsert_custom_range_cache(
  p_store_id UUID,
  p_org_id UUID,
  p_range_start DATE,
  p_range_end DATE,
  p_period_start TIMESTAMPTZ,
  p_period_end TIMESTAMPTZ,
  p_klaviyo_total_revenue NUMERIC,
  p_klaviyo_campaign_revenue NUMERIC,
  p_klaviyo_flow_revenue NUMERIC,
  p_currency VARCHAR,              -- ATENCAO: VARCHAR, nao TEXT (deve match o tipo original)
  p_expires_at TIMESTAMPTZ,
  p_store_total_revenue NUMERIC DEFAULT 0  -- NOVO: Story 58.4
)
RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER                   -- OBRIGATORIO: manter do original
SET search_path = public           -- OBRIGATORIO: manter do original
AS $$
DECLARE
  v_period_label VARCHAR(30);      -- ATENCAO: VARCHAR(30), nao TEXT (deve match o original)
BEGIN
  v_period_label := 'custom:' || p_range_start::text || ':' || p_range_end::text;

  INSERT INTO store_revenue_summary (
    store_id, period_label, org_id, range_start, range_end,
    period_start, period_end,
    klaviyo_total_revenue, klaviyo_campaign_revenue, klaviyo_flow_revenue,
    store_total_revenue, currency,
    sync_status, sync_source, expires_at, fetched_at, created_at, updated_at
  ) VALUES (
    p_store_id, v_period_label, p_org_id, p_range_start, p_range_end,
    p_period_start, p_period_end,
    p_klaviyo_total_revenue, p_klaviyo_campaign_revenue, p_klaviyo_flow_revenue,
    p_store_total_revenue, p_currency,
    'ok', 'report', p_expires_at, NOW(), NOW(), NOW()
  )
  ON CONFLICT (store_id, period_label)
  DO UPDATE SET
    klaviyo_total_revenue = EXCLUDED.klaviyo_total_revenue,
    klaviyo_campaign_revenue = EXCLUDED.klaviyo_campaign_revenue,
    klaviyo_flow_revenue = EXCLUDED.klaviyo_flow_revenue,
    store_total_revenue = EXCLUDED.store_total_revenue,  -- NOVO: Story 58.4
    currency = EXCLUDED.currency,
    sync_status = 'ok',
    sync_error = NULL,
    expires_at = EXCLUDED.expires_at,
    fetched_at = NOW(),
    updated_at = NOW();
END;
$$;

COMMENT ON FUNCTION upsert_custom_range_cache IS
  'Atomic UPSERT for custom range cache rows in store_revenue_summary. '
  'Builds composite period_label (custom:YYYY-MM-DD:YYYY-MM-DD). '
  'Story 58.4: Added p_store_total_revenue parameter.';

-- OBRIGATORIO: preservar restricoes de acesso do original
REVOKE EXECUTE ON FUNCTION upsert_custom_range_cache FROM PUBLIC;
REVOKE EXECUTE ON FUNCTION upsert_custom_range_cache FROM authenticated;
GRANT EXECUTE ON FUNCTION upsert_custom_range_cache TO service_role;
```
