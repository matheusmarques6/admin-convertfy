# Story 37.2 — Email Humanizado de Rejeicao

## Contexto

Quando o COO rejeita um onboarding, o cliente recebe um email generico com o texto cru dos comentarios do COO. Nao ha contexto acolhedor, nao ha explicacao clara do que aconteceu, e o link aponta para `/cliente/onboarding` sem instrucoes.

O email deve tranquilizar o cliente, explicar que basta preencher novamente, e incluir o motivo da rejeicao.

## Objetivo

Enriquecer o payload enviado ao N8N para que o email de rejeicao tenha: titulo claro, texto acolhedor, motivo do COO, e link direto para re-preenchimento.

## Criterios de Aceitacao

- [x] **AC 37.2.1**: Sanitizar `body.comments` antes de enviar ao N8N — remover tags HTML para prevenir XSS no email. Usar strip simples (regex), nao biblioteca pesada.
- [x] **AC 37.2.2**: Payload enviado ao N8N inclui campos adicionais: `action_type` ("rejected" ou "revision_requested"), `store_name`, `rejection_comments` (comments sanitizado), `resubmit_url` (link direto para `/cliente/onboarding`), `subject` ("Seu formulario precisa de ajustes").
- [x] **AC 37.2.3**: O metodo `triggerClientNotification` em `n8n-trigger.service.ts` aceita os novos campos sem quebrar chamadas existentes (campos opcionais).
- [x] **AC 37.2.4**: Diferenciar tom entre `rejected` e `revision_requested` no payload: rejected usa `subject: "Seu formulario precisa de ajustes"`, revision usa `subject: "Revisao solicitada no seu cadastro"`.
- [x] **AC 37.2.5**: O `portal_url` enviado no payload aponta para `/cliente/onboarding` (formulario publico, nao portal).
- [x] **AC 37.2.6**: Se `NEXT_PUBLIC_APP_URL` nao estiver configurado, usar fallback `http://localhost:3000` (ja existente).

> **Nota**: O template visual do email (HTML/CSS) e responsabilidade do N8N workflow e esta fora do escopo desta story. Esta story cobre apenas o payload enriquecido enviado ao webhook.

## Cenarios de Teste

1. Rejeicao com comments `<script>alert('xss')</script>` → deve ser sanitizado antes de enviar ao N8N
2. Rejeicao com comments contendo `<b>negrito</b>` → tags removidas, texto puro
3. Payload enviado ao N8N contem `action_type`, `store_name`, `rejection_comments`, `resubmit_url`, `subject`
4. Payload para `rejected` vs `revision_requested` tem `subject` diferente
5. `resubmit_url` aponta para `/cliente/onboarding` (nao `/portal/onboarding`)
6. N8N retorna 500 → rejeicao completa normalmente, log captura o erro

## Dependencia

- Story 37.1 (comments garantidamente nao-vazio)

## Risco

Baixo. Mudanca aditiva no payload — campos novos sao opcionais para o N8N. Se o workflow N8N nao for atualizado, ignora os campos extras e funciona como antes.
