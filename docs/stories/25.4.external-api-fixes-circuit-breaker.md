## Story

**Como** engine multi-carrier que depende de APIs externas instaveis,
**Quero** que providers com falha recorrente sejam temporariamente desabilitados via circuit breaker,
**Para que** nao desperdicem 5-8s de timeout por request quando sabemos que vao falhar.

---

## Contexto

### Providers com problemas conhecidos

| Provider | Erro | Impacto |
|----------|------|---------|
| Correios | 403 Forbidden (IPs de datacenter bloqueados) | 5s desperdicados por lookup BR |
| Cainiao | 302 Redirect (endpoint mudou) | 5s desperdicados por lookup CN |
| TrackingMore | 412 "format doesn't meet requirements" | Falha silenciosa em tracking real |

## Acceptance Criteria

### 25.4.1 — Kill switch + circuit breaker para Correios

**Controle primario (persistente):**
- [ ] Adicionar env var `CORREIOS_ENABLED` (default `"true"`) — se `"false"`, skip permanentemente
- [ ] No `canRun()` do provider: `if (process.env.CORREIOS_ENABLED === "false") return false`
- [ ] Este e o kill switch principal para quando IPs de datacenter estao bloqueados

**Controle secundario (best-effort in-memory):**
- [ ] Implementar variavel `correiosDisabledUntil: number` (timestamp) no modulo
- [ ] Se Correios retornar 403, setar `correiosDisabledUntil = Date.now() + 30 * 60_000` (30min)
- [ ] No `canRun()` do provider, verificar `Date.now() < correiosDisabledUntil` — se sim, skip
- [ ] Log especifico para 403: `log.debug("Correios 403 (cloud IP blocked)")` em vez de `log.warn`

**LIMITACAO DOCUMENTADA:** O circuit breaker in-memory reseta em cada cold start do Vercel serverless. Multiplas instancias concorrentes NAO compartilham estado. O circuit breaker funciona apenas como otimizacao oportunista dentro de uma instancia warm. Para desabilitar Correios de forma persistente, usar `CORREIOS_ENABLED=false`.

### 25.4.2 — Kill switch + guard para Cainiao redirect

**Controle primario (persistente):**
- [ ] Adicionar env var `CAINIAO_ENABLED` (default `"true"`) — se `"false"`, skip permanentemente
- [ ] No `canRun()`: `if (process.env.CAINIAO_ENABLED === "false") return false`

**Guard de redirect:**
- [ ] Adicionar `redirect: "manual"` no fetch do Cainiao para nao seguir redirects
- [ ] Se response status 301/302, logar URL de redirect e retornar `null` imediatamente
- [ ] Verificar `content-type` da resposta antes de `response.json()` — se nao for JSON, retornar `null`

**Circuit breaker secundario (best-effort):**
- [ ] Implementar `cainiaoDisabledUntil` similar ao Correios (30min cooldown apos redirect)
- [ ] Mesma limitacao de cold start documentada acima

### 25.4.3 — TrackingMore: avaliar upgrade v3 para v4

- [ ] Investigar se `api.trackingmore.com/v4/trackings/realtime` funciona com as mesmas keys
- [ ] Se v4 funcionar: atualizar `TRACKINGMORE_API_BASE` de `/v3` para `/v4`
- [ ] Se v4 NAO funcionar: manter v3 e adicionar fallback — quando 412, retry sem `courier_code`:
  ```typescript
  if (response.status === 412 && courierCode) {
    // Retry sem courier_code (auto-detect)
    return trackViaTrackingMore(trackingNumber, apiKey, undefined)
  }
  ```
- [ ] Alinhar `test/route.ts` com a mesma versao usada em `carriers.ts`

## Dev Notes

### Circuit breaker pattern

```typescript
// No topo de carriers.ts
let correiosDisabledUntil = 0
let cainiaoDisabledUntil = 0

// No PROVIDER_REGISTRY:
correios: {
  label: "Correios",
  canRun: (_k, c) => {
    if (process.env.CORREIOS_ENABLED === "false") return false
    if (Date.now() < correiosDisabledUntil) return false
    return c.code === "correios"
  },
  execute: async (tn) => {
    const result = await trackViaCorreios(tn)
    // Se retornou null E o ultimo erro foi 403, ativar circuit breaker
    return result
  },
},
```

### Cainiao redirect guard

```typescript
const response = await fetch("https://global.cainiao.com/global/detail.json", {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded", "Accept": "application/json" },
  body: `mailNoList=${encodeURIComponent(trackingNumber)}&language=en`,
  signal: controller.signal,
  redirect: "manual",  // NAO seguir redirect
})

if (response.status >= 300 && response.status < 400) {
  log.warn("Cainiao returned redirect", {
    status: response.status,
    location: response.headers.get("location"),
  })
  cainiaoDisabledUntil = Date.now() + 30 * 60_000
  return null
}

const contentType = response.headers.get("content-type") || ""
if (!contentType.includes("application/json")) {
  log.warn("Cainiao returned non-JSON", { contentType })
  return null
}
```
