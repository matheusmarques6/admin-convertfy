# Story 57.4 — Passar orgId no getStoreCredentials do revalidate

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint"]

## Story

**Como** engenheiro de segurança,
**Quero** que a rota `/api/client-stores/credentials/revalidate` passe `orgId` para `getStoreCredentials()`,
**Para que** haja defense-in-depth contra acesso cross-tenant nas credenciais.

## Contexto

### Problema

A rota de revalidação chama `getStoreCredentials(storeId)` sem passar `orgId`, potencialmente permitindo leitura de credenciais cross-tenant se `requireStoreAccess` falhar:

```typescript
// ATUAL:
const creds = await getStoreCredentials(storeId)  // ← sem orgId

// CORRETO (como outras rotas fazem):
const creds = await getStoreCredentials(storeId, orgId)  // ← com orgId
```

Outras rotas já passam `orgId` como defense-in-depth. Esta rota deve ser consistente.

## Acceptance Criteria

### 57.4.1 — Passar orgId para getStoreCredentials

- [x] Obter `orgId` do resultado de `requireStoreAccess()` (se disponível) ou de `resolveOrgId()`
- [x] Passar `orgId` como segundo parâmetro para `getStoreCredentials(storeId, orgId)`

**Given-When-Then:**

```
GIVEN User A belongs to Org A
AND Store S1 belongs to Org B
WHEN User A calls POST /api/client-stores/credentials/revalidate with storeId=S1
THEN request is rejected (requireStoreAccess already blocks)
AND even if requireStoreAccess were bypassed, getStoreCredentials would reject due to orgId mismatch
```

### 57.4.2 — Typecheck

- [x] `npm run typecheck` passa sem erros novos
