# Story 45.3 — Fix Hardcoded BRL Currency in Campaign API

## Status: Ready for Review
## Effort: LOW (30min)
## Priority: HIGH

## Context

The portal campaigns API route hardcodes every store's currency to "BRL":

```typescript
const storeCurrencyMap = Object.fromEntries(clientStoreIds.map(id => [id, "BRL"]))
```

The `client_stores` table already has a `currency` column (added in commit `4fc08f9`), but this route never reads it. Multi-currency clients see wrong currency symbols on all campaign revenue.

## File

`src/app/api/portal/campaigns/route.ts` — line ~36

## Important: `resolvePortalClient()` does NOT expose currency

`PortalClientContext` (from `src/lib/api/portal-auth.ts`) only returns `storeIds: string[]` and `storeNameMap: Record<string, string>`. It does NOT return store objects or currency. **Option 1 (ctx.stores) will NOT work.**

## Recommended Fix

**Extend `resolvePortalClient()`** to include a `storeCurrencyMap` in the context. This is the cleanest approach because:
- It's reusable by other portal routes that may need currency
- Story 45.12 also needs to extend this context (for org_id) — combining avoids two changes to the same file

```typescript
// In resolvePortalClient() — extend the select:
const { data: stores } = await supabase
  .from("client_stores")
  .select("id, store_name, currency")
  .eq("client_id", clientId)

// Add to PortalClientContext:
interface PortalClientContext {
  // ...existing fields...
  storeCurrencyMap: Record<string, string>  // NEW: storeId → currency code
  orgId: string                              // NEW: for 45.12 defense-in-depth
}

// Build the map:
storeCurrencyMap: Object.fromEntries(
  (stores || []).map(s => [s.id, s.currency || "BRL"])
)
```

Then in the campaigns route:
```typescript
const storeCurrencyMap = ctx.storeCurrencyMap  // Simple, no extra query
```
