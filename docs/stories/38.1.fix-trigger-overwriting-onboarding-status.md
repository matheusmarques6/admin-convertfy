# Story 38.1 -- Fix trigger `update_onboarding_progress` sobrescrevendo status de fase

## Story

Como engenheiro de dados,
Quero corrigir a trigger `update_onboarding_progress` para nao sobrescrever o campo `status` com valores genericos,
Para que o phase service e a trigger nao conflitem e o tracking de fases funcione corretamente.

## Contexto

### Problema observado

A trigger `update_onboarding_progress` (criada em `20250125_08_onboarding.sql:390-423`) dispara quando qualquer `client_onboarding_steps.status` muda. Ela:

1. Recalcula `progress_percent` (OK)
2. **Sobrescreve `client_onboardings.status`** com `in_progress` ou `completed` (CONFLITO)
3. Se 100%, atualiza `clients.status` para `active` (DUPLICADO com phase service)

O phase service (`onboarding-phase.service.ts`) usa o campo `status` para tracking de fases como `design`, `implementation`, etc. Quando a trigger dispara, ela sobrescreve esse valor para `in_progress`, quebrando o tracking.

### Codigo atual da trigger

```sql
-- 20250125_08_onboarding.sql:390-417
CREATE OR REPLACE FUNCTION update_onboarding_progress()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE client_onboardings
  SET
    progress_percent = calculate_onboarding_progress(NEW.onboarding_id),
    status = CASE
      WHEN calculate_onboarding_progress(NEW.onboarding_id) = 100 THEN 'completed'::onboarding_status
      WHEN calculate_onboarding_progress(NEW.onboarding_id) > 0 THEN 'in_progress'::onboarding_status
      ELSE status
    END,
    completed_at = CASE
      WHEN calculate_onboarding_progress(NEW.onboarding_id) = 100 THEN NOW()
      ELSE completed_at
    END
  WHERE id = NEW.onboarding_id;

  IF calculate_onboarding_progress(NEW.onboarding_id) = 100 THEN
    UPDATE clients
    SET status = 'active'
    WHERE id = (SELECT client_id FROM client_onboardings WHERE id = NEW.onboarding_id);
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

### Phase service (sistema atual)

O phase service (`onboarding-phase.service.ts:87-88`) faz:
```typescript
status: toPhase,        // ex: "design", "implementation"
current_phase: toPhase, // redundante mas defensivo
```

E na fase `completed` (linha 261-265), tambem atualiza `clients.status = 'active'`.

### Cenario de conflito

1. Onboarding esta em fase `design` (status = `design`, current_phase = `design`)
2. Admin marca um step como `completed` na UI
3. Trigger dispara: `status` vira `in_progress` (sobrescrevendo `design`)
4. O phase service agora ve `status = in_progress` em vez de `design`
5. A UI do portal pode mostrar a fase errada se consultar `status` em vez de `current_phase`

## Acceptance Criteria

### 38.1.1 -- Modificar trigger para nao sobrescrever `status`

- [x] Criar nova migration que substitui a funcao `update_onboarding_progress`
- [x] A trigger deve APENAS atualizar `progress_percent` e `completed_at`
- [x] Nao deve tocar no campo `status` (gerenciado exclusivamente pelo phase service)
- [x] Nao deve tocar no `clients.status` (gerenciado exclusivamente pelo phase service)
- [x] Manter o calculo de `completed_at` quando progress = 100%

**Nova versao sugerida:**

```sql
CREATE OR REPLACE FUNCTION update_onboarding_progress()
RETURNS TRIGGER AS $$
DECLARE
  _progress INTEGER;
BEGIN
  _progress := calculate_onboarding_progress(NEW.onboarding_id);

  UPDATE client_onboardings
  SET
    progress_percent = _progress,
    completed_at = CASE
      WHEN _progress = 100 AND completed_at IS NULL THEN NOW()
      ELSE completed_at
    END
  WHERE id = NEW.onboarding_id;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```
