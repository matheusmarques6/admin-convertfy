## Contexto

O portal dashboard (`/api/portal/dashboard`) le dados Klaviyo de cache tables e Shopify via `generateShopifyReport()`. Quando o cache Klaviyo esta vazio, retorna `dataStatus: "syncing"` com tudo zero:

```typescript
// portal/dashboard/route.ts (linhas 553-557)
} else {
  response.dataStatus = "syncing"
  response.lastFetchedAt = null
}
```

Para o portal, o comportamento esperado e diferente do admin:
1. **Auto-fallback**: se cache vazio, fazer live fetch AUTOMATICAMENTE (sem `force_refresh`)
2. **Stale-refresh**: se cache stale (expirado mas existente), retornar dados stale + refresh em background
3. **Sem refresh button**: portal nao tem UI para force_refresh (e para clientes, nao admins)

A logica e:
- Cache fresh → retornar (como hoje)
- Cache vazio → live fetch automatico (com cooldown)
- Cache stale → retornar stale + marcar `isRefreshing: true` (cron atualiza proximo ciclo)

---

## Objetivo

Adicionar auto-fallback ao portal dashboard para Klaviyo e Shopify, garantindo que clientes sempre vejam dados reais, protegido por cooldown atomico.

- [x] **10.6.3** Criar funcao `liveFetchKlaviyoForPortal` que usa cooldown + sync service:
  ```typescript
  async function liveFetchKlaviyoForPortal(
    store: StoreInfo,
    period: string,
    supabase: SupabaseClient,
  ): Promise<CachedKlaviyoData | null> {
    const fetchKey = getFetchKey(period)
    const canFetch = await tryAcquireLiveFetch(supabase, store.id, fetchKey, "portal-fallback")

    if (!canFetch) {
      // Cooldown active — someone else is fetching, return null (show loading)
      return null
    }

    try {
      const credentials = await getStoreCredentials(store.id)
      const apiKey = credentials.klaviyo_private_key || credentials.klaviyo_api_key
      if (!apiKey) { await releaseLiveFetch(supabase, store.id, fetchKey, "failed"); return null }

      const accountInfo = await getCachedAccountInfo(apiKey)
      const metricId = await getCachedPlacedOrderMetric(apiKey)
      if (!metricId) { await releaseLiveFetch(supabase, store.id, fetchKey, "failed"); return null }

      const [flowNames, campNames] = await Promise.all([
        fetchFlowNames(apiKey),
        fetchCampaignNames(apiKey),
      ])

      const syncResult = await syncKlaviyoForPeriod({
        storeId: store.id, orgId: store.orgId, apiKey,
        timezone: accountInfo.timezone,
        timezoneOffset: getTimezoneOffset(accountInfo.timezone),
        metricId, period, flowNames, campNames,
      })

      if (syncResult.success && syncResult.data) {
        // Save to cache tables
        await upsertSyncResults(supabase, store, syncResult.data, period)
        await releaseLiveFetch(supabase, store.id, fetchKey, "completed")

        // Return as CachedKlaviyoData format for mapCacheToPortalKlaviyo
        return buildCachedKlaviyoData(syncResult.data, store.id, period)
      }

      await releaseLiveFetch(supabase, store.id, fetchKey, "failed")
      return null
    } catch (err) {
      await releaseLiveFetch(supabase, store.id, fetchKey, "failed")
      log.error(`[Portal LiveFetch] Error for store ${store.id}:`, err)
      return null
    }
  }
  ```

## Arquitetura Tecnica

### Fluxo Portal: Single Store

```
GET /api/portal/dashboard?period=30d&store_id=abc

  Cache FRESH → { dataStatus: "ready", source: "cache" }
  Cache STALE → { dataStatus: "stale", source: "stale-cache", isRefreshing: false }
  Cache EMPTY + Cached Period → tryAcquireLiveFetch()
    → acquired: live fetch → upsert → { dataStatus: "ready", source: "live" }
    → cooldown: { dataStatus: "loading", isRefreshing: true }
  Cache EMPTY + LIVE_ONLY → tryAcquireLiveFetch()
    → acquired: live fetch → { dataStatus: "ready", source: "live" }
    → cooldown/fail: { dataStatus: "empty" }
```

### Fluxo Portal: All Stores

```
GET /api/portal/dashboard?period=30d

  1. Fetch cache for all stores in parallel (DB reads, fast)
  2. Stores WITH cache → aggregate normally
  3. Stores WITHOUT cache (max 5) → live fetch with cooldown
  4. Merge all results
  5. If some stores still loading: dataStatus = "stale" (partial data)
```

### Helper: `buildCachedKlaviyoData`

Converte `KlaviyoSyncData` (do service) para `CachedKlaviyoData` (formato que `mapCacheToPortalKlaviyo` espera):

```typescript
function buildCachedKlaviyoData(
  syncData: KlaviyoSyncData,
  storeId: string,
  period: string,
): CachedKlaviyoData {
  return {
    summary: {
      klaviyo_total_revenue: syncData.campaignRevenue + syncData.flowRevenue,
      klaviyo_campaign_revenue: syncData.campaignRevenue,
      klaviyo_flow_revenue: syncData.flowRevenue,
      shopify_total_revenue: syncData.storeRevenue,
      total_leads: 0, // audience not fetched in live fallback (optional)
      engaged_leads: 0,
      engagement_rate: 0,
      period_start: syncData.startDateStr,
      period_end: syncData.endDateStr,
      fetched_at: new Date().toISOString(),
      sync_status: "ok",
    },
    campaigns: syncData.campRows.map(row => ({ ...row })),
    flows: syncData.flowRows.map(row => ({ ...row })),
  }
}
```

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Live fetch lento (>15s) para store com muitos flows/campaigns | Timeout de 15s + retorno parcial |
| All stores com 10 sem cache = 10 live fetches simultaneos | Limitar live fetch a max 5 stores (restantes mostram "loading") |
| Audience metrics zero no live fallback | Aceitavel — cron popula na proxima execucao; nao e critico |
| Portal usa `createAdminClient()` para upserts — seguro? | Sim, portal ja usa adminClient para reads (bypass RLS de portal_users) |
| Shopify live fetch + Klaviyo live fetch simultaneos = lento | Shopify e Klaviyo rodam em paralelo (Promise.all), nao sequenciais |
