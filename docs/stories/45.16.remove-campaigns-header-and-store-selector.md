# Story 45.16 — Remove Campaigns Header and Store Selector from Portal

## Status: Ready for Dev
## Effort: LOW (~30min)
## Priority: MEDIUM

## Context

Portal campaigns page (`src/app/client/campaigns/page.tsx`) currently renders two unnecessary UI elements:

1. **Header block** — "Campanhas" title + subtitle "Acompanhe campanhas de marketing e gere copies". This is redundant; the page context is already clear from navigation.
2. **Store selector dropdown** in `CampaignFilterBar` — unnecessary because the portal already resolves all stores the client has access to via `resolvePortalClient()`. The current "Todas as lojas" default behavior is the only behavior needed.

Both elements add visual noise and dead code paths (store state management, URL sync for `store` param) without providing value.

## Prerequisites

- **Story 45.8** — CampaignFilterBar already extracted as standalone component
- **Story 45.9** — Modals already extracted (page.tsx is lean)

## Objective

Remove the header block and store selector from the portal campaigns page. Campaigns load for ALL client stores by default (current "Todas as lojas" behavior). Clean up all associated dead code: store-related state, memos, URL sync, types, and imports.

## Acceptance Criteria

- [ ] **AC 45.16.1** Header "Campanhas" + subtitle removed from page.tsx
- [ ] **AC 45.16.2** Store selector dropdown removed from CampaignFilterBar (only Channel + Status dropdowns remain)
