# Story 52.1 — Fix Asaas Sync: Phone Format + Error Visibility

## Story

**Como** operador do admin que edita clientes,
**Quero** que a sincronizacao com o Asaas nao falhe por formato de telefone e que o erro real seja visivel,
**Para que** eu consiga diagnosticar e corrigir problemas de sincronizacao sem precisar acessar logs do servidor.

## Contexto

### Problema observado em producao

Ao editar o cliente "Romario de Santana Lima" (Dripslum, email `empresasveronica1@gmail.com`), o sistema exibe:

- Toast verde: "Cliente atualizado!" (save local OK)
- Toast vermelho: "Aviso: Erro ao sincronizar com Asaas" (sync falhou)

O usuario nao tem como saber o motivo real do erro porque o toast hardcoda a mensagem generica.

### Analise de codigo — 5 bugs identificados

#### BUG 1 (CRITICO): Telefone com codigo de pais `+55` causa rejeicao no Asaas

**Fluxo do telefone `+5511976674459`:**

1. `edit/page.tsx` linha 163-167 — normaliza mantendo `+`:
   ```typescript
   data.phone = hasPlus ? `+${digits}` : digits  // → "+5511976674459"
   ```

2. Salva no banco como `+5511976674459`

3. `update/route.ts` linha 68 — strip `/\D/g` remove `+` mas MANTEM `55`:
   ```typescript
   const cleanPhone = client.phone?.replace(/\D/g, "") || undefined  // → "5511976674459" (13 digitos)
   ```

4. Envia `phone: "5511976674459"` e `mobilePhone: "5511976674459"` ao Asaas

5. Asaas espera formato brasileiro sem codigo de pais: `11976674459` (11 digitos)
   → **400: "Telefone invalido"**

**Arquivos afetados:**
- `src/app/api/integrations/asaas/customers/update/route.ts` (linha 68)
- `src/app/api/integrations/asaas/customers/create/route.ts` (linhas 81-82)

#### BUG 2 (ALTO): Toast esconde o erro real do Asaas

**`edit/page.tsx` linhas 310-314:**
```typescript
toast({
  title: "Aviso: Erro ao sincronizar com Asaas",
  description: "Cliente atualizado localmente, mas houve erro ao sincronizar com o Asaas."
  // ❌ asaasUpdateData.error EXISTE mas nunca e mostrado!
})
```

O backend ja retorna `asaasUpdateData.error` com a mensagem exata da API do Asaas (ex: "Telefone invalido", "CPF/CNPJ invalido", "Email ja cadastrado"), mas o frontend descarta essa informacao.

**Mesmo problema no catch** (linhas 318-322): nao mostra erro.

#### BUG 3 (MEDIO): `create/route.ts` retorna sempre status 500

**Linha 110-116:** Todos os erros retornam `status: 500`, mesmo erros de validacao (400). O `update/route.ts` ja faz certo usando `error.statusCode`.

#### BUG 4 (MEDIO): Telefone tambem nao e limpo no endpoint de criacao

**`create/route.ts` linhas 81-82:** Mesmo problema do BUG 1 — strip de `\D` nao remove o prefixo `55`.

#### BUG 5 (BAIXO): Email duplicado no Asaas nao tratado

Se o email do cliente local ja pertence a OUTRO customer no Asaas, o `PUT /customers/{id}` retorna 400. Nao ha tratamento especifico.

## Acceptance Criteria

### AC 52.1.1 — Strip codigo de pais do telefone antes de enviar ao Asaas

- [x] Criar funcao utilitaria `stripBrazilCountryCode(phone: string): string` em `src/lib/utils/phone.ts` (usada em 2 arquivos — extrair para DRY) que:
  - Remove prefixo `55` de telefones com 12-13 digitos (fixo/movel com DDI)
  - Mantem telefones com 10-11 digitos intactos (ja sem DDI)
  - Retorna `undefined` se o resultado tiver menos de 10 digitos
- [x] Aplicar em `update/route.ts` linha 68 (phone e mobilePhone)
- [x] Aplicar em `create/route.ts` linhas 81-82 (phone e mobilePhone)

**Logica:**
```typescript
function stripBrazilCountryCode(phone: string | null | undefined): string | undefined {
  if (!phone) return undefined
  const digits = phone.replace(/\D/g, "")
  // Se tem 12-13 digitos e comeca com 55, remover prefixo
  if ((digits.length === 12 || digits.length === 13) && digits.startsWith("55")) {
    return digits.slice(2)
  }
  // Se tem 10-11 digitos, ja esta no formato correto
  if (digits.length >= 10 && digits.length <= 11) {
    return digits
  }
  // Formato inesperado — retornar como esta (deixar Asaas validar)
  return digits || undefined
}
```
