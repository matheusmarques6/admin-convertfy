## Story

**Como** usuario do portal do cliente com sessao longa,
**Quero** que minha sessao seja renovada automaticamente durante chamadas API,
**Para que** eu nao perca acesso ao portal sem aviso apos o token JWT expirar.

---

## Contexto

O middleware do Next.js (`src/lib/supabase/middleware.ts`) pula a renovacao de sessao
para todas as rotas `/api/`:

```typescript
// src/lib/supabase/middleware.ts:9
if (request.nextUrl.pathname.startsWith('/api/')) {
  return NextResponse.next() // SEM updateSession!
}
```

Isso significa que:
1. Token JWT do Supabase expira (default 3600s = 1h)
2. Chamadas API do portal continuam usando token expirado
3. `createClient()` no server retorna sessao invalida
4. `requireAuth()` retorna 401
5. Frontend recebe erro, mostra "Erro ao carregar" — mas NAO redireciona para login
6. Usuario ve dados zerados sem entender que precisa relogar

**Nota:** O Supabase client-side (browser) faz refresh automatico do token,
mas o server-side depende dos cookies que o middleware atualiza.

---

## Criterios de Aceitacao

- [ ] **CA1**: Rotas `/api/portal/*` renovam sessao via updateSession
      (ou mecanismo equivalente que atualiza cookies)
- [ ] **CA2**: Frontend redireciona para `/portal/login` quando recebe 401 de qualquer API route
- [ ] **CA3**: Nao impactar performance de API routes que nao precisam de auth
      (ex: `/api/script/*`, webhooks)
- [ ] **CA4**: Sessao renovada nao causa double-fetch ou loop de requisicoes
- [ ] **CA5**: Typecheck + lint passando

## Riscos

- Renovar sessao em API routes adiciona latencia (~50ms por request)
  → Impacto minimo para portal, mas nao habilitar para TODAS as /api/ routes
- Middleware com cookie set em API routes pode causar problemas com CDN/cache
  → Portal routes nao sao cacheadas em CDN, entao risco baixo
