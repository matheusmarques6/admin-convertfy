## Story

**Como** usuario do portal,
**Quero** ver o historico de campanhas geradas com detalhes por loja,
**Para que** eu possa acompanhar o status, acessar o Drive e re-gerar copies com erro.

---

## Contexto

A tela de historico lista todas as `campaign_generations` do client, ordenadas por data de criacao (mais recente primeiro). Cada item pode ser expandido para mostrar a tabela de lojas com status individuais, versao, link para Drive, e acoes (regerar/tentar novamente).

Dados vem de:
- `campaign_generations` filtrado por `client_id` (via portal auth)
- `campaign_generation_stores` para cada generation expandida (lazy load ou pre-loaded)

## Acceptance Criteria

### 20.8.1 — Lista de campanhas

- [x] Criar componente `CampaignHistoryList` em `src/components/campaigns/campaign-history-list.tsx`
- [x] Ou integrar diretamente na pagina de historico
- [x] Listar campanhas com: nome, data, status (badge colorido), link Drive (se disponivel), data de criacao
- [x] Badges de status: `processing` (amarelo/pulse), `done` (verde), `draft` (cinza)
- [x] Link Drive: icone + "Abrir no Drive" quando `drive_folder_url` disponivel
- [x] Ordenar por `created_at` DESC

### 20.8.2 — Expand com tabela de lojas

- [x] Clicar na campanha expande/colapsa a tabela de lojas
- [x] Tabela com colunas: Loja (nome), Pais, Idioma, Status (badge), Versao, Acao
- [x] Status badge por loja: `pending` (cinza), `generating` (amarelo/pulse), `done` (verde), `error` (vermelho)
- [x] Se loja com erro: mostrar `error_message` em tooltip ou texto abaixo do badge
- [x] Coluna Acao:
  - Loja "done": botao "Regerar" (dispara regeneracao com version+1)
  - Loja "error": botao "Tentar novamente" (mesma acao que regerar)
  - Loja "generating"/"pending": desabilitado

### 20.8.3 — Acoes de regeneracao

- [x] Botao "Regerar"/"Tentar novamente" chama `POST /api/campaigns/generate` com `generation_id` + `store_ids: [store_id]`
- [x] Loading state no botao durante request
- [x] Toast de sucesso/erro apos resposta
- [x] Apos regeneracao, atualizar status local para "processing"

### 20.8.4 — Dados de campanhas via Supabase client

- [x] Usar `createClient()` (RLS) direto no componente Server para listar `campaign_generations` do client
- [x] RLS policy SELECT (story 20.2) garante que portal user so ve campanhas do proprio client_id
- [x] Fetch de `campaign_generation_stores` como query separada ao expandir (lazy load)
- [x] Nota: NAO criar endpoint API separado — usar Supabase client direto e mais simples e seguro via RLS

### 20.8.5 — Empty state

- [x] Se nenhuma campanha criada: mostrar mensagem "Nenhuma campanha gerada ainda" + link para o formulario
- [x] Se campanha sem lojas (edge case): mostrar "-" nas colunas

### Tipagem

```typescript
interface CampaignGeneration {
  id: string
  name: string
  date: string
  status: "draft" | "processing" | "done"
  drive_folder_url: string | null
  created_at: string
  stores: CampaignGenerationStore[]
}

interface CampaignGenerationStore {
  id: string
  store_id: string
  store_name: string
  country: string
  language: string
  status: "pending" | "generating" | "done" | "error"
  version: number
  error_message: string | null
  generated_at: string | null
}
```
