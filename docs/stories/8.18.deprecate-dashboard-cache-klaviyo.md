## Contexto

Apos Stories 8.16 e 8.17, o portal dashboard le TODOS os dados Klaviyo de tabelas cacheadas pelo cron:
- `store_revenue_summary` — revenue agregado + audience metrics
- `klaviyo_campaign_metrics` — detalhes individuais por campanha
- `klaviyo_flow_metrics` — detalhes individuais por flow

A tabela `dashboard_cache` (criada na migration `20250123_dashboard_cache.sql`) era o mecanismo original de cache do portal. Ela armazena:
- `cache_type = "klaviyo_perf"` — dados de performance Klaviyo (agora redundante)
- `cache_type = "shopify"` — dados de report Shopify (AINDA necessario)

### Uso atual de `dashboard_cache` no portal

O portal dashboard (`/api/portal/dashboard/route.ts`) usa `getCachedData`/`saveToCache`/`getStaleData` para:
1. **Klaviyo** (`klaviyo_perf`): cache de `KlaviyoPerformanceData` — **SERA REMOVIDO** (substituido por cron tables)
2. **Shopify** (`shopify`): cache de Shopify report data — **MANTER** (Shopify nao tem cron equivalente)

### Outros usos de `dashboard_cache`

Verificar se `dashboard_cache` e usado em outros endpoints:
- `src/lib/integrations/klaviyo/cached-metadata.ts` — usa para cache de metadata (account info, metric IDs). Esse e um uso DIFERENTE e deve ser avaliado separadamente.
- `src/app/api/client-stores/[id]/route.ts` — pode usar dashboard_cache. Verificar.
- `src/lib/cache.ts` — `cleanExpiredCache()` limpa entries expirados da `dashboard_cache`.

---

## Objetivo

Remover todo o fluxo de Klaviyo data via `dashboard_cache` no portal, deixando essa tabela apenas para dados Shopify (e quaisquer outros usos nao-Klaviyo). Limpar dead code e imports nao utilizados.
