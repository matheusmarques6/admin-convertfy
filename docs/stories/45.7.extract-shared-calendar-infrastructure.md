# Story 45.7 — Extract Shared Calendar Infrastructure

## Status: Ready for Review
## Effort: MEDIUM (2-3h)
## Priority: MEDIUM

## Context

Admin and portal calendars duplicate constants (CHANNEL_CONFIG, STATUS_CONFIG, MONTH_NAMES, WEEK_DAYS), date utility functions, and transform logic. This story extracts shared infrastructure into reusable modules.

## Deliverables

### 1. Calendar Constants (`src/lib/constants/calendar.ts`)

Extract from both admin and portal:
- `CHANNEL_CONFIG` — include WhatsApp (currently missing from portal, see L1)
- `STATUS_CONFIG` — unified status colors/labels
- `MONTH_NAMES` — Portuguese month names
- `WEEK_DAYS` — Portuguese day abbreviations
- `COLOR_MAP` — default campaign colors by channel
- `STATUS_MAP` — status normalization (completed→sent, processing→scheduled, etc.)
- `CHANNEL_MAP` — channel resolution from campaign_type

### 2. Date Utilities (`src/lib/utils/date.ts`)

Extract from portal page.tsx:
- `getStartOfWeek(date)` — (keep if week view survives Story 45.2)
- `getEndOfWeek(date)`
- `addDays(date, n)`
- `isSameDay(a, b)`
- `formatDateKey(date)` — returns YYYY-MM-DD

### 3. Campaign Transform (`src/lib/utils/campaign-transform.ts`)

Extract from portal page.tsx:
- `transformCampaignData(raw: PortalCampaignApiResponse): PortalCampaign`
- Uses properly typed input (from Story 45.6)
