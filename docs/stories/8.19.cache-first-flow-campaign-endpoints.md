## Contexto

As paginas de detalhe de store (tabs Flows e Campaigns em `/stores/[id]`) usam os endpoints:
- `GET /api/integrations/klaviyo/flows?store_id=X&period=30d` — lista todos os flows com metricas
- `GET /api/integrations/klaviyo/campaigns?store_id=X&period=30d` — lista todas as campaigns com metricas

Atualmente, esses endpoints SEMPRE fazem chamadas live a Klaviyo API:
1. Paginam `/flows/` ou `/campaigns` para listar todos (3-8 API calls por paginacao)
2. Chamam o reporting API (`/flow-values-reports/` ou `/campaign-values-reports/`) para metricas (1 API call)
3. Fazem cache write-through para `klaviyo_flow_metrics` / `klaviyo_campaign_metrics` (ja implementado)

O cron `sync-reports` JA popula essas mesmas tabelas a cada 2h. Os endpoints de detalhe podem ler do cache primeiro e so fazer live fetch se o cache estiver stale ou vazio.

### Endpoints atuais

**Flows endpoint** (`src/app/api/integrations/klaviyo/flows/route.ts`):
- Busca lista de flows (paginacao) + metricas (reporting API)
- Faz upsert em `klaviyo_flow_metrics` (write-through cache)
- Retorna flows com metricas combinadas

**Campaigns endpoint** (`src/app/api/integrations/klaviyo/campaigns/route.ts`):
- Busca lista de campaigns (paginacao por canal) + metricas (reporting API)
- Faz upsert em `klaviyo_campaign_metrics` (write-through cache)
- Retorna campaigns com metricas combinadas

### Dados no cache vs live

O cache (cron-populated) tem:
- Todas as metricas (recipients, delivered, opened, clicked, conversion_value, etc.)
- Nome, status, trigger_type (flows) ou send_time, channel, subject (campaigns)
- `fetched_at` timestamp para determinar freshness
- Dados para os periodos 7d, 15d, 30d, 90d

O cache NAO tem:
- Periodos custom (custom start/end dates)
- Periodo "1d" ou "12m" (cron so sincroniza 7d, 15d, 30d, 90d)

---

## Objetivo

Implementar estrategia cache-first nos endpoints de flows e campaigns: ler do cache quando dados sao frescos, fallback para live API quando stale ou indisponivel. Isso reduz load time das paginas de detalhe e evita rate limit issues.

## Arquitetura Tecnica

### Cache-First Pattern (Flows)

```typescript
// src/app/api/integrations/klaviyo/flows/route.ts

const CACHED_PERIODS = new Set(["7d", "15d", "30d", "90d"])
const CACHE_MAX_AGE_MS = 2 * 60 * 60 * 1000 // 2 hours

export async function GET(request: NextRequest) {
  // ... existing auth + param parsing ...

  const forceRefresh = searchParams.get("force_refresh") === "true"
  const isCustomPeriod = period === "custom" || !CACHED_PERIODS.has(period)

  // Try cache first for standard periods
  if (!forceRefresh && !isCustomPeriod) {
    const cachedFlows = await readFlowsFromCache(storeId, period, adminClient)
    if (cachedFlows) {
      return NextResponse.json({
        success: true,
        period: { start: cachedFlows.periodStart, end: cachedFlows.periodEnd, label: period },
        fromCache: true,
        fetchedAt: cachedFlows.fetchedAt,
        currency: "BRL", // default, cache doesn't store currency
        summary: cachedFlows.summary,
        flows: cachedFlows.flows,
      }, { headers: corsHeaders(request.headers.get("origin")) })
    }
  }

  // Fall through to live fetch (existing code)
  // ...
}

async function readFlowsFromCache(storeId: string, period: string, supabase: SupabaseClient) {
  const { data: rows, error } = await supabase
    .from("klaviyo_flow_metrics")
    .select("*")
    .eq("store_id", storeId)
    // Match by checking fetched_at freshness across all rows for this store
    .order("fetched_at", { ascending: false })

  if (error || !rows || rows.length === 0) return null

  // Find the most recent fetched_at for this period
  // Group by period_start/period_end to find the right period
  const latestFetchedAt = new Date(rows[0].fetched_at)
  if (Date.now() - latestFetchedAt.getTime() > CACHE_MAX_AGE_MS) return null

  // Filter to rows matching the latest period dates
  const periodStart = rows[0].period_start
  const periodEnd = rows[0].period_end
  const periodRows = rows.filter(r => r.period_start === periodStart && r.period_end === periodEnd)

  // Map to response format
  const flows = periodRows
    .filter(r => r.flow_status !== "archived")
    .map(r => ({
      id: r.flow_id,
      name: r.flow_name,
      status: r.flow_status,
      triggerType: r.trigger_type,
      created: "", // not stored in cache
      recipients: r.recipients || 0,
      delivered: r.delivered || 0,
      deliveryRate: r.delivery_rate || 0,
      opened: r.opened || 0,
      openRate: r.open_rate || 0,
      clicked: r.clicked || 0,
      clickRate: r.click_rate || 0,
      clickToOpenRate: r.click_to_open_rate || 0,
      conversions: r.conversions || 0,
      conversionRate: r.conversion_rate || 0,
      conversionValue: r.conversion_value || 0,
      revenuePerRecipient: r.revenue_per_recipient || 0,
      averageOrderValue: r.average_order_value || 0,
      bounced: r.bounced || 0,
      bounceRate: r.bounce_rate || 0,
      unsubscribed: r.unsubscribed || 0,
      unsubscribeRate: r.unsubscribe_rate || 0,
      revenue: r.conversion_value || 0,
    }))
    .sort((a, b) => b.conversionValue - a.conversionValue)

  // Calculate summary
  const summary = flows.reduce((acc, flow) => ({
    totalFlows: acc.totalFlows + 1,
    liveFlows: acc.liveFlows + (flow.status === 'live' ? 1 : 0),
    draftFlows: acc.draftFlows + (flow.status === 'draft' ? 1 : 0),
    manualFlows: acc.manualFlows + (flow.status === 'manual' ? 1 : 0),
    totalRecipients: acc.totalRecipients + flow.recipients,
    totalDelivered: acc.totalDelivered + flow.delivered,
    totalOpened: acc.totalOpened + flow.opened,
    totalClicked: acc.totalClicked + flow.clicked,
    totalConversions: acc.totalConversions + flow.conversions,
    totalRevenue: acc.totalRevenue + flow.conversionValue,
    totalBounced: acc.totalBounced + flow.bounced,
    totalUnsubscribed: acc.totalUnsubscribed + flow.unsubscribed,
  }), { /* zero initial values */ })

  return {
    periodStart,
    periodEnd,
    fetchedAt: rows[0].fetched_at,
    summary: {
      ...summary,
      avgOpenRate: summary.totalDelivered > 0 ? Math.round((summary.totalOpened / summary.totalDelivered) * 10000) / 100 : 0,
      avgClickRate: summary.totalDelivered > 0 ? Math.round((summary.totalClicked / summary.totalDelivered) * 10000) / 100 : 0,
      avgConversionRate: summary.totalDelivered > 0 ? Math.round((summary.totalConversions / summary.totalDelivered) * 10000) / 100 : 0,
      avgBounceRate: summary.totalRecipients > 0 ? Math.round((summary.totalBounced / summary.totalRecipients) * 10000) / 100 : 0,
      revenuePerRecipient: summary.totalRecipients > 0 ? Math.round((summary.totalRevenue / summary.totalRecipients) * 100) / 100 : 0,
    },
    flows,
  }
}
```

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Cache stale mostra dados desatualizados | 2h max age; `force_refresh=true` disponivel; `fetchedAt` mostra quando dados foram buscados |
| Period dates nao batem (timezone fix de 8.15) | Usar `period_start`/`period_end` do cache, nao recalcular; fallback para live se nao encontrar |
| Cache nao tem `created` date para flows | Campo `created` fica vazio no cache response — avaliar se frontend depende desse campo |
| Cache nao tem `currency` | Usar "BRL" como default ou buscar de `getCachedAccountInfo` (rapido, cached in-memory) |
| Custom period sempre faz live fetch | Correto e esperado; custom periods nao sao cacheados pelo cron |
