## Story

**Como** usuario que visualiza campanhas no calendario,
**Quero** que o status e as metricas das campanhas Klaviyo sejam exibidos corretamente,
**Para que** o calendario mostre campanhas "sent" com recipients, revenue, etc — nao tudo como "draft" com zeros.

---

## Contexto

A tabela `campaigns` tem 96 rows sincronizadas do Klaviyo, **todas** com:
- `status = 'draft'` (incorreto — deveria ser "sent" para campanhas enviadas)
- `recipients = 0`, `delivered = 0`, `opened = 0`, `clicked = 0`, `revenue = 0.00`

### Causa do status errado

Em `sync-persistence.service.ts`, a funcao `mapCampaignStatus(status)` recebe `null`/`undefined` quando o campo `campaign_status` da tabela `klaviyo_campaign_metrics` e NULL. O switch/case nao trata null e cai no `default: return "draft"`.

### Causa das metricas zeradas

Duas fontes de sync para a tabela `campaigns`:

1. **Cron path** (`syncCampaignsToCalendarFromCron`): filtra `campRows.filter(r => r.send_time)` e mapeia metricas. Mas como o campaign report retorna null (story 27.2), `campRows` e vazio e **nenhuma campanha e sincronizada** por este path.

2. **Live path** (`syncCampaignsToCalendarFromLive`): mapeia `KlaviyoCampaignItem` para a tabela, mas o objeto nao inclui metricas (ou sao 0/undefined). As 96 rows atuais vieram deste path com metricas zeradas.

## Acceptance Criteria

### 27.6.1 — Fix mapCampaignStatus para tratar null/undefined

- [x] Em `mapCampaignStatus()` (`sync-persistence.service.ts` linha ~367), tratar `null` e `undefined` como input valido
- [x] Quando status e null/undefined, tentar inferir do campo `send_time`:
  - Se `send_time` existe e esta no passado → "sent"
  - Se `send_time` existe e esta no futuro → "scheduled"
  - Se `send_time` nao existe → "draft"
- [x] Alternativamente, usar o status do `campNames` map (que vem de `fetchCampaignNames()` e tem o status correto)
- [x] **Nota QA**: Investigar se os 96 rows "draft" vieram do live path (`syncCampaignsToCalendarFromLive` linha ~276 que hardcoda `status: "sent"`) ou de uma versao anterior do codigo. Se o live path JA hardcoda "sent", as 96 rows "draft" podem ser de um code path diferente ou legado. Logar a origem durante a investigacao.

### 27.6.2 — Cron path: popular campaign_status corretamente

- [x] Em `klaviyo-sync.service.ts`, ao construir `campRows`, garantir que `campaign_status` e populado:
  ```typescript
  campaign_status: info?.status || "sent" // info vem do campNames map
  ```
- [x] Verificar que o campo nao e null quando escrito em `klaviyo_campaign_metrics`

### 27.6.3 — Live path: incluir metricas no sync para calendario

- [x] Em `syncCampaignsToCalendarFromLive()`, ao construir a row para upsert na tabela `campaigns`:
  - Incluir `recipients: c.recipients || 0`
  - Incluir `delivered: c.delivered || 0`
  - Incluir `opened: c.opened || 0`
  - Incluir `clicked: c.clicked || 0`
  - Incluir `revenue: c.revenue || 0`
  - Incluir `converted: c.conversions || 0`
- [x] O tipo `KlaviyoCampaignItem` esta definido em `src/lib/services/klaviyo-performance.service.ts` (NAO em `src/types/`). Se nao tem campos `opened`/`clicked`/`conversions`, adiciona-los ao type e ao mapeamento no endpoint live.

### 27.6.4 — Verificar status mapping correto end-to-end

- [x] Campanhas Klaviyo com status "Sent" devem aparecer como "sent" no calendario
- [x] Campanhas com status "Scheduled" devem aparecer como "scheduled"
- [x] Campanhas com status "Draft" devem aparecer como "draft"
- [x] Campanhas com status "Cancelled" devem aparecer como "cancelled"
