# Story 55.4 — Aumentar Metadata Cache TTL

## Story

**Como** engenheiro de performance do cron,
**Quero** que os metadados Klaviyo (accountInfo e placedOrderMetricId) tenham TTL de 24h em vez de 30 minutos,
**Para que** eliminemos ~24 API calls redundantes por run em dados que quase nunca mudam.

## Contexto

### Problema

Em `src/lib/cache.ts` (linha 17):

```typescript
klaviyo_metadata: { account_info: 30, placed_order_metric: 30 },
```

O TTL de `accountInfo` (timezone, currency, public_api_key) e `placedOrderMetricId` (UUID do metric "Placed Order") e de **30 minutos**. Esses dados praticamente nunca mudam — timezone e currency sao configurados 1x na conta Klaviyo, e o metric ID e imutavel.

### Impacto

- Cada loja busca 2 metadados: `accountInfo` + `placedOrderMetricId`
- Cron roda a cada 30min, TTL = 30min → cache expira EXATAMENTE a cada run
- 42 lojas x 2 calls = **84 API calls** gastas em metadados por run
- Com TTL 24h e ~20 API key groups: **~40 API calls** no primeiro run, **0** nos 47 runs seguintes
- Economia media: **~24 API calls por run** (considerando distribuicao de expiracoes)

### Dados que sao cacheados

| Cache Key | Conteudo | Frequencia de mudanca |
|-----------|----------|-|
| `account_info` | `{ timezone, currency, public_api_key }` | Quase nunca (config da conta) |
| `placed_order_metric` | `{ metricId: "abc-123" }` | Nunca (UUID imutavel) |

## Riscos

| Risco | Mitigacao |
|-------|----------|
| Timezone ou currency mudam e ficam stale 24h | Extremamente raro; invalidacao manual disponivel via SQL |
| Cache DB falha e todos fazem API call | Graceful degradation ja implementada em cached-metadata.ts |
| metricId muda (novo "Placed Order" metric) | Nunca acontece; ID e imutavel no Klaviyo |
