# Story 50.1 — DB Migration: Add Refund Support

## Story

**Como** desenvolvedor que precisa persistir dados de reembolso,
**Quero** aplicar a migration que adiciona 'refunded' ao CHECK de client_charges, cria a tabela refunds com triggers de protecao, e atualiza as VIEWs unified_invoices e refund_summaries,
**Para que** toda a infraestrutura de banco esteja pronta para as stories subsequentes do Epic 50.

## Contexto

A migration ja esta finalizada e revisada (Architect + QA) no arquivo `supabase/migrations/20260315_add_refund_support.sql`. Esta story trata de **aplica-la via Supabase MCP** e **verificar** que todos os componentes funcionam corretamente.

### O que a migration faz

1. Estende o CHECK de `client_charges.status` para incluir 'refunded'
2. Cria tabela `refunds` com constraints (XOR parent, amount > 0, status lifecycle)
3. Cria trigger `check_refund_total_limit()` — impede refund_total > original_amount usando `SELECT FOR UPDATE`
4. Cria trigger `check_refund_client_consistency()` — valida client_id denormalizado
5. Cria trigger `update_refunds_updated_at` — auto-update de updated_at
6. Cria indexes (invoice_id, charge_id, client_id, status, asaas_refund_id UNIQUE)
7. Habilita RLS com 3 policies (org member SELECT, admin ALL, portal SELECT)
8. Cria VIEW `refund_summaries` (agregacao por charge/invoice)
9. Atualiza VIEW `unified_invoices` com colunas `refund_total` e `net_amount`

### Arquivo da migration

`supabase/migrations/20260315_add_refund_support.sql`
