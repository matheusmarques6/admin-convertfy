# Story 54.2 — Fix `org_id: null` Violating NOT NULL in sync-persistence

## Story

**Como** engenheiro responsavel pelo pipeline de sync,
**Quero** que o upsert em `store_revenue_summary` nunca tente inserir `org_id: null`,
**Para que** o sync nao falhe silenciosamente para lojas sem `org_id`, deixando o portal em estado "syncing" infinito.

## Contexto

### Problema

A tabela `store_revenue_summary` tem `org_id UUID NOT NULL` (migration `20260228`). Porem, o codigo em `sync-persistence.service.ts` escreve:

```typescript
// Linha ~73
org_id: store.org_id || null,
```

Se `store.org_id` for falsy (undefined, null, empty string), o upsert tenta inserir `org_id: null`, violando a constraint NOT NULL. O Supabase retorna erro, mas o codigo apenas loga e continua — o portal nunca ve dados para essa loja.

### Mesmo problema em `savePerfDataToCache`

```typescript
// Linha ~165
org_id: orgId,  // orgId pode ser null
```

### Impacto em producao

Qualquer loja onde `client_stores.org_id` esteja null tera:
1. Upsert falhando silenciosamente a cada execucao do cron
2. Portal mostrando "syncing" indefinidamente
3. Zero dados no dashboard

### Evidencia

O cron ja filtra `not("org_id", "is", null)` na query de lojas (linha ~444), mas:
1. A filtragem pode falhar se o campo vier vazio string em vez de null
2. O `savePerfDataToCache` (path de live fetch) NAO tem esse filtro

## Acceptance Criteria

### 54.2.1 — Guard no upsertSyncResults

- [x] Antes de fazer upsert em `store_revenue_summary`, validar que `store.org_id` e um UUID valido
- [x] Se `org_id` for falsy, logar warning e skip o upsert (nao crashar):
  ```typescript
  if (!store.org_id) {
    console.warn(`[Sync] Skipping revenue summary for store ${store.id}: missing org_id`)
    return
  }
  ```
- [x] Remover o `|| null` fallback — se org_id e required, deve ser tratado como tal

**Arquivo:** `src/lib/services/sync-persistence.service.ts`

### 54.2.2 — Guard no savePerfDataToCache

- [x] Mesma validacao no path de live fetch (`savePerfDataToCache`):
  ```typescript
  if (!orgId) {
    console.warn(`[Sync] Skipping perf cache save: missing orgId for store ${storeId}`)
    return
  }
  ```
- [x] Garantir que o parametro `orgId` seja required (nao optional) na assinatura

**Arquivo:** `src/lib/services/sync-persistence.service.ts`

### 54.2.3 — Propagar org_id para flow/campaign metrics

- [x] Verificar que `org_id` tambem e propagado corretamente nos upserts de `klaviyo_flow_metrics` e `klaviyo_campaign_metrics`
- [x] Se `org_id` for nullable nessas tabelas, o guard do AC 54.2.1 ja previne o caso — nao precisa de guard separado, mas deve propagar o valor

### 54.2.4 — Validacao

- [x] `npm run build` passa
- [x] `npm run lint` passa
- [x] Simular cenario: loja com org_id null nao causa crash no cron
