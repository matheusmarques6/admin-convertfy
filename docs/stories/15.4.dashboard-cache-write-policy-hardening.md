# Story 15.4 — Harden dashboard_cache: Migrar Writes para adminClient + Policy Guard

## Contexto

A tabela `dashboard_cache` tem uma policy de escrita permissiva (`FOR ALL USING(true) WITH CHECK(true)`) que permite qualquer usuário autenticado inserir, atualizar ou deletar qualquer linha.

**Análise do código real** (confirmada pelo @qa via grep):

A v1 desta story assumia que todos os writes em `dashboard_cache` já usavam `createAdminClient()`. Isso é falso — dois endpoints usam `createClient()` (user RLS) para chamar `setCache()`:

```typescript
// src/app/api/integrations/shopify/report/route.ts
const supabase = await createClient()        // ← user RLS
await setCache(supabase, storeId, "shopify", ...)  // ← write via RLS user

// src/app/api/integrations/google-analytics/report/route.ts
const supabase = await createClient()        // ← user RLS
await setCache(supabase, storeId, "ga4", ...)      // ← write via RLS user
```

`setCache()` usa `UPSERT`. Se a policy `FOR ALL USING(true)` for removida e substituída por uma policy de INSERT apenas, o UPSERT que resulta em UPDATE seria bloqueado — **quebrando Shopify e GA4 em produção**.

**Solução em duas fases:**

1. **Fase A (esta story):** Migrar os dois endpoints para usar `createAdminClient()` ao chamar `setCache()`.
2. **Fase B (esta story, após A):** Aplicar a migration de hardening da policy — agora segura.

## Objetivo

**Como** engenheiro de segurança,
**Quero** que todos os writes em `dashboard_cache` usem `createAdminClient()` e que a policy de escrita tenha defense-in-depth via `WITH CHECK`,
**Para que** um bug de aplicação que use o client errado não permita sobrescrever dados de outro tenant.

### Fase B — Migration de Hardening

**Arquivo:** `supabase/migrations/20260304_dashboard_cache_policy_hardening.sql`

```sql
-- Harden dashboard_cache write policies
-- Story 15.4 — safe to apply AFTER all setCache() calls use createAdminClient()

-- Remove the permissive FOR ALL policy
DROP POLICY IF EXISTS "Service role can manage dashboard cache" ON dashboard_cache;

-- Service role: unrestricted access (bypasses RLS anyway via createAdminClient)
-- Policy kept for intent documentation
CREATE POLICY "dashboard_cache_service_all" ON dashboard_cache
  FOR ALL
  TO service_role
  USING (true)
  WITH CHECK (true);

-- Authenticated users: INSERT only for own org
-- (In practice, all writes now use createAdminClient — this is defense-in-depth)
CREATE POLICY "dashboard_cache_insert_authenticated" ON dashboard_cache
  FOR INSERT
  TO authenticated
  WITH CHECK (
    org_id = current_org_id()
    OR org_id IS NULL
  );

-- No UPDATE/DELETE policy for authenticated role = denied by default
-- All updates/deletes must use createAdminClient() (service role)
```
