# Story 29.2 — Persistir Listas e Segmentos Klaviyo (klaviyo_audiences)

## Contexto

Hoje buscamos listas e segmentos da Klaviyo API via `getLists()` e `getSegments()`, mas **não persistimos os dados individuais** no banco. Apenas 3 campos agregados (`total_leads`, `engaged_leads`, `engagement_rate`) são salvos em `store_revenue_summary`. O objetivo é criar uma tabela unificada `klaviyo_audiences` para armazenar nome e profile_count de cada lista e segmento.

## Decisoes de Design

### Dev (Dex) — Aprovado
- **Tabela unificada** é melhor que 2 separadas: lists e segments compartilham o mesmo schema base (`id`, `name`, `profile_count`). Os campos extras de segments (`is_active`, `is_starred`) são metadata simples como colunas nullable.
- Segue o princípio do projeto de unificar quando schemas são compatíveis (ex: `store_revenue_summary` unifica dados de flow, campaign, audience num único row).
- **Sync via cron** reaproveitando `fetchAudienceForStore()` que já pagina tudo. Só falta persistir os arrays completos em vez de descartar.
- Estimativa: ~1 dia (story S/M).

### QA (Quinn) — PASS COM RESSALVAS
1. **Delete-then-insert** (não upsert puro) — garante que listas/segmentos deletados na Klaviyo desaparecem do banco. Mesmo padrão de `sync-persistence.service.ts` para flows/campaigns.
2. **NÃO alterar o caminho de escrita do `store_revenue_summary`** — tabela nova é detalhe adicional, não substitui os 3 campos agregados que alimentam KPIs do portal.
3. **RLS obrigatória** — copiar padrão de `klaviyo_flow_metrics`.
4. **Edge cases tratados:**
   - Listas/segmentos deletados no Klaviyo → resolvido pelo delete-then-insert
   - Nomes duplicados → `klaviyo_id` é unique, não `name`
   - `profile_count=0` → manter fallback de fetch individual já existente
   - Conta Klaviyo vazia → zero rows, sem erro
5. **Observabilidade:** `fetched_at` para detectar staleness.
6. **Risco de regressão:** LOW se aditivo. Não mudar `store_revenue_summary`.

## Schema

```sql
CREATE TABLE IF NOT EXISTS klaviyo_audiences (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  store_id UUID NOT NULL REFERENCES client_stores(id) ON DELETE CASCADE,
  org_id UUID REFERENCES organizations(id),
  klaviyo_id TEXT NOT NULL,
  type TEXT NOT NULL CHECK (type IN ('list', 'segment')),
  name TEXT NOT NULL,
  profile_count INTEGER DEFAULT 0,
  is_active BOOLEAN,
  is_starred BOOLEAN,
  is_main_list BOOLEAN DEFAULT false,
  is_engaged_segment BOOLEAN DEFAULT false,
  created_at_klaviyo TIMESTAMPTZ,
  fetched_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(store_id, klaviyo_id)
);
```
