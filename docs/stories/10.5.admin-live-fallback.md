# Story 10.5 - Admin Live Fallback com force_refresh

**Prioridade:** P1 (Alta — dashboard admin mostra zero para lojas sem cache)
**Sprint:** Current
**Assignee:** @dev
**Revisao:** @sm (River)
**Status:** Ready for Review
**Epic:** 10 - Cache-First + Live Fallback Unificado
**Fase:** 3 - Live Fallback

---

## Contexto

O admin dashboard (`/api/dashboard/total-revenue`) le exclusivamente de `store_revenue_summary`. Se o cron nunca rodou para uma loja (nova loja, cron falhou, primeira implantacao), o dashboard mostra zero:

```typescript
// total-revenue/route.ts (linhas 86-117)
if (rows.length === 0) {
  // ... retorna dataStatus: "syncing" com tudo zero
}
```

Para o admin, o esperado e:
1. Cache-first: tentar `store_revenue_summary` (rapido, ~50ms)
2. Se vazio E admin solicita `force_refresh=true`: fazer live fetch via sync service
3. Respeitar cooldown atomico (Story 10.4) para nao sobrecarregar Klaviyo
4. Para periodos LIVE_ONLY (1d, 12m, custom): sempre fazer live fetch (sem cache do cron)

Alem disso, o endpoint deve suportar `force_refresh=true` como query param para permitir refresh manual pelo admin.

---

## Objetivo

Adicionar live fallback ao endpoint `/api/dashboard/total-revenue` para que o admin veja dados reais mesmo quando o cache esta vazio, com suporte a `force_refresh` e proteido por cooldown atomico.

- [x] **10.5.3** Funcao `liveFetchForStores` que coordena live fetch para N stores:
  ```typescript
  async function liveFetchForStores(
    stores: StoreRow[],
    period: string,
    supabase: SupabaseClient,
  ): Promise<RevenueSummary[]> {
    const results: RevenueSummary[] = []

    for (const store of stores) {
      const fetchKey = getFetchKey(period)
      const canFetch = await tryAcquireLiveFetch(supabase, store.id, fetchKey, "admin-fallback")

      if (!canFetch) {
        // Cooldown active — try to read (possibly stale) cache
        const cached = await getCachedSummary(store.id, period, supabase)
        if (cached) results.push(cached)
        continue
      }

      try {
        // Get credentials + metadata
        const credentials = await getStoreCredentials(store.id)
        const apiKey = credentials.klaviyo_private_key || credentials.klaviyo_api_key
        if (!apiKey) continue

        const accountInfo = await getCachedAccountInfo(apiKey, store.org_id)
        const metricId = await getCachedPlacedOrderMetric(apiKey, store.org_id)
        if (!metricId) continue

        const [flowNames, campNames] = await Promise.all([
          fetchFlowNames(apiKey),
          fetchCampaignNames(apiKey),
        ])

        const syncResult = await syncKlaviyoForPeriod({
          storeId: store.id, orgId: store.org_id, apiKey,
          timezone: accountInfo.timezone,
          timezoneOffset: getTimezoneOffset(accountInfo.timezone),
          metricId, period, flowNames, campNames,
        })

        if (syncResult.success && syncResult.data) {
          // Save to cache tables for future requests
          await upsertSyncResults(supabase, store, syncResult.data, period)
          results.push(buildSummaryFromSync(store, syncResult.data))
        }

        await releaseLiveFetch(supabase, store.id, fetchKey, "completed")
      } catch (err) {
        await releaseLiveFetch(supabase, store.id, fetchKey, "failed")
        log.warn(`[LiveFetch] Error for store ${store.store_name}:`, err)
      }
    }

    return results
  }
  ```

## Arquitetura Tecnica

### Fluxo Completo

```
GET /api/dashboard/total-revenue?period=30d

  ┌─ Cache HIT (normal) ──────────────────────────────────────┐
  │  1. Query store_revenue_summary → rows found              │
  │  2. Return { dataStatus: "ready", source: "cache" }       │
  └────────────────────────────────────────────────────────────┘

  ┌─ Cache MISS + Cached Period ───────────────────────────────┐
  │  1. Query store_revenue_summary → empty                   │
  │  2. isCachedPeriod("30d") → true                          │
  │  3. Return { dataStatus: "loading", isRefreshing: false }  │
  │     (wait for cron to populate)                            │
  └────────────────────────────────────────────────────────────┘

  ┌─ Cache MISS + force_refresh=true ──────────────────────────┐
  │  1. Query store_revenue_summary → empty (or ignored)      │
  │  2. tryAcquireLiveFetch → true                            │
  │  3. syncKlaviyoForPeriod(...)                             │
  │  4. Upsert results to cache tables                        │
  │  5. releaseLiveFetch("completed")                         │
  │  6. Return { dataStatus: "ready", source: "live" }        │
  └────────────────────────────────────────────────────────────┘

  ┌─ Cache MISS + LIVE_ONLY period (1d, 12m) ──────────────────┐
  │  1. isCachedPeriod("1d") → false                          │
  │  2. tryAcquireLiveFetch → true/false                      │
  │  3. If true: live fetch + cache result                     │
  │  4. If false: return stale cache or "loading"              │
  │  5. Return { dataStatus: "ready", source: "live" }        │
  └────────────────────────────────────────────────────────────┘
```

### Upsert Helper (reutilizado do cron)

```typescript
async function upsertSyncResults(
  supabase: SupabaseClient,
  store: StoreRow,
  data: KlaviyoSyncData,
  period: string,
): Promise<void> {
  // Upsert flow metrics
  if (data.flowRows.length > 0) {
    await supabase.from("klaviyo_flow_metrics")
      .upsert(data.flowRows, { onConflict: "store_id,flow_id,period_start,period_end" })
  }

  // Upsert campaign metrics
  if (data.campRows.length > 0) {
    await supabase.from("klaviyo_campaign_metrics")
      .upsert(data.campRows, { onConflict: "store_id,campaign_id,period_start,period_end" })
  }

  // Upsert revenue summary
  await supabase.from("store_revenue_summary")
    .upsert({
      store_id: store.id,
      org_id: store.org_id,
      period_label: period,
      period_start: data.startDateStr,
      period_end: data.endDateStr,
      klaviyo_total_revenue: data.campaignRevenue + data.flowRevenue,
      klaviyo_campaign_revenue: data.campaignRevenue,
      klaviyo_flow_revenue: data.flowRevenue,
      shopify_total_revenue: data.storeRevenue,
      sync_status: "ok",
      sync_error: null,
      expires_at: new Date(Date.now() + 6 * 60 * 60 * 1000).toISOString(),
      fetched_at: new Date().toISOString(),
    }, { onConflict: "store_id,period_label" })
}
```

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Live fetch demora >30s (muitas stores) | Timeout de 30s + retorno de dados parciais |
| Rate limiting Klaviyo no live fetch | Cooldown atomico garante max 1 fetch por store/period por minuto |
| `force_refresh` abusado por scripts | Cooldown protege independente de force_refresh |
| Live fetch salva em cache com expires_at de 6h | Igual ao cron — cron vai sobrescrever na proxima execucao |
| Admin endpoint usa `createClient()` com RLS — pode nao ter permissao para upsert | Usar `createAdminClient()` para upserts (ja existe no cron) |
