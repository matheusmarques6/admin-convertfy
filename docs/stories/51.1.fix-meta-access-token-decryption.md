# Story 51.1 — Fix `meta_access_token` Decryption + Unificar `ENCRYPTED_FIELDS`

## Story

**Como** engenheiro de backend,
**Quero** que a lista de campos encriptados seja unica e consistente em todo o codebase,
**Para que** todos os campos de credenciais sejam encriptados na escrita e decriptados na leitura corretamente.

## Contexto

### Problema

`ENCRYPTED_FIELDS` esta definido em 3 lugares diferentes e eles DIVERGEM:

| Arquivo | Campos | Inclui `meta_access_token`? |
|---------|--------|---------------------------|
| `src/lib/services/credentials.service.ts` (L32-40) | 7 campos | SIM |
| `src/lib/crypto.ts` (L52-59) `STORE_CREDENTIAL_FIELDS` | 6 campos | NAO |
| `src/app/api/client-stores/credentials/route.ts` (L101) | 6 campos | NAO |

**Bug resultante**: `updateStoreCredentials()` encripta `meta_access_token` corretamente (usa a lista do service com 7 campos). Mas `decryptStoreCredentials()` em `crypto.ts` usa `STORE_CREDENTIAL_FIELDS` com 6 campos — NAO decripta `meta_access_token`. Qualquer leitura de credenciais Meta retorna ciphertext `enc:v1:...` ao inves do token real.

### Impacto

- Meta integration (Facebook/Instagram) pode estar quebrada para lojas que configuraram via `updateStoreCredentials()`

> **NOTA (QA C1):** `google_ads_credentials` e `google_calendar_credentials` NAO devem entrar em `ENCRYPTED_FIELDS`. Eles usam um path separado de encryption/decryption (`encryptCredentialsJson`/`decryptCredentialsJson`) que trata JSON blobs. O `decryptStoreCredentials()` faz `decrypt()` que retorna string — para JSON blobs isso retornaria a string JSON sem parse, causando inconsistencia. Esses campos ja sao tratados corretamente em `getStoreCredentials()` L149-159.

## Acceptance Criteria

### 51.1.1 — Fonte unica para `ENCRYPTED_FIELDS`

- [ ] Exportar `ENCRYPTED_FIELDS` de `src/lib/services/credentials.service.ts` como `export const`
- [ ] Lista de campos string (encrypt/decrypt via `encrypt()`/`decrypt()`):
  ```typescript
  export const ENCRYPTED_FIELDS = [
    "shopify_access_token",
    "shopify_api_key",
    "shopify_api_secret",
    "klaviyo_api_key",
    "klaviyo_private_key",
    "klaviyo_public_key",
    "meta_access_token",
  ] as const
  ```
- [ ] Tipo derivado: `export type EncryptedField = (typeof ENCRYPTED_FIELDS)[number]`
- [ ] Separar lista de campos JSON blob (encrypt/decrypt via `encryptCredentialsJson()`/`decryptCredentialsJson()`):
  ```typescript
  // JSON blob fields — handled separately, NOT in ENCRYPTED_FIELDS
  export const ENCRYPTED_JSON_FIELDS = [
    "google_ads_credentials",
    "google_calendar_credentials",
    "ga4_credentials",
  ] as const
  ```
- [ ] Criar superset para sanitizacao (usado em Story 51.4):
  ```typescript
  export const ALL_SENSITIVE_FIELDS = [
    ...ENCRYPTED_FIELDS,
    ...ENCRYPTED_JSON_FIELDS,
  ] as const
  ```

### 51.1.2 — Atualizar `crypto.ts`

- [ ] Remover `STORE_CREDENTIAL_FIELDS` local de `src/lib/crypto.ts`
- [ ] Importar `ENCRYPTED_FIELDS` de `credentials.service.ts`
- [ ] `decryptStoreCredentials()` deve usar `ENCRYPTED_FIELDS` importado
- [ ] `encryptStoreCredentials()` (se existir) deve usar `ENCRYPTED_FIELDS` importado
- [ ] **Atencao a dependencia circular**: se `crypto.ts` importa de `credentials.service.ts` e vice-versa, extrair `ENCRYPTED_FIELDS` para um arquivo separado (ex: `src/lib/constants/credentials.ts`)

**Arquivo:** `src/lib/crypto.ts`

### 51.1.3 — Atualizar `client-stores/credentials/route.ts`

- [ ] Remover `ENCRYPTED_FIELDS` local da route
- [ ] Importar de `credentials.service.ts` (ou do constants file)
- [ ] `processFields()` deve usar a lista importada

**Arquivo:** `src/app/api/client-stores/credentials/route.ts`

### 51.1.4 — Validacao

- [ ] `npm run typecheck` passa sem erros
