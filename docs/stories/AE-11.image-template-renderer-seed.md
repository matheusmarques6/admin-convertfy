# Story AE-11 — Template renderer (handlebars-lite) + seed `email_agent_configs.image` v1

## User Story

**Como** plataforma de geracao de email,
**quero** carregar o prompt do agente de imagem do DB (versionado via AE-8) e renderizar com switch por `(flow_type, email_number)`,
**para que** cada email do Welcome flow (E1..E6) use seu proprio prompt mestre niche-adaptive — e dev/architect possa editar via UI sem deploy.

---

## Contexto

Hoje (apos AE-10):
- `email_agent_configs` aceita `agent_type='image'` (AE-1)
- `buildImagePromptVars` retorna 12 vars UPPERCASE niche-adaptive + 19 legacy (AE-10)
- 4 helpers puros derivam MOOD/CENARIO/NEUTRO/LOGO_STYLE (AE-10)
- `image.chain.ts` ainda usa `DEFAULT_IMAGE_PROMPT_TEMPLATE` hardcoded (sem mudanca nesta story)
- **NAO HA seed de `email_agent_configs.image`** — tab "Image" no `/admin/agents/prompts` aparece vazia

Esta story:
1. Cria parser handlebars-lite em `template-renderer.ts` com 2 primitivas: `{{#case X}}{{#when Y}}...{{/when}}{{/case}}` (switch) e `{{#if VAR}}...{{/if}}` (condicional simples). Sem dep externa.
2. Cria migration seed inicial de `email_agent_configs.image` v1 com `user_template` contendo:
   - Switch `(flow_type, email_number)` cobrindo Welcome E1..E6 (placeholders por enquanto, prompts mestres reais entram na AE-14)
   - Fallback generico pra flows nao mapeados (cart, browse, win-back, upsell, post-purchase)
   - Restricoes universais ao final
   - **Placeholder `{{#if INSTRUCAO_ADICIONAL}}...{{/if}}`** pra futura AE-16 (instrucao por bloco)
3. Integra no `phase2-runner.service.ts`: ao gerar imagem, carrega config ativo do DB; se nao houver, fallback pro template hardcoded de `image.chain.ts` (compat retroativa). Renderiza com vars + flow_type + email_number.

A integracao com `image.chain.ts` propria (resize, aspect, mode) fica para AE-12 e AE-13.

## Dev Notes

### Sintaxe handlebars-lite — exemplo

```
{{#case flow_type}}
  {{#when "welcome"}}
    {{#case email_number}}
      {{#when 1}}Hero lifestyle E1 com {{PRODUTO_HEROI}} em {{CENARIO}}.{{/when}}
      {{#when 2}}Produto E2 com overlay 10%OFF. Mood {{MOOD}}.{{/when}}
    {{/case}}
  {{/when}}
  {{#when "abandoned_cart"}}
    Fallback generico para abandoned_cart: produto {{PRODUTO_HEROI}}.
  {{/when}}
{{/case}}

Paleta: {{PALETA_1}} e {{PALETA_2}}. Idioma do contexto: {{IDIOMA}}.

{{#if INSTRUCAO_ADICIONAL}}
INSTRUCOES ADICIONAIS DESTE BLOCO:
{{INSTRUCAO_ADICIONAL}}
{{/if}}
```

### Por que parser proprio em vez de Handlebars/Mustache real?

- Dep zero (no bundle Next ja eh grande)
- 2 primitivas cobrem 100% do uso atual e futuro previsivel
- ~50 linhas + testes
- Sintaxe identica a Handlebars facilita migrar depois se precisar

### Fallback hardcoded preservado

Mantemos `DEFAULT_IMAGE_PROMPT_TEMPLATE` em `image.chain.ts` como rede de seguranca. Logica:

```ts
const cfg = await loadActiveImageConfig() // SELECT WHERE agent_type='image' AND is_active=true
const prompt = cfg
  ? renderImageTemplate(cfg.user_template, vars)
  : renderImageTemplate(DEFAULT_IMAGE_PROMPT_TEMPLATE, vars) // legacy
```

Se DB cai ou config sem ativa: pipeline nao quebra.

### Comentarios sobre os 6 prompts mestres

Os prompts mestres reais (Welcome E1..E6) vivem no documento que o user passou. AE-14 (story posterior, data-only) faz o `INSERT` desses prompts no template. AE-11 apenas garante a estrutura.
