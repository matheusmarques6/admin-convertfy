# Story 20.11 - Fix: Copy Generation falha para lojas sem client_id

**Epic:** [Epic 20 - Campaign Copy Generation](./epic-20-campaign-copy-generation.md)
**Status:** Ready
**Prioridade:** P1 (Bug - bloqueia uso da feature para maioria das lojas)
**Sprint:** Current
**Revisado por:** QA, Dev, DBM

---

## Contexto

A geracao de copies de campanha funciona apenas para a loja "Karm" e falha para as demais. A investigacao revelou duas causas raiz:

### Causa 1: Lojas sem `client_id` (16 de 61 lojas ativas)

No endpoint `POST /api/campaigns/generate` (linha 55-66), o backend extrai `client_id` da primeira loja selecionada com `.limit(1)`:
```typescript
clientId = orgStores[0].client_id // null para lojas orfas
```

Na segunda query (linha 89), `.eq("client_id", null)` em PostgREST/SQL nao retorna resultados (SQL requer `IS NULL`, nao `= NULL`), causando erro 400: "Nenhuma loja valida encontrada".

**Safety net do DB:** `campaign_generations.client_id` ja e `NOT NULL` (migration `20260305_campaign_generations.sql`), entao o INSERT falharia de qualquer forma com erro 500 (Postgres 23502). O fix na aplicacao transforma isso em 400 user-friendly.

**Lojas afetadas:** Direct Ofertas, Eporth, HeroBoxers, HOVX Watches, InnovaBay UK, InnovaBay US, JouePlus, Kits Foot, Klarwen, Luxor Men, Luxury Club, Marie Curie, Pablo Raez, Poedagar, Telune, Vorttexia.

**Origem do NULL:** A migration `20260224_standalone_stores.sql` dropou `NOT NULL` de `client_stores.client_id` para suportar "standalone stores". Nao reinstalar a constraint — o fix pertence a camada de aplicacao.

### Causa 2: Selecao multi-client silenciosamente descarta lojas

O frontend (`copy-tab.tsx`) lista TODAS as lojas ativas da org, independente do cliente. Quando o usuario seleciona lojas de clientes diferentes, o backend pega o `client_id` da primeira loja (`.limit(1)`) e descarta todas as lojas de outros clientes sem aviso.

### Caminho do portal user NAO e afetado

O fluxo de portal user (linhas 67-81) deriva `client_id` de `client_portal_users.client_id` que e NOT NULL por definicao. Este bug afeta apenas o caminho de org members (admin/agency).

    throw new AppError("Nenhuma loja valida encontrada", 400)
  }

      "Loja(s) selecionada(s) nao vinculada(s) a um cliente. Vincule antes de gerar copies.",

## Notas Tecnicas

- PostgREST `.eq("column", null)` gera `column=null` que e sempre falso em SQL. A solucao correta e impedir que `client_id` null chegue a essa query, nao tratar null como caso valido.
- `campaign_generations.client_id` e `NOT NULL` no schema (safety net). O fix na aplicacao transforma erro 500 (constraint violation) em 400 user-friendly.
- `client_stores.client_id` teve `NOT NULL` dropado na migration `20260224_standalone_stores.sql`. Nao reinstalar — o fix e na aplicacao.
- A query na linha 60 usa `.limit(1)` que mascara o problema multi-client. Remover para validar todas as lojas.
- O endpoint `/api/stores` retorna `client_id` no response (sobrevive ao destructuring de credenciais). O frontend pode usar para filtrar.
- A segunda query (linhas 86-94) que busca `store_name, country, language` e redundante apos remover `.limit(1)`. Pode ser otimizada buscando esses campos na primeira query, mas nao e critico para este fix.
- RLS policies em `campaign_generations` dependem de `client_id` nao-null, mas o constraint `NOT NULL` ja garante isso.
