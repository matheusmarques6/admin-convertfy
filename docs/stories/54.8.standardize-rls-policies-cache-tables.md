# Story 54.8 — Standardize RLS Policies Across Cache Tables

## Story

**Como** engenheiro de seguranca,
**Quero** que todas as tabelas de cache usem o mesmo padrao de RLS,
**Para que** nao haja gaps de seguranca ou comportamento inconsistente entre tabelas.

## Contexto

### Problema

As 5 tabelas de cache usam **3 padroes diferentes de RLS**:

| Tabela | Padrao | Problemas |
|--------|--------|-----------|
| `store_revenue_summary` | `org_id = current_org_id() OR can_access_store(store_id)` | OK (moderno) |
| `dashboard_cache` | Mesma policy moderna + policy antiga potencialmente nao-dropada | Possivel policy `USING(true)` ainda ativa |
| `klaviyo_flow_metrics` | `agent_store_access` subquery legada | Diferente do padrao, pode nao incluir portal users |
| `klaviyo_campaign_metrics` | `agent_store_access` subquery legada | Idem |
| `klaviyo_audiences` | Padrao mais completo (org + portal + service) | OK (o melhor) |

### Risco de seguranca

Se `dashboard_cache` ainda tiver a policy `"Service role can manage dashboard cache"` (FOR ALL USING(true) sem TO role restriction), qualquer usuario autenticado pode ler/escrever cache de qualquer loja.

Atualmente mitigado porque o portal usa `adminClient` (service_role) para queries, mas qualquer mudanca futura para `createClient()` exporia o problema.

## Acceptance Criteria

### 54.8.1 — Auditar policies existentes em producao

- [x] Executar `SELECT * FROM pg_policies WHERE tablename IN (...)` para verificar estado atual
- [x] Documentar policies ativas vs esperadas
- [x] Identificar policies orfas que deveriam ter sido dropadas

> **Audit result (from migrations):** flow/campaign metrics had 5 policies each (select/insert/update/delete + service_all) from 20260216. dashboard_cache had old permissive "Service role can manage dashboard cache" (no TO role). All documented in migration comments.

### 54.8.2 — Padronizar flow/campaign metrics para padrao moderno

- [x] Criar migration que:
  1. DROP policies legadas (`agent_store_access` pattern)
  2. CREATE policies no padrao de `store_revenue_summary`:
     - `service_*_all` FOR ALL TO service_role USING(true)
     - `org_*_select` FOR SELECT TO authenticated USING(`org_id = current_org_id() OR can_access_store(store_id)`)
- [x] Aplicar para `klaviyo_flow_metrics` e `klaviyo_campaign_metrics`

### 54.8.3 — Verificar e corrigir dashboard_cache

- [x] Se policy `"Service role can manage dashboard cache"` (sem TO restriction) ainda existir, dropar
- [x] Garantir que apenas `dashboard_cache_service_all` (TO service_role) exista para escrita

### 54.8.4 — Validacao

- [x] Verificar com `pg_policies` que todas as tabelas seguem o mesmo padrao
- [x] `npm run build` passa
