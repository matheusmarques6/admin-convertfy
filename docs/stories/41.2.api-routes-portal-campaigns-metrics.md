# Story 41.2 — API Routes: Portal Auth Helper + Campaigns Endpoints

## Story

**Como** portal user acessando o calendario de campanhas,
**Quero** que a API retorne dados enriquecidos com metricas Klaviyo e que eu possa ver detalhes completos de uma campanha,
**Para que** o frontend possa exibir performance sem chamadas extras.

## Contexto

### Estado atual

O endpoint `GET /api/portal/campaigns` faz query direta na tabela `campaigns` e retorna dados brutos. Nao existe endpoint de detalhe para metricas individuais.

### Mudancas

1. **Extrair helper `resolvePortalClient()`** — logica de autenticacao portal repetida em multiplos endpoints
2. **Atualizar `/api/portal/campaigns`** — usar RPC `get_portal_campaigns_with_metrics` (criada em 41.1)
3. **Criar `/api/portal/campaigns/[id]/metrics`** — endpoint lazy para metricas completas

### Helper `resolvePortalClient()`

A logica de resolver `auth_user_id -> client_id -> store_ids` e repetida em varios endpoints portal. Extrair para helper reutilizavel:

```typescript
// src/lib/api/portal-auth.ts
export async function resolvePortalClient(
  adminClient: SupabaseClient,
  authUserId: string
): Promise<{
  clientId: string
  storeIds: string[]
  storeNameMap: Record<string, string>
}>
```

Fluxo:
1. `client_portal_users` WHERE `auth_user_id` = param AND `is_active = true`
2. Se nao encontrar ou `is_active = false` -> throw com status 401
3. `client_stores` WHERE `client_id` = result.client_id
4. Retorna `clientId`, `storeIds[]`, `storeNameMap` (id -> store_name)

## Acceptance Criteria

### 41.2.1 — Extrair helper `resolvePortalClient()`

- [x] Criar arquivo `src/lib/api/portal-auth.ts`
- [x] Implementar funcao `resolvePortalClient(adminClient, authUserId)`:
  ```typescript
  import { SupabaseClient } from "@supabase/supabase-js"

  export interface PortalClientContext {
    clientId: string
    storeIds: string[]
    storeNameMap: Record<string, string>
  }

  export class PortalAuthError extends Error {
    constructor(
      message: string,
      public statusCode: number = 401
    ) {
      super(message)
      this.name = "PortalAuthError"
    }
  }

  export async function resolvePortalClient(
    adminClient: SupabaseClient,
    authUserId: string
  ): Promise<PortalClientContext> {
    // 1. Buscar portal user ativo
    const { data: portalUser, error: puError } = await adminClient
      .from("client_portal_users")
      .select("client_id, is_active")
      .eq("auth_user_id", authUserId)
      .single()

    if (puError || !portalUser) {
      throw new PortalAuthError("Portal user not found")
    }

    if (!portalUser.is_active) {
      throw new PortalAuthError("Portal user is inactive")
    }

    // 2. Buscar lojas ATIVAS do cliente
    const { data: stores, error: stError } = await adminClient
      .from("client_stores")
      .select("id, store_name")
      .eq("client_id", portalUser.client_id)
      .eq("is_active", true)  // F6 fix: filtrar apenas lojas ativas

    if (stError || !stores) {
      throw new PortalAuthError("Failed to resolve client stores", 500)
    }

    const storeIds = stores.map((s) => s.id)
    const storeNameMap: Record<string, string> = {}
    for (const s of stores) {
      storeNameMap[s.id] = s.store_name
    }

    return {
      clientId: portalUser.client_id,
      storeIds,
      storeNameMap,
    }
  }
  ```
- [x] Portal user com `is_active = false` DEVE retornar 401 antes de qualquer query de dados
- [x] O helper usa `adminClient` (service role) — nao depende de RLS

**Arquivo:** `src/lib/api/portal-auth.ts`

### 41.2.3 — Criar endpoint `/api/portal/campaigns/[id]/metrics`

- [x] Criar novo endpoint GET para metricas completas de uma campanha especifica
- [ ] Implementacao:
  ```typescript
  // src/app/api/portal/campaigns/[id]/metrics/route.ts
  import { createAdminClient } from "@/lib/supabase/admin"
  import { createClient } from "@/lib/supabase/server"
  import { resolvePortalClient, PortalAuthError } from "@/lib/api/portal-auth"
  import { NextRequest, NextResponse } from "next/server"

  export async function GET(
    request: NextRequest,
    { params }: { params: Promise<{ id: string }> }
  ) {
    const { id: campaignId } = await params
    const supabase = await createClient()
    const adminClient = createAdminClient()

    // Auth
    const { data: { user } } = await supabase.auth.getUser()
    if (!user) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
    }

    let ctx
    try {
      ctx = await resolvePortalClient(adminClient, user.id)
    } catch (err) {
      if (err instanceof PortalAuthError) {
        return NextResponse.json(
          { error: err.message },
          { status: err.statusCode }
        )
      }
      throw err
    }

    // 1. Validar que a campanha pertence a uma store do cliente
    const { data: campaign } = await adminClient
      .from("campaigns")
      .select("id, store_id, klaviyo_campaign_id")  // F9: campo real e klaviyo_campaign_id (NAO campaign_id)
      .eq("id", campaignId)  // id = UUID PK da tabela campaigns
      .in("store_id", ctx.storeIds)
      .single()

    if (!campaign) {
      return NextResponse.json({ metrics: null })
    }

    // 2. Buscar metricas completas do cache
    // Defesa em profundidade: filtrar por store_id mesmo apos validar ownership
    const { data: metrics } = await adminClient
      .from("klaviyo_campaign_metrics")
      .select("*")
      .eq("store_id", campaign.store_id)
      .eq("campaign_id", campaign.klaviyo_campaign_id)  // campaign_id na tabela metrics = klaviyo_campaign_id na tabela campaigns
      .order("fetched_at", { ascending: false })
      .limit(1)
      .single()

    if (!metrics) {
      return NextResponse.json({ metrics: null })
    }

    // 3. Retornar metricas (remover TODOS campos internos)
    const {
      org_id, period_start, period_end, period_label,  // F7: incluir period_label
      ...safeMetrics
    } = metrics
    return NextResponse.json({ metrics: safeMetrics })
  }
  ```
- [x] Campanha que nao pertence a nenhuma `storeId` do cliente retorna `{ metrics: null }` (nao 403)
- [x] Defesa em profundidade: filtrar por `store_id` na query de metricas mesmo apos validar ownership
- [x] Remover campos internos (`org_id`, `period_start`, `period_end`, `period_label`) do response
- [x] Se `klaviyo_campaign_id` for null na campanha (campanha manual), retornar `{ metrics: null }`

**Arquivo:** `src/app/api/portal/campaigns/[id]/metrics/route.ts`
