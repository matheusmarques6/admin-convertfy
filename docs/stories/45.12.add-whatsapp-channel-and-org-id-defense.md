# Story 45.12 — Add org_id Defense-in-Depth to RPC

## Status: Done
## Effort: LOW (30min)
## Priority: LOW

## Context

The RPC `get_portal_campaigns_with_metrics` filters by `store_id = ANY(p_store_ids)` but does NOT include an `org_id` filter. While UUIDs are unguessable, defense-in-depth (consistent with Story 15.6 pattern) would add `org_id` filtering.

**Note**: WhatsApp channel was moved to Story 45.7 (AC 45.7.6) as part of shared constants extraction. This story focuses only on org_id defense.

## Prerequisites

- **Story 45.3** adds `orgId` to `PortalClientContext` (combined with currency extension)
- **Story 45.10** has the latest RPC signature (with pagination params) — this migration must build on that

## Acceptance Criteria

- [ ] **AC 45.12.1** RPC `get_portal_campaigns_with_metrics` accepts optional `p_org_id UUID DEFAULT NULL` parameter
- [ ] **AC 45.12.2** When `p_org_id` is provided, RPC adds `AND c.org_id = p_org_id` to WHERE clause (or JOIN through client_stores.org_id)
- [ ] **AC 45.12.3** API route passes `ctx.orgId` from PortalClientContext to RPC
- [ ] **AC 45.12.4** Migration includes DROP old signature + REVOKE/GRANT for new signature (incorporates 45.4 + 45.10 changes)
- [ ] **AC 45.12.5** Backward compatible — `p_org_id DEFAULT NULL` means existing calls without org_id still work
- [ ] **AC 45.12.6** Lint + typecheck pass
