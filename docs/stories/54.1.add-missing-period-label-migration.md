# Story 54.1 — Add Missing `period_label` Column Migration

## Story

**Como** engenheiro de dados responsavel pela integridade do schema,
**Quero** que a coluna `period_label` em `klaviyo_flow_metrics` e `klaviyo_campaign_metrics` esteja documentada em uma migration oficial,
**Para que** o schema seja reproduzivel a partir das migrations e novos ambientes nao quebrem.

## Contexto

### Problema

As tabelas `klaviyo_flow_metrics` e `klaviyo_campaign_metrics` sao consultadas e escritas com a coluna `period_label`, porem esta coluna **nao existe em nenhuma migration**. Foi adicionada ad-hoc diretamente no banco de producao.

### Evidencias no codigo

**Escrita** em `sync-persistence.service.ts`:
```typescript
// Linha ~40: DELETE por period_label
.eq("period_label", period)

// Linha ~44: INSERT com period_label
data.flowRows.map(r => ({ ...r, period_label: period }))

// Linha ~58: DELETE por period_label
.eq("period_label", period)

// Linha ~62: INSERT com period_label
data.campRows.map(r => ({ ...r, period_label: period }))
```

**Leitura** em `portal/dashboard/route.ts`:
```typescript
.eq("period_label", period)
```

### Risco

Se alguem fizer bootstrap do banco a partir das migrations (novo ambiente, staging, CI), as tabelas nao terao `period_label` e o cron + portal vao falhar silenciosamente.

## Acceptance Criteria

### 54.1.1 — Migration para `klaviyo_flow_metrics.period_label`

- [x] Criar migration que adiciona coluna `period_label TEXT` a `klaviyo_flow_metrics`
- [x] Usar `IF NOT EXISTS` (coluna ja existe em producao)
- [x] Valor default: NULL (rows existentes ja tem o valor populado pelo cron)
- [x] Adicionar CHECK constraint: `period_label IN ('7d', '15d', '30d', '90d')` ou NULL

### 54.1.2 — Migration para `klaviyo_campaign_metrics.period_label`

- [x] Criar migration que adiciona coluna `period_label TEXT` a `klaviyo_campaign_metrics`
- [x] Mesmas regras: `IF NOT EXISTS`, CHECK constraint
- [x] Usar a MESMA migration file (ambas tabelas juntas)

### 54.1.3 — Backfill de rows sem period_label

- [x] Na mesma migration, fazer UPDATE para popular `period_label` em rows que possam estar sem:
  ```sql
  -- Derivar period_label da diferenca entre period_end e period_start
  UPDATE klaviyo_flow_metrics
  SET period_label = CASE
    WHEN period_end - period_start <= interval '8 days' THEN '7d'
    WHEN period_end - period_start <= interval '16 days' THEN '15d'
    WHEN period_end - period_start <= interval '31 days' THEN '30d'
    ELSE '90d'
  END
  WHERE period_label IS NULL;
  ```
- [x] Mesmo UPDATE para `klaviyo_campaign_metrics`

### 54.1.4 — Validacao

- [x] Verificar que `npm run build` passa sem erros
- [x] Verificar que a migration e idempotente (pode rodar multiplas vezes sem erro)

## Ordem de Implementacao

1. Criar arquivo de migration com timestamp adequado
2. ADD COLUMN IF NOT EXISTS para ambas tabelas
3. Backfill rows existentes
4. ADD CHECK constraint

## Riscos

| Risco | Mitigacao |
|-------|----------|
| Coluna ja existe em producao | `IF NOT EXISTS` garante idempotencia |
| Backfill com calculo errado | Logica baseada na diferenca de datas e conservadora; valores existentes nao sao sobrescritos |
| CHECK constraint falha se houver valores invalidos | Backfill roda ANTES do CHECK |
