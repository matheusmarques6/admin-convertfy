## Contexto

Existem atualmente 3 metodos diferentes de calculo de date range no projeto, causando uma discrepancia de 1 dia entre os dados do cron e os dados do portal:

1. **Cron (`sync-reports/route.ts`)**: Usa `parseDateRange(period, null, null)` que retorna `Date` objects baseados em UTC do servidor Vercel. A funcao `parseDateRange` em `src/lib/integrations/klaviyo/client.ts` (linha 171) usa `new Date()` sem considerar timezone.

2. **Portal dashboard (`/api/portal/dashboard/route.ts`)**: Usa `new Date()` com `setDate()` e formata manualmente com pad — tambem UTC do servidor (linhas 60-91).

3. **Klaviyo performance service (`klaviyo-performance.service.ts`)**: Usa `parseDateRangeInTimezone` — a unica implementacao correta que considera o timezone da conta Klaviyo.

O cron JA busca o timezone da conta (`getCachedAccountInfo`) na linha 389 e calcula o offset na linha 390, mas usa `parseDateRange` (sem timezone) na linha 102 para calcular `startDate`/`endDate`. Isso significa que os `period_start`/`period_end` salvos em `store_revenue_summary` podem estar 1 dia errados dependendo do timezone da conta Klaviyo vs UTC.

### Exemplo do Problema

Para uma conta com timezone `America/Sao_Paulo` (UTC-3):
- As 23:30 BRT (02:30 UTC do dia seguinte), `parseDateRange("30d")` calcula baseado na data UTC (dia seguinte)
- `parseDateRangeInTimezone("30d", "America/Sao_Paulo")` calcula baseado na data local (dia correto)
- Resultado: 1 dia de diferenca nos periodos

```typescript

```

```typescript
// src/lib/integrations/klaviyo/client.ts — linha 234
// CORRETO: funcao que ja existe e considera timezone
export function parseDateRangeInTimezone(
  period: string,

  customStartDate?: string | null,
```

---

## Objetivo

Unificar todas as calculos de date range para usar `parseDateRangeInTimezone` com o timezone da conta Klaviyo, eliminando a discrepancia de 1 dia e garantindo que cron, portal e admin mostrem os mesmos periodos.

### Mudanca na funcao `syncStoreForPeriod`

```typescript
// ANTES:
async function syncStoreForPeriod(
  store: StoreRow,
  period: string,
  supabase: SupabaseClient,
  apiKey: string,
  timezoneOffset: string,
  metricId: string,
  flowNames: Map<...>,
  campNames: Map<...>,

// DEPOIS:
async function syncStoreForPeriod(
  store: StoreRow,
  period: string,
  supabase: SupabaseClient,
  apiKey: string,
  timezone: string,          // Changed: full timezone name instead of offset
  timezoneOffset: string,
  metricId: string,
  flowNames: Map<...>,
  campNames: Map<...>,
): Promise<{ status: "ok" | "skipped"; campaignRevenue: number; flowRevenue: number; startDateStr: string; endDateStr: string }> {
  const { startDateStr, endDateStr } = parseDateRangeInTimezone(period, timezone)
```
