**Prioridade:** Media
**Sprint:** Next
**Assignee:** @dev
**Revisao:** @sm (River)
**Status:** In Progress

## Contexto

Agencias que gerenciam lojas de e-commerce precisam criar links de campanha com parametros UTM padronizados. Hoje, cada operador cria UTMs manualmente, gerando inconsistencias (ex: `utm_source=Klaviyo` vs `utm_source=klaviyo` vs `utm_source=email_klaviyo`). Isso compromete a analise de atribuicao.

Esta story implementa um sistema de templates de UTM por loja, permitindo que a agencia configure templates reutilizaveis e gere links prontos para colar em campanhas do Klaviyo, SMS, redes sociais, etc.

**Multi-tenant:** A tabela `utm_templates` usa `org_id` + `store_id` para isolamento. RLS policies usam `can_access_store()` para SELECT/UPDATE e `org_members` para INSERT/DELETE, seguindo o padrao existente do projeto (ex: `order_tracking_cache`, `tracking_config`).

---

## Objetivo

Implementar CRUD completo de templates UTM por loja, incluindo migration com RLS, API routes, e UI integrada na tab UTM criada na Story 6.1.

  - **UPDATE**: `USING (can_access_store(store_id))` — qualquer membro com acesso pode editar
  - **DELETE**: `USING (EXISTS (...org_members...role IN ('owner', 'manager')))` — apenas owner/manager podem deletar (soft delete via UPDATE, hard delete apenas para cleanup)
  - Formato: `DROP POLICY IF EXISTS ... ; CREATE POLICY ...` (padrao do projeto, sem `IF NOT EXISTS`)

## Arquitetura Tecnica

### Schema da Tabela

```sql
CREATE TABLE utm_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  store_id UUID NOT NULL REFERENCES client_stores(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  description TEXT,
  utm_source TEXT NOT NULL,
  utm_medium TEXT NOT NULL,
  utm_campaign TEXT NOT NULL,
  utm_content TEXT,
  utm_term TEXT,
  is_active BOOLEAN DEFAULT true,
  usage_count INTEGER DEFAULT 0,
  created_by UUID REFERENCES profiles(id),
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now(),
  deleted_at TIMESTAMPTZ DEFAULT NULL
);

CREATE UNIQUE INDEX idx_utm_templates_unique_active
  ON utm_templates(store_id, utm_source, utm_medium, utm_campaign)
  WHERE is_active = true AND deleted_at IS NULL;
```

### Padrao de API Route (seguir existente)

```typescript
// src/app/api/stores/[id]/utm-templates/route.ts
import { NextRequest } from "next/server"
import { createClient } from "@/lib/supabase/server"
import { createAdminClient } from "@/lib/supabase/admin"
import { resolveOrgId } from "@/lib/api/resolve-org"
import { errorResponse } from "@/lib/api/error-response"
import { AppError } from "@/lib/api/errors"

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  try {
    const { id: storeId } = await params
    const supabase = await createClient()
    const { data: { user } } = await supabase.auth.getUser()
    if (!user) throw new AppError("Unauthorized", 401)

    const orgId = await resolveOrgId(user.id)
    const admin = createAdminClient()

    // Validar acesso a loja
    const { data: store } = await admin
      .from("client_stores")
      .select("id, store_url")
      .eq("id", storeId)
      .eq("org_id", orgId)
      .single()

    if (!store) throw new AppError("Store not found", 404)

    // Buscar templates
    const { data: templates } = await admin
      .from("utm_templates")
      .select("*")
      .eq("store_id", storeId)
      .eq("org_id", orgId)
      .order("created_at", { ascending: false })

    // Gerar URLs
    const templatesWithUrl = (templates || []).map(t => ({
      ...t,
      generatedUrl: generateUtmUrl(store.store_url, t)
    }))

    return Response.json({ success: true, templates: templatesWithUrl })
  } catch (error) {
    return errorResponse(request, error, "GET /api/stores/[id]/utm-templates")
  }
}
```

### Geracao de URL

```typescript
function generateUtmUrl(storeUrl: string | null, template: {
  utm_source: string
  utm_medium: string
  utm_campaign: string
  utm_content?: string | null
  utm_term?: string | null
}): string | null {
  // Se store_url nao existe, retornar null (UI deve exibir aviso)
  if (!storeUrl) return null

  try {
    // Usar new URL() para tratar URLs que ja tem query params
    // e normalizar trailing slash
    const url = new URL(storeUrl.replace(/\/+$/, ''))
    url.searchParams.set("utm_source", template.utm_source)
    url.searchParams.set("utm_medium", template.utm_medium)
    url.searchParams.set("utm_campaign", template.utm_campaign)
    if (template.utm_content) url.searchParams.set("utm_content", template.utm_content)
    if (template.utm_term) url.searchParams.set("utm_term", template.utm_term)
    return url.toString()
  } catch {
    // URL invalida — retornar null
    return null
  }
}
```

**IMPORTANTE**: Preservar o case original dos valores UTM na URL gerada (nao forcar lowercase). O match com dados de conversao Shopify deve ser feito case-insensitive no cruzamento.

## Consideracoes de Seguranca

- **RLS multi-tenant**: `utm_templates` isolada por `org_id`. SELECT/UPDATE usam `can_access_store()`. INSERT valida `org_members.is_active`. DELETE restrito a owner/manager.
- **Validacao server-side**: Todos os endpoints validam que `storeId` pertence ao `orgId` do usuario autenticado antes de qualquer operacao.
- **Sanitizacao de input**: Valores UTM sao trimados. Case original e preservado no armazenamento; o indice UNIQUE parcial previne duplicatas (comparacao case-sensitive no indice; considerar `LOWER()` no indice se necessario). Match com dados de conversao e case-insensitive.
- **Sem SQL injection**: Usa Supabase query builder com parametros tipados.
- **CSRF**: Next.js App Router com cookies httpOnly (padrao).
