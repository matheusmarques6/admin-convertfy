## Story

**Como** usuario que visualiza metricas de campanhas em diferentes interfaces,
**Quero** que open rate e click rate sejam calculados da mesma forma em todas as interfaces,
**Para que** os numeros sejam consistentes entre store detail, portal dashboard, e admin dashboard.

---

## Contexto

O cron (`klaviyo-sync.service.ts`) usa `opens` e `clicks` (totais — incluem reaberturas/recliques):
```typescript
opened: (ex.opened || 0) + (s.opens || 0)
clicked: (ex.clicked || 0) + (s.clicks || 0)
```

Os endpoints live (`campaigns/route.ts`, `flows/route.ts`) usam `opens_unique` e `clicks_unique`:
```typescript
const newOpened = existing.opened + (stats.opens_unique || 0)
const newClicked = existing.clicked + (stats.clicks_unique || 0)
```

Resultado: quando o usuario ve dados do cache (cron), open/click counts sao inflados vs quando ve dados live. Total opens >= unique opens, entao as taxas parecem "erradas" ao alternar entre fontes.

O dashboard do Klaviyo mostra **unique** opens/clicks por padrao. Recomendacao: padronizar em `opens_unique`/`clicks_unique`.

---

## Acceptance Criteria

### 27.4.1 — Cron: usar `opens_unique` e `clicks_unique`

- [x] Em `klaviyo-sync.service.ts`, no loop de agregacao de campaign metrics, trocar:
  - `s.opens` → `s.opens_unique`
  - `s.clicks` → `s.clicks_unique`
  - Manter `s.unsubscribes` como esta (`unsubscribes_unique` NAO existe na API Klaviyo)
- [x] Mesma mudanca para o loop de flow metrics
- [x] **Nota QA**: As statistics solicitadas no POST body (linhas ~432-438) ja incluem AMBOS `opens` e `opens_unique`. NAO e necessario alterar a lista de statistics — apenas o codigo de agregacao precisa mudar.

### 27.4.2 — Recalcular rates a partir de unique

- [x] Apos a mudanca, verificar que `open_rate` e `click_rate` sao recalculados como:
  - `open_rate = (opens_unique / delivered) * 100`
  - `click_rate = (clicks_unique / delivered) * 100`
- [x] Verificar que `click_to_open_rate` usa `clicks_unique / opens_unique * 100`

### 27.4.3 — Verificar live endpoints (confirmacao)

- [x] Confirmar que `campaigns/route.ts` e `flows/route.ts` ja usam `opens_unique` e `clicks_unique` — se sim, nenhuma mudanca necessaria
- [x] Se nao, alinhar com o mesmo padrao

### 27.4.4 — Atualizar testes

- [x] Em `klaviyo-sync.service.test.ts`, atualizar mocks para usar `opens_unique` ao inves de `opens`
- [x] Garantir que os testes passam com os novos nomes de campo
