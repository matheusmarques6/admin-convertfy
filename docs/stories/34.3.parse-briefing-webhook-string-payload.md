# Story 34.3 — Parse briefing_generated Webhook String Payload

## Story

**Como** sistema de onboarding que recebe callbacks do N8N,
**Quero** que o webhook `briefing_generated` trate corretamente payloads enviados como JSON string,
**Para que** o briefing seja persistido como objeto estruturado em vez de raw_text.

## Contexto

### Problema observado em producao

O N8N envia `body.data` como JSON string (ex: `"{\"dados_loja\":...}"`) em vez de objeto parsed. O handler em `src/app/api/onboarding/webhook/route.ts:142-195` verifica `typeof body.data === "object"` para decidir se e structured, mas como `typeof "string" !== "object"`, o payload cai no fallback `raw_text`.

### Codigo atual (linhas 148-195)

```typescript
// Resilient handling: accept both structured JSON and raw text from n8n
const isStructured = body.data && typeof body.data === "object" && !Array.isArray(body.data)

// ... se isStructured: valida required keys
// ... se NAO isStructured: wraps em { raw_text: String(body.data) }
```

O problema: quando N8N envia `body.data` como string JSON valida, o dado e salvo como:
```json
{ "raw_text": "{\"dados_loja\": {...}, \"foco_campanhas\": {...}, ...}" }
```

Em vez de:
```json
{ "dados_loja": {...}, "foco_campanhas": {...}, ... }
```

### Fix proposto

Adicionar `JSON.parse()` quando `typeof body.data === "string"` ANTES do check de `isStructured`:

```typescript
// Parse string payload from N8N if it's valid JSON
let parsedData = body.data
if (typeof body.data === "string") {
  try {
    const parsed = JSON.parse(body.data)
    if (typeof parsed === "object" && parsed !== null && !Array.isArray(parsed)) {
      log.warn("[Webhook] briefing_generated body.data was JSON string, parsed to object", {
        onboarding_id: body.onboarding_id,
      })
      parsedData = parsed
    }
  } catch {
    // Not valid JSON — will fall through to raw_text fallback below
  }
}

const isStructured = parsedData && typeof parsedData === "object" && !Array.isArray(parsedData)
```

E depois usar `parsedData` em vez de `body.data` no restante do bloco.

## Acceptance Criteria

### 34.3.1 — Parse JSON string para objeto

- [x] Quando `body.data` e uma string JSON valida que parseia para objeto, fazer `JSON.parse()` e tratar como structured
- [x] Usar o objeto parseado para a validacao de required keys e persistencia
- [x] NAO modificar `body.data` diretamente — usar variavel local `parsedData`

**Arquivo:** `src/app/api/onboarding/webhook/route.ts`

### 34.3.2 — Manter fallback raw_text para strings invalidas

- [x] Quando `body.data` e uma string que NAO e JSON valido, manter fallback `raw_text` existente
- [x] Quando `body.data` e uma string que parseia para array ou primitivo, manter fallback `raw_text`
- [x] Quando `body.data` e a string `"null"` (`JSON.parse("null")` retorna `null`), manter fallback `raw_text`
- [x] `try/catch` no `JSON.parse` para nunca quebrar o handler

### 34.3.3 — Log de warn indicando parse

- [x] Log de warn quando string e parseada com sucesso para JSON, incluindo `onboarding_id`
- [x] Log existente de `data_type` e `is_structured` deve refletir o tipo APOS o parse

## Ordem de Implementacao

1. Adicionar bloco de parse antes do check `isStructured` (AC 34.3.1)
2. Garantir fallback seguro (AC 34.3.2)
3. Adicionar log de warn (AC 34.3.3)
4. Atualizar referencias de `body.data` para `parsedData` no bloco `briefing_generated`

## Riscos

| Risco | Mitigacao |
|-------|----------|
| Double-parse se N8N mudar para enviar objeto no futuro | O bloco so executa `JSON.parse` quando `typeof === "string"` — objeto passa direto |
| String JSON valida mas com estrutura inesperada | Validacao de required keys continua funcionando apos o parse |
| Double-encoded JSON (`"\"{\\\"key\\\"...}\""`) | Parse retorna string, falha no `typeof === "object"` check, cai no raw_text — comportamento aceitavel |
