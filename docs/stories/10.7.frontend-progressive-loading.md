## Contexto

Com o live fallback implementado (Stories 10.5/10.6), os endpoints agora retornam `DataStatusMeta` com informacoes ricas sobre o estado dos dados:

```typescript
{
  dataStatus: "ready" | "stale" | "loading" | "error" | "empty",
  lastFetchedAt: "2026-03-01T12:00:00Z" | null,
  isRefreshing: boolean,
  source: "cache" | "live" | "stale-cache"
}
```

O frontend precisa:
1. Exibir loading states progressivos (skeleton → dados parciais → dados completos)
2. Mostrar indicador de "dados antigos" quando stale
3. Botao de refresh no admin dashboard (portal nao tem refresh manual)
4. Indicador de "fonte dos dados" para admin (cache vs live)

---

## Objetivo

Atualizar o frontend (admin dashboard e portal) para consumir `DataStatusMeta` e exibir estados de carregamento progressivos, stale indicators e refresh controls.

## Arquitetura Tecnica

### Componente DataStatusBanner

```tsx
// src/components/ui/data-status-banner.tsx

import { AlertCircle, Clock, Loader2, Info } from "lucide-react"
import { DataStatus } from "@/lib/shared/data-status"

interface DataStatusBannerProps {
  status: DataStatus
  lastFetchedAt?: string | null
  isRefreshing?: boolean
  className?: string
}

export function DataStatusBanner({ status, lastFetchedAt, isRefreshing, className }: DataStatusBannerProps) {
  if (status === "ready" && !isRefreshing) return null

  const variants: Record<DataStatus, { icon: React.ReactNode; message: string; color: string }> = {
    loading: {
      icon: <Loader2 className="h-4 w-4 animate-spin" />,
      message: "Carregando dados...",
      color: "bg-blue-50 text-blue-700 dark:bg-blue-950 dark:text-blue-300",
    },
    stale: {
      icon: <Clock className="h-4 w-4" />,
      message: `Dados de ${getFreshnessLabel(lastFetchedAt)}${isRefreshing ? " — atualizando..." : ""}`,
      color: "bg-yellow-50 text-yellow-700 dark:bg-yellow-950 dark:text-yellow-300",
    },
    error: {
      icon: <AlertCircle className="h-4 w-4" />,
      message: "Erro ao carregar dados. Tentando novamente...",
      color: "bg-red-50 text-red-700 dark:bg-red-950 dark:text-red-300",
    },
    empty: {
      icon: <Info className="h-4 w-4" />,
      message: "Nenhum dado disponivel para este periodo.",
      color: "bg-muted text-muted-foreground",
    },
    ready: {
      icon: null,
      message: isRefreshing ? "Atualizando dados em segundo plano..." : "",
      color: "bg-green-50 text-green-700 dark:bg-green-950 dark:text-green-300",
    },
  }

  const variant = variants[status]
  if (!variant.message) return null

  return (
    <div className={`flex items-center gap-2 rounded-md px-3 py-2 text-sm ${variant.color} ${className}`}>
      {variant.icon}
      <span>{variant.message}</span>
    </div>
  )
}
```

### Nota sobre waitUntil (L1)

Next.js 15 expoe `waitUntil` via `unstable_after` ou atraves do `AsyncLocalStorage`. Se disponivel:

```typescript
import { after } from "next/server"

// No endpoint, apos retornar dados stale:
if (isStale && !isRefreshing) {
  after(async () => {
    // Background refresh — nao bloqueia response
    await liveFetchForStores(stores, period, supabase)
  })
}
```

Se nao disponivel (depende da versao do Next.js e do provider), ignorar — o cron e o mecanismo de refresh.
