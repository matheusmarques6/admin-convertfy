## Contexto
Os botoes de paginacao em `clients-table.tsx` usam `router.push(\`/clients?page=${N}\`)` de forma hardcoded (linhas 529 e 540). Isso descarta qualquer filtro ativo na URL (`search`, `status`, `health`).

Exemplo: usuario esta em `/clients?search=maria&status=active&page=1`, clica "Proxima" e vai para `/clients?page=2` — perdendo os filtros "maria" e "active". A tabela na pagina 2 mostra todos os clientes sem filtro.

## Objetivo
Fazer os botoes de paginacao preservar todos os searchParams existentes ao mudar de pagina, para que filtros ativos sejam mantidos durante a navegacao.

---

## Acceptance Criteria

- [x] **30.2.1** `ClientsTable` usa `useSearchParams()` para ler os parametros atuais da URL

- [x] **30.2.3** Botao "Proxima" preserva todos os params existentes e apenas altera `page`

### DEPOIS
```typescript
import { useSearchParams } from "next/navigation"

export function ClientsTable({ clients, totalCount, currentPage }: ClientsTableProps) {
  const searchParams = useSearchParams()
  // ... existing code ...

  function buildPageUrl(page: number): string {
    const params = new URLSearchParams(searchParams.toString())
    if (page <= 1) {
      params.delete("page")
    } else {
      params.set("page", String(page))
    }
    const qs = params.toString()
    return qs ? `/clients?${qs}` : "/clients"
  }

  // Nos botoes:
  // onClick={() => router.push(buildPageUrl(currentPage - 1))}
  // onClick={() => router.push(buildPageUrl(currentPage + 1))}
}
```
