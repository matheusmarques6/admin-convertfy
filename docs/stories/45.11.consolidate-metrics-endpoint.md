# Story 45.11 — Consolidate Metrics Endpoint (2 Queries → 1 JOIN)

## Status: Ready for Dev
## Effort: LOW (30min)
## Priority: MEDIUM

## Context

The metrics endpoint (`/api/portal/campaigns/[id]/metrics`) makes 2 sequential queries:
1. Query `campaigns` table to get `klaviyo_campaign_id` + `store_id`
2. Query `klaviyo_campaign_metrics` table with the resolved IDs

This can be a single query with JOIN. Also:
- No UUID validation on `campaignId` — Postgres errors leak to client
- Batch campaigns (from `campaign_batches`) trigger a wasted call that always returns null

## Fix

```sql
SELECT m.*
FROM klaviyo_campaign_metrics m
INNER JOIN campaigns c
  ON c.klaviyo_campaign_id = m.campaign_id
  AND c.store_id = m.store_id
WHERE c.id = $1
  AND c.store_id = ANY($2)
ORDER BY m.fetched_at DESC
LIMIT 1
```
