# Story 36.10 — Review Interativo (Botao Editar por Secao)

## Contexto

O step de revisao do form publico mostra dados em grid `grid-cols-2` com pares label/valor. Problemas:
- Campos condicionais quebram o ritmo do grid
- Textos longos (publico-alvo, direcao de design) ficam `truncate` sem possibilidade de expandir
- Nao ha botao "Editar" para voltar ao step correto
- Visualmente parece dump de dados

## Objetivo

Transformar o review em secoes interativas com botao de edicao e textos expansiveis.

## Criterios de Aceitacao

- [x] **AC 36.10.1**: Cada secao do review (Dados Pessoais, Dados da Loja, Codigo Colaborador, Identidade Visual) tem botao "Editar" no canto superior direito
- [x] **AC 36.10.2**: Clicar "Editar" navega diretamente para o step correspondente via `setCurrentStepId(stepId)`
- [x] **AC 36.10.3**: Textos longos (publico-alvo, direcao de design, observacoes) mostram texto completo sem truncate — usar max-height com scroll se muito longo, ou mostrar primeiras 2 linhas com "ver mais"
- [x] **AC 36.10.4**: Secoes usam layout de definition list (label em cima, valor embaixo) em vez de grid 2 colunas — melhor leitura em mobile
- [x] **AC 36.10.5**: Campos vazios/opcionais nao aparecem no review (comportamento atual, manter)
- [x] **AC 36.10.6**: Uploads mostram nome do arquivo com icone de tipo (imagem/PDF)

## Impacto por Disciplina

- **Dev**: 1 arquivo, ~30 linhas de diff. Reestruturar JSX do step review
- **Arquiteto**: Zero
- **DB**: Zero
- **QA**: Testar botao "Editar" volta ao step certo. Alterar dado e voltar ao review → atualizado?
