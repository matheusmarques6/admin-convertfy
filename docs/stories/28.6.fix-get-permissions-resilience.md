## Story

**Como** sistema que carrega o dashboard layout,
**Quero** que falhas parciais no carregamento de permissoes nao derrubem a pagina inteira,
**Para que** o usuario veja o dashboard com permissoes minimas em vez de tela de erro.

---

## Contexto

Em `src/app/(dashboard)/layout.tsx` (linhas 9-152), a funcao `getPermissions()` faz **6 queries sequenciais** ao Supabase:
1. Busca user profile
2. Busca org membership
3. Busca role
4. Busca features
5. Busca clients
6. Busca stores

Se qualquer query falhar (timeout, Supabase downtime, RLS error), o erro borbulha sem catch e se manifesta como "An error occurred in the Server Components render" no ErrorBoundary.

### Arquivos afetados

- `src/app/(dashboard)/layout.tsx` (linhas 9-152: `getPermissions()`)

---

## Acceptance Criteria

### 28.6.1 — Envolver getPermissions em try/catch

- [ ] Envolver o corpo de `getPermissions()` em try/catch
- [ ] No catch, logar o erro com `console.error`
- [ ] Retornar um objeto de permissoes minimas (fallback seguro) que permite ao usuario ver a pagina mas sem acesso a features sensiveis
- [ ] NAO engolir silenciosamente — manter log para diagnostico

### 28.6.2 — Queries individuais resilientes

- [ ] Cada query individual deve ter seu proprio try/catch ou usar `.maybeSingle()` onde aplicavel
- [ ] Se uma query falhar, as demais devem continuar executando
- [ ] Preencher o campo correspondente com valor default seguro (ex: `features: []`, `clients: []`)

### 28.6.3 — Validacao

- [ ] Dashboard carrega mesmo se Supabase retornar erro em uma das queries
- [ ] Log de erro visivel no server console
- [ ] `npm run lint` e `npm run typecheck` passam
