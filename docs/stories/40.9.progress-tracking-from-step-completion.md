# Story 40.9 — Progress Tracking from Step Completion

## Story

**Como** coordenador/manager,
**Quero** que o progresso do onboarding (%) seja calculado automaticamente a partir dos steps concluidos,
**Para que** eu veja o progresso real sem depender de atualizacoes manuais.

## Contexto

O trigger `onboarding_step_progress_trigger` ja existe no banco e calcula `progress_percent` quando um step muda de status. Porem, ele precisa ser atualizado para:

1. Considerar os novos status (`waiting`, `pending`) no calculo
2. Marcar o onboarding como `completed` quando TODOS os steps `is_required` estiverem `completed` ou `skipped`
3. Recalcular progresso quando steps sao criados pelo sync (novos steps de templates adicionados)

Alem disso, o `OnboardingSyncService` deve verificar apos cada cascade se o onboarding inteiro foi concluido.

## Acceptance Criteria

- [x] **AC 40.9.1**: Trigger `update_onboarding_progress` atualizado para considerar `waiting` e `pending` como "nao concluido" no calculo de progresso
- [x] **AC 40.9.2**: Progresso calculado como: `count(completed + skipped) / count(total required steps) * 100`
- [x] **AC 40.9.3**: Steps com `is_required = false` NAO contam no denominador (mas contam no numerador se completados)
- [x] **AC 40.9.4**: Quando progresso atinge 100%, onboarding status muda para `completed` e `completed_at` e preenchido
- [x] **AC 40.9.5**: `OnboardingSyncService.handleNewlyPendingSteps()` verifica progresso apos cada cascade e dispara transicao para `completed` se aplicavel
- [x] **AC 40.9.6**: Na transicao para `completed`, cliente muda para `status = 'active'` (comportamento existente preservado)
- [x] **AC 40.9.7**: Progress bar no card de onboarding (tanto no kanban quanto em listagens) reflete o novo calculo

## Technical Notes

### Atualizar trigger existente

```sql
CREATE OR REPLACE FUNCTION update_onboarding_progress()
RETURNS TRIGGER AS $$
DECLARE
  v_total INT;
  v_completed INT;
  v_progress INT;
BEGIN
  -- Contar apenas steps required
  SELECT
    COUNT(*) FILTER (WHERE is_required = true OR is_required IS NULL),
    COUNT(*) FILTER (WHERE (status = 'completed' OR status = 'skipped')
                     AND (is_required = true OR is_required IS NULL))
  INTO v_total, v_completed
  FROM client_onboarding_steps
  WHERE onboarding_id = NEW.onboarding_id;

  IF v_total = 0 THEN
    v_progress := 0;
  ELSE
    v_progress := ROUND((v_completed::DECIMAL / v_total) * 100);
  END IF;

  UPDATE client_onboardings
  SET
    progress_percent = v_progress,
    status = CASE
      WHEN v_progress = 100 THEN 'completed'::onboarding_status
      WHEN v_progress > 0 THEN 'in_progress'::onboarding_status
      ELSE status
    END,
    completed_at = CASE
      WHEN v_progress = 100 AND completed_at IS NULL THEN NOW()
      ELSE completed_at
    END
  WHERE id = NEW.onboarding_id;

  -- Ativar cliente quando onboarding completa
  IF v_progress = 100 THEN
    UPDATE clients
    SET status = 'active'
    WHERE id = (SELECT client_id FROM client_onboardings WHERE id = NEW.onboarding_id);
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

### Nota sobre `is_required`

A coluna `is_required BOOLEAN DEFAULT true` sera adicionada a `client_onboarding_steps` na migration de 40.1 (AC 40.1.10), com backfill a partir do template step correspondente. O trigger pode referencar diretamente `client_onboarding_steps.is_required` sem JOIN.
