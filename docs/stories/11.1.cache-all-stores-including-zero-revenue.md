# Story 11.1 - Cache All Stores Including Zero Revenue

**Prioridade:** P0 (Critica — root cause principal da inconsistencia)
**Sprint:** Current
**Assignee:** @dev
**Revisao:** @sm (River)
**Status:** Ready
**Epic:** 11 - Dashboard Store Count Integrity
**Fase:** 1 - Integridade

---

## Contexto

O dashboard mostra 2 lojas com receita quando na verdade 4 lojas tem Klaviyo configurado. O problema principal e que o live fetch path so grava no `store_revenue_summary` quando `revenue.totalRevenue > 0`. Lojas com receita zero (ex: loja nova, periodo sem vendas) nunca entram no cache. No request seguinte (cache hit), `storesCount` conta apenas as rows cacheadas, resultando em contagem incorreta.

O mesmo pattern `if (revenue.totalRevenue > 0)` aparece em dois arquivos:
- `src/app/api/dashboard/total-revenue/route.ts` linha 208
- `src/app/api/stores/control/route.ts` linha 464

---

## Objetivo

Remover o guard `revenue.totalRevenue > 0` de ambos os arquivos, garantindo que todas as lojas com credenciais Klaviyo validas sejam cacheadas no `store_revenue_summary` independente do valor da receita. Usar `sync_status: 'ok'` para distinguir "receita zero real" de "nunca sincronizado".

## Arquitetura Tecnica

### Arquivo: `src/app/api/dashboard/total-revenue/route.ts`

**Antes (linhas 207-228):**
```typescript
// Fire-and-forget: save revenue to cache for next request
if (revenue.totalRevenue > 0 && (CACHED_PERIODS as readonly string[]).includes(period)) {
  Promise.resolve(
    adminSupabase
      .from("store_revenue_summary")
      .upsert({
        store_id: store.id,
        org_id: store.org_id || null,
        period_label: period,
        klaviyo_total_revenue: revenue.totalRevenue,
        // ...
        sync_status: "ok",
        // ...
      }, { onConflict: "store_id,period_label" })
  )
    .then(() => log.info(`[LiveFetch] Cached revenue for ${store.store_name}/${period}`))
    .catch((e) => log.warn(`[LiveFetch] Cache upsert failed for ${store.store_name}:`, e))
}
```

**Depois:**
```typescript
// Fire-and-forget: save revenue to cache for next request (including zero revenue stores)
if ((CACHED_PERIODS as readonly string[]).includes(period)) {
  Promise.resolve(
    adminSupabase
      .from("store_revenue_summary")
      .upsert({
        store_id: store.id,
        org_id: store.org_id || null,
        period_label: period,
        klaviyo_total_revenue: revenue.totalRevenue,
        // ...
        sync_status: "ok",
        // ...
      }, { onConflict: "store_id,period_label" })
  )
    .then(() => log.info(`[LiveFetch] Cached revenue for ${store.store_name}/${period} (${revenue.currency} ${revenue.totalRevenue})`))
    .catch((e) => log.warn(`[LiveFetch] Cache upsert failed for ${store.store_name}:`, e))
}
```
