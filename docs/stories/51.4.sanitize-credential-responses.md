# Story 51.4 — Sanitizar Responses de Credenciais

## Story

**Como** engenheiro de seguranca,
**Quero** que nenhum endpoint retorne ciphertext (`enc:v1:...`) ou valores de credenciais no response body,
**Para que** credenciais nao vazem para o frontend mesmo em formato encriptado.

## Contexto

### Problema

O endpoint `POST /api/client-stores/credentials` retorna `{ store: data }` diretamente do `INSERT(...).select()` do Supabase. Esse `data` contem strings `enc:v1:...` para todos os campos encriptados. Embora nao seja plaintext, expor ciphertext:

1. Revela quais campos estao populados
2. Permite ataques de manipulacao de ciphertext se combinado com outras vulnerabilidades
3. E desnecessario — o frontend so precisa saber se a operacao foi bem-sucedida

### Bom exemplo existente

`/api/stores` GET (L82-93) ja sanitiza corretamente, removendo todos os campos de credenciais antes de responder.

## Acceptance Criteria

### 51.4.1 — Criar `sanitizeStoreResponse()`

- [ ] Adicionar ao `credentials.service.ts` (ou `crypto.ts`):
  ```typescript
  import { ALL_SENSITIVE_FIELDS } from "@/lib/constants/credentials"

  export function sanitizeStoreResponse(store: Record<string, unknown>): Record<string, unknown> {
    const sanitized = { ...store }
    for (const field of ALL_SENSITIVE_FIELDS) {
      if (field in sanitized) {
        sanitized[field] = sanitized[field] ? true : false  // boolean flag apenas
      }
    }
    return sanitized
  }
  ```
- [ ] Usar `ALL_SENSITIVE_FIELDS` (definido em Story 51.1) que inclui TANTO campos string (`ENCRYPTED_FIELDS`) QUANTO JSON blobs (`ENCRYPTED_JSON_FIELDS`: `google_ads_credentials`, `google_calendar_credentials`, `ga4_credentials`)
- [ ] Retorna a store com TODOS os campos sensiveis substituidos por boolean flags (`true`/`false`)

> **DBM C8-DB:** Se usar apenas `ENCRYPTED_FIELDS`, os JSON blob fields (`google_ads_credentials`, etc.) vazariam no response. `ALL_SENSITIVE_FIELDS` cobre ambos.

**Arquivo:** `src/lib/services/credentials.service.ts`

### 51.4.2 — Sanitizar POST `/api/client-stores/credentials`

- [ ] Ler `src/app/api/client-stores/credentials/route.ts`
- [ ] No POST handler, substituir `return NextResponse.json({ store: data })` por:
  ```typescript
  return NextResponse.json({ store: sanitizeStoreResponse(data) })
  ```
- [ ] Ou retornar apenas `{ success: true, store_id: data.id, validation_results }`

**Arquivo:** `src/app/api/client-stores/credentials/route.ts`

### 51.4.3 — Sanitizar PUT `/api/client-stores/credentials`

- [ ] No PUT handler, aplicar mesma sanitizacao ao response
- [ ] Garantir que nenhum `enc:v1:` aparece no response body

**Arquivo:** `src/app/api/client-stores/credentials/route.ts`

### 51.4.4 — Audit de outros endpoints

- [ ] Grep por `.json(.*store` ou `.json(.*data` em TODAS as routes sob `src/app/api/` (nao apenas `client-stores/credentials`)
- [ ] Incluir explicitamente na busca:
  - `src/app/api/portal/stores/` (GET/PUT responses)
  - `src/app/api/portal/integrations/` (GET/PUT responses)
  - `src/app/api/stores/` (GET response — ja sanitiza, verificar)
  - `src/app/api/portal/onboarding/wizard/` (GET response)
- [ ] Verificar que nenhum endpoint retorna campos encriptados (string `enc:v1:` ou JSON blob) no response
- [ ] Se encontrar, aplicar `sanitizeStoreResponse()` ou retornar apenas os campos necessarios

### 51.4.5 — Validacao

- [ ] `npm run lint` passa sem erros
- [ ] Testar POST client-stores/credentials — response NAO deve conter `enc:v1:`
