# Story AE-13 — Modo PRODUCT-REF (img2img) com fallback TEXT2IMG

## User Story

**Como** plataforma de geracao de imagem,
**quero** que slots especificos (Welcome E1/E2/E3/E6) usem a foto real do produto como referencia visual (img2img / multimodal),
**para que** o hero do email mostre o SKU exato — nao uma reinterpretacao livre do modelo.

---

## Contexto

O plano (`/root/.claude/plans/muito-bom-agora-vamos-playful-marble.md` §4) define:

| Email | Modo padrao | Fallback se top_products vazio |
|---|---|---|
| Welcome E1 | product_ref | text2img com descricao detalhada |
| Welcome E2 | product_ref (obrigatorio) | skip imagem + log warn |
| Welcome E3 | product_ref | text2img |
| Welcome E4 | text2img | — |
| Welcome E5 | text2img | — |
| Welcome E6 | product_ref | text2img |

Override por blueprint via coluna `email_blueprints.image_mode ∈ {auto, product_ref, text2img}` (default `auto`, resolve pela matriz — coluna ja criada em AE-10).

**Multimodal OpenRouter (spike pendente)**: o modelo `openai/gpt-5.4-image-2` aceita input image via content array?
```json
{ "role": "user", "content": [
  { "type": "image_url", "image_url": { "url": "<top_product image_url>" } },
  { "type": "text", "text": "<prompt renderizado>" }
] }
```
**Plano**: implementar o caminho multimodal + fallback text2img + feature flag `IMAGE_MULTIMODAL_ENABLED` (default `false`). Quando spike confirmar funcionamento, admin liga em prod via env var.

## Acceptance Criteria

### AC AE-13.1 — Helper `mode-resolution.ts`
- [ ] Arquivo `src/lib/agents/image/mode-resolution.ts`
- [ ] Tipo `ImageMode = 'product_ref' | 'text2img'`
- [ ] Funcao `resolveImageMode(input: { blueprintMode?: 'auto' | 'product_ref' | 'text2img' | null; flowType?: string | null; emailNumber?: number | null; topProductImageUrl?: string | null; multimodalEnabled?: boolean }): { mode: ImageMode; source: 'blueprint' | 'matrix' | 'default' | 'fallback_text2img_no_product' | 'fallback_text2img_disabled' }`:
  - Se `multimodalEnabled === false` e mode resolveria `product_ref`: retorna `text2img` + source `fallback_text2img_disabled`
  - Se mode resolveria `product_ref` mas `topProductImageUrl` ausente: retorna `text2img` + source `fallback_text2img_no_product`
  - Blueprint override (`product_ref` | `text2img`) sempre vence se `multimodalEnabled` permitir
  - Matriz Welcome: E1/E2/E3/E6 → `product_ref`; E4/E5 → `text2img`
  - Default: `text2img`
- [ ] Funcao `productRefDescriptionFallback(input: { productName: string; productImageUrl?: string }): string` — quando vamos pra `text2img` mas era pra ser `product_ref`, monta descricao textual rica do produto pra injetar no prompt (compensa a perda de fidelidade visual)

### AC AE-13.2 — Estender `image.chain.ts` com modo multimodal
- [ ] `generateEmailImage` aceita opcional adicional:
  ```ts
  options?: {
    aspect?: AspectKey
    overlayReserveBottom?: boolean
    mode?: ImageMode
    referenceImageUrl?: string  // obrigatorio quando mode='product_ref'
  }
  ```
- [ ] Se `mode === 'product_ref' && referenceImageUrl`:
  - Constroi body OpenRouter com `content` array contendo `{type:'image_url',image_url:{url:referenceImageUrl}}` + `{type:'text',text:prompt}`
  - Loga `image.multimodal.attempted` com `{ refUrl, model }`
- [ ] Se `mode === 'text2img'` ou sem ref:
  - Body padrao atual (sem content array)
- [ ] Try/catch em volta da chamada OpenRouter: se request der erro estruturado (400 com mensagem "image input not supported" ou similar), loga `image.multimodal.fallback_text2img` + retry **uma vez** em modo text2img puro

## Dev Notes

### Por que feature flag desligada por default?
- Spike empirico nao foi feito (modelo pode nao aceitar multimodal)
- Custo de falha alta: cada request perdido = ~1.5¢ + latencia +30s
- Liga apenas quando confirmar manualmente que `gpt-5.4-image-2` aceita content array

### Como confirmar o spike?
```bash
# Manual: curl direto pro OpenRouter
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -d '{
    "model": "openai/gpt-5.4-image-2",
    "messages": [{"role":"user","content":[
      {"type":"image_url","image_url":{"url":"https://example.com/capa.jpg"}},
      {"type":"text","text":"Re-render this seat cover in a car interior"}
    ]}]
  }'
```
Se retornar imagem coerente com a referencia: liga flag em prod.

### `productRefDescriptionFallback` — exemplo de output
Input: `{ productName: "Capa banco couro preto", productImageUrl: "https://..." }`
Output: `"Featured product reference: 'Capa banco couro preto' (style guide image at https://...). Match material, color and proportions closely."`

### Fallback chain dentro de generateEmailImage
1. Tenta multimodal (se mode='product_ref')
2. Se erro 4xx com texto "not supported"/"image": retry text2img puro
3. Se outro erro: throw (deixa caller decidir)

## Riscos

| Risco | Probabilidade | Mitigacao |
|-------|---------------|-----------|
| Modelo `gpt-5.4-image-2` nao aceita multimodal | Alta | Feature flag desligada por default; retry fallback text2img dentro da chain |
| Custo do retry (request perdido) | Media | Apenas 1 retry; depois throw e deixa watchdog (AE-4) lidar |
| Imagem de referencia produz output mediocre (modelo "copia demais") | Media | `productRefDescriptionFallback` adiciona descricao rica; testes manuais com designers em AE-14 |
| Latencia adicional do multimodal | Baixa | OpenRouter cobra mesmo tempo; sem impacto |
