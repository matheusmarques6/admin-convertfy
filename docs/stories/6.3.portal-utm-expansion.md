# Story 6.3 - Portal do Cliente: Expansao de Dados UTM com Medium e Campaign

**Prioridade:** Baixa
**Sprint:** Next
**Assignee:** @dev
**Revisao:** @sm (River)
**Status:** Ready
**Depende de:** Story 6.1

---

## Contexto

O portal do cliente ja possui um card "Conversoes por UTM" em `src/app/portal/dashboard/conversions-section.tsx` que exibe apenas dados por **source** (top 5 sources). Os dados de `byMedium` e `byCampaign` ja estao disponiveis no response da API (tipados em `src/app/portal/dashboard/types.ts`) mas **nao sao renderizados**.

Alem disso, a pagina de detalhe da loja no portal (`/portal/stores/[id]`) nao possui nenhuma secao de UTM. O cliente ve o relatorio de e-commerce mas sem breakdown de atribuicao por UTM.

**Multi-tenant (Portal):** O portal usa autenticacao separada. O endpoint `/api/portal/dashboard` ja filtra dados pelo `client_id` do usuario autenticado no portal. O endpoint `/api/portal/stores/[id]/report` valida acesso via o vinculo `client_stores.client_id`. Nenhuma alteracao de seguranca necessaria.

---

## Objetivo

Expandir a exibicao de dados UTM no portal do cliente em dois pontos: (1) adicionar sub-tabs Source/Medium/Campaign no card existente do dashboard, e (2) adicionar secao UTM na pagina de relatorio da loja individual no portal.

utmConversions: {

  byCampaign: [],   // <-- VAZIO!

// DEPOIS (corrigido):
// Agregar byMedium
const utmMediumMap = new Map<string, { medium: string; orders: number; revenue: number }>()
shopifyDataList.forEach((s) => {
  ((s.utmConversions?.byMedium || []) as Array<Record<string, unknown>>).forEach((u) => {
    const medium = (u.medium as string) || ''
    const existing = utmMediumMap.get(medium)
    if (existing) {
      existing.orders += (u.orders as number) || 0
      existing.revenue += (u.revenue as number) || 0
    } else {
      utmMediumMap.set(medium, {
        medium,
        orders: (u.orders as number) || 0,
        revenue: (u.revenue as number) || 0,
      })
    }
  })
})

## Consideracoes de Seguranca

- **Portal isolado**: O portal usa autenticacao propria. O `client_id` e extraido do usuario autenticado no portal, nao do admin.
- **Dados read-only**: O portal so exibe dados, nunca modifica. Nao ha CRUD de templates no portal.
- **Sem dados sensiveis**: UTM params sao metadados publicos de marketing.
- **RLS do portal**: Endpoints `/api/portal/*` filtram por `client_id` do usuario portal. Sem cross-tenant risk.
