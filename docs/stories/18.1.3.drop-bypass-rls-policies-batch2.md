## Story

**Como** administrador do sistema,
**Quero** remover as bypass policies restantes em `client_charges`, `client_subscriptions` e `client_reports`,
**Para que** nenhuma tabela com dados financeiros ou de relatorios fique exposta cross-tenant.

---

## Contexto

### Tabelas afetadas neste batch

| Tabela | Policies bypass a dropar | Policies hardened existentes |
|--------|--------------------------|------------------------------|
| `client_charges` | 1: `"Allow all on client_charges"` | `org_client_charges_*` (SELECT/INSERT/UPDATE/DELETE com org_id) |
| `client_subscriptions` | 1: `"Allow all on client_subscriptions"` | `org_client_subscriptions_*` (SELECT/INSERT/UPDATE/DELETE com org_id) |
| `client_reports` | 5: ver lista abaixo | `org_client_reports_*` (SELECT/INSERT/UPDATE/DELETE com org_id) + `service_client_reports_all` |

### Policies de `client_reports` a dropar

1. `"Allow all operations on client_reports"` — bypass classica (`USING(true)`)
2. `"Users can view client reports"` — bypass (`USING(true)`)
3. `"Users can create client reports"` — bypass (`WITH CHECK(true)`)
4. `"Users can update client reports"` — **bypass disfaracada** (R5 do QA: `auth.role() = 'authenticated'` equivale a `true` para qualquer user logado)
5. `"Users can delete client reports"` — bypass (`USING(true)`)

### NOTA CRITICA (R4 do QA)

`client_reports` JA possui policies hardened (`org_client_reports_select`, `org_client_reports_insert`, `org_client_reports_update`, `org_client_reports_delete`, `service_client_reports_all`). NAO criar novas policies — apenas dropar as bypass e bypass-disfaracadas.

### Dependencias

- **Bloqueada por 18.1.1** (codigo DEVE estar deployado antes)
- **PODE rodar em paralelo com 18.1.2** (tabelas diferentes, sem conflito)
- Nenhuma rota portal acessa `client_charges`, `client_subscriptions` ou `client_reports` via user RLS

