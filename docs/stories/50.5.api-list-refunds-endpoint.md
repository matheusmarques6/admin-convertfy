# Story 50.5 — API Endpoint: GET /api/financial/refunds (List)

## Story

**Como** admin que precisa visualizar o historico de reembolsos,
**Quero** um endpoint que retorne refunds paginados com filtros por cliente e status,
**Para que** o dashboard de metricas (story 50.9) e futuras UIs de historico tenham dados disponiveis.

## Contexto

Este endpoint retorna refunds da org do admin logado. Suporta filtros e paginacao para uso em tabelas e dashboards.

O portal do cliente NAO usa este endpoint — ele acessa refund info via `unified_invoices` (refund_total + net_amount), conforme ADR-4.

### Referencia: Arquitetura

Ver secao 4.3 de `docs/architecture/refund-processing-architecture.md`.

### AC 50.5.2 — Query params com validacao

- [ ] Aceitar query params: `client_id` (UUID, optional), `status` (string, optional), `page` (number, optional), `limit` (number, optional)
- [ ] Validar `status` se fornecido: deve ser 'requested', 'processed', ou 'failed'
- [ ] Default: page=1, limit=20
- [ ] Limit maximo: 100 (cap silenciosamente se excedido)

```typescript
const url = new URL(request.url)
const clientId = url.searchParams.get('client_id') || undefined
const status = url.searchParams.get('status') || undefined
const page = Math.max(1, parseInt(url.searchParams.get('page') || '1'))
const limit = Math.min(100, Math.max(1, parseInt(url.searchParams.get('limit') || '20')))

if (status && !['requested', 'processed', 'failed'].includes(status)) {
  return NextResponse.json({ error: 'Status invalido' }, { status: 400 })
}
```

## Riscos

| Risco | Mitigacao |
|-------|----------|
| JOIN em clients + invoices/charges pode ser lento com muitos refunds | Indexes em client_id, invoice_id, charge_id ja criados na migration |
| Diretorio `src/app/api/financial/refunds/` pode conflitar com `/financial/refund/` | Next.js trata como routes distintas (singular vs plural) — sem conflito |
