# Story 54.6 — Decompose Portal Dashboard God Route (1100+ Lines)

## Story

**Como** desenvolvedor que precisa manter o portal,
**Quero** que a route do dashboard seja decomposta em modulos focados,
**Para que** mudancas em Klaviyo nao arrisquem quebrar Shopify, e vice-versa.

## Contexto

### Problema

O arquivo `src/app/api/portal/dashboard/route.ts` tem **1100+ linhas** e mistura:
- Autenticacao e resolucao de contexto portal
- Leitura de cache Klaviyo (3 tabelas)
- Transformacao de dados Klaviyo (rates ponderadas, aggregation)
- Fetch live + cache Shopify
- Resolucao de meetings (Google Calendar)
- Aggregation de invoices
- Deteccao de staleness
- Touch pattern
- Multi-store aggregation

Este e um "god route" classico. Qualquer mudanca requer entender todo o arquivo.

### Precedente no projeto

Epic 45 ja decompos a `page.tsx` do calendario de campanhas de 1309 para 260 linhas (Stories 45.7-45.9). Mesmo approach deve ser aplicado aqui.

### 54.6.4 — Route simplificada

- [x] A route `portal/dashboard/route.ts` deve ficar com ~466 linhas (de 1153; meetings resolver mantido inline — candidato a futura extracao)
- [x] Responsabilidades restantes: auth, orquestrar servicos, compor response JSON
- [x] Pattern:
  ```typescript
  export async function GET(request: NextRequest) {
    const ctx = await resolvePortalClient(request)
    const stores = await resolveStores(ctx, storeId)

    const klaviyo = await fetchKlaviyoFromCache(stores, period)
    const shopify = await fetchShopifyFromCache(stores, period)

    return NextResponse.json({
      klaviyo: klaviyo.data,
      shopify: shopify.data,
      dataStatus: resolveStatus(klaviyo, shopify),
    })
  }
  ```
