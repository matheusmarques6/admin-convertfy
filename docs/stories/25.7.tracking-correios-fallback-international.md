## Contexto

Hoje, a API dos Correios so e tentada quando o codigo de rastreio **termina com "BR"** (regex `/^[A-Z]{2}\d{9}BR$/`). Pacotes internacionais com destino ao Brasil (ex: `LP00123456789CN`, `RR123456789CN`, `YT2012345678901234`) nunca tentam a API dos Correios, mesmo quando o pacote ja entrou no Brasil e tem eventos registrados no sistema dos Correios.

Isso causa uma experiencia degradada para lojas brasileiras que importam da China/Asia — o rastreio depende exclusivamente de Cainiao/17track, que frequentemente tem menos detalhes da etapa nacional.

### Problema especifico
- `detectCarrierProvider()` em `carriers.ts:44` — regex `/^[A-Z]{2}\d{9}BR$/` so detecta codigos BR
- `PROVIDER_REGISTRY.correios.canRun()` em `carriers.ts:547` — `c.code === "correios"` so permite Correios se detectado como tal
- Resultado: codigos `CN`, `HK`, `SG`, etc. **nunca** passam pelo provider Correios

---

## Objetivo

Permitir que a API dos Correios seja tentada como **fallback** para codigos de rastreio internacionais no formato UPU (Universal Postal Union: 2 letras + 9 digitos + 2 letras pais), independentemente do pais de origem.

---

## Solucao Implementada

### Abordagem: `isUpu` calculado automaticamente + Correios como fallback

Em vez de marcar `isUpu` manualmente em cada return, a flag e calculada **uma vez no topo** de `detectCarrierProvider()` via regex e propagada automaticamente.

### Mudancas realizadas (3 pontos em `carriers.ts`)

#### 1. `CarrierInfo` — nova flag `isUpu` (linha 30)
```typescript
export interface CarrierInfo {
  code: string
  name: string
  provider: "correios" | "cainiao" | "postnl" | "trackingmore" | "seventeen_track" | "unknown"
  /** UPU postal format (XX000000000YY) -- eligible for Correios fallback */
  isUpu?: boolean
}
```

#### 2. `detectCarrierProvider()` — calculo automatico de `isUpu` (linhas 36-89)
```typescript
const isUpu = /^[A-Z]{2}\d{9}[A-Z]{2}$/.test(num)
```
- `isUpu` calculado uma vez, propagado em todos os returns que casam com formato UPU
- Carriers nao-UPU (WanbExpress, SDH, Cainiao longo, Jadlog, TotalExpress) NAO recebem `isUpu`
- Catch-all UPU no final para paises nao mapeados (ex: AR, JP, SG)

#### 3. `PROVIDER_REGISTRY.correios.canRun()` — aceita UPU (linha 549)
```typescript
canRun: (_k, c) => c.code === "correios" || c.isUpu === true,
```

## Decisoes Tomadas (QA + Dev Review)

| Questao | Decisao | Justificativa |
|---------|---------|---------------|
| Yanwen CN tenta Correios? | **Sim** | Yanwen entrega ao Correios no Brasil. Custo zero (null rapido se sem dados) |
| PostNL NL tenta Correios? | **Sim** (via `isUpu`) | Se pacote holandes esta no Brasil, Correios pode ter dados. Overhead minimo |
| Correios primeiro ou segundo? | **Primeiro** | Rejeicao rapida (~200-800ms). Quando tem dados, economiza chamadas pagas |
| Short-circuit com dados parciais? | **Aceito** | Dados do Correios sao mais uteis para etapa nacional. Merge de eventos = story futura |

## Criterios de Aceitacao

### AC 25.7.1 — Correios tentado para codigos UPU nao-BR
- [x] Codigo `XX123456789CN` passa por `trackViaCorreios()` na cascade
- [x] Codigo `XX123456789HK` passa por `trackViaCorreios()` na cascade
- [x] Codigo `XX123456789SG` passa por `trackViaCorreios()` na cascade
- [x] Log confirma tentativa: `Trying Correios` para codigos internacionais

### AC 25.7.2 — Comportamento BR inalterado
- [x] Codigo `XX123456789BR` continua detectado como `code: "correios"`
- [x] Correios continua sendo o **primeiro** provider para codigos BR
- [x] Short-circuit funciona normalmente para BR

### AC 25.7.3 — Fallback funciona quando Correios nao tem dados
- [x] Se Correios retorna null/vazio para codigo CN → cascade continua para Cainiao
- [x] Se Correios retorna null/vazio para codigo HK → cascade continua para proximo provider
- [x] Nao ha impacto no timeout global (5s por provider, 25s total)

### AC 25.7.4 — Codigos nao-UPU nao sao afetados
- [x] Codigos Cainiao longos (`LP00000000000000000`) NAO tentam Correios
- [x] Codigos Jadlog (14 digitos) NAO tentam Correios
- [x] Codigos PostNL proprietarios (`3S...`, `JVGL...`) NAO tentam Correios (nao sao UPU)
- [x] Codigo `unknown` NAO tenta Correios

### AC 25.7.5 — Catch-all UPU para paises nao mapeados
- [x] Codigo `XX123456789AR` (Argentina) detectado como UPU com `isUpu: true`
- [x] Codigo `XX123456789JP` (Japao) detectado como UPU com `isUpu: true`
- [x] Esses codigos tentam Correios na cascade

### AC 25.7.6 — Dados parciais aceitos (tradeoff documentado)
- [x] Se Correios retorna eventos apenas da etapa nacional, short-circuit aceita
- [x] Merge de eventos internacionais + nacionais fica para story futura
