# Story 42.8 — Calendar selector e settings de sincronizacao

## Story

**Como** admin user da plataforma,
**Quero** escolher em qual calendario Google as reunioes serao criadas e configurar preferencias de Meet,
**Para que** eu tenha controle sobre onde as reunioes aparecem e se Meet e criado automaticamente.

## Contexto

### Estado atual

- `GoogleCalendarService` usa `calendarId` no constructor (default: 'primary')
- `user_google_tokens` nao tem campo para calendario selecionado
- `GoogleCalendarService.getCalendarList()` ja retorna lista de calendarios do usuario
- Nao existe preferencia de Meet automatico per-user

### O que precisa mudar

1. Endpoint para listar calendarios do usuario
2. Adicionar campo `selected_calendar_id` e `auto_meet` a `user_google_tokens`
3. Dropdown de selecao de calendario nos settings
4. Toggle de Meet automatico

## Acceptance Criteria

- [x] **AC 42.8.1**: Endpoint `GET /api/integrations/google/calendar/calendars`:
  - Busca token valido do user via `getValidAccessToken()`
  - Instancia `GoogleCalendarService` com o token
  - Chama `getCalendarList()`
  - Retorna lista: `{ id, summary, primary, accessRole }[]`
  - Se token invalido: retorna `{ error: 'not_connected' }` com status 401

- [x] **AC 42.8.2**: Coluna `selected_calendar_id TEXT DEFAULT 'primary'` adicionada a `user_google_tokens` (micro migration)

- [x] **AC 42.8.3**: Coluna `auto_meet BOOLEAN DEFAULT true` adicionada a `user_google_tokens` (mesma migration)

- [x] **AC 42.8.4**: Dropdown de selecao de calendario no card Google Calendar dos settings:
  - Lista calendarios do user (busca do endpoint AC 42.8.1)
  - Marca o calendario atual como selecionado
  - Ao mudar, salva `selected_calendar_id` via endpoint de update
  - Default: 'primary' (calendario principal)
  - So visivel quando conectado e ativo

- [x] **AC 42.8.5**: Toggle "Criar Google Meet automaticamente" no card Google Calendar:
  - Default: ON
  - Ao mudar, salva `auto_meet` via endpoint de update
  - `syncMeetingToGoogle` usa essa preferencia para decidir se inclui conferenceData

- [x] **AC 42.8.6**: Endpoint `PATCH /api/integrations/google/calendar/settings`:
  - Aceita body `{ selected_calendar_id?: string, auto_meet?: boolean }`
  - Atualiza `user_google_tokens` do user logado
  - Retorna dados atualizados

## Technical Notes

### Micro migration

```sql
-- supabase/migrations/20260315_google_calendar_settings.sql
ALTER TABLE user_google_tokens
  ADD COLUMN IF NOT EXISTS selected_calendar_id TEXT DEFAULT 'primary',
  ADD COLUMN IF NOT EXISTS auto_meet BOOLEAN DEFAULT true;
```

### Integracao com sync service

O `google-calendar-sync.service` precisa ler `selected_calendar_id` e `auto_meet` ao criar eventos:

```typescript
const tokenRecord = await getTokenRecord(organizerUserId, 'profile')
const calendarId = tokenRecord.selected_calendar_id || 'primary'
const autoMeet = tokenRecord.auto_meet ?? true

const calendarService = new GoogleCalendarService({
  accessToken: validToken,
  calendarId,
})
```
