# Story 50.4 — API Endpoint: POST /api/financial/refund (Manual)

## Story

**Como** admin que precisa reembolsar uma cobranca local (pix_direto, wise, boleto, cartao),
**Quero** um endpoint que marque a cobranca como reembolsada imediatamente e registre no audit trail,
**Para que** cobranças que nao passam pelo Asaas tambem possam ser rastreadas como reembolsadas.

## Contexto

Cobranças locais (`client_charges`) nao possuem gateway de pagamento. O reembolso real acontece fora do sistema (transferencia manual no Wise, estorno de PIX, etc). Este endpoint apenas **registra** o reembolso no sistema.

Diferenca do endpoint Asaas (story 50.3):
- Asaas: status = 'requested' (async, aguarda webhook)
- Manual: status = 'processed' (sync, imediato)

## Acceptance Criteria

### AC 50.4.1 — Criar route file

- [ ] Criar `src/app/api/financial/refund/route.ts`
- [ ] Exportar apenas `POST` handler
- [ ] Importar `requireAuth`, `errorResponse`, `AppError` de `@/lib/api/errors`
- [ ] Importar `resolveOrgId` de `@/lib/api/resolve-org`
- [ ] Importar `createClient` de `@/lib/supabase/server`
- [ ] Importar `processManualRefund` de `@/lib/services/refund.service`

### AC 50.4.2 — Validacao de request body com Zod

- [ ] Schema Zod para body:
  ```typescript
  const manualRefundSchema = z.object({
    charge_id: z.string().uuid(),
    amount: z.number().positive().optional(),
    reason: z.string().min(3).max(500),
  })
  ```
- [ ] Parse body com `manualRefundSchema.safeParse()` — se invalido, retornar 400

### AC 50.4.3 — Autenticacao e autorizacao

- [ ] Seguir padrao existente nos routes do projeto (ver `charges/route.ts`):
  ```typescript
  const supabase = await createClient()
  const user = await requireAuth(supabase)
  const orgId = await resolveOrgId(user.id)
  ```
- [ ] Passar `orgId` e `user.id` para o service

### AC 50.4.4 — Chamar RefundService e retornar response

- [ ] Chamar `processManualRefund({ chargeId, orgId, userId, amount, reason })`
- [ ] Response 200:
  ```json
  {
    "refund_id": "uuid",
    "status": "processed",
    "original_amount": 300.00,
    "refund_amount": 300.00
  }
  ```
- [ ] Erros do service propagam via `errorResponse()`:
  - 400: charge nao encontrada, status != paid, valor invalido
  - 403: org_id mismatch
  - 409: ja reembolsada totalmente
  - 429: rate limit excedido

### AC 50.4.5 — Error handling padronizado

- [ ] Wrap do handler em try/catch com `errorResponse(request, error, 'POST /api/financial/refund')`
