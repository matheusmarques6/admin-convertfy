**Epic:** [Epic 20 - Campaign Copy Generation](./epic-20-campaign-copy-generation.md)

**Sprint:** Current

## Contexto

O N8N precisa do briefing de cada loja para gerar copies de campanha contextualizadas. Hoje o payload do webhook (`POST /api/campaigns/generate`) envia apenas `store_id`, `store_name`, `country`, `language` e `version` — sem nenhum dado de briefing.

A infraestrutura de briefing ja existe:
- **Tabela `store_briefings`**: JSONB `briefing_data` versionado (`current`/`archived`)
- **Tipo `BriefingData`**: `src/types/onboarding.ts:193-233`
- **Service `generateBriefing()`**: `src/lib/services/briefing.service.ts`
- **Endpoint existente**: `GET /api/onboarding/store-briefing?store_id=X` (requer sessao de usuario — N8N nao pode usar)

O gap: nao existe endpoint que o N8N possa chamar com auth machine-to-machine para buscar o briefing.

### Fluxo proposto

```
1. Usuario clica "Gerar Copies"
2. Backend valida lojas -> dispara webhook N8N com {store_id, store_name, ...}
3. N8N recebe o webhook
4. Para cada loja, N8N chama: GET /api/n8n/store-briefing?store_id=X
5. N8N recebe o briefing completo
6. N8N gera copies usando o briefing como contexto
7. N8N retorna via callback
```

## Tasks

### Task 1: Criar helper reutilizavel de auth N8N
- [x] Criar `src/lib/api/n8n-auth.ts` com funcao `requireWebhookSecret()`:
  ```typescript
  import crypto from "crypto"
  import { AppError } from "@/lib/api/errors"
  import { NextRequest } from "next/server"

  export function requireWebhookSecret(
    request: NextRequest,
    envVar = "N8N_WEBHOOK_SECRET",
    headerName = "x-webhook-secret",
  ): void {
    const secret = request.headers.get(headerName)
    const expected = process.env[envVar]
    if (!expected) throw new AppError("Webhook secret not configured", 500)
    if (!secret) throw new AppError("Missing webhook secret", 401)
    const a = Buffer.from(secret)
    const b = Buffer.from(expected)
    if (a.byteLength !== b.byteLength || !crypto.timingSafeEqual(a, b)) {
      throw new AppError("Unauthorized", 401)
    }
  }
  ```
- [x] Este helper elimina duplicacao de ~10 linhas em cada endpoint N8N
- [x] Nao migrar endpoints existentes agora (refactor futuro)

## Acceptance Criteria

### AC 20.12.1: Endpoint retorna briefing com auth valida
**Given** um request com `x-webhook-secret` valido e `store_id` de uma loja com briefing
**When** N8N chama `GET /api/n8n/store-briefing?store_id=X`
**Then** retorna 200 com `store` (metadados) e `briefing` (briefing_data completo + version)

### AC 20.12.2: Endpoint rejeita auth invalida
**Given** um request sem header ou com secret errado
**When** qualquer chamada ao endpoint
**Then** retorna 401 "Unauthorized"

### AC 20.12.3: Loja sem briefing retorna null
**Given** uma loja existente sem briefing gerado
**When** N8N chama `GET /api/n8n/store-briefing?store_id=X`
**Then** retorna 200 com `briefing: null` e `store` preenchido

### AC 20.12.4: Loja inexistente retorna 404
**Given** um `store_id` que nao existe no banco
**When** N8N chama o endpoint
**Then** retorna 404 generico (sem diferenciar "loja nao existe" de "store_id invalido")

### AC 20.12.5: Parametro store_id obrigatorio
**Given** um request sem `store_id` no query string
**When** N8N chama o endpoint
**Then** retorna 400 com mensagem "store_id e obrigatorio"

### AC 20.12.6: Cache header presente
**Given** um request valido
**When** endpoint retorna 200
**Then** response inclui `Cache-Control: private, max-age=300`

## Ressalvas QA

### C1 (MEDIUM): UUID malformado pode retornar 500 em vez de 404
Postgres rejeita `.eq("id", "abc")` em coluna UUID com erro `invalid input syntax for type uuid`. Sem validacao previa, isso gera 500 em vez do 404 esperado.
**Mitigacao:** Validar formato UUID antes da query. Adicionado como subtask na Task 2 e cenario T9.

### C4 (MEDIUM): Sem scoping por `org_id` na query
O endpoint busca briefing por `store_id` sem filtrar por `org_id`. Qualquer `store_id` valido retorna o briefing, independente da org. Isso e aceitavel porque:
- N8N e um sistema interno confiavel
- N8N so conhece `store_ids` que o proprio sistema forneceu via webhook
- O shared secret e a barreira primaria
**Trade-off documentado:** Se multiplas orgs forem onboarded e o secret vazar, qualquer briefing seria acessivel. Para mitigar no futuro, adicionar parametro `org_id` obrigatorio.

## Notas Tecnicas

- **Path `/api/n8n/`**: Namespace dedicado para endpoints machine-to-machine consumidos pelo N8N. Futuros endpoints (ex: `/api/n8n/store-performance`) seguem o mesmo padrao.
- **Sem JOIN**: `briefing_data` JSONB ja contem dados da loja (niche, target_audience, country, language, etc). A query a `client_stores` busca apenas `id`, `store_name`, `platform` como metadados de roteamento.
- **Secret reutilizado**: Usa `N8N_WEBHOOK_SECRET` (mesmo do webhook-callback de campanhas). Mesmo consumer, mesmo blast radius. Nao justifica secret separado.
- **`createAdminClient()`**: N8N nao tem sessao Supabase. RLS em `store_briefings` e `USING(true)` (bypass) — nao filtra por org. A seguranca vem do shared secret + validacao de existencia do store.
- **Indice existente**: `idx_sb_store` em `store_briefings(store_id)` e suficiente para o volume atual. Indice composto `(store_id, status)` e nice-to-have futuro.
- **Helper reutilizavel**: `requireWebhookSecret()` pode ser adotado por `webhook-callback/route.ts` e `onboarding/webhook/route.ts` em refactor futuro, eliminando ~10 linhas duplicadas por endpoint.

## Decisoes Arquiteturais

| Decisao | Escolha | Alternativa rejeitada | Razao |
|---------|---------|----------------------|-------|
| Path | `/api/n8n/store-briefing` | `/api/campaigns/store-briefing` | Coesao de dominio — briefing nao pertence a campanhas |
| Auth | `N8N_WEBHOOK_SECRET` reutilizado | Secret dedicado | Mesmo consumer, complexidade desnecessaria |
| Granularidade | Single store_id | Batch POST | Alinhado ao workflow N8N, simples, cacheavel |
| Payload | Briefing completo | Subconjunto curado | Evita acoplamento rigido — N8N evolui independente |
| Cache | 5 min (max-age=300) | Nenhum | Briefing muda raramente (dias/semanas) |
| Rate limiting | Nenhum | Upstash Redis | Endpoint interno, volume baixo |
| Migration | Nenhuma | Indice composto | Volume tiny, idx_sb_store suficiente |
