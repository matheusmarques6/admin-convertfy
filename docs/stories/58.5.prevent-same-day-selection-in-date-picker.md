# Story 58.5 — Impedir selecao de mesmo dia no date picker personalizado

## Executor Assignment

executor: "@dev"
quality_gate: "@qa"
quality_gate_tools: ["typecheck", "lint"]

## Story

**Como** operador do admin,
**Quero** que o seletor de periodo personalizado nao permita selecionar a mesma data de inicio e fim,
**Para que** eu nao gere relatorios de "0 dias" que nao fazem sentido.

## Contexto

### Problema

Em `period-picker.tsx:71-76`, o botao "Aplicar" so verifica se `from` e `to` existem:

```typescript
const handleApplyCustom = () => {
  if (range?.from && range?.to) {  // ← nao valida from !== to
    onChange({ period: "custom", customStart: range.from, customEnd: range.to })
  }
}
```

O mesmo problema existe em `date-range-picker.tsx:52-56`:

```typescript
const handleApply = () => {
  if (range?.from && range?.to) {  // ← mesma falta de validacao
    onApply(range.from, range.to)
  }
}
```

O usuario pode selecionar ex: "3 de marco" como inicio E fim, gerando um periodo de 0 dias.

### Impacto

- A API Klaviyo retorna dados vazios ou identicos ao "today" para ranges de 0 dias
- Gera confusao para o operador
- Timeframe `start: 2026-03-03T00:00:00, end: 2026-03-03T23:59:59` pode ter comportamento imprevisivel dependendo da timezone

## Acceptance Criteria

### 58.5.1 — Desabilitar botao "Aplicar" quando from === to

- [ ] Em `src/components/ui/period-picker.tsx`:
  - No botao "Aplicar" (linha ~106), adicionar condicao de disabled:
    ```typescript
    disabled={!range?.from || !range?.to || range.from.getTime() === range.to.getTime()}
    ```
  - Atualizar o texto de hint (linha ~149) para indicar quando as datas sao iguais:
    - Se `from` e `to` existem e sao iguais: mostrar "Selecione dias diferentes"
    - Caso contrario: manter comportamento atual

### 58.5.2 — Aplicar mesma validacao no DateRangePicker standalone

- [ ] Em `src/components/ui/date-range-picker.tsx`:
  - No botao "Aplicar" (linha ~106), adicionar mesma condicao de disabled:
    ```typescript
    disabled={!range?.from || !range?.to || range.from.getTime() === range.to.getTime()}
    ```
  - Atualizar hint text quando datas sao iguais

### 58.5.3 — Garantir minimo de 1 dia de diferenca

- [ ] A validacao deve ser por DIA (ignorar horario):
  - Comparar `range.from.toDateString() === range.to.toDateString()` para ser robusto contra diferencas de horario
  - Ou usar: `range.from.getTime() === range.to.getTime()` ja que react-day-picker normaliza para meia-noite

### Comportamento do react-day-picker

O componente `Calendar` com `mode="range"` define `from` e `to` como `Date` objects com hora 00:00:00. Quando o usuario clica no mesmo dia duas vezes:
- Primeiro clique: `from = date, to = undefined`
- Segundo clique no mesmo dia: `from = date, to = date` (ambos com mesmo timestamp)

Portanto, `range.from.getTime() === range.to.getTime()` e a comparacao correta.

### Nao precisa de validacao no backend

O backend (`parseDateRangeInTimezone`) recebe `customStartDate` e `customEndDate` como strings ISO. Se forem iguais, o timeframe seria `T00:00:00` a `T23:59:59` do mesmo dia — tecnicamente valido para a API, mas semanticamente sem sentido. A validacao no frontend e suficiente.
