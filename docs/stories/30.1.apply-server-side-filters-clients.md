## Contexto
A pagina de clientes (`/clients`) tem uma barra de filtros que gera URL params (`?search=texto&status=active&health=good`) corretamente via `clients-filters.tsx`. Porem, o server component `page.tsx` **ignora completamente** esses parametros. O `PageProps` declara apenas `{ page?: string }` e a funcao `getClients(page)` nao recebe nem aplica nenhum filtro na query Supabase.

Resultado: o usuario digita na busca, clica "Aplicar", a URL muda mas a tabela continua mostrando todos os clientes sem filtro.

## Objetivo
Fazer o server component ler `search`, `status` e `health` dos searchParams e aplica-los como filtros WHERE na query Supabase, para que a tabela retorne apenas os clientes que correspondem aos criterios.

---

## Acceptance Criteria

- [x] **30.1.1** `PageProps.searchParams` aceita `search`, `status` e `health` alem de `page`
- [x] **30.1.2** `getClients()` recebe um objeto de filtros `{ page, search?, status?, health? }` em vez de apenas `page: number`
- [x] **30.1.3** Quando `search` esta presente, a query aplica `.or()` com `ilike` em `name`, `email` e `company` (pattern: `%search%`)
- [x] **30.1.4** Quando `status` esta presente (e nao e `"all"`), a query aplica `.eq("status", status)`
- [x] **30.1.5** Quando `health` esta presente (e nao e `"all"`), a query aplica filtro de range no `health_score`:
  - `good`: `.gte("health_score", 70)`
  - `warning`: `.gte("health_score", 40).lt("health_score", 70)`
  - `critical`: `.lt("health_score", 40)`
- [x] **30.1.6** Filtros sao composiveis — search + status + health podem ser aplicados simultaneamente
- [x] **30.1.7** A contagem (`count: 'exact'`) reflete os filtros aplicados (nao o total geral)
- [x] **30.1.8** Sem filtros ativos, o comportamento e identico ao atual (todos os clientes, paginados)
- [x] **30.1.9** Search input e sanitizado: caracteres `%`, `_` e `\` sao escapados antes de interpolar no `.or()` ilike pattern. Extrair helper `sanitizeSearch()` reutilizavel (referencia: `src/app/api/stores/control/route.ts` ja faz isso)
- [x] **30.1.10** No server component, `status` e validado contra a lista de valores permitidos: `["active", "inactive", "prospect", "onboarding", "churned"]`. Valor invalido e ignorado (tratado como sem filtro)
- [x] **30.1.11** No server component, `health` e validado contra a lista de valores permitidos: `["good", "warning", "critical"]`. Valor invalido e ignorado
- [x] **30.1.12** No server component, `search` recebe `.trim()` e strings vazias apos trim sao ignoradas
- [x] **30.1.13** `page` no server e validado: valores negativos ou NaN resultam em `page = 1`
- [x] **30.1.14** Quando filtros produzem zero resultados, mostrar mensagem "Nenhum cliente encontrado para os filtros aplicados" com botao "Limpar filtros", em vez do empty state padrao "Comece adicionando seu primeiro cliente". Requer prop adicional `hasActiveFilters` na `ClientsTable`

### DEPOIS
```typescript
// --- Helper reutilizavel (extrair para src/lib/utils/sanitize-search.ts) ---
/**
 * Escapa caracteres especiais do ILIKE: %, _, \
 * Referencia: src/app/api/stores/control/route.ts ja faz algo similar
 */
export function sanitizeSearch(input: string): string {
  return input
    .replace(/\\/g, '\\\\')
    .replace(/%/g, '\\%')
    .replace(/_/g, '\\_')
}

// --- Constantes de validacao ---
const VALID_STATUSES = ["active", "inactive", "prospect", "onboarding", "churned"] as const
const VALID_HEALTH = ["good", "warning", "critical"] as const

interface ClientFilters {
  page: number
  search?: string
  status?: string
  health?: string
}

interface PageProps {
  searchParams: Promise<{
    page?: string
    search?: string
    status?: string
    health?: string
  }>
}

async function getClients(filters: ClientFilters) {
  const supabase = await createClient()
  const { page, search, status, health } = filters
  const from = (page - 1) * PAGE_SIZE
  const to = from + PAGE_SIZE - 1

  let query = supabase
    .from("clients")
    .select(`
      *,
      contracts ( id, plan_name, monthly_value, status ),
      owner:profiles!clients_owner_id_fkey ( id, name, avatar_url ),
      client_stores ( id, store_name, platform, is_active )
    `, { count: 'exact' })

  // Filtro de busca textual (com sanitizacao de caracteres ILIKE)
  if (search) {
    const safe = sanitizeSearch(search)
    const pattern = `%${safe}%`
    query = query.or(`name.ilike.${pattern},email.ilike.${pattern},company.ilike.${pattern}`)
  }

  // Filtro de status
  if (status && status !== "all") {
    query = query.eq("status", status)
  }

  // Filtro de saude
  // NOTA: clientes com health_score NULL serao excluidos de todos os filtros de health.
  // Isso e comportamento esperado pois o schema tem DEFAULT 50 — NULLs indicam dados inconsistentes.
  if (health && health !== "all") {
    if (health === "good") {
      query = query.gte("health_score", 70)
    } else if (health === "warning") {
      query = query.gte("health_score", 40).lt("health_score", 70)
    } else if (health === "critical") {
      query = query.lt("health_score", 40)
    }
  }

  const { data: clients, error, count } = await query
    .order("created_at", { ascending: false })
    .range(from, to)

  if (error) {
    console.error("Error fetching clients:", error)
    return { clients: [], totalCount: 0 }
  }

  return { clients: clients || [], totalCount: count || 0 }
}

export default async function ClientsPage({ searchParams }: PageProps) {
  const params = await searchParams
  const page = Math.max(1, Math.floor(Number(params.page) || 1))
  const search = params.search?.trim() || undefined
  const status = VALID_STATUSES.includes(params.status as any) ? params.status : undefined
  const health = VALID_HEALTH.includes(params.health as any) ? params.health : undefined

  const hasActiveFilters = !!(search || status || health)
  const { clients, totalCount } = await getClients({ page, search, status, health })

  // Passar hasActiveFilters para ClientsTable para empty state diferenciado
  // ...
}
```

## Decisoes Tecnicas

### health_score NULL
Clientes com `health_score` NULL serao excluidos de todos os filtros de health. Isso e comportamento esperado pois o schema da tabela `clients` tem `DEFAULT 50` para `health_score`. Valores NULL indicam dados inconsistentes que precisam de correcao separada, nao um caso de uso valido.
