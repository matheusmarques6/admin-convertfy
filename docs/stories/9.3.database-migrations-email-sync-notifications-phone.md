## Contexto

Existem lacunas de integridade de dados que afetam as configuracoes de conta:

1. **Email desincronizado:** Quando o email eh alterado em `auth.users` (via Supabase dashboard ou futuro fluxo de email change), ele nao propaga para `profiles.email` nem `client_portal_users.email`. Isso causa inconsistencias visuais e de autenticacao.

2. **Tabela notification_preferences inexistente:** A UI de notificacoes em `/settings/notifications/page.tsx` ja faz queries para esta tabela, mas ela nunca foi criada via migration. A pagina quebra silenciosamente.

3. **Coluna phone ausente:** O campo telefone no perfil precisa da coluna `profiles.phone` que nao existe.

---

## Objetivo

1. Criar trigger para sincronizar email de `auth.users` para tabelas dependentes
2. Criar tabela `notification_preferences` com RLS
3. Adicionar coluna `phone` a tabela `profiles`
4. Verificar e corrigir mismatches de email existentes

## Arquitetura Tecnica

### Migration 1: Email Sync Trigger

```sql
-- migration: handle_user_email_change

-- Funcao trigger (SECURITY DEFINER para acessar auth schema)
CREATE OR REPLACE FUNCTION public.handle_user_email_change()
RETURNS TRIGGER AS $$
BEGIN
  -- Sincronizar com profiles
  UPDATE public.profiles
  SET email = NEW.email
  WHERE id = NEW.id;

  -- Sincronizar com client_portal_users (se existir)
  UPDATE public.client_portal_users
  SET email = NEW.email
  WHERE auth_user_id = NEW.id;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- Trigger (idempotente)
DROP TRIGGER IF EXISTS on_user_email_change ON auth.users;
CREATE TRIGGER on_user_email_change
  AFTER UPDATE OF email ON auth.users
  FOR EACH ROW
  WHEN (OLD.email IS DISTINCT FROM NEW.email)
  EXECUTE FUNCTION public.handle_user_email_change();
```

### Migration 2: Notification Preferences Table

```sql
-- migration: create_notification_preferences

CREATE TABLE IF NOT EXISTS public.notification_preferences (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  preference_key text NOT NULL,
  enabled boolean NOT NULL DEFAULT true,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now(),
  CONSTRAINT unique_user_preference UNIQUE (user_id, preference_key)
);

-- RLS
ALTER TABLE public.notification_preferences ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own notification preferences"
  ON public.notification_preferences FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own notification preferences"
  ON public.notification_preferences FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own notification preferences"
  ON public.notification_preferences FOR UPDATE
  USING (auth.uid() = user_id);

CREATE POLICY "Users can delete own notification preferences"
  ON public.notification_preferences FOR DELETE
  USING (auth.uid() = user_id);

-- Trigger updated_at
CREATE OR REPLACE FUNCTION public.update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS update_notification_preferences_updated_at
  ON public.notification_preferences;
CREATE TRIGGER update_notification_preferences_updated_at
  BEFORE UPDATE ON public.notification_preferences
  FOR EACH ROW
  EXECUTE FUNCTION public.update_updated_at_column();
```

### Verification Query (Email Mismatches)

```sql
-- Mismatches auth.users vs profiles
SELECT u.id, u.email AS auth_email, p.email AS profile_email
FROM auth.users u
JOIN public.profiles p ON p.id = u.id
WHERE u.email IS DISTINCT FROM p.email;

-- Mismatches auth.users vs client_portal_users
SELECT u.id, u.email AS auth_email, cpu.email AS portal_email
FROM auth.users u
JOIN public.client_portal_users cpu ON cpu.auth_user_id = u.id
WHERE u.email IS DISTINCT FROM cpu.email;

-- Backfill (se necessario)
UPDATE public.profiles p
SET email = u.email
FROM auth.users u
WHERE p.id = u.id AND p.email IS DISTINCT FROM u.email;

UPDATE public.client_portal_users cpu
SET email = u.email
FROM auth.users u
WHERE cpu.auth_user_id = u.id AND cpu.email IS DISTINCT FROM u.email;
```

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Trigger em auth.users requer permissoes especiais | SECURITY DEFINER resolve; testar em staging antes de prod |
| Migration nao idempotente pode falhar em re-run | Usar CREATE OR REPLACE, IF NOT EXISTS, DROP IF EXISTS |
| Backfill de email pode afetar sessoes ativas | Backfill apenas atualiza profiles/portal_users, nao auth.users |
| update_updated_at_column() ja pode existir | CREATE OR REPLACE evita conflito |
