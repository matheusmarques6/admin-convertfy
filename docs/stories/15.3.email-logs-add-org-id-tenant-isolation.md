# Story 15.3 — email_logs: Add org_id for Multi-tenant Isolation

## Contexto

A tabela `email_logs` (migration `20260302_email_logs.sql`) rastreia todos os emails transacionais enviados via Resend. O schema atual **não possui coluna `org_id`**, quebrando o padrão multi-tenant do restante do sistema.

**Problemas identificados:**
1. **Sem isolamento no SELECT**: A policy `email_logs_select_admin` filtra por role, mas não por `org_id`. Um admin de uma organização pode ver logs de outra.
2. **INSERT sem tenant context**: O método `logEmailSent()` em `src/lib/email/email.service.ts` não passa `org_id` ao inserir (confirmado via leitura do código — linha 203-210).

**O que já funciona:**
- Todos os inserts em `email_logs` passam por `createAdminClient()` (linha 202 de `email.service.ts`) — o path de insert não é afetado por RLS. O `org_id` precisa ser passado como dado, não como guarda de RLS.
- A Story 14.2 já corrigiu a lista de roles do SELECT (removeu `coo`).

> **Correção v2 vs v1:** O @qa identificou que AC 15.3.3 da v1 prometia `WITH CHECK` na policy de INSERT, mas o SQL não implementava isso. Corrigido: como os inserts usam `createAdminClient()` (bypass de RLS), a policy de INSERT não precisa de tenant guard. O AC agora reflete a realidade corretamente.

## Objetivo

**Como** administrador de segurança do sistema,
**Quero** que `email_logs` tenha `org_id` e que o SELECT filtre por tenant,
**Para que** admins de uma organização não vejam logs de emails de outras organizações.

## Arquitetura Técnica

### Migration a Criar

**Arquivo:** `supabase/migrations/20260304_email_logs_add_org_id.sql`

```sql
-- Add org_id to email_logs for multi-tenant isolation
-- Story 15.3

ALTER TABLE email_logs
  ADD COLUMN IF NOT EXISTS org_id UUID REFERENCES organizations(id) ON DELETE SET NULL;

-- Index for tenant-filtered queries
CREATE INDEX IF NOT EXISTS idx_email_logs_org_id
  ON email_logs(org_id, created_at DESC);

-- Recreate SELECT policy with tenant filter
DROP POLICY IF EXISTS "email_logs_select_admin" ON email_logs;

CREATE POLICY "email_logs_select_admin" ON email_logs
  FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM profiles
      WHERE profiles.id = auth.uid()
      AND profiles.role IN ('admin', 'manager')
    )
    AND (org_id = current_org_id() OR org_id IS NULL)
  );

-- INSERT policy: unchanged — all inserts use createAdminClient() (bypasses RLS)
-- org_id enforcement is at application level, not RLS level
COMMENT ON COLUMN email_logs.org_id IS
  'Organization tenant ID. Set by application code on insert. NULL = legacy/system logs.';
```
