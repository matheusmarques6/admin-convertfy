# Story 40.2 — Step Dependency Resolution Service

## Story

**Como** sistema de onboarding,
**Quero** um servico que resolva o DAG de dependencias entre steps,
**Para que** eu saiba quais steps estao prontos para iniciar apos a conclusao de um step.

## Contexto

Cada step de onboarding pode depender de zero ou mais steps anteriores (`depends_on_step_ids UUID[]` em client steps, `depends_on_steps UUID[]` em template steps). Quando um step e completado, o sistema precisa:

1. Identificar quais steps dependiam do step completado
2. Verificar se TODAS as dependencias de cada candidato estao satisfeitas
3. Marcar como `pending` os steps cujas dependencias estao todas `completed` ou `skipped`
4. Detectar e rejeitar ciclos no DAG (protecao contra dados invalidos)

## Technical Notes

### Interface do Servico

```typescript
// src/lib/services/step-dependency.service.ts

interface StepForResolution {
  id: string
  onboarding_id: string
  status: OnboardingStepStatus
  depends_on_step_ids: string[] // UUIDs of other client_onboarding_steps
}

interface DagValidation {
  valid: boolean
  cycle?: string[] // IDs dos steps no ciclo, se houver
}

export class StepDependencyService {
  /**
   * Dado um onboardingId, retorna IDs dos steps que devem ser `pending`
   * (status = waiting, todas dependencias completed/skipped)
   */
  static async resolvePending(onboardingId: string): Promise<string[]>

  /**
   * Retorna os steps que bloqueiam um step especifico
   * (dependencias com status != completed/skipped)
   */
  static async getBlockedBy(stepId: string): Promise<StepForResolution[]>

  /**
   * Executa a transicao: waiting -> pending para steps elegiveis
   * Retorna IDs dos steps que foram transicionados
   */
  static async transitionToPending(onboardingId: string): Promise<string[]>

  /**
   * Valida que o grafo de dependencias nao tem ciclos (DFS)
   */
  static validateDag(steps: StepForResolution[]): DagValidation
}
```

### Algoritmo de Resolucao

```
1. Buscar todos os steps do onboarding
2. Filtrar steps com status = 'waiting'
3. Para cada step waiting:
   a. Buscar status de cada step em depends_on_step_ids[]
   b. Se TODOS estao 'completed' ou 'skipped' → step e elegivel para `pending`
4. Retornar lista de elegiveis
```

### Deteccao de Ciclos (DFS)

```
1. Construir grafo de adjacencia: step_id -> depends_on_step_ids[]
2. DFS com 3 cores: WHITE (nao visitado), GRAY (em progresso), BLACK (visitado)
3. Se encontrar edge para node GRAY → ciclo detectado
4. Retornar path do ciclo para debug
```

### Performance

- Buscar todos os steps do onboarding em UMA query (nao N+1)
- Resolver dependencias in-memory (steps tipicamente < 20 por onboarding)
- Usar batch update para transicionar multiplos steps de uma vez
