# Story 57.3 — Validar tamanho da ENCRYPTION_KEY

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint"]

## Story

**Como** engenheiro de segurança,
**Quero** que a função `getKey()` valide que a ENCRYPTION_KEY tem exatamente 64 caracteres hex (32 bytes),
**Para que** keys inválidas sejam detectadas imediatamente no startup em vez de causar erros silenciosos em runtime.

## Contexto

### Problema

`src/lib/crypto.ts` (linhas 12-18) carrega a key sem validar tamanho:

```typescript
function getKey(): Buffer {
  const key = process.env.ENCRYPTION_KEY
  if (!key) {
    throw new Error("ENCRYPTION_KEY environment variable is not set")
  }
  return Buffer.from(key, "hex")  // ← SEM VALIDAÇÃO DE TAMANHO
}
```

AES-256 requer exatamente 32 bytes (64 hex chars). Key menor causa erro em `createCipheriv()`, key maior causa truncamento silencioso.

## Acceptance Criteria

### 57.3.1 — Validar tamanho da key

- [x] `getKey()` deve validar que `key.length === 64` (64 hex chars = 32 bytes)
- [x] Se tamanho inválido, lançar erro descritivo: `"ENCRYPTION_KEY must be exactly 64 hex characters (32 bytes for AES-256)"`
- [x] Validação deve ocorrer ANTES de `Buffer.from(key, "hex")`

**Given-When-Then:**

```
GIVEN ENCRYPTION_KEY env var is set to a 60-character hex string
WHEN getKey() is called
THEN it throws Error with message about 64 hex characters requirement

GIVEN ENCRYPTION_KEY env var is set to a valid 64-character hex string
WHEN getKey() is called
THEN it returns a 32-byte Buffer successfully
```

### 57.3.2 — Typecheck

- [x] `npm run typecheck` passa sem erros novos

## Tasks / Subtasks

- [x] Task 1: Adicionar validação de tamanho em `getKey()` (AC 57.3.1)
  - [x] Adicionar check `if (key.length !== 64)` após `if (!key)`
  - [x] Lançar erro descritivo
- [x] Task 2: Typecheck (AC 57.3.2)
