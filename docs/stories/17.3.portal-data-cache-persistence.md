## Story

**Como** usuario do portal do cliente,
**Quero** que ao dar refresh, os dados anteriores aparecam imediatamente enquanto novos dados carregam em background,
**Para que** eu nao veja uma tela zerada/vazia a cada navegacao ou refresh.

---

## Contexto

Atualmente o portal usa `useState` local em cada pagina sem nenhuma camada de cache:

```typescript
// Padrao repetido em TODAS as paginas:
const [data, setData] = useState<DashboardData | null>(null) // ZERADO no refresh
```

O dashboard admin ja possui hooks SWR (`useKlaviyoReport`, `useShopifyReport` em
`src/lib/hooks/use-api-data.ts`) com dedup de 60s e keepPreviousData, mas o portal
NAO os utiliza — faz `fetch()` direto.

**Stores Zustand existentes (nenhum usado no portal):**
- `useAuthStore` — sem persist
- `useUIStore` — com persist (unico)
- `useClientsStore` — sem persist
- `usePipelineStore` — sem persist
- `useIntegrationsStore` — sem persist

---

## Solucao: SWR com cache (decidido)

Usar **SWR** (ja presente no projeto) para cache in-memory dos dados do portal:
- Criar hooks `usePortalDashboard(storeId, period)`, `usePortalCampaigns(...)`, `usePortalFlows(...)`
- Usar SWR com `keepPreviousData: true` e `dedupingInterval: 60000`
- Dados ficam em cache SWR (in-memory) durante a sessao
- Ao trocar de pagina e voltar, dados aparecem instantaneamente

**Scope:** Cache in-memory para navegacao interna. NAO sobrevive a F5 (hard refresh).
O F5 fara novo fetch, mas com as correcoes de 17.2 (PortalContext) o fetch sera confiavel.
Se no futuro quiser persist no F5, pode-se adicionar Zustand persist com sessionStorage.

---

## Criterios de Aceitacao

- [ ] **CA1**: Dados do dashboard aparecem instantaneamente ao navegar de volta (sem loading flash)
- [ ] **CA2**: Dados persistem entre navegacoes dentro do portal (campanhas → dashboard → campanhas)
- [ ] **CA3**: Dados sao revalidados em background (stale-while-revalidate)
- [ ] **CA4**: Troca de store invalida o cache e faz novo fetch
- [ ] **CA5**: Troca de periodo invalida o cache e faz novo fetch
- [ ] **CA6**: Loading skeleton mostrado APENAS no primeiro carregamento (cache vazio)
- [ ] **CA7**: Typecheck + lint passando
