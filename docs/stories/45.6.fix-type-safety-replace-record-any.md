# Story 45.6 — Fix Type Safety: Replace Record<string, any> With Proper Types

## Status: Ready for Review
## Effort: MEDIUM (1-2h)
## Priority: HIGH

## Context

The portal campaigns hook defines `RawApiCampaign = Record<string, any>` (line 119), which loses all type safety. The page.tsx then casts to `ApiCampaignRaw` via `as` assertion (line 523).

**Important**: `ApiCampaignRaw` in page.tsx (lines 338-370) is already a well-typed interface with 30+ fields properly defined. The problem is NOT that the type doesn't exist — it's that:
1. The hook returns `Record<string, any>`, forcing a cast
2. The type lives in page.tsx instead of a shared location

Three separate Campaign types coexist:
1. `src/types/campaign.ts` — `Campaign` (snake_case, admin)
2. `src/lib/hooks/use-portal-campaigns-calendar.ts` — `PortalCampaign` (camelCase, hook line 119)
3. `src/app/client/campaigns/page.tsx` — `ApiCampaignRaw` (snake_case, already well-typed, lines 338-370)

## Goal

Move the existing `ApiCampaignRaw` interface to a shared location and wire it into the hook's SWR type. No need to create a new interface from scratch.

## Acceptance Criteria

- [x] **AC 45.6.1** Rename `ApiCampaignRaw` to `PortalCampaignApiResponse` and move to `src/types/campaign.ts` (or the hook file)
- [x] **AC 45.6.2** Hook `useSWR` uses `PortalCampaignApiResponse[]` instead of `Record<string, any>`
- [x] **AC 45.6.3** Remove inline `ApiCampaignRaw` from page.tsx — import the shared type
- [x] **AC 45.6.4** `transformCampaignData` receives typed input, no `as` casts
- [x] **AC 45.6.5** No `Record<string, any>` remains in campaign-related code
- [x] **AC 45.6.6** Lint + typecheck pass (this validates field names actually match)

## Notes

- The transform bridges `PortalCampaignApiResponse` (snake_case) → `PortalCampaign` (camelCase)
- Do NOT change the API response format — only move and wire existing types
- The existing `ApiCampaignRaw` is already correct — reuse it, don't recreate
