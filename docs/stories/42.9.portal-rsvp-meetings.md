# Story 42.9 — Portal: RSVP de reunioes

## Story

**Como** cliente no portal,
**Quero** aceitar, recusar ou marcar "talvez" nas reunioes agendadas comigo,
**Para que** a equipe saiba se eu vou participar e meu Google Calendar reflita minha resposta.

## Contexto

### Estado atual

- Portal exibe reunioes em `NextMeetingCard` e `MeetingsSection` (read-only)
- `PortalMeeting` type nao inclui acoes de RSVP
- `meeting_participants` tem `response_status` mas portal nao atualiza
- Nao existe endpoint de RSVP no namespace portal

### O que precisa mudar

1. Endpoint dedicado no namespace portal para RSVP
2. Validacao de que portal user so pode RSVP em meetings do seu client_id
3. Botoes de RSVP na UI do portal
4. Propagacao opcional para Google Calendar

## Acceptance Criteria

- [x] **AC 42.9.1**: **[C10]** Endpoint `POST /api/portal/meetings/[id]/rsvp`:
  - Body: `{ response: 'accepted' | 'declined' | 'tentative' }`
  - Autenticado pelo portal user (via `getPortalUser()` de `src/lib/portal/auth.ts`)
  - Retorna `{ success: true, response_status: '...' }`

- [x] **AC 42.9.2**: Validacao de seguranca:
  - Portal user so pode dar RSVP em meetings do seu `client_id`
  - Verificar: meeting.client_id === portalUser.client_id
  - Se meeting nao pertence ao client: retorna 403
  - Portal user deve ser participante da meeting (existir em `meeting_participants`)

- [x] **AC 42.9.3**: Atualiza `meeting_participants.response_status` com o valor do RSVP:
  - **[M4] Estrategia de matching:** Portal users sao adicionados como participantes por EMAIL (campo `meeting_participants.email`). Para encontrar o registro do portal user:
    1. Buscar `portalUser.email` (de `client_portal_users`)
    2. Query: `meeting_participants WHERE meeting_id = $1 AND email = portalUser.email`
    3. Fallback: se `email` estiver vazio em `meeting_participants`, tentar match por `participant_id = portalUser.id AND participant_type = 'portal_user'` (para casos onde o participant foi adicionado diretamente pelo ID)
  - Se nenhum participant encontrado: retorna 403 ("Voce nao e participante desta reuniao")
  - UPDATE `response_status` com novo valor
  - UPDATE `updated_at` com timestamp atual

- [x] **AC 42.9.4**: Propagacao para Google Calendar (best-effort):
  - Buscar organizador da meeting (user_id) e verificar se tem Calendar conectado
  - Se sim: atualizar attendee responseStatus no evento do organizador
  - Se propagacao falha: log warning, RSVP local e fonte de verdade

- [x] **AC 42.9.5**: UI no portal — botoes RSVP no `MeetingsSection`:
  - Para cada reuniao futura com `response_status = 'pending'`: mostrar botoes "Aceitar" / "Recusar" / "Talvez"
  - Apos RSVP: mostrar status atual com opcao de mudar
  - Loading state durante chamada API
  - Feedback visual: toast de sucesso/erro

- [x] **AC 42.9.6**: Badge de status de participacao visivel em cada meeting:
  - `pending`: badge cinza "Pendente"
  - `accepted`: badge verde "Confirmado"
  - `declined`: badge vermelho "Recusado"
  - `tentative`: badge amarelo "Talvez"

## Technical Notes

### Endpoint RSVP

```typescript
// src/app/api/portal/meetings/[id]/rsvp/route.ts
import { getPortalUser } from '@/lib/portal/auth'
import { createAdminClient } from '@/lib/supabase/admin'

export async function POST(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const portalUser = await getPortalUser(request)
  if (!portalUser) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })

  const { response } = await request.json()
  if (!['accepted', 'declined', 'tentative'].includes(response)) {
    return NextResponse.json({ error: 'Invalid response' }, { status: 400 })
  }

  const meetingId = params.id
  const adminClient = createAdminClient()

  // Validar que meeting pertence ao client do portal user
  const { data: meeting } = await adminClient
    .from('meetings')
    .select('id, client_id, user_id')
    .eq('id', meetingId)
    .single()

  if (!meeting || meeting.client_id !== portalUser.client_id) {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 })
  }

  // Atualizar response_status do participante...
}
```
