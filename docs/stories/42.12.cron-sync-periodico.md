# Story 42.12 — Cron de sync periodico

## Story

**Como** plataforma,
**Quero** executar sync reversa periodicamente de forma automatica,
**Para que** os status de RSVP estejam sempre atualizados sem acao manual do usuario.

## Contexto

### Estado atual

- Story 42.11 implementa `syncRsvpFromGoogle()` como funcao chamavel manualmente
- `vercel.json` define cron schedules para jobs existentes (ex: sync-reports)
- Cron pattern: `src/app/api/cron/` com route handlers
- Nao existe cron para Google Calendar sync

### O que precisa mudar

1. Endpoint cron dedicado
2. Iteracao sobre todas as orgs/users com Calendar conectado
3. Retry de meetings com `google_sync_status = 'error'`
4. Rate limiting respeitando limits do Google
5. Registro em `vercel.json`

## Acceptance Criteria

- [x] **AC 42.12.1**: Endpoint `GET /api/cron/google-calendar-sync` (GET para compatibilidade com Vercel Cron):
  - Protegido por `CRON_SECRET` (mesmo padrao dos outros crons)
  - Nao requer autenticacao de user (roda como service)

- [x] **AC 42.12.2**: Busca usuarios com Google Calendar conectado:
  - Query `user_google_tokens WHERE is_active = true`
  - Agrupa por org_id para logging

- [x] **AC 42.12.3**: Para cada usuario conectado:
  - Chama `syncRsvpFromGoogle(userId)` da story 42.11
  - Apenas meetings futuras (proximos 30 dias)
  - Limita a meetings com `google_event_id IS NOT NULL`

- [x] **AC 42.12.4**: Rate limiting do Google Calendar API:
  - Respeitar 500 req/100s/user
  - Delay de 500ms entre users
  - Se token revoked: skip user, continuar com proximo

- [x] **AC 42.12.5**: Log de execucao com stats:
  - Total de users processados
  - Total de meetings sincronizadas
  - Total de erros
  - Duracao total
  - Exemplo: `GoogleCalendarCron: completed. users=5, meetings_synced=23, errors=1, duration=4.2s`

- [x] **AC 42.12.6**: **[R6]** Retry de meetings com `google_sync_status = 'error'`:
  - Alem do sync de RSVP, tentar re-sync meetings com status 'error' (que falharam na criacao)
  - Para cada meeting com `google_sync_status = 'error'` e `google_event_id IS NULL`:
    - Tentar `syncMeetingToGoogle(meetingId, organizerUserId)` novamente
  - Limitar retries: so meetings dos ultimos 7 dias (max 20 por execucao)

- [x] **AC 42.12.8**: **[M5]** Lock/dedup para evitar execucao concorrente:
  - Usa `acquire_sync_lock` RPC com lock_name `google_calendar_sync`
  - Se lock ja ativo: retorna `{ skipped: true, reason: 'lock_active' }` com status 409
  - No fim (success ou error): libera lock via finally
  - TTL do lock: 5 minutos (safety — se cron crashar, lock expira automaticamente)
  - Migration criada para inserir row na `cron_locks` table

- [x] **AC 42.12.7**: Registrar cron no `vercel.json`:
  - Schedule: a cada hora (`0 * * * *`)
  - Suficiente para RSVP sync

## Technical Notes

### Estrutura do cron

```typescript
// src/app/api/cron/google-calendar-sync/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { syncRsvpFromGoogle, syncMeetingToGoogle } from '@/lib/services/google-calendar-sync.service'
import { createAdminClient } from '@/lib/supabase/admin'
import { logger } from '@/lib/logger'

const log = logger.child('GoogleCalendarCron')

export async function POST(request: NextRequest) {
  const authHeader = request.headers.get('authorization')
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
  }

  const startTime = Date.now()
  const adminClient = createAdminClient()

  const { data: activeTokens } = await adminClient
    .from('user_google_tokens')
    .select('user_id, user_type, org_id')
    .eq('is_active', true)

  let totalSynced = 0
  let totalErrors = 0

  for (const token of activeTokens || []) {
    try {
      const result = await syncRsvpFromGoogle(token.user_id)
      totalSynced += result.synced_count
      totalErrors += result.errors_count
    } catch (error) {
      log.error('Sync failed for user', { userId: token.user_id, error })
      totalErrors++
    }
    await new Promise(resolve => setTimeout(resolve, 100))
  }

  // Retry meetings com erro (ultimos 7 dias)...

  const duration = ((Date.now() - startTime) / 1000).toFixed(1)
  log.info('GoogleCalendarCron: completed', {
    users: activeTokens?.length || 0,
    meetings_synced: totalSynced,
    errors: totalErrors,
    duration: `${duration}s`,
  })

  return NextResponse.json({
    users_processed: activeTokens?.length || 0,
    meetings_synced: totalSynced,
    errors: totalErrors,
    duration_s: parseFloat(duration),
  })
}
```

### Timeout safety

- Vercel Pro: 60s timeout
- Se muitos users: parar processamento se tempo > 50s
- Log parcial com users restantes
