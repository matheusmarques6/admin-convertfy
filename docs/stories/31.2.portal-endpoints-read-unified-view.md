# Story 31.2 - Portal Endpoints: Migrar Leitura para unified_invoices

## Epic
Epic 31 - Unified Invoices: Portal Visibility for All Charges

## Contexto
Com a VIEW `unified_invoices` criada (Story 31.1), os endpoints do portal precisam ser atualizados para ler da VIEW em vez de direto da tabela `invoices`. Isso faz com que cobranças manuais (PIX direto, Wise, Boleto, Cartao) aparecam automaticamente no portal.

## Riscos
| Risco | Severidade | Mitigacao |
|-------|-----------|-----------|
| Guard de Asaas insuficiente | ALTO | Testar com cobrança local pendente — nao pode chamar Asaas API |
| Tipo do status incompativel | MEDIO | VIEW faz cast para TEXT; verificar se comparacoes de status funcionam |
| Revenue guard muda comportamento | MEDIO | Com cobranças locais no total, `revenueGenerated >= totalInvoices` resulta `false` mais vezes — banner de receita some. Avaliar se guard deve considerar apenas invoices Asaas ou total unificado. Documentar decisao no PR |
| Performance com mais registros | BAIXO | Volume e pequeno; indexes compostos cobrem |

## Notas Tecnicas
- O endpoint `portal/invoices/route.ts` usa `adminClient` (service_role), entao RLS nao e fator
- O overdue e calculado server-side comparando `due_date < hoje` para status `pending` — funciona independente de source
- Payment links (PIX QR, boleto URL) so existem para cobranças Asaas — cobranças locais mostram metodo alternativo
