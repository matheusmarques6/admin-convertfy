# Story 32.1 - Integracao API YunExpress para Rastreamento de Encomendas

**Epic:** 32 - Integracao YunExpress
**Prioridade:** Alta
**Estimativa:** M (Medium)
**Status:** Draft
**Revisado por:** QA (Quinn) + Dev (Dex) - 2026-03-07

---

## Contexto

O sistema de tracking atual suporta multiplos carriers (Correios, Cainiao, PostNL, TrackingMore, 17track) via provider registry em `src/lib/tracking/carriers.ts`. O `tracking.service.ts` ja mapeia YunExpress (code 190131) e detecta prefixo "YT" para 17track.

Porem, ao inves de depender de intermediarios (17track/TrackingMore) para rastrear encomendas YunExpress, queremos integrar **diretamente** com a API oficial da YunExpress (`open.yunexpress.cn`), garantindo dados mais rapidos e sem custo adicional por consulta.

**Regra de roteamento:** Codigos de rastreio que comecam com `YT` devem ser roteados para a API YunExpress diretamente, com fallback para os providers existentes caso a API YunExpress falhe.

---

## Pre-requisito: Validacao da API

> **IMPORTANTE**: Os schemas de response nesta story sao estimativas baseadas em padroes comuns da API YunExpress. A documentacao oficial esta atras de autenticacao em open.yunexpress.cn.
>
> **Antes de iniciar a implementacao**, o dev deve:
> 1. Obter credenciais reais (Customer_Number + API_Key) do cliente ou da conta YunExpress
> 2. Validar a URL base, endpoints, e schemas com chamadas reais
> 3. Ajustar os tipos/interfaces conforme a resposta real da API
>
> A implementacao deve usar **parsing defensivo** (optional chaining, campos opcionais) para acomodar diferencas no schema real.

## API YunExpress - Especificacao (Estimada)

### Base URL
```
Producao: https://oms-api.yunexpress.com/api
Sandbox:  https://oms-api-sandbox.yunexpress.com/api
```
Configuravel via env var `YUNEXPRESS_API_BASE_URL` com fallback para o valor default.

> NOTA: A URL exata deve ser confirmada com as credenciais do cliente via portal open.yunexpress.cn. Pode variar por regiao (BR/CN/EU).

### Autenticacao
```
Header: Authorization: Basic base64(Customer_Number:API_Key)
Content-Type: application/json
Accept: application/json
```
- **Customer_Number**: Numero do cliente fornecido pela YunExpress
- **API_Key**: Chave de API gerada no portal YunExpress

### Endpoints

#### 1. GET - Detalhes da Guia de Remessa (Single)
```
GET /WayBill/GetTrackingNumber?trackingNumber={number}
```
- Consulta detalhes de uma guia usando numero de rastreamento
- Compativel com: numero da guia (WaybillNumber), numero de rastreamento do cliente (CustomerNumber), numero de rastreamento (TrackingNumber)
- **Response esperado:**
```typescript
interface YunExpressWaybillResponse {
  Code: number           // 0 = success
  Message: string
  Data: {
    WaybillNumber: string
    TrackingNumber: string
    CustomerNumber: string
    Status: string       // e.g. "Delivered", "InTransit"
    ReceiverCountry: string
    SenderCountry: string
    Weight: number
    CreatedAt: string    // ISO date
    // ... outros campos (parsing defensivo)
  } | null
}
```

#### 2. GET - Pesquisar Remetente (Single)
```
GET /WayBill/GetSender?trackingNumber={number}
```
- Pesquisa informacoes do remetente baseado no numero de rastreamento
- Compativel com os mesmos formatos do endpoint 1
- **Response esperado:**
```typescript
interface YunExpressSenderResponse {
  Code: number
  Message: string
  Data: {
    SenderName: string
    SenderCompany: string
    SenderAddress: string
    SenderCity: string
    SenderState: string
    SenderCountry: string
    SenderPhone: string
    SenderEmail: string
  } | null
}
```

#### 3. POST - Rastreamento Last Mile (Batch)
```
POST /Tracking/GetTrackInfo
Content-Type: application/json
Body: ["YT0000000001", "YT0000000002", ...] // max 20 por request
```
- Pesquisa informacoes do fornecedor de entrega de ultima milha
- Maximo 20 numeros por requisicao
- **Response esperado:**
```typescript
interface YunExpressTrackInfoResponse {
  Code: number
  Message: string
  Data: Array<{
    WaybillNumber: string
    TrackingNumber: string
    TrackingEvents: Array<{
      ProcessDate: string      // ISO datetime
      ProcessContent: string   // Descricao do evento
      ProcessLocation: string  // Local
    }>
    DeliveryStatus: string     // "Delivered", "InTransit", "Exception", etc.
    LastMileCarrier: string    // Nome do carrier de ultima milha
    LastMileTrackingNumber: string
  }>
}
```

## Notas Tecnicas

### Provider Order (novo)
```
correios -> postnl -> yunexpress -> cainiao -> trackingmore -> seventeen_track
```
YunExpress fica ANTES de Cainiao pois e direto (sem intermediario) e gratuito para clientes com conta YunExpress.

### Timeout Strategy
- **Producao** (provider registry): 5s por provider (consistente com Correios, Cainiao, PostNL, TrackingMore)
- **Test endpoint**: 15s (consistente com testes de outros carriers)
- Motivo da diferenca: teste precisa de margem maior para validar conectividade; producao prioriza velocidade com fallback

### Batch vs Single
- **Provider Registry** (`PROVIDER_REGISTRY.execute`): aceita single `trackingNumber: string`, retorna `TrackingResult | null`. Usa `trackViaYunExpress()`.
- **Batch** (`trackViaYunExpressLastMile`): aceita `string[]` (max 20), retorna `TrackingResult[]`. Disponivel para otimizacao futura do sync loop.
- O sync loop atual processa um codigo por vez. Batch e uma otimizacao para story futura.

### Seguranca
- Credenciais SEMPRE encrypted via AES-256-GCM (`encrypt()`/`decrypt()`)
- Portal NUNCA retorna credenciais raw, apenas boolean `has_key`
- Auth header construido server-side apenas no momento da chamada
- Caracteres especiais em credenciais devem ser corretamente encodados em base64

## Riscos
1. **API URL/schema incertos**: Documentacao oficial atras de auth. Mitigacao: env var configuravel, parsing defensivo, validacao no teste de conexao
2. **Response schema pode variar**: Mitigacao: optional chaining, campos opcionais, testes com responses malformed
3. **Rate limits desconhecidos**: Mitigacao: timeout de 5s, fallback para outros providers, rate limit handling (429)
4. **Credenciais compostas quebram padrao flat**: Mitigacao: documentado como excecao, PUT handler com branch especifico, `StoreCarrierApiKeys` tipado
