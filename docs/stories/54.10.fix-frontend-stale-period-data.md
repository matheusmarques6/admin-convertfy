# Story 54.10 — Fix Frontend Preserving Stale Period Data

## Story

**Como** usuario do portal,
**Quero** que ao trocar o periodo (ex: 30d para 7d), eu veja dados do periodo correto ou um loading state,
**Para que** eu nao tome decisoes baseadas em dados do periodo errado.

## Contexto

### Problema

Em `src/app/client/dashboard/page.tsx` (linhas ~98-103):

```typescript
setData(prev => {
  if (!result.klaviyo && prev?.klaviyo) {
    return { ...result, klaviyo: prev.klaviyo }
  }
  return result
})
```

Quando o usuario troca de periodo (ex: 30d → 7d), se o novo periodo nao tem cache ainda (`result.klaviyo` e null), o frontend **preserva os dados do periodo anterior**. O usuario ve dados de 30 dias rotulados como "7 dias".

### Impacto

Dados incorretos podem levar a decisoes erradas sobre performance de campanhas, revenue, etc.

## Acceptance Criteria

### 54.10.1 — Limpar dados ao trocar periodo

- [x] Ao trocar de periodo, setar `klaviyo: null` imediatamente (mostrar loading/skeleton)
- [x] Somente preservar dados anteriores se o periodo NAO mudou (ex: refresh do mesmo periodo)
- [x] Implementacao:
  ```typescript
  setData(prev => {
    // So preserva se mesmo periodo e sem dados novos
    if (!result.klaviyo && prev?.klaviyo && prev.period === result.period) {
      return { ...result, klaviyo: prev.klaviyo }
    }
    return result
  })
  ```

### 54.10.2 — Mostrar estado adequado

- [x] Se `klaviyo: null` apos troca de periodo, mostrar skeleton/spinner na secao Klaviyo
- [x] Nao mostrar "$0" ou "0 flows" — deve ser claramente um loading state

### 54.10.3 — Validacao

- [x] `npm run build` passa
- [x] Trocar periodo mostra loading ate dados chegarem
- [x] Dados corretos sao exibidos apos cache hit
