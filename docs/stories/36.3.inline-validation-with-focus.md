# Story 36.3 — Validacao Inline com Focus no Erro

## Contexto

Ambos os formularios de onboarding validam campos apenas via toast generico que desaparece em segundos. O usuario nao sabe QUAL campo esta errado — nao ha highlight, mensagem inline, nem focus automatico.

### Comportamento atual
1. Usuario clica "Proximo"
2. `validateStep()` retorna `string | null` (primeira mensagem de erro encontrada)
3. Toast aparece por ~5s e desaparece
4. Nenhum campo recebe destaque visual

### Comportamento desejado
1. Usuario clica "Proximo"
2. Validacao retorna `Record<string, string>` (campo → mensagem)
3. Cada campo invalido mostra mensagem vermelha inline abaixo dele
4. Campo recebe `ring-destructive` border
5. Focus vai automaticamente para o primeiro campo com erro
6. Mensagens somem ao corrigir o campo

## Criterios de Aceitacao

### Form Publico (`/cliente/onboarding`)
- [x] **AC 36.3.1**: Adicionar estado `errors: Record<string, string>` ao componente
- [x] **AC 36.3.2**: Refatorar `validateStep()` para retornar `Record<string, string>` em vez de `string | null`
- [x] **AC 36.3.3**: Renderizar `<p className="text-sm text-destructive">` abaixo de cada campo com erro
- [x] **AC 36.3.4**: Adicionar `aria-invalid="true"` e `aria-describedby="{fieldId}-error"` nos campos com erro
- [x] **AC 36.3.5**: Implementar focus automatico no primeiro campo com erro via `ref`
- [x] **AC 36.3.6**: Limpar erro do campo especifico ao alterar seu valor (`onChange` limpa `errors[field]`)
- [x] **AC 36.3.7**: Remover toast de validacao — manter toast apenas para erros de rede/servidor

### Wizard Portal (`/portal/onboarding/wizard`)
- [x] **AC 36.3.8**: Mesmo pattern: estado `errors`, mensagens inline, `aria-invalid`, focus
- [x] **AC 36.3.9**: Expandir validacoes do wizard para incluir: email (formato), URL (formato), CPF/CNPJ (quando preenchido)
