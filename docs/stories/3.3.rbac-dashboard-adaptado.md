# Story 3.3 - Dashboard Adaptado por Role

## Contexto
O dashboard atual mostra os mesmos 9 componentes para todos os usuários. Cada role precisa ver uma versão adaptada à sua função.

## Objetivo
Renderizar componentes do dashboard condicionalmente baseado no role/features do usuário logado.

## Acceptance Criteria

- [x] **3.3.1** Definir layout do dashboard por role:

### Admin (owner)
Todos os componentes (estado atual):
- TotalRevenueBanner, QuickActions, BoardPreview, WeekCalendarPreview
- TopStoresCard, WorstPerformersCard, OnboardingPreview
- DashboardAlerts, RecentActivity

### COO (manager)
Mesmo que Admin, exceto:
- DashboardAlerts: filtrar alertas de `payment_overdue` (financeiro)
- QuickActions: remover ações financeiras

### Design (designer)
- QuickActions adaptado (ações de copy/design)
- BoardPreview (filtrado: tasks de design)
- WeekCalendarPreview (reuniões próprias)
- OnboardingPreview (novos onboardings pendentes de design)
- RecentActivity (filtrado: atividades de copy/design)

### Implementação (developer)
- QuickActions adaptado (ações de implementação)
- BoardPreview (filtrado: tasks de implementação)
- WeekCalendarPreview (reuniões próprias)
- TopStoresCard (lojas em implementação)
- OnboardingPreview (em fase de implementação)
- RecentActivity (filtrado: atividades de implementação)

- [x] **3.3.2** Criado `DashboardLayout` client component que adapta visibilidade por role via `usePermissions()`. Removido redirect para `/dashboard/operational` — agora todos usam o mesmo dashboard adaptado.

- [x] **3.3.3** Adaptado `QuickActions` com ações contextuais por feature:
  - Admin: Novo Cliente, Nova Automação
  - COO: Aprovar Onboarding
  - Design: Ver Copys
  - Implementação: Ver Board, Nova Campanha
  - Compartilhadas: Agendar Reunião, Criar Relatório, Ver Lojas
  - Máximo 5 ações visíveis, filtradas por `hasAnyFeature()`

- [x] **3.3.4** Adaptado `DashboardAlerts` com `ALERT_FEATURE_MAP`:
  - `payment_overdue` → só visível com `view_financial`
  - `report_pending` → só visível com `view_reports`
  - Admin/owner sempre veem todos

- [x] **3.3.5** `BoardPreview` já é genérico (conta status de tasks). `OnboardingPreview` já tem `ROLE_PHASE_MAP` interno que filtra por role. `WorstPerformersCard` só aparece para quem tem `view_reports`.

## Notas Técnicas

- Componentes: `src/components/dashboard/`
- Permissões: `usePermissions()` hook
- Usar `<PermissionGate>` para gating inline
