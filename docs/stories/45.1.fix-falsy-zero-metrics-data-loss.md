# Story 45.1 — Fix Falsy-Zero Metrics Data Loss

## Status: Ready for Review
## Effort: LOW (15min)
## Priority: CRITICAL

## Context

In `transformCampaignData()`, the `||` operator treats `0` as falsy, causing campaigns with zero recipients/delivered/opened/clicked/converted/revenue to have those values erased to `undefined`. This corrupts aggregate stats (totalRecipients, weightedOpenRate denominator).

## File

`src/app/client/campaigns/page.tsx` — lines 436-441

## Current (Broken)

```typescript
recipients: apiCampaign.recipients || undefined,
delivered: apiCampaign.delivered || undefined,
opened: apiCampaign.opened || undefined,
clicked: apiCampaign.clicked || undefined,
converted: apiCampaign.converted || undefined,
revenue: apiCampaign.revenue || undefined,
```

## Fix

Replace `||` with `??` (nullish coalescing) for ALL numeric fields:

```typescript
recipients: apiCampaign.recipients ?? undefined,
delivered: apiCampaign.delivered ?? undefined,
opened: apiCampaign.opened ?? undefined,
clicked: apiCampaign.clicked ?? undefined,
converted: apiCampaign.converted ?? undefined,
revenue: apiCampaign.revenue ?? undefined,
```

## Rate fields — already safe, but note cross-dependency with 45.4

The rate fields (lines ~449-454) already use `??`: `openRate: apiCampaign.open_rate ?? 0`. These are currently correct.

**However**: Story 45.4 will change the RPC to return NULL (instead of 0) for rates when no Klaviyo data exists. After 45.4, the `?? 0` fallback will kick in and display "0%" for manual campaigns — which is the same misleading behavior. Story 45.4 must also update these lines to `?? undefined` (or just `apiCampaign.open_rate`) so null rates propagate to the UI as "—".

**For this story**: Only fix the 6 count/revenue fields (`||` → `??`). Do NOT touch rate fields — they will be addressed in 45.4.
