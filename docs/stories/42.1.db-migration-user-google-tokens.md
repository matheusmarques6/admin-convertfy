# Story 42.1 — DB Migration: user_google_tokens + ALTER meetings/participants

## Story

**Como** desenvolvedor da plataforma,
**Quero** que o schema do banco suporte tokens Google per-user e campos de sync no meetings,
**Para que** as stories subsequentes possam implementar OAuth, sync bidirecional e controle de status.

## Contexto

### Estado atual

- `meetings` ja tem `google_event_id TEXT` (coluna existe mas nunca e populada)
- `meeting_participants` nao tem campo de email nem RSVP do Google
- Nao existe tabela para armazenar tokens Google per-user
- OAuth atual salva tokens em `client_stores` (incorreto para Calendar — e per-user, nao per-store)

### O que precisa mudar

1. Nova tabela `user_google_tokens` para armazenar tokens OAuth per-user (admin e portal)
2. ALTER `meetings` com colunas de sync status, timezone, meeting_url_source
3. ALTER `meeting_participants` com email e google_rsvp_status (SEM google_event_id — R8)
4. RLS policies usando `auth.uid() = user_id` (C5 — NAO usar `is_admin()`)
5. Indexes para performance de queries de retry e sync

## Acceptance Criteria

- [x] **AC 42.1.1**: Tabela `user_google_tokens` criada com todas as colunas do schema:
  - `id UUID DEFAULT uuid_generate_v4() PRIMARY KEY`
  - `user_type TEXT NOT NULL CHECK (user_type IN ('profile', 'portal_user'))`
  - `user_id UUID NOT NULL`
  - `google_email TEXT NOT NULL`
  - `google_account_id TEXT`
  - `access_token TEXT NOT NULL` (sera encriptado pela aplicacao, prefix `enc:v1:`)
  - `refresh_token TEXT NOT NULL` (sera encriptado pela aplicacao, prefix `enc:v1:`)
  - `token_type TEXT DEFAULT 'Bearer'`
  - `expires_at TIMESTAMPTZ NOT NULL`
  - `scopes TEXT[] DEFAULT '{}'`
  - `is_active BOOLEAN DEFAULT true`
  - `last_synced_at TIMESTAMPTZ`
  - `sync_error TEXT`
  - `org_id UUID REFERENCES organizations(id) NOT NULL`
  - `created_at TIMESTAMPTZ DEFAULT NOW()`
  - `updated_at TIMESTAMPTZ DEFAULT NOW()`
  - `UNIQUE(user_type, user_id)`

- [x] **AC 42.1.2**: `meetings` alterada com novas colunas:
  - `google_calendar_id TEXT`
  - `meeting_url_source TEXT DEFAULT 'manual' CHECK (meeting_url_source IN ('manual', 'google_meet', 'external'))`
  - `google_sync_status TEXT DEFAULT 'not_connected' CHECK (google_sync_status IN ('synced', 'pending', 'error', 'not_connected'))`
  - `google_sync_error TEXT`
  - `timezone TEXT DEFAULT 'America/Sao_Paulo'`

- [x] **AC 42.1.3**: `meeting_participants` alterada com:
  - `email TEXT`
  - `google_rsvp_status TEXT`
  - **NAO criar `google_event_id` em meeting_participants** (R8 — evento e criado no calendar do organizador, nao per-participant)

- [x] **AC 42.1.4**: **[C5]** RLS em `user_google_tokens`:
  - SELECT: `auth.uid() = user_id` (NAO usar `is_admin()`)
  - UPDATE: `auth.uid() = user_id`
  - DELETE: `auth.uid() = user_id`
  - Policy para `service_role` com bypass (para cron/admin operations)
  - **[H4] NOTA:** A policy `auth.uid() = user_id` funciona apenas para admin users (`user_type = 'profile'`), pois `profiles.id = auth.users.id`. Para portal users (`user_type = 'portal_user'`), `client_portal_users.id` NAO e `auth.uid()` — portanto portal users NUNCA acessam tokens via RLS direto. Todo acesso de portal users a tokens deve ser via `createAdminClient()` (service role). Se no futuro for necessario acesso client-side para portal users, criar policy adicional: `auth.uid() IN (SELECT auth_user_id FROM client_portal_users WHERE id = user_id)`

- [x] **AC 42.1.5**: RLS INSERT em `user_google_tokens`:
  - User pode inserir apenas para si mesmo (`auth.uid() = user_id`)

- [x] **AC 42.1.6**: **[C9]** Index parcial unique: `CREATE UNIQUE INDEX idx_meetings_google_event_id ON meetings(google_event_id) WHERE google_event_id IS NOT NULL`

- [x] **AC 42.1.7**: **[R6]** Index para queries de retry: `CREATE INDEX idx_meetings_google_sync_status ON meetings(google_sync_status)`

- [x] **AC 42.1.8**: Migration e idempotente (usa `IF NOT EXISTS` em todas as operacoes, pode rodar multiplas vezes sem erro)

## Technical Notes

### Migration SQL

```sql
-- 1. Nova tabela user_google_tokens
CREATE TABLE IF NOT EXISTS user_google_tokens (
  id UUID DEFAULT uuid_generate_v4() PRIMARY KEY,
  user_type TEXT NOT NULL CHECK (user_type IN ('profile', 'portal_user')),
  user_id UUID NOT NULL,
  google_email TEXT NOT NULL,
  google_account_id TEXT,
  access_token TEXT NOT NULL,
  refresh_token TEXT NOT NULL,
  token_type TEXT DEFAULT 'Bearer',
  expires_at TIMESTAMPTZ NOT NULL,
  scopes TEXT[] DEFAULT '{}',
  is_active BOOLEAN DEFAULT true,
  last_synced_at TIMESTAMPTZ,
  sync_error TEXT,
  org_id UUID REFERENCES organizations(id) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_type, user_id)
);

-- 2. Indexes
CREATE INDEX IF NOT EXISTS idx_user_google_tokens_user ON user_google_tokens(user_type, user_id);
CREATE INDEX IF NOT EXISTS idx_user_google_tokens_org ON user_google_tokens(org_id);

-- 3. RLS [C5]
ALTER TABLE user_google_tokens ENABLE ROW LEVEL SECURITY;

CREATE POLICY user_google_tokens_select ON user_google_tokens
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY user_google_tokens_insert ON user_google_tokens
  FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY user_google_tokens_update ON user_google_tokens
  FOR UPDATE USING (auth.uid() = user_id);

CREATE POLICY user_google_tokens_delete ON user_google_tokens
  FOR DELETE USING (auth.uid() = user_id);

-- Service role bypass (para cron e admin operations)
CREATE POLICY user_google_tokens_service ON user_google_tokens
  FOR ALL TO service_role USING (true) WITH CHECK (true);

-- 4. ALTER meetings
ALTER TABLE meetings
  ADD COLUMN IF NOT EXISTS google_calendar_id TEXT,
  ADD COLUMN IF NOT EXISTS meeting_url_source TEXT
    DEFAULT 'manual'
    CHECK (meeting_url_source IN ('manual', 'google_meet', 'external')),
  ADD COLUMN IF NOT EXISTS google_sync_status TEXT
    DEFAULT 'not_connected'
    CHECK (google_sync_status IN ('synced', 'pending', 'error', 'not_connected')),
  ADD COLUMN IF NOT EXISTS google_sync_error TEXT,
  ADD COLUMN IF NOT EXISTS timezone TEXT DEFAULT 'America/Sao_Paulo';

-- [C9] Unique constraint parcial
CREATE UNIQUE INDEX IF NOT EXISTS idx_meetings_google_event_id
  ON meetings(google_event_id) WHERE google_event_id IS NOT NULL;

-- [R6] Index para retry queries
CREATE INDEX IF NOT EXISTS idx_meetings_google_sync_status
  ON meetings(google_sync_status);

-- 5. ALTER meeting_participants (SEM google_event_id — R8)
ALTER TABLE meeting_participants
  ADD COLUMN IF NOT EXISTS email TEXT,
  ADD COLUMN IF NOT EXISTS google_rsvp_status TEXT;
```
