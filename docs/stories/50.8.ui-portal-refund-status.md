# Story 50.8 — UI Portal: Status Refunded + Display refund_total/net_amount

## Story

**Como** cliente do portal que teve uma cobranca reembolsada,
**Quero** ver o status "Reembolsada" com os valores corretos (valor original, reembolsado, liquido),
**Para que** eu tenha transparencia sobre o estado das minhas faturas.

## Contexto

O portal de faturas (`src/app/client/invoices/page.tsx`) exibe cobranças com badges de status (Pendente, Paga, Atrasada, Cancelada). O status 'refunded' NAO esta configurado — faturas reembolsadas aparecem com badge generico.

A `unified_invoices` VIEW (atualizada na story 50.1) agora inclui `refund_total` e `net_amount`. O endpoint `src/app/api/portal/invoices/route.ts` precisa expor esses campos.

O portal e **read-only** para refunds (ADR-4). O cliente pode ver, mas nao pode disparar reembolsos.

### Referencia: Arquitetura

Ver secao 6.3 de `docs/architecture/refund-processing-architecture.md`.

## Acceptance Criteria

### AC 50.8.1 — Adicionar 'refunded' ao STATUS_CONFIG

- [ ] Em `src/app/client/invoices/page.tsx`, adicionar ao `STATUS_CONFIG` (linha 87):
  ```typescript
  refunded: {
    label: "Reembolsada",
    color: "bg-violet-50 text-violet-700 border-violet-200 dark:bg-violet-500/10 dark:text-violet-400 dark:border-violet-500/20",
    dotColor: "bg-violet-500",
    icon: RotateCcw,
  }
  ```
- [ ] Importar `RotateCcw` de `lucide-react`

### AC 50.8.2 — Esconder botoes de pagamento para faturas reembolsadas

- [ ] Para faturas com status 'refunded': NAO exibir botoes de pagamento (PIX, boleto, cartao)
- [ ] Mesma logica ja aplicada para status 'cancelled' e 'paid' — adicionar 'refunded' a condicao

### AC 50.8.3 — Exibir valores de reembolso

- [ ] Para faturas com `refund_total > 0`:
  - Se `status === 'refunded'` (full): exibir "Reembolsado: R$ 500,00"
  - Se `status !== 'refunded'` e `refund_total > 0` (partial): exibir "Reembolsado: R$ 50,00 de R$ 500,00"
  - Exibir `net_amount` como "Valor liquido: R$ 450,00" quando houver refund parcial
- [ ] Formatar valores com `toLocaleString('pt-BR', { style: 'currency', currency: 'BRL' })`

```tsx
// Exemplo de display condicional
{invoice.refund_total > 0 && (
  <div className="text-sm text-muted-foreground">
    {invoice.status === 'refunded' ? (
      <span>Reembolsado: {formatCurrency(invoice.refund_total)}</span>
    ) : (
      <>
        <span>Reembolsado: {formatCurrency(invoice.refund_total)} de {formatCurrency(invoice.amount)}</span>
        <span className="ml-2">Valor liquido: {formatCurrency(invoice.net_amount)}</span>
      </>
    )}
  </div>
)}
```

### AC 50.8.4 — Atualizar endpoint portal/invoices para incluir refund data

- [ ] Em `src/app/api/portal/invoices/route.ts`: verificar que a query retorna `refund_total` e `net_amount`
- [ ] Se a query usa `unified_invoices` VIEW: os campos ja estao disponiveis (adicionados na migration 50.1)
- [ ] Se a query usa tabelas diretas (`invoices` + `client_charges`): adicionar LEFT JOIN com `refund_summaries` ou migrar para usar `unified_invoices`
- [ ] Incluir os campos no response JSON

### AC 50.8.5 — Atualizar type do invoice no frontend

- [ ] Adicionar `refund_total: number` e `net_amount: number` ao tipo/interface do invoice usado no portal
- [ ] Garantir que valores default sao 0 (nao undefined) para faturas sem refunds
