# Story 50.7 — UI Admin: RefundDialog + Integracao no ChargesManager

## Story

**Como** admin que precisa reembolsar uma cobranca,
**Quero** um dialog intuitivo com opcao de reembolso total/parcial, motivo obrigatorio, e feedback visual,
**Para que** eu possa processar reembolsos com seguranca e sem confusao.

## Contexto

O `ChargesManager` (`src/components/financial/charges-manager.tsx`) ja possui um DropdownMenu de acoes por cobranca (ver detalhes, cancelar). Esta story adiciona:
1. Opcao "Reembolsar" no dropdown (visivel apenas para status = 'paid')
2. Novo componente `RefundDialog` com form de reembolso
3. Chamada ao endpoint correto baseado no tipo de cobranca (Asaas vs local)

### Tipo de cobranca determina o endpoint

- **Asaas** (cobranca com `asaas_id`): POST `/api/integrations/asaas/refund` com `invoice_id`
- **Local** (pix_direto, wise, boleto, cartao): POST `/api/financial/refund` com `charge_id`

O dialog deve identificar o tipo automaticamente e chamar o endpoint correto.

### Referencia: Arquitetura

Ver secao 6.1 e 6.2 de `docs/architecture/refund-processing-architecture.md`.

- [ ] Usar componentes shadcn/ui: Dialog, RadioGroup, Input, Textarea, Button, Alert

### AC 50.7.2 — Form de reembolso

- [ ] RadioGroup "Tipo de Reembolso":
  - "Reembolso Total" (default)
  - "Reembolso Parcial"
- [ ] Se parcial selecionado: mostrar Input de valor (type=number, min=0.01, max=remaining)
- [ ] Se ja houve refund parcial anterior: exibir "Ja Reembolsado: R$ X" e limitar max ao remaining
- [ ] Textarea "Motivo" (obrigatorio, min 3 chars, max 500)
- [ ] Validacao client-side antes de submit

```typescript
// Dados que o dialog precisa exibir
const originalAmount = charge.amount
const alreadyRefunded = charge.refund_total ?? 0  // da unified_invoices
const remaining = originalAmount - alreadyRefunded
```

### AC 50.7.3 — Warning para cobranças com subscription

- [ ] Se `charge.subscription_id` nao e null, exibir Alert warning:
  - "Esta cobranca pertence a assinatura [nome]. O reembolso nao cancela a assinatura."
- [ ] Warning e informativo — nao bloqueia o submit

### AC 50.7.4 — Confirmacao antes de submit

- [ ] Exibir Alert destrutivo com icone:
  - Asaas: "Esta acao nao pode ser desfeita. O valor sera devolvido ao cliente via Asaas."
  - Manual: "Esta acao nao pode ser desfeita. O reembolso sera registrado imediatamente."
- [ ] Botao "Confirmar Reembolso" com variante destructive
- [ ] Botao "Cancelar" fecha o dialog

### AC 50.7.5 — Chamar endpoint correto

- [ ] Se cobranca tem `asaas_id` (source === 'asaas'):
  - POST `/api/integrations/asaas/refund` com body `{ invoice_id: charge.id, amount?, reason }`
- [ ] Se cobranca e local (source === 'local'):
  - POST `/api/financial/refund` com body `{ charge_id: charge.id, amount?, reason }`
- [ ] Para reembolso total: omitir `amount` do body (service usa valor total)
- [ ] Para reembolso parcial: enviar `amount` no body

### AC 50.7.6 — Loading state e feedback

- [ ] Botao "Confirmar Reembolso" mostra spinner durante request
- [ ] Desabilitar todos os inputs e botoes durante request
- [ ] Sucesso: toast "Reembolso processado com sucesso" (manual) ou "Reembolso solicitado ao Asaas" (asaas)
- [ ] Erro: toast com mensagem do erro (vinda do API)
- [ ] Apos sucesso: fechar dialog e chamar callback `onSuccess` para refresh da tabela

### AC 50.7.7 — Integrar no ChargesManager

- [ ] No DropdownMenu de acoes de cada cobranca em `charges-manager.tsx`:
  - Adicionar item "Reembolsar" com icone RotateCcw
  - Visivel apenas quando `charge.status === 'paid'`
  - Ao clicar: abrir RefundDialog com dados da cobranca
- [ ] Adicionar state `refundCharge` e `showRefundDialog` no componente
- [ ] Renderizar `<RefundDialog>` condicionalmente

```tsx
// No DropdownMenu, apos os items existentes:
{charge.status === 'paid' && (
  <DropdownMenuItem onClick={() => {
    setRefundCharge(charge)
    setShowRefundDialog(true)
  }}>
    <RotateCcw className="mr-2 h-4 w-4" />
    Reembolsar
  </DropdownMenuItem>
)}
```

### AC 50.7.8 — Exibir badge "Reembolsada" no ChargesManager

- [ ] Para cobranças com status 'refunded': exibir badge com cor violet
- [ ] Para cobranças com `refund_total > 0` e status != 'refunded' (partial): exibir badge "Reembolso parcial" com cor amber
- [ ] Esconder botao "Reembolsar" para cobranças com status 'refunded'
