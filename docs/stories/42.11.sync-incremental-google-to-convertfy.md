# Story 42.11 — Sync incremental Google -> Convertfy (RSVP status)

## Story

**Como** admin user da plataforma,
**Quero** que respostas de RSVP dadas no Google Calendar reflitam automaticamente no sistema,
**Para que** eu veja o status real de confirmacao dos participantes sem precisar perguntar.

## Contexto

### Estado atual

- Meetings criadas via 42.5 tem `google_event_id` no banco
- `meeting_participants` tem `google_rsvp_status` (adicionado em 42.1) mas nunca e populado
- Nao existe sync reversa (Google -> Convertfy)
- `GoogleCalendarService.getEvent()` ja funciona para buscar evento por ID

### O que precisa mudar

1. Service de sync reversa que busca RSVP do Google e atualiza `meeting_participants`
2. Endpoint manual para forcar sync
3. Mapeamento de status Google -> sistema
4. Atualizacao de `last_synced_at` no token do user

## Acceptance Criteria

- [x] **AC 42.11.1**: Funcao `syncRsvpFromGoogle(organizerUserId)` em `google-calendar-sync.service.ts`:
  - Busca meetings ativas (status = 'scheduled', scheduled_at > now) com `google_event_id` NOT NULL
  - Filtra meetings onde o organizador e o `organizerUserId`
  - Para cada meeting: busca evento no Google Calendar via `getEvent(google_event_id)`
  - Extrai `attendees[].responseStatus` do evento Google

- [x] **AC 42.11.2**: Endpoint `POST /api/integrations/google/calendar/sync`:
  - Autenticado pelo user logado
  - Chama `syncRsvpFromGoogle(user.id)`
  - Retorna `{ synced_count, errors_count, details: [...] }`

- [x] **AC 42.11.3**: Atualiza `meeting_participants.google_rsvp_status` com RSVP do Google:
  - Match participante por email (attendee.email vs participant.email ou profile.email)
  - So atualiza se valor mudou (evitar writes desnecessarios)
  - Case insensitive no match de email

- [x] **AC 42.11.4**: Mapeamento Google RSVP -> sistema:
  - `'accepted'` -> `google_rsvp_status = 'accepted'`
  - `'declined'` -> `google_rsvp_status = 'declined'`
  - `'tentative'` -> `google_rsvp_status = 'tentative'`
  - `'needsAction'` -> `google_rsvp_status = 'pending'`
  - Nota: `google_rsvp_status` e separado de `response_status` (local permanece como estava)

- [x] **AC 42.11.5**: `user_google_tokens.last_synced_at` atualizado apos sync bem-sucedido

- [x] **AC 42.11.6**: Erros de sync nao afetam dados locais:
  - Se getEvent falha para uma meeting: log error e continuar com as proximas
  - Se token expirou e refresh falha: marcar `is_active = false` e parar sync
  - Retornar contagem de erros no resultado

- [x] **AC 42.11.7**: Se evento Google nao existe mais (404): marcar `google_sync_status = 'error'` com mensagem "Evento deletado no Google Calendar"

## Technical Notes

### Fluxo de sync

```typescript
async function syncRsvpFromGoogle(organizerUserId: string): Promise<SyncReport> {
  const token = await getValidAccessToken(organizerUserId, 'profile')
  if (!token) return { synced_count: 0, errors_count: 0, details: [] }

  const adminClient = createAdminClient()

  const { data: meetings } = await adminClient
    .from('meetings')
    .select('id, google_event_id, google_calendar_id')
    .eq('user_id', organizerUserId)
    .eq('status', 'scheduled')
    .gt('scheduled_at', new Date().toISOString())
    .not('google_event_id', 'is', null)

  const calendarService = new GoogleCalendarService({ accessToken: token })

  for (const meeting of meetings || []) {
    try {
      const event = await calendarService.getEvent(meeting.google_event_id)
      const attendees = event.attendees || []

      const { data: participants } = await adminClient
        .from('meeting_participants')
        .select('id, email, participant_id, participant_type')
        .eq('meeting_id', meeting.id)

      for (const participant of participants || []) {
        const attendee = attendees.find(
          a => a.email?.toLowerCase() === participant.email?.toLowerCase()
        )
        if (attendee) {
          const rsvpStatus = mapGoogleRsvp(attendee.responseStatus)
          // So atualiza se mudou
          await adminClient
            .from('meeting_participants')
            .update({ google_rsvp_status: rsvpStatus })
            .eq('id', participant.id)
            .neq('google_rsvp_status', rsvpStatus) // skip se igual
        }
      }
    } catch (error) {
      // Log e continuar com proxima meeting
    }
  }
}
```

### Match de participantes

O match entre attendees do Google e `meeting_participants` e feito por email:
- `meeting_participants.email` precisa estar populado (feito na criacao — story 42.4)
- Se email nao esta preenchido: buscar email do profile via participant_id + participant_type
