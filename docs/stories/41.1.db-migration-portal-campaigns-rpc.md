# Story 41.1 — DB Migration: Indice de Deduplicacao + RPC get_portal_campaigns_with_metrics

## Story

**Como** portal user visualizando o calendario de campanhas,
**Quero** que a API retorne campanhas enriquecidas com metricas de performance Klaviyo do cache,
**Para que** eu veja open rate, click rate, receita e outras metricas sem chamadas extras a API Klaviyo.

## Contexto

### Problema

O portal do cliente mostra apenas contagens brutas da tabela `campaigns`. Os dados ricos de performance (open rate, click rate, bounce rate, RPR, AOV) ja existem na tabela `klaviyo_campaign_metrics`, populada pelo cron de sync. Porem, nao existe nenhuma query otimizada para jointar esses dados de forma segura (multi-tenant via `store_id`).

### Tabela `klaviyo_campaign_metrics`

A tabela `klaviyo_campaign_metrics` armazena metricas por campanha por periodo. A constraint UNIQUE e `(store_id, campaign_id, period_start, period_end)`, ou seja, o cron pode inserir rows com periodos diferentes para a mesma campanha (ex: `30d` e `90d`). Precisamos de deduplicacao via `DISTINCT ON` para pegar a row mais recente (`fetched_at DESC`) independente do periodo.

### Por que RPC e nao Query Builder

O Supabase JS client nao suporta `DISTINCT ON`. A query precisa de:
1. `DISTINCT ON (store_id, campaign_id)` para deduplicar metricas
2. `LEFT JOIN` para preservar campanhas sem metricas Klaviyo (campanhas manuais)
3. `COALESCE` para fallback de valores

Isso so e possivel com uma funcao SQL (RPC).

### 41.1.2 — Criar RPC `get_portal_campaigns_with_metrics`

- [x] Criar funcao PL/pgSQL com a seguinte assinatura:
  ```sql
  CREATE OR REPLACE FUNCTION get_portal_campaigns_with_metrics(
    p_store_ids UUID[],
    p_start_date DATE,
    p_end_date DATE,
    p_status TEXT DEFAULT NULL,
    p_channel TEXT DEFAULT NULL
  )
  RETURNS TABLE (
    -- campos da tabela campaigns (nomes REAIS verificados)
    id UUID,
    store_id UUID,
    store_name TEXT,
    name TEXT,                      -- campaigns.name (NAO campaign_name)
    klaviyo_campaign_id TEXT,       -- campaigns.klaviyo_campaign_id (NAO campaign_id)
    description TEXT,
    status TEXT,
    channel TEXT,
    campaign_type TEXT,
    scheduled_date DATE,            -- campaigns.scheduled_date (NAO send_date)
    scheduled_time TIME,
    send_datetime TIMESTAMPTZ,
    subject_line TEXT,
    segment_name TEXT,
    estimated_recipients INTEGER,
    color TEXT,
    -- metricas enriquecidas (COALESCE: cache > campaigns)
    recipients INTEGER,
    delivered INTEGER,
    opened INTEGER,
    clicked INTEGER,
    converted INTEGER,
    revenue NUMERIC,
    open_rate NUMERIC,
    click_rate NUMERIC,
    bounce_rate NUMERIC,
    conversion_rate NUMERIC,
    delivery_rate NUMERIC,
    click_to_open_rate NUMERIC,
    revenue_per_recipient NUMERIC,
    average_order_value NUMERIC,
    bounced INTEGER,
    unsubscribed INTEGER,
    unsubscribe_rate NUMERIC,
    -- metadata de cache
    has_klaviyo_metrics BOOLEAN,
    metrics_fetched_at TIMESTAMPTZ
    -- NOTA: campaign_batches NAO sao incluidos nesta RPC.
    -- Batches sao buscados separadamente na API route (schema diferente).
  )
  LANGUAGE plpgsql
  SECURITY DEFINER
  SET search_path = public
  ```
- [x] Corpo da funcao deve:
  1. CTE `latest_metrics` com `DISTINCT ON (store_id, campaign_id)` + `WHERE store_id = ANY(p_store_ids)` para pegar metricas mais recentes
  2. `LEFT JOIN` da tabela `campaigns` com a CTE usando **AMBOS** `store_id` E `klaviyo_campaign_id` (isolamento tenant)
  3. `INNER JOIN client_stores` para trazer `store_name`
  4. `COALESCE` para campos que existem em ambas tabelas (recipients, delivered, opened, clicked, converted/conversions, revenue/conversion_value): preferir cache, fallback para `campaigns`
  5. `WHERE c.store_id = ANY(p_store_ids)` para isolamento multi-tenant
  6. Filtro de data: `c.scheduled_date >= p_start_date AND c.scheduled_date < (p_end_date + INTERVAL '1 day')`
  7. Filtro opcional de status: `AND (p_status IS NULL OR c.status::text = p_status)`
  8. Filtro opcional de channel: `AND (p_channel IS NULL OR c.channel::text = p_channel)`
  9. `ORDER BY c.scheduled_date DESC`
  - **NAO incluir LEFT JOIN campaign_batches** — batches tem schema diferente (store_ids array, sem klaviyo_campaign_id) e sao buscados separadamente na API route

- [x] Implementacao de referencia (nomes de colunas VERIFICADOS contra o schema real):
  ```sql
  AS $$
  BEGIN
    RETURN QUERY
    WITH latest_metrics AS (
      SELECT DISTINCT ON (km.store_id, km.campaign_id)
        km.store_id,
        km.campaign_id,
        -- Nomes REAIS de klaviyo_campaign_metrics (verificados em 20250213_advanced_reporting.sql):
        km.recipients     AS km_recipients,
        km.delivered      AS km_delivered,
        km.opened         AS km_opened,       -- coluna real: "opened" (NAO "opens")
        km.clicked        AS km_clicked,      -- coluna real: "clicked" (NAO "clicks")
        km.conversions    AS km_conversions,
        km.conversion_value AS km_revenue,
        km.open_rate      AS km_open_rate,
        km.click_rate     AS km_click_rate,
        km.bounce_rate    AS km_bounce_rate,
        km.conversion_rate AS km_conversion_rate,
        km.delivery_rate  AS km_delivery_rate,
        km.click_to_open_rate AS km_ctor,
        km.revenue_per_recipient AS km_rpr,
        km.average_order_value AS km_aov,
        km.bounced        AS km_bounced,
        km.unsubscribed   AS km_unsubscribed,
        km.unsubscribe_rate AS km_unsub_rate,
        km.fetched_at
      FROM klaviyo_campaign_metrics km
      WHERE km.store_id = ANY(p_store_ids)   -- pre-filtro por tenant
      ORDER BY km.store_id, km.campaign_id, km.fetched_at DESC
    )
    SELECT
      -- Campos de campaigns (nomes REAIS verificados)
      c.id,
      c.store_id,
      cs.store_name,
      c.name,                                              -- NAO campaign_name
      c.klaviyo_campaign_id,                               -- NAO campaign_id
      c.description,
      c.status::TEXT,
      c.channel::TEXT,
      c.campaign_type::TEXT,
      c.scheduled_date,                                    -- NAO send_date
      c.scheduled_time,
      c.send_datetime,
      c.subject_line,
      c.segment_name,
      c.estimated_recipients,
      c.color,
      -- Metricas com COALESCE (cache preferido, campaigns fallback)
      COALESCE(lm.km_recipients, c.recipients)::INTEGER    AS recipients,
      COALESCE(lm.km_delivered, c.delivered)::INTEGER      AS delivered,
      COALESCE(lm.km_opened, c.opened)::INTEGER           AS opened,
      COALESCE(lm.km_clicked, c.clicked)::INTEGER         AS clicked,
      COALESCE(lm.km_conversions, c.converted)::INTEGER   AS converted,
      COALESCE(lm.km_revenue, c.revenue)::NUMERIC         AS revenue,
      COALESCE(lm.km_open_rate, 0)::NUMERIC               AS open_rate,
      COALESCE(lm.km_click_rate, 0)::NUMERIC              AS click_rate,
      COALESCE(lm.km_bounce_rate, 0)::NUMERIC             AS bounce_rate,
      COALESCE(lm.km_conversion_rate, 0)::NUMERIC         AS conversion_rate,
      COALESCE(lm.km_delivery_rate, 0)::NUMERIC           AS delivery_rate,
      COALESCE(lm.km_ctor, 0)::NUMERIC                    AS click_to_open_rate,
      COALESCE(lm.km_rpr, 0)::NUMERIC                     AS revenue_per_recipient,
      COALESCE(lm.km_aov, 0)::NUMERIC                     AS average_order_value,
      COALESCE(lm.km_bounced, 0)::INTEGER                 AS bounced,
      COALESCE(lm.km_unsubscribed, 0)::INTEGER            AS unsubscribed,
      COALESCE(lm.km_unsub_rate, 0)::NUMERIC              AS unsubscribe_rate,
      -- Metadata
      (lm.fetched_at IS NOT NULL)::BOOLEAN                 AS has_klaviyo_metrics,
      lm.fetched_at                                        AS metrics_fetched_at
    FROM campaigns c
    INNER JOIN client_stores cs ON cs.id = c.store_id
    LEFT JOIN latest_metrics lm
      ON lm.campaign_id = c.klaviyo_campaign_id            -- NAO c.campaign_id
      AND lm.store_id = c.store_id                         -- duplo filtro tenant
    WHERE c.store_id = ANY(p_store_ids)
      AND c.scheduled_date >= p_start_date                 -- NAO send_date
      AND c.scheduled_date < (p_end_date + INTERVAL '1 day')
      AND (p_status IS NULL OR c.status::TEXT = p_status)
      AND (p_channel IS NULL OR c.channel::TEXT = p_channel)
    ORDER BY c.scheduled_date DESC;
  END;
  $$;
  ```

## Riscos

| Risco | Mitigacao |
|-------|----------|
| Nomes de colunas em `klaviyo_campaign_metrics` podem diferir do esperado | AC 41.1.4 obriga verificacao antes de implementar |
| Indice pode impactar performance de escrita do cron | Indice e B-tree com 3 colunas — impacto minimo em INSERT |
| `DISTINCT ON` pode ser lento com muitas rows | Indice `idx_kcm_dedup_lookup` elimina sort step |
| Campanhas manuais (sem `campaign_id` Klaviyo) ficam sem metricas | `LEFT JOIN` preserva essas campanhas com `has_klaviyo_metrics = false` |
