## Story

**As a** membro da equipe,
**I want** ver claramente quais lojas sao avulsas e quais sao vinculadas,
**so that** eu possa gerenciar e priorizar vinculacoes pendentes.

## Acceptance Criteria

1. Badge visual em cada loja na listagem: "Avulsa" (variante `secondary`) ou "Vinculada: [Nome Cliente]" (variante `default`)
2. Filtro na listagem de lojas: Todas / Avulsas (com contagem) / Vinculadas (com contagem)
3. Filtro persiste durante a sessao (nao reseta ao navegar e voltar)
4. Pagina de detalhe `/stores/[id]` exibe status de vinculo no header
5. Se avulsa: mostra "Loja Avulsa — Sem cliente vinculado" com botao [Vincular] (link para Story 1.6)
6. Se vinculada: mostra "Vinculada a [Nome Cliente]" com link clicavel para `/clients/[client_id]`
7. Contagem de lojas avulsas e vinculadas e precisa e atualiza ao criar/vincular/desvincular
8. **[ARCH-C1 CRITICO]** Query do `/api/stores/control` corrigida: `clients!inner` mudado para `clients` (LEFT JOIN) para incluir lojas avulsas na listagem
9. **[ARCH-C1]** `store-control-panel.tsx` trata `client_name: null` sem crash — exibe badge "Avulsa" ao inves do nome do cliente
10. **[GAP-G5]** `StoreDetailTabs` prop `clientId` atualizada para `string | null`. Componentes filhos `StoreFormTab` e `StoreBriefingTab` tratam `clientId: null` sem crash

## Integration Verification

- IV1: Lojas vinculadas existentes exibem corretamente o nome do cliente (join com tabela `clients`)
- IV2: Tab "Lojas" em `/clients/[id]` NAO e afetada (componente `client-stores.tsx` continua igual)
- IV3: Performance da listagem nao degrada visivelmente com o filtro adicional

**Listagem de lojas:**

**Detalhe da loja:**
- `src/app/(dashboard)/stores/[id]/page.tsx` — Pagina de detalhe
  - Usa `createAdminClient()` para buscar loja (bypassa RLS)
  - Faz join: `.select("*, clients(id, name)")` — quando `client_id` e NULL, `clients` sera `null`
  - Renderiza: `<Link href={/clients/${store.client_id}}>Cliente: {store.clients.name}</Link>`
  - **PRECISA de null check** para evitar crash quando `client_id` e NULL

**Componente Badge (shadcn):**
- `src/components/ui/badge.tsx` — Componente Badge com variantes (default, secondary, destructive, outline)

**API de lojas — CORRECAO CRITICA (ARCH-C1):**
- `src/app/api/stores/control/route.ts` — Usa `clients!inner (id, name, company, status)` no select
- `!inner` = INNER JOIN — **EXCLUI lojas com client_id NULL** da listagem
- **CORRIGIR PARA:** `clients (id, name, company, status)` (sem `!inner` = LEFT JOIN)
- Apos correcao, `clients` sera `null` para lojas avulsas — tratar no frontend

**Interface StoreData local (store-control-panel.tsx):**
- O componente tem 966 linhas e uma interface `StoreData` local (NAO usa `ClientStore` do types)
- `StoreData.client_name` vem do `/api/stores/control` que faz join com `clients.name`
- Apos correcao do JOIN, `client_name` sera `null` para lojas avulsas — tratar com fallback

**Padrao de filtro existente:**
- `src/components/clients/clients-table.tsx` — Referencia de como filtros sao implementados no projeto
