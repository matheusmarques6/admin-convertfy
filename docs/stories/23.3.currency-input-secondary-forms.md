# Story 23.3 -- Correcao de Inputs Monetarios em Formularios Secundarios

## Status
Pending

## Story

**Como** usuario do admin,
**Quero** que todos os campos de valor monetario usem formatacao BRL correta,
**Para que** nenhum formulario do sistema tenha o bug de interpretacao de `.` como decimal.

---

## Dependencia

> Story 23.1 deve estar concluida (componente CurrencyInput criado e testado).
> Esta story reutiliza o componente criado em 23.1.

## Contexto

QA identificou que o mesmo bug (`type="number"` + locale BRL) existe em outros formularios alem dos financeiros principais. Esta story corrige os formularios secundarios por ordem de prioridade.

### Arquivos identificados pelo QA

| Arquivo | Contexto | Prioridade | Monetario? |
|---------|----------|------------|------------|
| `src/components/pipeline/deal-dialog.tsx` | Valor do deal (R$) -- afeta pipeline revenue | HIGH | SIM |
| `src/components/pipeline/import-rule-form.tsx` | Valor do deal, probabilidade | MEDIUM | PARCIAL (valor sim, % nao) |
| `src/components/stores/store-control-panel.tsx` | `duration_minutes` | LOW | NAO -- descartar |
| `src/app/(dashboard)/tools/page.tsx` | Calculadora revenue/ad-spend | LOW | Avaliar |
| `src/app/(dashboard)/reports/[id]/edit/page.tsx` | Metricas de report manual (~20 campos) | MEDIUM | PARCIAL |

### Arquivos avaliados e descartados (NAO monetarios)

| Arquivo | Campo | Motivo de exclusao |
|---------|-------|--------------------|
| `src/components/automations/workflow-builder.tsx` | `delay_minutes`, thresholds | Nao e monetario |
| `src/app/(dashboard)/automations/[id]/page.tsx` | `delay_minutes` | Nao e monetario |
| `src/components/stores/store-control-panel.tsx` | `duration_minutes` | Nao e monetario |
| `src/components/dashboard/financial-charts.tsx` | Recharts `<XAxis type="number">` | Chart axis, nao input |

---

## Acceptance Criteria

### 23.3.1 -- Deal Dialog (pipeline)

- [ ] Substituir input `type="number"` de valor em `deal-dialog.tsx`
- [ ] Usar componente `CurrencyInput` de 23.1
- [ ] Atualizar state e handlers para usar centavos + `centsToReais()`
- [ ] Se usa schema Zod: alterar `.min(0)` para `.min(1)` (centavos) para nao permitir zero
- [ ] Verificar que pipeline board soma valores corretamente (deals armazenados em reais no banco)
- [ ] Se deal tem modo de edicao: carregar valor do banco com `reaisToCents()` para popular CurrencyInput
- [ ] Auditar tabela `deals` antes de implementar (verificar se ha valores corrompidos)

### 23.3.2 -- Import Rule Form (pipeline)

- [ ] Substituir input(s) de valor monetario em `import-rule-form.tsx`
- [ ] Campos de probabilidade (%) NAO devem usar CurrencyInput -- apenas valores em R$
- [ ] Atualizar state e handlers

### 23.3.3 -- Reports Edit Page

- [ ] Ler `reports/[id]/edit/page.tsx` e classificar cada campo `type="number"`:
  - Campos monetarios (revenue, valor, etc.) -> usar CurrencyInput
  - Campos de metricas (contagem, percentual, taxa) -> manter `type="number"`
- [ ] Documentar decisao para cada campo na secao Dev Notes abaixo

### 23.3.4 -- Calculadora (tools page)

- [ ] Ler `tools/page.tsx` e avaliar se campos sao inputs do usuario ou calculadora
- [ ] Se calculadora read-only ou ferramenta de calculo rapido: pode manter `type="number"` (decisao documentada)
- [ ] Se input monetario usado para gerar resultados: usar CurrencyInput

---

## Dev Notes

- O componente `CurrencyInput` ja esta pronto em `src/components/ui/currency-input.tsx`
- Helpers `centsToReais` e `reaisToCents` disponiveis em `src/lib/currency.ts`
- Campos que NAO sao monetarios (percentuais, quantidades, contagens, delays) devem continuar com `type="number"`
- **IMPORTANTE**: para formularios de edicao (deal-dialog), valores carregados do banco (reais) devem ser convertidos com `reaisToCents()` antes de popular o CurrencyInput
- Documentar aqui a decisao para cada campo avaliado em reports e tools apos analise
