# Story 33.4 — Auto-Skip Stores Without Reporting Access

## Story

**Como** engenheiro de infraestrutura responsavel pelo cron,
**Quero** que lojas com falha recente de permissao do Klaviyo sejam automaticamente skipadas no cron,
**Para que** nao desperdicemos chamadas de API e tempo do orcamento de 300s em lojas que vao falhar de qualquer forma.

## Contexto

### Problema observado em producao

Quando uma loja tem uma API key com escopos faltando (ex: `accounts:read`, `metrics:read`), o cron:

1. Busca credenciais da loja
2. Tenta chamar `getCachedAccountInfo()` → falha com `KlaviyoPermissionError`
3. Registra erro para todos os periodos
4. Atualiza `client_stores.klaviyo_has_reporting_access = false`

Este ciclo se repete a cada execucao do cron (a cada 30min), desperdicando:
- 1-3 chamadas de API por loja
- 3-5 segundos do orcamento de 300s
- Log noise

### Evidencias de producao

```
[Cron] Almira: [PERMISSION] Klaviyo API key missing scopes: accounts:read
[Cron] ToysLand: [PERMISSION] Klaviyo API key missing scopes: metrics:read
```

Essas mesmas mensagens aparecem em CADA execucao do cron, sem mudanca.

### Mecanismo existente

O cron ja atualiza os campos de validacao na `client_stores` quando detecta erro de permissao (linhas 206-216 do `sync-reports/route.ts`):

```typescript
await supabase
  .from("client_stores")
  .update({
    klaviyo_validation_error: errorMsg,
    klaviyo_missing_scopes: err.missingScopes,
    klaviyo_validated_at: new Date().toISOString(),
    klaviyo_has_reporting_access: false,
  })
  .eq("id", store.id)
```

Porem, a query inicial que busca lojas (linhas 440-444) **nao filtra** por esses campos:

```typescript
const { data: stores } = await supabase
  .from("client_stores")
  .select("id, store_name, org_id")
  .or(KLAVIYO_CREDENTIALS_FILTER)
  .not("org_id", "is", null)
```

## Acceptance Criteria

### 33.4.1 — Filtrar lojas com falha recente de permissao

- [x] Modificar a query de busca de lojas para excluir lojas onde:
  - `klaviyo_has_reporting_access = false` **E**
  - `klaviyo_validated_at` esta dentro das ultimas 24 horas
- [x] Implementar via subquery ou filtro adicional no Supabase client:
  ```typescript
  // Opcao 1: filtro direto (se Supabase client suportar OR com date comparison)
  // Opcao 2: buscar todas e filtrar no app
  const now = new Date()
  const retryThreshold = new Date(now.getTime() - 24 * 60 * 60 * 1000).toISOString()

  const filteredStores = stores.filter(store => {
    // Include if has reporting access (or field is null/undefined)
    if (store.klaviyo_has_reporting_access !== false) return true
    // Include if validation is older than 24h (retry)
    if (!store.klaviyo_validated_at) return true
    return store.klaviyo_validated_at < retryThreshold
  })
  ```
- [x] Atualizar a query `select` para incluir `klaviyo_has_reporting_access, klaviyo_validated_at`

**Arquivo:** `src/app/api/cron/sync-reports/route.ts`

### 33.4.2 — Retry apos 24h

- [x] Lojas com `klaviyo_has_reporting_access = false` mas `klaviyo_validated_at` mais antigo que 24h devem ser incluidas (retry)
- [x] Definir constante `PERMISSION_RETRY_MS = 24 * 60 * 60 * 1000` (24 horas)
- [x] Se o retry falhar novamente, o mecanismo existente atualiza `klaviyo_validated_at` para agora, efetivamente adiando o proximo retry por mais 24h

### 33.4.3 — Logging de lojas skipadas

- [x] Log resumo de lojas skipadas com motivo:
  ```
  [Cron] Skipping 2 stores with recent permission failures: Almira (missing accounts:read, validated 3h ago), ToysLand (missing metrics:read, validated 1h ago)
  ```
- [x] Log total de lojas processadas vs skipadas:
  ```
  [Cron] Found 8 stores with credentials, processing 6 (skipping 2 with recent permission failures)
  ```

### 33.4.4 — Atualizar StoreRow interface

- [x] Atualizar a interface `StoreRow` (ou usar tipo separado para a query) para incluir os novos campos:
  ```typescript
  interface StoreRow {
    id: string
    store_name: string
    org_id: string | null
    klaviyo_has_reporting_access?: boolean
    klaviyo_validated_at?: string
    klaviyo_missing_scopes?: string[]
  }
  ```

## Riscos

| Risco | Mitigacao |
|-------|----------|
| Cliente corrige a key mas tem que esperar 24h | 24h e conservador; pode reduzir para 12h se necessario. Cliente pode re-salvar pelo portal a qualquer momento (reseta `klaviyo_has_reporting_access`) |
| Campos `klaviyo_has_reporting_access`/`klaviyo_validated_at` podem nao existir em lojas antigas | Filtro trata `null`/`undefined` como "include" (retry) |
