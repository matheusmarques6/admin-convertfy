## Story

**Como** usuario do portal do cliente,
**Quero** que quando o cache esta vazio, o sistema tente carregar dados de forma mais resiliente,
**Para que** eu veja dados reais em vez de uma tela vazia apos o primeiro acesso ou periodo sem sync.

---

## Contexto

Quando o cache esta vazio para um store+period, o fluxo atual e:

```
fetchKlaviyoFromCache() → null (cache miss)
  └→ liveFetchKlaviyoForPortal() com timeout de 45s
       ├→ tryAcquireLiveFetch() → pode estar em COOLDOWN (bloqueado)
       ├→ fetchKlaviyoPerformance() → pode dar TIMEOUT (Klaviyo rate limit)
       └→ Se falha → tenta stale cache → se tambem vazio → dataStatus = "error"
```

**Problemas:**
1. Cooldown bloqueia retry por minutos apos primeira falha
2. Timeout de 45s pode nao ser suficiente para Klaviyo em periodos grandes (90d)
3. Se stale cache tambem esta vazio → resposta com `dataStatus = "error"` sem dados
4. Nenhuma indicacao ao usuario de que dados estao sendo carregados

---

## Criterios de Aceitacao

- [ ] **CA1**: Se live fetch esta em cooldown, retornar resposta com `dataStatus = "syncing"`
      e mensagem "Dados estao sendo preparados. Tente novamente em X minutos"
- [ ] **CA2**: Se live fetch timeout, retornar `dataStatus = "timeout"` com mensagem especifica
      em vez de generico "error"
- [ ] **CA3**: Adicionar retry automatico no frontend quando `dataStatus` e "syncing" ou "timeout"
      (poll a cada 30s ate dados estarem disponiveis, max 3 tentativas)
- [ ] **CA4**: Se cache miss para ALL stores, tentar stores individualmente e retornar parciais
- [ ] **CA5**: Logar motivo exato da falha (cooldown, timeout, api error, no credentials)
      para facilitar debugging
- [ ] **CA6**: Typecheck + lint passando
