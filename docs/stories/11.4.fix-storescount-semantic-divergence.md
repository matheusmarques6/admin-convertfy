## Contexto

O campo `storesCount` na response do endpoint `total-revenue` tem semantica diferente dependendo do path executado:

- **Cache hit path** (linha 142): `storesCount: storeBreakdown.length` — conta apenas rows existentes no `store_revenue_summary`. Se uma loja nunca foi sincronizada (cron nao rodou, loja nova), ela nao aparece.
- **Live fetch path** (linha 453): `storesCount: stores.length` no log, mas o response e montado por `buildResponse()` que usa `storeBreakdown.length` — que neste path inclui todas as lojas buscadas via live.

Apos as Stories 11.1 e 11.2, o cache vai ter TODAS as lojas (incluindo zero revenue) e o filtro vai ser unificado. Mas ainda existe um window entre o deploy e o primeiro sync completo onde o cache pode ter lojas parciais.

A solucao definitiva e: `storesCount` deve vir de uma query separada a `client_stores` (quantas lojas TEM credenciais Klaviyo nesta org), nao de `rows.length` do cache.

---

## Objetivo

Garantir que `storesCount` sempre represente "total de lojas com credenciais Klaviyo na org", independente de quantas rows existem no cache.

## Arquitetura Tecnica

### Semantica dos campos na response

| Campo | Semantica | Fonte |
|-------|-----------|-------|
| `storesCount` | Total de lojas com Klaviyo na org | `client_stores` query (count) |
| `storesWithRevenue` | Lojas com `totalRevenueBRL > 0` | `storeBreakdown.filter()` |
| `storeBreakdown.length` | Lojas presentes no resultado | Cache rows ou live results |

### Query de contagem (lightweight)

A query usa `{ count: "exact", head: true }` que retorna apenas o count sem payload de dados. Custo minimo no Supabase.

```typescript
const { count: totalKlaviyoStores } = await adminSupabase
  .from("client_stores")
  .select("id", { count: "exact", head: true })
  .eq("org_id", orgId)
  .or(KLAVIYO_CREDENTIALS_FILTER)
```

### Impacto na Response

**Antes (cache com 2 lojas, org tem 4):**
```json
{
  "storesCount": 2,
  "storesWithRevenue": 2,
  "storeBreakdown": [/* 2 lojas */]
}
```

**Depois (cache com 2 lojas, org tem 4):**
```json
{
  "storesCount": 4,
  "storesWithRevenue": 2,
  "storeBreakdown": [/* 2 lojas */],
  "hasPartialData": true
}
```

Nota: `hasPartialData` pode ser true quando `storesCount > storeBreakdown.length` (cache incompleto). Considerar adicionar essa logica se nao existir.

## Riscos e Mitigacoes

| Risco | Mitigacao |
|-------|-----------|
| Query adicional no cache hit path adiciona latencia | `head: true` com count e <5ms no Supabase. Custo negligivel |
| `count` pode retornar null se query falhar | Fallback para `storeBreakdown.length` (comportamento atual) |
| Frontend pode nao exibir `storesCount` vs `storesWithRevenue` corretamente | Verificar componente do dashboard — campo ja existe na interface |
