## Story

**Como** administrador que configura uma API key da Klaviyo com scopes insuficientes,
**Quero** que o erro de permissao seja propagado corretamente ate o log do sistema com os scopes faltando identificados,
**Para que** eu possa diagnosticar o problema sem precisar comparar logs genericos com a documentacao da Klaviyo.

---

## Contexto

A story 16.3 introduziu `KlaviyoPermissionError` em `klaviyoRequest()` — quando a Klaviyo retorna 403 com `permission_denied`, o client agora lanca essa excecao com `missingScopes[]` preenchido.

Porem, os callers em `klaviyo-performance.service.ts` nao foram atualizados. Os tres catch blocks existentes (campaign report, flow report, metric aggregates) so tratam `KlaviyoRateLimitError` — qualquer outro erro e logado e a execucao continua com `campaignReport = null` / `flowReport = null`.

**Fluxo de falha atual:**

```
klaviyoRequest()
  → lanca KlaviyoPermissionError (com missingScopes[])
    → catch em klaviyo-performance.service.ts (linhas 318-325, 343-350, 390-397)
      → nao reconhece KlaviyoPermissionError → log.error generico + continue
        → campaignReport = null, flowReport = null
          → linha 429: !campaignReport && !flowReport → true
            → rateLimited = false
              → throw new Error("Falha ao conectar com a API do Klaviyo. Verifique as credenciais.")
                → [Portal LiveFetch] catch (linha 373-377) → log.error generico + return null
```

O resultado: o log de producao mostra `[Portal LiveFetch] Error for store X: Falha ao conectar...` em vez de `[Portal LiveFetch] Permission denied for store X: missing scopes [accounts:read, metrics:read]`. A informacao diagnostica de qual scope esta faltando e perdida.

**Por que o re-throw e a correcao correta:**

`KlaviyoPermissionError` indica erro de *configuracao permanente* — a API key nao tem os scopes necessarios. Ao contrario de erros transitorios (rate limit, timeout), nao ha retentativa que resolva. Engolir o erro e continuar executando e semanticamente incorreto: o resultado e dados falsos (null/vazios) apresentados como se a integracao estivesse funcionando.
