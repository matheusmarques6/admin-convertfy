## Story

**Como** administrador que configura uma API key da Klaviyo sem scopes para lists/segments,
**Quero** que o erro de permissao seja propagado e logado com os scopes faltando tambem para os dados de audiencia,
**Para que** eu possa identificar que a ausencia de dados de audiencia e causada por permissao insuficiente, e nao por listas vazias ou outro motivo.

---

## Contexto

As stories 16.5 e 16.5b corrigiram a propagacao de `KlaviyoPermissionError` nos callers de campaign report, flow report e metric-aggregates. Porem, existe um quarto ponto de silenciamento no mesmo service que ficou fora do escopo dessas stories: `fetchAudienceMetrics`.

**Localizacao exata do problema:**

`src/lib/services/klaviyo-performance.service.ts`, linhas 229-232:

```typescript
  } catch (error) {
    log.error("[KlaviyoPerf] Failed to fetch audience metrics:", error)
    return empty
  }
```

Este catch captura qualquer excecao lancada por `klaviyoRequest()` dentro de `fetchAudienceMetrics` — incluindo `KlaviyoPermissionError` — e a descarta, retornando `{ totalLeads: 0, engagedLeads: 0, engagementRate: 0 }` silenciosamente.

**Fluxo de falha atual:**

```
klaviyoRequest() — chamado com endpoint /lists/ ou /segments/
  → lanca KlaviyoPermissionError (scope insuficiente para leitura de lists/segments)
    → catch em fetchAudienceMetrics (linha 229)
      → log.error generico ("Failed to fetch audience metrics")
        → return { totalLeads: 0, engagedLeads: 0, engagementRate: 0 }
          → audiencePromise (linha 283) resolve com zeros
            → linha 625: audience = await audiencePromise → objeto vazio sem erro
              → KlaviyoPerformanceData retornado com audience zerada, sem indicacao do motivo
```

O resultado no dashboard: campos de audiencia (`totalLeads`, `engagedLeads`, `engagementRate`) aparecem como zero, indistinguivel de uma conta com listas vazias. O scope faltando e completamente perdido.

**Como `audiencePromise` e consumida:**

```typescript
// Linha 283 — iniciada em paralelo, antes dos catch blocks cobertos pelas stories 16.5/16.5b
const audiencePromise = fetchAudienceMetrics(apiKey)

// ... campanhas, flows, metric-aggregates executam aqui ...

// Linha 625 — awaited ao final da funcao, sem catch externo
const audience = await audiencePromise
```

O `await audiencePromise` na linha 625 **nao tem catch externo**. Se `fetchAudienceMetrics` lancasse, a excecao propagaria para o caller de `fetchKlaviyoPerformance` (portal dashboard ou clients route), onde ja existe tratamento para `KlaviyoPermissionError`. Ou seja: o re-throw dentro de `fetchAudienceMetrics` e suficiente — o caller ja esta preparado para receber `KlaviyoPermissionError`.
