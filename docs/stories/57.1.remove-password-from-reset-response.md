# Story 57.1 — Remover senha temporária da response do reset-password

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint", "manual-review"]

## Story

**Como** engenheiro de segurança,
**Quero** que o endpoint de reset de senha NÃO retorne a senha temporária no body da response,
**Para que** a senha não seja exposta em logs de request, proxies, error tracking ou network inspectors.

## Contexto

### Problema

O endpoint `src/app/api/portal-users/reset-password/route.ts` (linhas 93-96) retorna a senha em plaintext:

```typescript
return successResponse(request, {
  success: true,
  new_password: passwordToSet,  // ← EXPOSTA NA RESPONSE
}, { message: "Senha resetada com sucesso" })
```

A senha já é enviada por email (linhas 75-90). Não há razão para incluí-la na response HTTP.

### Risco

Se a request for logada por um proxy, interceptada via MITM, ou capturada por error tracking (Sentry, LogRocket), a senha fica comprometida. Isso é especialmente grave porque é uma senha de acesso ao portal do cliente.

## Acceptance Criteria

### 57.1.1 — Remover new_password da response

- [x] Remover o campo `new_password` do objeto de resposta
- [x] Response deve conter apenas `{ success: true }` com mensagem de sucesso
- [x] O envio de email com a senha temporária deve permanecer inalterado

**Given-When-Then:**

```
GIVEN Admin calls POST /api/portal-users/reset-password with valid userId
WHEN password is successfully reset
THEN response body does NOT contain new_password field
AND response body contains { success: true }
AND email with temporary password is sent to the user
```
