# Story 15.2 — Deprecar e Dropar Tabelas Legacy Klaviyo

## Contexto

A migration `20250125_10_klaviyo_metrics.sql` criou um sistema de sync de campanhas com 6 tabelas. A v1 desta story assumia que essas tabelas eram órfãs, mas o @qa identificou via grep que **elas ainda são usadas ativamente**:

| Objeto | Usado em | Como |
|--------|----------|------|
| `klaviyo_sync_jobs` | `src/lib/integrations/klaviyo-sync.ts` (5 locais) | INSERT + UPDATE |
| `klaviyo_sync_config` | `klaviyo-sync.ts` + `src/app/api/cron/sync-reports/route.ts` | UPSERT |
| `campaign_metrics_history` | `klaviyo-sync.ts` (linha 824) | SELECT |
| `campaign_alerts` | `klaviyo-sync.ts` (linhas 871, 886) | UPDATE |
| `v_campaigns_with_metrics` (view) | `klaviyo-sync.ts` (linhas 666, 718, 745) | SELECT |
| `v_unread_alerts` (view) | `klaviyo-sync.ts` (linha 844) | SELECT |

A migration original também criou 3 views (`v_campaigns_with_metrics`, `v_campaign_rankings_revenue`, `v_unread_alerts`) que serão derrubadas pelo `CASCADE` no DROP TABLE da Story 15.2b. Dois dessas views têm referências ativas no código e **precisam ser removidas aqui** — do contrário a pre-condição "zero referências" da Story 15.2b não será satisfeita.

O módulo `klaviyo-sync.ts` é o sistema de sync antigo. O sistema ativo atual usa `klaviyo_campaign_metrics`, `klaviyo_flow_metrics` e `store_revenue_summary`. Para poder dropar as tabelas legadas, é necessário primeiro **remover as referências de código**.

Esta story é redesenhada em **duas fases sequenciais**:

- **Fase A (this story):** Remover as referências às tabelas e views legacy no código TypeScript
- **Fase B (story futura 15.2b):** Dropar as tabelas e views do banco — a ser executada após Fase A concluída

## Objetivo

**Como** engenheiro de software,
**Quero** remover as referências ativas às tabelas e views legacy (`klaviyo_sync_jobs`, `klaviyo_sync_config`, `campaign_metrics_history`, `campaign_alerts`, `v_campaigns_with_metrics`, `v_unread_alerts`) do código TypeScript,
**Para que** seja seguro dropar esses objetos do banco em uma etapa posterior sem quebrar o sistema.
