# Story 53.1 — Fix lojas invisíveis por org_id NULL/mismatch

## Epic 53 — Client Stores Visibility & Multi-Org Fixes

## Contexto

Clientes como "Romario de Santana Lima" (org Dripslum) têm lojas no banco que NÃO aparecem na tab "Lojas" do admin. A UI mostra "Nenhuma loja vinculada" mesmo com stores existentes.

### Causa raiz (duas falhas encadeadas)

1. **`org_id` NULL em `client_stores` e `clients`**: 5 stores e 3 clients com `org_id = NULL`. Stores com `org_id NULL` são invisíveis tanto pela query `.eq("org_id", X)` (SQL: `NULL = X` é FALSE) quanto pelo RLS `can_access_store()` (JOIN via `org_id` falha em NULL).

2. **`/api/stores` usa org do admin, não do cliente**: `resolveOrgId(user.id)` retorna a primeira org do admin logado. Quando admin vê cliente de outra org, o filtro `.eq("org_id", orgDoAdmin)` exclui todas as lojas desse cliente.

## Acceptance Criteria

### AC 53.1.1 — Fix API route: skip org_id filter when client_id is provided + user is admin
- [x] Em `src/app/api/stores/route.ts`, quando `client_id` está presente:
  - Se user é system admin (`profiles.role = 'admin'`): NÃO aplicar `.eq("org_id", orgId)`
  - Se user é owner/member: manter filtro `.eq("org_id", orgId)` como defense-in-depth
- [x] Reutilizar info de `getAccessibleStoreIds()` (que já checa `profiles.role`) para evitar query extra

### AC 53.1.2 — Fix store creation: fallback org_id from resolveOrgId
- [x] Em `src/app/api/client-stores/credentials/route.ts` POST:
  - Se `client.org_id` é NULL, usar `resolveOrgId(user.id)` como fallback
  - Log warning quando fallback é usado (indica client sem org)

### AC 53.1.3 — Migration: backfill org_id + NOT NULL constraint
- [x] Criar migration que:
  - Backfill `client_stores.org_id` a partir de `clients.org_id` onde ambos existem
  - Backfill `clients.org_id` a partir de `org_members` do criador (via `created_by` ou first member)
  - Adicionar `NOT NULL` constraint em `client_stores.org_id` (com default derivado)
  - Criar trigger BEFORE INSERT que auto-preenche `org_id` a partir de `clients.org_id`

### AC 53.1.4 — UX: diferenciar empty state vs error state
- [x] Em `client-stores.tsx`, adicionar estado `error` separado de `stores === []`
- [x] Mostrar banner persistente de erro com botão "Tentar novamente" quando fetch falha
