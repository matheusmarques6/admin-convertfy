## Story

**Como** usuario do portal,
**Quero** criar uma campanha de copy generation selecionando lojas e disparar a geracao automatica,
**Para que** o n8n receba o pedido e gere as copies para cada loja.

---

## Contexto

Esta e a rota principal da feature. Ela:
1. Valida o body com `generateRequestSchema` (story 20.1)
2. Autentica o portal user via `createClient()` + lookup em `client_portal_users`
3. Filtra store_ids para garantir que pertencem ao client (seguranca multi-tenant)
4. Cria registro em `campaign_generations` com status `processing`
5. Cria registros em `campaign_generation_stores` para cada loja
6. Dispara webhook n8n com payload completo (non-blocking — falha nao impede response)
7. Suporta regeneracao: se `generation_id` informado, incrementa version das lojas existentes

Os testes TDD cobrem: validacao (5), auth (2), criacao nova (4), regeneracao (2), webhook dispatch (6), edge cases (2) = 20+ testes.

## Acceptance Criteria

### 20.3.1 — Validacao do request body

- [x] Parsear body com `generateRequestSchema` da story 20.1
- [x] Retornar 400 se `name` ausente ou vazio
- [x] Retornar 400 se `date` ausente ou formato invalido (aceitar apenas YYYY-MM-DD)
- [x] Retornar 400 se `store_ids` ausente ou array vazio
- [x] Retornar 400 se `store_ids` contem non-UUIDs

### 20.3.2 — Autenticacao e autorizacao

- [x] Usar `createClient()` para obter user autenticado via `auth.getUser()`
- [x] Lookup em `client_portal_users` com `user_id` para obter `client_id`
- [x] Retornar 401 se portal user nao encontrado
- [x] Consultar `client_stores` filtrando por `client_id` para obter lojas validas
- [x] Filtrar `store_ids` do request — remover qualquer store_id que NAO pertence ao client
- [x] Deduplicar `store_ids` (remover duplicatas)

### 20.3.3 — Criacao de nova campanha

- [x] Inserir em `campaign_generations` usando `adminClient`: name, date, reference_doc_url (ou null), client_id, status="processing"
- [x] Inserir em `campaign_generation_stores` um registro por loja: generation_id, store_id, status="pending", version=1
- [x] Retornar 200 com `{ generation_id, status: "processing" }`
- [x] Se `reference_doc_url` nao fornecido, salvar como null

### 20.3.4 — Regeneracao (generation_id existente)

- [x] Se `generation_id` informado no body, buscar `campaign_generations` por id
- [x] Retornar 403 se a campaign pertence a outro `client_id`
- [x] Atualizar status da campaign para `processing`
- [x] Para lojas que ja existem na campaign: incrementar `version` e setar `status="generating"`
- [x] Para lojas novas: inserir com version=1

### 20.3.5 — Disparo webhook n8n

- [x] Fazer POST para `process.env.N8N_CAMPAIGNS_WEBHOOK_URL`
- [x] Headers: `Content-Type: application/json`
- [x] Payload conforme contrato:
  ```json
  {
    "generation_id": "uuid",
    "campaign_name": "...",
    "campaign_date": "YYYY-MM-DD",
    "reference_doc_url": "..." | null,
    "drive_folder_id": "..." | null,
    "callback_url": "https://.../api/campaigns/webhook-callback",
    "stores": [{ "store_id", "store_name", "country", "language", "version" }]
  }
  ```
- [x] `drive_folder_id` vem da campaign existente (regeneracao) ou null (nova)
- [x] `callback_url` deve usar `process.env.NEXT_PUBLIC_APP_URL || "http://localhost:3000"` (padrao do projeto)
- [x] Cada store deve incluir `version` (1 para novo, incrementado para regeneracao)
- [x] Webhook failure e NON-BLOCKING: logar erro mas retornar 200 ao client

### 20.3.6 — Error handling

- [x] Se insert em `campaign_generations` falha, retornar >= 400
- [x] Usar `logger.child()` para logging contextual
- [x] Usar `adminClient` para todos os writes (contorna RLS)

### 20.3.7 — Todos os testes TDD passando

- [x] Executar `npx vitest run src/app/api/campaigns/generate/route.test.ts`

### Fluxo resumido

```
Request -> Validate body -> Auth (getUser + portal lookup)
  -> Filter store_ids by client ownership
  -> Dedup store_ids
  -> If generation_id: load existing + increment versions
  -> Else: insert new campaign_generations + stores
  -> Fire webhook (non-blocking)
  -> Return { generation_id, status }
```
