# Story 57.7 — Sanitizar logs de erros (crypto + callbacks externos)

## Executor Assignment

executor: "@dev"
quality_gate: "@architect"
quality_gate_tools: ["typecheck", "lint"]

## Story

**Como** engenheiro de segurança,
**Quero** que logs de erro não incluam objetos de erro completos de APIs externas nem dados sensíveis,
**Para que** tokens, credentials e PII não vazem para sistemas de logging.

## Contexto

### Problema

Vários pontos do código logam objetos de erro completos que podem conter dados sensíveis:

1. **crypto.ts:46-49**: `log.error("Failed to decrypt value", { error })` — pode conter contexto sensível
2. **meta/callback/route.ts:108**: `log.error("Shopify token exchange error:", errorData)` — response body completo
3. **google/callback/route.ts:94**: `log.error(errorData)` — response body completo
4. **errors.ts:122-127**: `pgError.details` e `pgError.hint` podem expor schema info

## Acceptance Criteria

### 57.7.1 — Sanitizar log de decriptação

- [x] Em `src/lib/crypto.ts` (~linha 47): logar apenas `error.message` e tipo do erro, não o objeto completo
- [x] Não logar nenhum dado que estava sendo decriptado

**Given-When-Then:**

```
GIVEN decryption fails for a credential
WHEN error is caught in crypto.ts
THEN log contains error type and message only
AND log does NOT contain the encrypted data or error stack
```

### 57.7.2 — Sanitizar logs de OAuth callbacks

- [x] Em callbacks Meta/Google: logar apenas `status` e `error` field da response, não o body completo
- [x] Nunca logar access_token, refresh_token, ou code

**Given-When-Then:**

```
GIVEN Meta token exchange fails with error response
WHEN error is logged
THEN log contains { status: 400, error: "invalid_grant" }
AND log does NOT contain access_token or full response body
```

### 57.7.3 — Sanitizar logs de erros Postgres

- [x] Em `src/lib/api/errors.ts` (~linha 122): logar `pgError.code` e `pgError.message`, mas NÃO `pgError.details` e `pgError.hint` (podem conter SQL)

### 57.7.4 — Typecheck

- [x] `npm run typecheck` passa sem erros novos

## Tasks / Subtasks
