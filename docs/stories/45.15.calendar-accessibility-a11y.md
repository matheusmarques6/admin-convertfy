# Story 45.15 — Calendar Accessibility (a11y)

## Status: Done
## Effort: MEDIUM (2-3h)
## Priority: LOW

## Context

The calendar grid uses `div` elements with `onClick` handlers but no ARIA roles, keyboard navigation, or focus management. This fails WCAG AA compliance. Screen reader users and keyboard-only users cannot interact with the calendar.

This was split from Story 45.14 because a11y is an independent concern with higher effort (arrow key grid navigation, focus management, screen reader testing).

## Acceptance Criteria

### ARIA Roles
- [ ] **AC 45.15.1** Calendar grid has `role="grid"` with `role="row"` on each week row and `role="gridcell"` on day cells
- [ ] **AC 45.15.2** Column headers (Dom, Seg, Ter...) have `role="columnheader"`

### Keyboard Navigation
- [ ] **AC 45.15.3** Day cells have `tabIndex={0}` on focused cell, `tabIndex={-1}` on others (roving tabindex pattern)
- [ ] **AC 45.15.4** Enter/Space on a day cell triggers the same action as click
- [ ] **AC 45.15.5** Arrow key navigation: left/right = prev/next day, up/down = prev/next week
- [ ] **AC 45.15.6** Home/End navigate to first/last day of month
- [ ] **AC 45.15.7** Focus wraps to next/prev week at row boundaries

### Screen Reader
- [ ] **AC 45.15.8** Focus indicator visible on selected day cell (meets 3:1 contrast ratio)
- [ ] **AC 45.15.9** Day cells have `aria-label` announcing: day number, month, and campaign count (e.g., "15 de março, 3 campanhas")
- [ ] **AC 45.15.10** Today's cell has `aria-current="date"`

### Visual Completeness
- [ ] **AC 45.15.11** Trailing empty cells rendered to complete last grid row visually (consistent grid shape)
- [ ] **AC 45.15.12** Lint + typecheck pass
