## Story

**Como** administrador do sistema,
**Quero** adicionar camadas extras de isolamento no dashboard do portal,
**Para que** mesmo com bugs no codigo aplicacional, os dados de um cliente nunca vazem para outro.

---

## Contexto

### Problema 1: `fetchKlaviyoFromCache` sem `org_id`

A funcao `fetchKlaviyoFromCache()` em `src/app/api/portal/dashboard/route.ts` (linha 111) filtra apenas por `store_id` sem `org_id` ao consultar `store_revenue_summary`, `klaviyo_campaign_metrics` e `klaviyo_flow_metrics`.

Embora o `store_id` ja seja validado contra o client do portal user (defense primaria), adicionar `org_id` como defense-in-depth garante que mesmo um bug no codigo de validacao nao expoe dados cross-org.

### Problema 2: `dashboard_cache` SELECT policy cross-org

A policy `"Users can view dashboard_cache"` usa `is_org_member()` sem filtrar QUAL org. Qualquer membro de qualquer org pode ler todo o cache. Fix: usar `can_access_store(store_id)`.

### Linhas especificas

`fetchKlaviyoFromCache` e chamada em 3 locais:
- Linha 757: single store, cache read
- Linha 787: single store, stale fallback
- Linha 840: multi store, parallel cache reads

A funcao recebe `(storeId, period, supabase)`. O parametro `supabase` na verdade recebe `adminClient` nos call sites.

### Parte B: Fix dashboard_cache SELECT policy

- [ ] **AC 18.1.4.5** — Criar migration `supabase/migrations/20260305_03_fix_dashboard_cache_policy.sql`:
  ```sql
  -- ============================================================
  -- Story 18.1.4: Fix dashboard_cache SELECT policy
  -- Problema: is_org_member() sem filtrar QUAL org
  -- Fix: can_access_store(store_id) valida ownership
  -- ============================================================

  DROP POLICY IF EXISTS "Users can view dashboard_cache" ON dashboard_cache;
  CREATE POLICY "Users can view dashboard_cache" ON dashboard_cache
    FOR SELECT TO authenticated
    USING (is_admin() OR can_access_store(store_id));
  ```

## Riscos

- **R1:** Se `org_id` nao estiver disponivel no fluxo, adicionar lookup extra (1 query a mais por request). Impacto de performance minimo.
- **R2:** `can_access_store()` pode nao funcionar para portal users, mas dashboard portal usa `adminClient` (bypassa RLS). Risco LOW — afeta apenas admin dashboard reads de `dashboard_cache`.
- **R3:** Se `store_revenue_summary` ou `klaviyo_*_metrics` nao tiverem coluna `org_id`, as queries com `.eq("org_id", orgId)` retornarao 0 rows. Verificar schema antes de implementar.

## Rollback

**Codigo:** Reverter `dashboard/route.ts` (remover parametro `orgId` e queries extras).
**Migration:**
```sql
DROP POLICY IF EXISTS "Users can view dashboard_cache" ON dashboard_cache;
CREATE POLICY "Users can view dashboard_cache" ON dashboard_cache
  FOR SELECT TO authenticated
  USING (is_org_member());
```
