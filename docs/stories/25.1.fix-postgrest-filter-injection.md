## Story

**Como** operador do sistema que expoe um endpoint publico de tracking para storefronts,
**Quero** que todo input do usuario seja sanitizado antes de ser usado em filtros PostgREST,
**Para que** visitantes maliciosos nao consigam extrair dados de pedidos (emails, nomes, enderecos, valores) via injection no parametro `q`.

---

## Contexto

### Vulnerabilidade identificada

O endpoint `GET /api/tracking/lookup?q=...&store=...` e publico (sem autenticacao, CORS `*`). Na linha 241 de `lookup/route.ts`, o `cleanQuery` (input do usuario com apenas `#` removido) e interpolado diretamente no filtro `.or()` do Supabase:

```typescript
// VULNERAVEL — linha 241
.or(`shopify_order_number.eq.${cleanQuery},order_name.ilike.%${cleanQuery}%`)
```

### Vetor de ataque

Um atacante pode enviar:
```
GET /api/tracking/lookup?q=,customer_email.neq.null&store=VALID_STORE_ID
```

O `.or()` resultante vira:
```
shopify_order_number.eq.,customer_email.neq.null,order_name.ilike.%,customer_email.neq.null%
```

PostgREST interpreta `customer_email.neq.null` como filtro valido, retornando **todos os pedidos da loja** com seus dados pessoais.

### Analise de impacto (QA)

| Fator | Valor |
|-------|-------|
| Autenticacao necessaria | NENHUMA — endpoint publico |
| Complexidade | BAIXA — GET request simples |
| Cross-tenant | MITIGADO — `.eq("tracking_store_id")` e AND separado |
| Within-store | **ALTO — dump completo de pedidos da loja** |
| PII exposta | Emails, nomes, valores, enderecos de entrega |

### Superficie adicional verificada

- Linha 221: `.ilike("customer_email", cleanQuery)` — **SEGURO** (SDK parametriza)
- Linha 260: `.ilike("tracking_number", ...)` — **SEGURO** (SDK parametriza)
- Apenas `.or()` e vulneravel por aceitar string raw

## Acceptance Criteria

### 25.1.1 — Sanitizar input para filtros PostgREST

- [x] Criar funcao `sanitizePostgrestValue(input: string): string` que remove caracteres perigosos para filtros PostgREST: `,`, `.` (em posicao de operador), `(`, `)`, `[`, `]`
- [x] Aplicar sanitizacao em `cleanQuery` ANTES de usar em qualquer filtro
- [x] A funcao deve permitir caracteres alfanumericos, espacos, hifens e `#`
- [x] Regex sugerida: `input.replace(/[^a-zA-Z0-9\s\-#]/g, "")`

### 25.1.2 — Substituir `.or()` interpolado por queries seguras

- [x] Substituir o `.or()` da linha 241 por duas queries separadas com `.eq()` e `.ilike()` parametrizados
- [x] Deduplicar resultados por `id` antes de processar
- [x] As queries devem rodar em `Promise.all` (paralelo) para nao adicionar latencia

### 25.1.3 — Sanitizar input do path de tracking code

- [x] Na linha 260, aplicar `escapePostgrestLike()` para escapar `%` e `_` no `query`
- [x] NOTA: `.ilike()` do SDK Supabase ja parametriza o valor (seguro contra PostgREST injection), mas o escape de wildcards LIKE evita buscas excessivamente amplas

### 25.1.4 — Validacao de input no entry point

- [x] Adicionar validacao no inicio do handler: rejeitar `q` que contenha operadores PostgREST obvios (`,` seguido de `.eq.`, `.neq.`, `.gt.`, `.lt.`, `.in.`, `.is.`)
- [x] Retornar 400 com mensagem generica (nao revelar detalhes da protecao)
- [x] Log com `log.warn("Suspicious query blocked", { query, ip })` para monitoramento

## Dev Notes

### Funcoes a criar

```typescript
// Em lookup/route.ts ou em um util compartilhado

/** Remove caracteres que podem manipular filtros PostgREST */
function sanitizePostgrestValue(val: string): string {
  return val.replace(/[^a-zA-Z0-9\s\-#]/g, "")
}

/** Escapa wildcards LIKE para uso seguro em ilike */
function escapePostgrestLike(val: string): string {
  return val.replace(/[%_\\]/g, "\\$&")
}
```

### Codigo de referencia — substituicao do .or()

```typescript
// ANTES (vulneravel):
const { data: orders } = await admin
  .from("tracking_orders")
  .select("id, order_name, ...")
  .eq("tracking_store_id", trackingStoreId)
  .or(`shopify_order_number.eq.${cleanQuery},order_name.ilike.%${cleanQuery}%`)
  .order("order_created_at", { ascending: false })
  .limit(10)

// DEPOIS (seguro):
const safeQuery = sanitizePostgrestValue(cleanQuery)

const [{ data: byNumber }, { data: byName }] = await Promise.all([
  admin
    .from("tracking_orders")
    .select("id, order_name, customer_name, customer_email, order_created_at, shipped_at, delivered_at, total_price, currency, line_items, shipping_address")
    .eq("tracking_store_id", trackingStoreId)
    .eq("shopify_order_number", safeQuery)
    .order("order_created_at", { ascending: false })
    .limit(10),
  admin
    .from("tracking_orders")
    .select("id, order_name, customer_name, customer_email, order_created_at, shipped_at, delivered_at, total_price, currency, line_items, shipping_address")
    .eq("tracking_store_id", trackingStoreId)
    .ilike("order_name", `%${safeQuery}%`)
    .order("order_created_at", { ascending: false })
    .limit(10),
])

// Deduplicar
const seen = new Set<string>()
const orders = [...(byNumber || []), ...(byName || [])].filter((o) => {
  if (seen.has(o.id)) return false
  seen.add(o.id)
  return true
})
```
