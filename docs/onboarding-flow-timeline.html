Fluxo de Onboarding — do cadastro à implementação na Omnisend

7 etapas no kanban · 8 agentes de IA + 1 workflow n8n · pipeline de geração em 2 fases com 2 gates manuais
Agente de IA (Claude / modelo de imagem) Workflow n8n (externo) Ação humana / manual Gate de aprovação (bloqueia avanço)
Etapa 1 · coluna entrada
Entrada
Responsável: CS · SLA 2h

Admin/CSM cadastra cliente + loja. Nasce o registro em onboardings com form_token (validade 30d) e a pipeline de 7 colunas é instanciada. Cliente recebe link do formulário por WhatsApp.

Cadastro & bootstrapManual
Input
  • client_id, store_id, plano, MRR
  • WhatsApp do cliente
Output
  • onboarding + form_token
  • 7 colunas / tasks por checklist
Etapa 2 · coluna cliente_formulario
Formulário — cliente preenche o briefing
Responsável: CS · SLA 72h

Cliente abre /form/{token} (sem login), responde ~24 perguntas e faz uploads (logo, manual de marca, referências). Ao completar seções, a IA gera o briefing; o cliente revisa, edita inline e confirma.

🤖 Agente · Geração de BriefingIA — cascata
claude-sonnet-4-6 (Anthropic) → fallback OpenRouter → fallback template determinístico
Input
  • respostas do formulário
  • Pesquisa & Diagnóstico (brand_*, icp_*, tone_*, ads_*) — fonte primária
  • dados da loja (nicho, país, moeda, idioma)
Output — BriefingContent (JSON)
  • about_brand, audience, language_tone
  • visual_identity {palette, fonts, references}
  • offers_and_differentials
Grava em onboardings.briefing (+ versão pura da IA). Estado: generating → generated_pending_review.
🔒
GATE 1 — confirmação do briefing pelo cliente. Ao confirmar, avança automático para a Etapa 3 e dispara (fire-and-forget) dois webhooks n8n: o de briefing e o de geração de copy dos emails.
Paralelo · workflow externo
Pesquisa & Diagnóstico + Ads Analyzer
Executa no n8n (fora do app) · alimenta o briefing e a copy

Workflow n8n investiga a marca e preenche os 5 pilares em client_stores. Ao terminar, faz callback para o app.

Workflow · Pesquisa (5 pilares) + Ads Analyzern8n
Input
  • store_id, marca, URL, produtos
  • dados de anúncios
Output → client_stores
  • brand_* · store_story · icp_* · tone_*
  • ads_score, strengths, risks, opportunities
Callback POST /api/webhooks/n8n/pesquisa-completa → dispara a geração de copy. Campo regeneration:true faz o callback pular a copy (só atualiza pesquisa).
Pipeline automático · Epic AE
Geração dos emails — Fase 1 (copy)
Disparado por briefing confirmado / pesquisa completa · orquestrado por dispatchEmailCopyWebhook

Antes da copy, o Arquiteto monta uma referência visual por loja×email e extrai a estrutura (blueprint). Depois a copy é escrita bloco a bloco.

🤖 Arquiteto · Montador (Component Assembler)IA
claude-sonnet-4-6
Input
  • outline do email + nicho + persona
  • tom de voz, mood, produtos
  • biblioteca de variantes de componentes
Output → store_email_references
  • HTML de referência montado
🤖 Arquiteto · Blueprint GeneratorIA
claude-sonnet-4-6
Input
  • HTML de referência (do Montador)
  • contexto da marca + outline
Output → store_email_blueprints
  • objective, messaging, subject_hint
  • blocks [{type, label, purpose, needs_image}]
Fallback: blueprint default por flow_type se o JSON vier inválido.
✍️ Copy — geração do texto dos blocosn8n (principal)
fallback in-app: claude-sonnet-4-6 (watchdog após 15 min)
Input (payload Convertfy)
  • briefing + brand + produtos
  • blueprints + blocos + referências
Output → email_flow_emails / email_blocks
  • subject, preheader
  • content de cada bloco
Callback POST /api/webhooks/n8n/email-copy → status copy_ready. Não dispara a Fase 2 — aguarda o gate de identidade visual.
🔒
GATE 2 — confirmação da identidade visual pelo designer. Valida cores, fontes e logo. Ao confirmar, um trigger enfileira o sinal render e a Fase 2 roda automaticamente nos emails em copy_ready.
Pipeline automático · Epic AE
Geração dos emails — Fase 2 (imagem → HTML → QA)
Orquestrado por runPhase2InBackground · watchdog recupera travamentos
🖼️ ImagemIA — imagem
openai/gpt-5.4-image-2 (via OpenRouter)
Input
  • Master Prompt v2 (marca, nicho, paleta, persona)
  • imagem do produto (modo product_ref)
Output → email_blocks.content
  • image_url (signed) + image_alt
Só blocos com needs_image=true · limite de 6 imagens por email.
🧱 HTMLIA
claude-opus-4-7

Output → email_flow_emails.html
  • HTML completo, email-safe
✅ QAIA
claude-sonnet-4-6 (+ pré-checagens determinísticas)
Input
  • HTML final + blocos + objetivo
Output → email_flow_emails.qa_issues

Etapa 3 · coluna preview_producao
Preview — designer cria os pilotos
Responsável: Designer · SLA 48h

Designer trabalha no workspace de produção e entrega 4 pilotos (welcome, carrinho ×2, pós-compra) usando os emails gerados como base.

Produção dos 4 pilotosManual
Input
  • Brand Brain + emails gerados
Output
  • 4 pilotos (uploads no workspace)
Etapa 4 · coluna preview_aprovacao
Aprovação do preview
Responsável: Estrategista · SLA 48h

Pilotos enviados ao cliente. Se aprovado → avança. Se ajustes solicitados → volta à Etapa 3 (incrementa versão).

Coleta de feedback + decisãoManual
Input
  • 4 pilotos + feedback do cliente
Output
  • aprovado / ajustes / sem resposta
Etapa 5 · coluna emails_finais
Emails finais em produção
Responsável: Designer · SLA 60h

7 tasks (uma por flow), cada uma listando os emails do flow. Os pilotos aprovados já entram marcados como ✓ (pré-fill). Designer finaliza os ~30 emails restantes. Ao concluir, gera o token de tutorial e cria a task de implementação.

Finalização dos 7 flows (~30 emails)Manual
Input
  • pilotos aprovados (pré-preenchidos)
  • emails gerados pelo pipeline
Output
  • todos os emails dos 7 flows prontos
Etapa 6 · coluna implementacao
Implementação na Omnisend
Responsável: Ops · SLA 36h

Time de implementação abre o Modo Implementação (handoff read-only) e monta as automações na Omnisend. Não há push automático — tudo é copiado/colado do handoff estruturado.

Handoff & montagem na OmnisendManual
Input — tela de handoff
  • setup: gatilho, público, evento, espera
  • envelope: remetente, assunto, pré-cabeçalho
  • UTM (Source / Medium / Campaign)
  • cupons a criar + copy bloco-a-bloco
Output — na Omnisend
  • automações criadas e ativas
  • cupons criados
  • teste E2E (screenshots)
UTM Campaign = automation: {Source} | {Flow} | {Loja} ({brandID Omnisend}) — brandID buscado ao vivo só se a Omnisend estiver conectada.

Cliente ativo — handoff final
Responsável: Estrategista · SLA 8h

Email de "conta ativa" ao cliente, criação do registro de Acompanhamento e agendamento da call de 30 dias.

Output
